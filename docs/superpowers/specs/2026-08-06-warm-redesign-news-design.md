# 設計: あたたかい紙のリデザイン + AIアップデート欄

作成: 2026-08-06。オーナーとのブレインストーミングで節ごとに承認済み。

## 決まったこと（経緯）

| 論点 | 決定 |
|---|---|
| 彩りの方向 | **A案「あたたかい紙」**（クリーム地＋暖色。B案の「色＝構造」の考え方も見出し帯に取り込む） |
| 画像の範囲 | **全部入り**（トップのヒーロー＋記事カードのアイキャッチ＋記事ページ冒頭＋見出し帯の塗り分け） |
| イラストの題材 | **状況で使い分け**：道具（基本）／小ロボット（AI情報・相棒役）／植物と太陽（余白の飾り） |
| 作り方 | **部品ライブラリ＋自動生成**（手描きはヒーロー1枚だけ） |
| ニュース | トラッカーの news.json を**トップに直近分**＋**全件は /news/**。major のお知らせは深掘りキューへ自動追記 |
| 優先順 | **先にニュース欄を出す**（オーナー指示「とりあえず、今日の更新、トップに載せて」2026-08-06） |

## ① 配色システム

`static/style.css` の `:root` 変数を暖色系へ差し替える。クラス名・レイアウトは変えない。

**ライト:**

| 変数 | 値 | 用途 |
|---|---|---|
| `--bg` | `#FAF5EC` | クリーム地 |
| `--fg` | `#3D3428` | 焦げ茶の本文 |
| `--muted` | `#857661` | 弱い文字 |
| `--line` | `#E8DCC8` | 罫線 |
| `--accent` | `#A8481D` | リンク（コントラスト確保のため深いレンガ色） |
| `--accent-deco` | `#D85A30` | 飾り専用のコーラル（帯・バー・アイコン。文字には使わない） |
| `--code-bg` | `#F3EBDD` | コード背景 |
| `--card-bg` | `#FFFDF8` | カード |
| `--prompt-bg` | `#FBF0DC` | 指示文（琥珀がかった紙色。左バーはコーラル） |

**ダーク:** 青灰色ではなく**茶系の暗色**で世界観を保つ。`--bg: #1C1712` / `--fg: #EFE7DA` / `--muted: #A99B87` / `--line: #3A3226` / `--accent: #F0997B` / `--code-bg: #262019` / `--card-bg: #241D15` / `--prompt-bg: #2C2317`。

**5ブロック見出し帯の塗り分け**（`h2.what/.need/.ask/.fix/.next` に個別の帯色＋バー色）:

| class | ライトのバー | 意味づけ |
|---|---|---|
| `.what` 🎯 | コーラル `#D85A30` | 主役の色 |
| `.need` 📋 | 琥珀 `#BA7517` | 準備 |
| `.ask` 💬 | オリーブ `#639922` | 実行 |
| `.fix` 🛠️ | レンガ赤 `#A32D2D` | 困りごと（警告系の赤に寄せる） |
| `.next` 🚀 | ピンク `#D4537E` | 発展 |

帯背景は各バー色の淡色。ダークは各色の明るい段（200相当）をバーに、暗い同系をベースに。class 無しの既定 `◆` はコーラル。

**変えないもの:** マーカーの意味（黄=重要 / 赤=事故る）と上限（13/5）、指示文ボックスが最も目立つ序列、本文コントラスト、`validate.py` の全チェック。

## ② イラスト部品ライブラリ

`tools/make_eyecatch.py` を新設。部品＝ノート・鉛筆・付箋・クリップ・コーヒー・ルーペ・歯車・小ロボット・芽・太陽。

- **配役**: ヒーロー＝机の道具＋小ロボット（`static/images/hero.svg`、手作り1枚）／アイキャッチ＝カテゴリ別（レシピ=ノート・鉛筆系、ツール=歯車・ルーペ系、深掘り=小ロボット登場）／余白の飾り＝芽・太陽
- **自動生成**: 記事slugをシードに配置・部品選択を揺らす（決定的＝同じslugなら同じ絵）。出力は `static/images/eyecatch/<slug>.svg`。ビルドで記事に対応するアイキャッチが無ければ生成する。**記事を足す手数はゼロ**（深掘りルーティンの自動公開記事にも絵が付く）
- SVGは `width`/`height`/`viewBox` 必須・`<style>` 内蔵・`@media (prefers-color-scheme: dark)` 対応（既存の図と同じ流儀）
- **黒塗り事故の封じ込め**: SVG内で使う class が `<style>` に定義されているかを `validate.py` に追加（2026-08-05 の実害の再発防止。座標検査は文字が無い絵を素通りするため、この検査が唯一の網）
- アイキャッチの `alt` は「<カテゴリの絵柄説明>のイラスト」を自動で付与（`validate.py` の alt 必須チェックに適合）

## ③ ページの変わり方

- **トップ** (`templates/index.html`): ヒーロー（題・リード＋イラスト右置き、スマホは下に回り込み）→ **AIアップデート欄（④）** → 新着記事カード
- **記事カード** (`_macros.html`): 左に80px角のアイキャッチ・カテゴリ色のバッジ
- **記事ページ** (`article.html`): パンくず → アイキャッチバナー（720×180）→ 題 → 本文（見出し帯の塗り分けが効く）
- 固定ページ・一覧は同じ変数と部品で自動的に変わる

## ④ AIアップデート欄（ニュース掲載）

データ源は `data/tracker/news.json`（2026-08-06 時点 187件・通常の増加は1日3件前後）。

- **トップに直近分だけ**：お知らせ系（rss / anthropic_news）は新しい順に**10件**、日付・ベンダーバッジ・3行要約（`summary_ja`）付き。モデル系（huggingface / openrouter / github_releases）は**同期間をベンダー単位で畳んで1〜2行**（例「Claude Code: v2.1.221〜223」）。メール配信と同じ粒度ルール（お知らせは読む・モデルは見る）
- **全件は `/news/`**：月別グルーピングで全項目。トップ欄の末尾に「すべて見る →」
- major には「重要」印。`summary_ja` が無い項目はタイトルのみで表示（壊れない）。欄の隅に**「要約は自動生成」**の注記
- 鮮度の表現は「1日数回、自動更新」（トラッカーの実測は平均112分間隔。「毎時」「即時」とは書かない）
- **ビルド**: `src/build.py` が news.json を読み描画。`build.yml` の `paths:` に `data/tracker/news.json` を追加（ニュースが増えた時だけ再デプロイ。seen.json だけの既読更新では動かない——1日13回の無駄ビルドを防ぐ既存設計を維持）
- news.json が無い/壊れている場合：**ビルドを止める**（「全部通る or 何も出さない」の既存方針どおり）

## ⑤ 重要なアップデートの記事化

- トラッカーの **check 実行時**（major が確定する場所。digest では major は既に流れてしまっている）、**major かつ お知らせ系**の新規項目を `content/_deepdive_queue.md` へ自動追記
- 歯止め: 1日3件まで／追記済み uid を状態に記録し二度追記しない／手動追記（スマホ3タップ）は併用可
- 出典が読めない場合（例: openai.com のHTMLは cf-mitigated 403 実測）、深掘りルーティンは書かずに `- [!]` で止まる——**この挙動は維持**（二次情報で作り話を書かない）。読めなかった件はダイジェストに出して人が判断
- 「重要」の基準はトラッカーの major 分類をそのまま使う（新しい判定は作らない）

## 実装の段階

1. **Phase 1（先行・今日）**: ④ニュース欄＝ build.py の news 読み込み・トップ欄・/news/・build.yml paths 追加。現行配色のまま出す
2. **Phase 2**: ①配色の暖色化（ライト/ダーク）＋③見出し帯の塗り分け
3. **Phase 3**: ②部品ライブラリ＋アイキャッチ自動生成＋ヒーロー1枚＋validate.py のSVG class検査
4. **Phase 4**: ⑤major自動追記（トラッカー側）

## テスト方針

各Phaseで pytest に追加（現在343 passed を維持）。Phase 1: news.json の読み込み・粒度ルール（お知らせ/モデルの振り分け・ベンダー畳み）・件数制限・summary_ja 欠落時の挙動・壊れたJSONでビルド停止。Phase 3: 生成SVGの viewBox/width/height/alt・class定義検査の赤緑両方。
