## 1. 全体像とデータフロー

```
稼ぎ方研究担当（新設・毎日15:30 JST・opus-5）
  │ 稼ぎ方を選ぶ → 最新化リサーチ → 工程分解 → 単価出典 → 計算式 → コンプラ照合
  ▼
content/_recipe_queue.md「### 副業」節に研究パック（1日1〜3件）
  │   作業ログ・見送り理由・沈黙禁止1行 → content/_earn_research.md（新設・_で始まりビルド対象外）
  ▼
書き手（21:00・変更最小）… パックを上から書く。実測（工程を架空データで試す）は書き手が実行
  ▼
validate.py（ビルドで強制）… 金額ブロックの型・禁止文字列
  ▼
公開 → 確認担当（22:38）… 観点5（金額の型）を追加
```

🔑 **役割分担の芯＝研究担当は「調べて設計する」、書き手は「試して書く」。**
実測を書き手に残すのは、書き手の縛り1「公開する指示文は必ず自分で試す」を
崩さないため（研究担当の実測結果を書き手が写すと、伝言ゲームで縛り1が形骸化する）。

時刻 15:30 の理由: 既存5本（06:12／08:00／13:47／21:00／22:38）とずらして
キューの取り合いを避け、当日21:00の書き手に間に合わせる。

## 2. 研究パックの様式（8点）

既存のネタ採用5点に金額3点を足す。**8点全部書けないパックはキューに入れない**
（既存ルールと同じ落とし方）。

| # | 項目 | 内容 |
|---|---|---|
| 1〜5 | 既存5点 | 題／根拠／実測の芯／既存との切り分け／節の縛り（ネタ帳の様式のまま） |
| 6 | **単価の出典** | URL＋確認日（YYYY-MM-DD）。プラットフォーム公表値・公的統計・大手調査に限る。🚨 **AIに相場を聞いて書かない**（下記） |
| 7 | **計算式** | 出典つき単価 × 明示した前提 → レンジ（例: 文字単価0.5〜3円 × 月2万字 = 月1〜6万円）。立たなければ直引き、どちらも無ければ金額欄なし |
| 8 | **帯の判定** | 副業帯／準本業帯／事業帯＋事業帯なら追加の縛り（§5） |

🚨 **単価はAIに聞かない。実在するページを開いて確かめる。**
うちの記事 `sell-what-you-already-do`（自分の棚卸しを売り物に変える）が**実測で出した結論がこれ**＝
「私は何で稼げますか」と聞くと、頼んでもいない金額が3〜4件返り、**どれにも出どころが書いていない**。
金額を禁じると0件になり、代わりに自分で確かめる手順が返った。
⚠️ **AIに相場を聞いて金額ブロックに書くのは、自分のサイトが実測で否定した型をそのままやることになる。**

## 4. 金額目安ブロックと機械検査

記事に収入金額を書くときは、この標準部品**だけ**を使う（自由記述の金額文は禁止）:

```html
<div class="money-note">
金額の目安: 月1〜6万円（副業帯）
根拠: 文字単価0.5〜3円（出典: <a href="...">○○公表価格</a>・2026-08-15確認）× 月2万字の場合
この金額は目安であり、収益を保証するものではありません。
</div>
```

`validate.py` の新検査（**完全一致の少数だけ＝誤検知ゼロ設計**）:

1. **ブロック整合**: earn記事に `money-note` ブロックがあれば、中に
   ①出典リンク（http）②確認日（YYYY-MM-DD）③固定免責文
   「収益を保証するものではありません」——の3点が揃わなければ exit 1
2. **禁止文字列**: 「必ず稼げ」「確実に稼げ」「絶対に稼げ」等の**完全一致6個**。
   誤検知してはいけないものが2つ＝①免責文自身（語を選んで避ける）
   ②🚨 **詐欺を防ぐ場面（`scene: safety`）**——この場面は**詐欺の勧誘文句を引用するのが仕事**
   （既に `too-good-offer-checklist.md` が「AIで稼げる」を引用している）。**場面ごと除外する**
3. **やらないこと**: ブロック外の収入金額の機械検出は**しない**。
   「月3,000円のツール」（価格）と「月3万円稼げる」（収入）を機械で確実に区別できず、
   誤検知は検査全体の信用を殺す（この家の判断済みの型）。
   ここは書き手の縛り＋確認担当の観点5（人間系）が持つ

🔑 **機械＝型の整合と黒文字列、人間＝意味の判定。**

見た目: `money-note` 用のCSSを1つ足す（既存の注記ボックスの型に合わせる。
ライト／ダーク両テーマで確認）。

## 5. 3帯の縛り

| 帯 | レンジ | 追加の縛り |
|---|---|---|
| 副業帯 | 月数万円 | 標準の型どおり（出典＋計算式＋免責） |
| 準本業帯 | 月数十万円 | ＋作業量の前提を必ず明示（週何時間相当か） |
| 事業帯 | 月百万円超〜（年商数百万〜数千万） | 具体額は出典があるときだけ。**構造の解説として書く**（「あなたも到達できる」とは書かない）＋**「この帯に到達するのはごく一部」を必ず明記**（生存者バイアス） |

- **「本業でも通用する」の実装**＝事業帯の記事は**構造の進化**を書く:
  自分が作業する（副業帯）→ AIで検品と段取りを仕組み化（準本業帯）→
  人に任せて自分は判断に回る（事業帯）。金額の夢ではなく構造の解説で上の帯を扱う
- どの帯でも黒レーンは不変: 投資・トレード系／情報商材紹介／規約違反のAI量産は書かない
