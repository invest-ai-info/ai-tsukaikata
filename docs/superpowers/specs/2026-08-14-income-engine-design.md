# 収入エンジン設計 — 一次情報の複利化 × 人間は判断ゲートだけ（2026-08-14）

オーナー指示「ネット上に落ちている情報をそのまま使うのではなく、独自に進化させて
常に改善する。人間とAIの融合は最小限の労力で最大限の効果。副業にとどまらず
本業としても収入が得られる設計を」。

設計の方法＝現状把握3体・独立設計4角度（20案）・検証3レンズ（法務・実行可能性・
誠実さ）のワークフローで出し、この文書に統合した。**検証済みの結論だけを書く。**

🚨 **この文書は法的助言ではない。**グレーの最終確定は弁護士相談（アジェンダ9項目
準備済み）で行う。収入の約束もしない——ここに書くのは**エンジンと測定ゲート**であり、
「儲かる」ではなく「続ける/やめるを何の数字で判定するか」である。

---

## 0. 設計の芯（3層）

| 層 | 中身 | いまの状態 |
|---|---|---|
| **資産層** | 実測の一次情報（証拠ファイル・台帳・検証済み研究）を「1記事1回きり」から「何度も働く資産」へ | 証拠20本・台帳33件・記事322本（両サイト計）が**1回しか使われていない** |
| **時間層** | 人間の仕事を「判断ゲート4種」だけに圧縮 | 実測 週190〜215分。**6割は判断ではなく摩擦**（Xコピペ・YTアップ・確認） |
| **収入層** | 複数エンジンを黒/グレー/白で登録し、測定ゲートで淘汰 | 稼働中の白は**A8のみ**（15ページ・絶対額僅少）。他は全部ゲート待ちか未着手 |

🔑 **なぜ「ネットの情報の再利用」に勝てるか＝うちは測るから。**
本もネット記事も「AIにはこう頼むとよい」で止まる。うちは架空データで実際に試し、
機械判定した結果を出せる（証拠照合129/129較正済み）。**この実測コーパスは、
同じ年月をかけない限り誰にも複製できない。**鮮度が落ちる情報ではなく、
**モデルが更新されるたびに価値が増す情報**（再実測でまた1本書ける）。

## 1. 人間とAIの契約（融合の形）

**人間専任は4種だけ＝法務・お金・アカウント操作・方向決定。**これはコードで守る
（判断の前例→ルール昇格の仕組みに、この4種を**恒久除外するデニーリスト**を入れる。
入れないと人間ゲートが静かに空洞化する——検証で最優先の指摘だった）。

| 接点 | 頻度 | 時間 | 中身 |
|---|---|---|---|
| **操縦席**（1画面） | 毎日 | **5〜8分** | X投稿ボタン（intentプリフィル・ボタンは人間のまま＝規約適合）・YTドラッグ・異常バッジ確認 |
| **司令室**（決裁パケット） | 週1・月曜 | **45〜60分** | 全判断を1本のmdに集約: 昇格判定・キュー採否・🚩エスカレ承認・進捗。チェックを入れるだけ |
| 突発の即日レーン | 稀 | 0〜10分/週 | 「出てしまう」型（黒混入・サイト不整合）だけ。「出ない」型（孤児化）は週次で安全 |

**現状 週190〜215分 → 目標 週90分前後。**さらに「決裁の前例台帳」で同型判断3回
→ルール昇格（昇格先は**コードのみ**。プロンプト文言への昇格は禁止＝腐りの型）により
週次時間は逓減する。⚠️ 全20案を採ると合算週110〜150分で現状と大差ない——
だから下の採択順とWIP規律が本体。

## 2. 段階機械（本業化の定義）

「本業化」は施策の積み増しではなく、**進級条件をコードで判定する4段階**として定義する
（`stage_gate.py`・閾値はYAMLが唯一の正＝既存文書側の数値は参照に置換。二重記載は腐る）。

| 段階 | 定義 | 進級条件（機械判定） |
|---|---|---|
| **S0**（現在地） | 供給自動・観測ほぼゼロ | AT: クリック0・表示17回／MW: 月380人・購読1（本人）／稼働白レーン=A8のみ |
| **S1** 検索の芽 | 集客が測定に乗る | AT週クリック10以上 かつ 2サイト合算 月間1,000人以上、またはメアド50件 |
| **S2** 副業 | 入金イベントの再現 | 任意の白レーンで入金3か月連続ゼロ超 かつ メアド500件（note Phase0トリガーと整合） |
| **S3** プロダクト | 本業級への入口 | Phase0（¥980で20〜30人）再現 **＋ 弁護士相談完了** |

⚠️ **AdSenseは前提に置かない**（追い風扱い）。前進は白レーンだけで可能な構成にする。

## 3. 採択と順序（20案 → 検証済みの実行計画）

検証結果: **黒0**・白多数・グレー3・要修正11（大半は「番人の欠落」という同じ型）。
**WIP規律＝同時進行2本まで。metric_gate の判定が出るまで次を開かない**
（first_step 20本を一斉に積むと、着手判断の隘路——この家の実測済みボトルネック——が再演する）。

### Phase 0 — 要石（今週。すべての前提）

| # | 何 | なぜ先か |
|---|---|---|
| **D-4 弁護士の期日ゲート** | 相談を「メアド100件 or 2026-10-31 の早い方」の進級条件としてコード化。期日までに未実施ならグレー全域（検証台帳公開・MW教材化・スクリーナー・メール送信自動化）を**自動で今四半期は白のみ設計に格下げ** | グレー3件＋要修正の過半の前提を兼ねる**要石**。どちらに転んでも「決めない状態」が消滅する。⚠️ 特商法（販売時の氏名住所表記）と J-Quants 派生データの規約もアジェンダに追加 |
| **計測の較正** | GA/UTM が両サイトで実際に発火しているかをエンドツーエンドで確認（既知流入を流して観測） | ほぼ全ゲートが GSC/GA の数字を前提にする。**計測が死んでいると全ゲートが「0=不人気」と誤判定して正しい施策を静かに殺す**——ゲート網全体の単一障害点 |
| **D-2 収益レーン・レジストリ + A8横展開** | 全経路を `income_lanes.yml` に三色登録（裏面に**支出台帳**も同形式で）。白の即時タスク=A8のFX/暗号資産系商材を該当guide末尾へ横展開（inject_ads.py 1行・15→20ページ超） | **唯一いま動いている白レーン**の増枠＝最初の入金イベント（S2条件）への最短経路。⚠️ track-record/シグナル系への注入禁止をコードで強制・about/privacyのASP開示を先に消化 |

### Phase 1 — 時間の基盤（人間の週90分体制）

順に: **B-4 静かな欠落の番人**（キュー↔公開↔サイトの三面突合。⚠️ 番人自身の
heartbeat＝走査のたび沈黙禁止の1行コミット＋automation-health登録が必須——
番人が死んだ状態と平穏が同じ見た目になるのは8/11型の再演）→ **B-1 週次司令室**
（0項目でも必ず生成＝沈黙禁止・月曜朝に存在チェック）→ **B-2 毎日の操縦席**
（常設ヘルス行＝データ取得時刻・件数・「本日0件と判定」の明示。バッジ0と生成停止を
視覚で区別）→ **B-3 🚩自動トリアージ** → **B-5 前例台帳**（デニーリスト必須）。

### Phase 2 — 資産の複利化

**A-1 実測コーパスの構造化**（証拠ファイルに機械可読ブロック→JSONコーパス→
横断ページ。⚠️ 横断ページは3枚固定・**noindexで開始**しGSCゲート通過後に解禁＝
AdSense総量リスク・「evidenceファイル数=コーパス行数」の突合をビルドに）→
**C-4 2サイト相互導線**（実測レシピ⇄実運用システムのペア注入。inject_ads.py方式・
1記事1リンク）→ **C-5 MWにRSS追加＋週次ダイジェスト下書き**（送信の自動化は
弁護士相談の結論が条件。登録者10件到達までは feed 生成とリンク併記のみ）→
**A-2 モデル更新追試エンジン**（更新検知でIssue起票・成果物コミットでのみクローズ・
月1ドライランでハーネスの腐りを平時検出）→ **A-5 運用実測レポート月次**
（素材から法務系を除外するフィルタをコードで）。

### Phase 3 — 収入の面を広げる（ゲート解放後）

- **D-3 検証済みレシピ集**: 無料PDF（メアド動線）だけ先行。**KDPは3条件**
  （AI生成申告・人間の通読1回・版更新は四半期1回）充足後。🚨 誠実さの検証が
  当てた急所＝**「追加執筆ゼロの自動編纂Kindle」は、うちの safety/earn が読者に
  警告している型と外形が一致する。**奥付とLPに「サイトの検証済み記事からの自動編纂・
  全内容は無料で読める」を明示し、自分の黒/グレー/白基準への自己判定を公開して透明化する
- **D-5 講座・テンプレの待機リストLP**: 🚨 同じ急所＝**収入実績ゼロの段階で
  「稼ぎ方」を売る外形は、詐欺シリーズが警告する型と正面衝突。**LPに「直接収益は
  現時点でゼロ」を明示・訴求は自動化と時間削減の実測に限定・**教材化の着手は
  S2到達（入金イベント実在）を前提条件**にして自己矛盾を構造的に消す
- **C-3 SNS自動投稿**: Bluesky単独で先行（審査不要・トークン管理単純）。対象は
  ai-tsukaikata系＋MW教育記事の告知に**レーン単位で限定**（シグナル・相場観系は
  弁護士相談まで自動レーンから除外）。投稿ごとにAPI応答検証・失敗即通知
- **C-1 台本アーカイブページ**: 主力1〜2chに限定・1日1本上限・noindex開始・
  AdSense再申請の前後で止められるスイッチ付き
- **A-3 検証台帳の公開**: ローカル生成まで今やってよい。**公開スイッチはD-4通過に従属**
- **A-4 データセット公開**: モデル出力の再配布規約の確認が先（A-2・D-3にも共通する基盤論点）

### 見送り（理由ごと固定）

受託・コンサル（時間の切り売り・複利ゼロ）／X API課金・ブラウザ自動化（凍結リスク非対称）／
YouTube API再挑戦（封印済みの袋小路）／3つ目のサイト（S1確認まで分散禁止）／
有料note即時開始（売る相手が実測1件=本人）／実測本数の量産加速（AdSenseリスクだけ増える）。

## 4. 横断標準（検証3体の「どの案も触れていない穴」への回答）

1. **新設の自動実行はすべて**: heartbeat＋沈黙禁止1行コミット＋automation-health登録を義務化（個別設計から通知設計を没収）
2. **最低母数ルール**: 表示回数が閾値未満のGSC/GAゲートは「判定持ち越し」（いまの母数=表示17回では大半のゲートがサイコロになる）
3. **自動生成ページの総量予算**: 月あたり新規自動ページ数を計測・上限管理（個別に注意しても総量は誰も見ていない→AdSense「規模拡大」判定に合算で効く）
4. **支出台帳**: income_lanes.yml の裏面として生成系コスト（API・ルーティン）を同形式で管理。収入ゼロ段階で支出総額に上限を置く
5. **凍結の後始末SOP**: 停止判定時の noindex化・sitemap除外・撤去の標準手順（残置ページはクロール評価に効き続ける）
6. **縮退運転**: オーナー不在1週間でも壊れない（X/YTは欠落を記録して再開・週次決裁は翌週に持ち越し・即日レーンのみメール）
7. **公開しない中間生成物**（決裁パケット・診断書・決裁ログ）は public リポジトリに置かない（drafts露出と同型の事故面を増やさない）
8. **人間時間の総予算=週90分**。超える採択はどれかを落とす（このWIP規律自体を週次パケットに1行で入れる）

## 5. オーナーにしかできないこと（この設計の人間側）

| いつ | 何 | 時間 |
|---|---|---|
| 期日ゲートまで | **弁護士相談の予約と実施**（アジェンダに特商法・J-Quants派生データを追加した版で） | 準備30分＋相談60〜90分・1回 |
| 任意 | AdSense申請ボタン（押す/押さないもレジストリの1行として扱う） | 1分 |
| A8横展開後 | A8管理画面での成果確認（APIが無いため） | 月数分 |
| 毎日 | 操縦席（X投稿ボタン・YTドラッグ） | 5〜8分 |
| 毎週月曜 | 司令室の決裁パケットにチェック | 45〜60分 |

**要約**: 資産＝実測の一次情報を「何度も働く」形に正規化し、人間＝週90分の
判断ゲートに圧縮し、収入＝白レーンから段階機械で育てる。約束するのは金額ではなく、
**すべてのエンジンに測定ゲートと番人が付いていること**。
