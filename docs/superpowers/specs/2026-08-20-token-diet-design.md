## 1. 触らないもの（品質の本体だから）— 先に宣言する

| 触らない | 理由 |
|---|---|
| **実測の回数**（2回転・全数実測） | 差別化の源泉。取材の全24回が「書かない判断」を生んだばかり |
| **証拠の全文主義**（`docs/evidence/`） | 畳むと `_evidence_errors()` が落ちる設計（較正73%の実測）。書き捨てで日々の読みには乗らない |
| **確認担当の読む量**（当日記事+証拠） | 唯一の人相当ゲート。ここを削ると🚩が出なくなる |
| **モデルの格下げ** | 「クオリティを下げずに」への正面回答は「死んだテキストを読ませない」こと。tiering は削減効果を測った後の別議題 |

## 2. 設計 — ローテーション（機械・LLM不要）

**原則: 生きているファイルのパスは変えない**（クラウド側プロンプトの修正が不要になる）。
重みだけを archive へ移す。要約はしない＝**逐語で移す**（機械にできるのはそれだけ。数値を扱わない）。

### 2-1. `tools/rotate_archives.py`（新規・TDDで書く）

| 対象 | 規則 | 移動先 |
|---|---|---|
| `_recipe_queue.md` 待ち行列 | `- [x]`/`- [!]` のブロック（字下げ行ごと）を逐語で移動。**跡地に索引1行**＝`- [x→保管] 題 — slug/理由の1行目`。`- [ ]` は順序ごと触らない。空になった小見出しは丸ごと移動 | `content/_recipe_queue_archive.md` |
| `_deepdive_queue.md` | **`- [x]` だけ**移動。⚠️ `- [!]` は残す（経路遮断の再試行対象＝CLAUDE.md の設計） | `content/_deepdive_queue_archive.md` |
| `_topic_ideas.md` | 日付見出しの節のうち**直近3日より古いもの**を移動。⚠️ 「申し送り」見出しの節は**逐語で「## 申し送りの繰り越し」へ移す**（消さない・畳まない。閉じるのは人） | `content/_topic_ideas_archive.md` |
| `_earn_research.md` 作業ログ | 直近3日より古い日付節を移動（**heartbeat が最終日付を見る設計＝3日残せば48h検知は無傷**。回帰テストで固定） | `content/_earn_research_archive.md` |
| `_review_log.md` | 直近3日より古い日次節を移動。跡地に索引1行＝`- 2026-08-15: 9本・直し10・🚩5 →保管`。⚠️ 未処理🚩の追跡は従来どおり SESSION_HANDOFF ②（今日の🚩2もそこで拾った実績） | `content/_review_log_archive.md` |

- archive は追記専用・誰も全文を読まない前提（真の保管庫は git 履歴）。`_` 始まりなのでビルド対象外（既存と同じ規約）
- 索引行の生成は**切り出しだけ**（項目の1行目＋`公開:` の slug）。要約・言い換えはしない

### 2-2. 実行の仕組み — GitHub Actions（毎日 04:30 JST・LLMトークン0）

- 06:12 のネタ探しより前。⚠️ 遅延は常態でよい＝キューは在庫なので回転が半日遅れても壊れない
- 変更が無い日はコミットしない（沈黙禁止の対象外＝これは担当ではなく機械）
- 実装時に skill `github-actions-cron-best-practice` を読むこと

### 2-3. 番人 — 回転が止まったことを検知する（rules as code）

- `check_freshness.py` に `file_budgets()` を追加＝生きているファイルが予算超過なら週次で赤:
  queue 1,500行 / topic_ideas 600行 / earn 700行 / review 800行 / deepdive 600行
- **ビルドは止めない**（記事の公開を人質にしない）。超過＝「回転が止まった」のシグナル（heartbeat と同じ思想）
- pytest には2倍の上限でハードテスト（暴走の底）

## 6. 実装で変わったこと（2026-08-20 実装時の追記・こちらが正）

- **マーカー行（`- [x] 題` / `- [x] URL`）は跡地に残す**＝深掘りの URL 重複防止
  （`tracker.deepdive.queued_urls`）とネタ探しの題での突き合わせが、この行を読むため。
  移すのは字下げの詳細だけ。跡地は `  - →保管: 公開: \`slug\``（slugが無ければ詳細の1行目60字）
- **申し送りの節は「繰り越しへ移動」ではなく、その場に残す（回転の対象外）**。閉じるのは人。
  溜まりすぎは行数予算が週次で知らせる
- **保持は「日数」ではなく「新しい日付3つぶんの節」**＝担当が止まっても空にならず、
  heartbeat の最新日付が必ず残る（回帰テストで固定）
- **pytest のハード上限はやめた**＝pytest は深掘りの関所（落ちると記事を削除）なので、
  トークンの無駄を理由に公開を止めるのは筋が悪い。検知は週次の `file_budgets()` のみ
- **予算は初回回転後の実測+5割**（2500/600/1500/800/1200行）。実測より小さい予算は
  初日から偽陽性になる（実際に一度やって引き直した）
- 初回回転の実測: queue 112k→41k・deepdive 18k→12k・ideas 38k→26k・review 18k→12k・
  earn 22k→19k toks。**合計 208k→111k（▲47%）**。保管庫5本に102k
- おまけ: `build.yml` の paths に `!content/_*.md` を足した＝キュー・ログだけの
  コミットでサイトを再デプロイしない（`_` 始まりはもともとビルド対象外）
