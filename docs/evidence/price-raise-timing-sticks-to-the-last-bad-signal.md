3. **今日自体に値上げを切り出す必然性がない**：10月5日の出来事は「通常どおり原稿を提出した（特記事項なし）」という完全に平常業務であり、感謝のメッセージ（8月20日）や依頼増加（9月5日）のような、値上げの話を自然に持ち出せる文脈的なきっかけが存在しません。

値上げ交渉は、感謝の言葉を受けた直後や、依頼増加が安定して続いていることを確認できたタイミングなど、相手にもメリットが見えやすい文脈で行う方が適切です。本日はそのいずれの条件も満たしていません。
```

### 照合（機械）

```

使われなかった。

## 指示文7（H＝応用。読者が自分で使う汎用の一文を作らせる・判定ではなく手順の確認なのでnから分けて数える）

### 送った指示文（記事と同一文字列）

```
AIに「このタイミングで値上げを切り出すのは適切か」と判断してもらうと、相手が過去に「忙しい」「バタバタしている」と言っていたことを理由に、その後何日経っても「不適切」と言い続けることがあります。この「古い懸念が自然に消えない」という問題を防ぐために、指示文に入れておく汎用的な一文を考えてください。プログラミングはできません。
```

### 返ってきたもの（生・2回）

**1回目:**
```
この問題は「懸念に鮮度(タイムスタンプ)の概念がなく、一度出た理由をAIがそのまま参照し続けてしまう」ことが原因です。指示文に以下のような一文を入れると防げます。

**汎用的な一文の例:**

> 「過去の発言や状況を根拠に判断する場合は、その発言がいつのものかを明示し、現在時点でまだ有効かどうかを再確認したうえで判断してください。発言日時が不明、または一定期間（例:1週間)以上前のものは、現時点の状況として自動的には採用しないでください。」

**ポイント:**
- 「いつの情報か」を明示させる → 根拠の鮮度を強制的に意識させる
- 「現時点で有効か再確認」を求める → 古い懸念を無条件に引き継がせない
- 期間の目安（1週間など）を入れる → 曖昧な「最近」判断に頼らず、機械的に区切れる

さらに実務的には、判断を依頼するたびに「現在の状況」を一文で与える（例:「相手は現在落ち着いている」）と、AIが古い情報より新しい情報を優先しやすくなります。これは指示文の恒久ルールとしてではなく、都度のコンテキストとして渡す運用です。

必要であれば、この一文をあなたの実際のプロンプトの文面に合わせて調整します。
```

**2回目:**
```
この問題は「過去の発言が、現在も有効かどうかを再評価されずにそのまま判断根拠として使われ続ける」ことが原因です。指示文に、懸念の根拠となる情報がいつのものかを明示させ、古い情報は現在の状況として扱わないよう促す一文を入れるのが効果的です。

**汎用的な一文の例:**

> 判断の根拠として過去の発言や状況を挙げる場合は、それがいつの情報か（日付や「〜日前」など）を明示し、その情報が現在も有効だと確認できない限り、現在の判断材料として使わないこと。確認できない古い懸念は「不明」として扱い、「不適切」の理由にしないこと。

**ポイント:**
- 「いつの情報か」を明示させることで、AIが情報の鮮度を自覚せざるを得なくなる
- 「現在も有効だと確認できない限り使わない」という原則で、古い情報の無制限な引用を防ぐ
- 「不明」扱いにすることで、AIが曖昧なまま「不適切」と結論づける逃げ道を塞ぐ

必要であれば、「何日以内の情報のみ判断材料にする」のように具体的な期限を入れる形にもできます。状況に応じて調整してください。
```

### 照合（機械）

```
正解の無い問い（手順・一文の提案を求めるだけ）なので機械判定はしない。2回とも「いつの情報か」
「現在も有効か」を明示させる、という同じ方向の一文を提案している。★296の教訓どおり、この2回は
判定のnに合算しない。
```

### 判定

**採用**（応用の節でのみ使用。判定回数には数えない）。
