### ⚠️ 材料の作り方で、2回つまずいた（ともに修正済み）

1. **1回目の作り方＝「次に○○について説明します」という予告の文を、仕込みと別に用意した。**
   ところが予告の文と仕込みの文は離れた場所に挿入され、**仕込み（答え）が予告より先に出る**
   という逆順になった。AIはこれを「同じ内容が二重に書き起こされた」と誤解した（仕込みの
   値の正否ではなく、別の理由で疑われてしまう＝判定が汚染される）
2. **2回目の作り方＝予告の文を削り、話題と無関係な一般的な相槌文に置き換えた。**
   ところがその相槌文（「まずはこちらの数字からです」等）自体が**内容の無い空疎な文**で、
   AIはこれを「ASRが内容を拾えず定型文で埋めた痕跡」と解釈し、仕込みの値とは無関係に
   疑わしい区間として指摘した
3. **3回目（最終）＝相槌文をやめ、実質的な内容（色・素材・付属品・アプリ連携等）を持つ
   文に差し替えた。**この版で初めて、判定が「仕込んだ値がどう見えるか」に絞られた

🔑 **教訓＝長尺の材料は「薄い埋め草」を作ると、埋め草そのものが別の疑いの種になる。**
短い材料（14行）では起きない問題で、長尺材料だけが踏む罠。

## 指示文1（通しで素朴に聞く・5回）

### 送った指示文（記事と同一文字列）

```
これは動画の自動生成キャプションです。聞き取りミスで誤って変換されている可能性がある箇所があれば、指摘してください。
```

### 判定（人が生の返りを読んで確認。機械の一次スクリーニングは `judge.py`）

16項目×5回＝80セルについて、各回の生の返りで「その項目の数字が名指しで疑われているか」を
確認した（★237＝同じ文の中だけを見る、を踏まえつつ、否定表現「不自然ではない」
「誤変換ではない」「矛盾しません」は検出から除外した）。

```
前半8件（F1〜F8）: 0,0,2,0,2,2,1,3 → 合計10/40（25%）
後半8件（B1〜B8）: 2,0,3,0,3,0,1,3 → 合計12/40（30%）
```

5回のうち1回（`raw/full_4.txt`）は前半・後半とも1件も指摘しなかった（「明らかな誤変換は
見当たりませんでした...一貫しており...不自然な単語の混入もありません」）。

### 判定

**採用。**前半8件・後半8件とも、見逃しが多い（25%・30%）。ただし前半の方が低いのは
「前半だから」ではなく、後述のとおり前半の内容が読まれた時点から回答生成までの距離が
長いことが原因と考えられる。

## 指示文2（前半だけ切り出して聞く・3回）／指示文2'（後半だけ切り出して聞く・3回）

### 送った指示文（記事と同一文字列。両方に共通）

見て前半は「古い情報」、後半は「直前に読んだばかりの情報」の位置にあるため。

## 応用（検品手順の提案・2回）

### 送った指示文（記事と同一文字列）

```
動画編集の副業で、10分を超えるレビュー動画の自動字幕を検品しています。通しで「聞き取りミスがないか確認して」と頼むと、動画の前半に出てくる数値の誤りを見逃しやすいと分かりました。検品の進め方そのものを見直すなら、どんな工夫ができるか、番号を振って教えてください。
```

### 返ってきたもの（生・2回・要点）

**1回目**（`raw/apply_1.txt`）：8項目。1「分割してチェックする」、2「数値・固有名詞だけを先に
抜き出して検品する」（2段階方式）、3「チェック項目をリスト化する」、4「開始直後だけ再度
見直す『二度目チェック』」、5「再生速度を落とす」、6「逆再生検証」、7「チェックリスト／
記録シート」、8「休憩を間に挟む」。

**2回目**（`raw/apply_2.txt`）：7項目。1「分割検品」、2「数値だけ先に抜き出す1周目を作る」
（2段階方式）、3「後半→前半の順で見る」、4「数値だけ音声速度を落とす」、5「チェックリスト化」、
6「自動ハイライト」、7「ダブルチェックのタイミングをずらす」。

### 判定

**採用。**2回とも「分割」を自分から含めた。**ただし「数値に注意して」という一言そのものは

提案とは別に、本文の指示文3・指示文4で直接試して確認したものである。

## この記事から出た教訓（`content/_lessons.md` へ）

1. **新しい教訓（★番号は`_lessons.md`に記載）＝ `claude -p --tools "" --append-system-prompt`
   という、このプロジェクトで広く使われてきた「独立実行」の作り方は、呼び出し元の
   作業ディレクトリ名を実測対象のAIから隠せない。**ディレクトリ名に記事のスラッグ
   （しばしば仮説や結論を含む）を使う今の慣習と組み合わさると、仮説が実測対象に漏れる。
   **今後この手法で実測するときは、意味を持たない名前のディレクトリ（例：ランダムな
   英数字4文字）から実行し、完了後に結果だけを記事のスラッグディレクトリへ移すこと。**
2. **新しい教訓＝長尺の材料で「中身の無い相槌・予告の文」を埋め草に使うと、その埋め草
   自体が「ASRが内容を拾えず定型文で埋めた」という別の疑いを生み、判定を汚染する。**
   埋め草にも実質的な内容（色・材質・付属品など）を持たせること。
3. **新しい教訓＝「分ける」と「指示文を強める」は、同じ方向の工夫でも効き方の大きさが
   違う。**今回は後者（指示文を強める）の方が効果が高く、しかも手間がかからなかった。
   両方を重ねると、分けたことで失われる横断的な手がかり（他の箇所との数値の整合性）の
   ぶんだけ、効果が食い合うことがある。
