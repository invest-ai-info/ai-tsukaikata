`material.txt` そのまま。経費精算規程7条＋問い合わせ6件。

```
【経費精算規程・抜粋(架空)】
第1条(交通費) 電車・バスは実費精算。新幹線は普通車のみ可。グリーン車・グランクラスは不可。
第2条(宿泊費) 出張1泊あたり上限12,000円(税込)。
第3条(会食費) 取引先との会食は一人当たり上限5,000円。参加者全員の氏名を申請書に記載する。
第4条(タクシー) 21時以降の帰宅、または同行者の体調不良、または10kg以上の荷物運搬に限り利用可。
第5条(備品購入) 3万円未満は課長決裁、3万円以上は部長決裁。
第6条(申請期限) 支出日から30日以内に申請すること。30日を超えた申請は原則却下。
第7条(私的な支出) 業務に関係しない飲食・購入は精算対象外。

【問い合わせ6件】
1. 出張先のホテル代が1泊11,000円でした。経費で落とせますか。
2. 取引先と5人で会食し、合計28,000円でした。一人当たりにすると5,600円になりますが、精算できますか。
3. 支出から35日後に精算を申請しました。受理されますか。
4. 出張中、駐車場代を3,200円立て替えました。経費で落とせますか。
5. 在宅勤務の日が増えたので、自宅の電気代の一部を経費にしたいのですが、できますか。
```

仕込み＝1〜3は規程だけで答えが決まる（真値: 1=精算できる／2=精算できない／3=精算できない）。
4・6は規程のどこにも書かれていない（真値: 規程に記載なし）。5は規程が直接は触れていないが、
第7条「私的な支出」の解釈しだいで「精算できない」とも「規程に記載なし」とも取れる、意図的なグレーゾーン。

🔒 **`role-prompt-same-answer.md` との違い**＝同じ「経費精算規程＋問い合わせ6件」という型を続編として
再利用したが、規程の条文・数字・会社設定・問い合わせ内容はすべて独立に作った別物。今回は単純な条文
検索だけでなく、一人当たり金額の割り算（②）と経過日数の比較（③）という計算を挟んだ。測る変数も
「役割」ではなく「口調（敬語／標準／ぞんざい）」で、役割の実測とは完全に別軸。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 口調（敬語／標準／ぞんざい）を変えても、規程に基づく正誤判定・捏造の有無は9回中9回・9回中0件で
   変わらなかった。ただし文字数は敬語版が最も長く（平均668字）、標準版が最も短かった（平均456字）。
2. 指示文を強く縛る（「その3語をそのまま使え」）と、指定フォーマットは守られやすくなる一方、
   質問の意味自体を読み違える新しい失敗が出ることがある（1/2回）。フォーマットの遵守と意味の
   理解は別物で、片方を縛っても他方は保証されない。
3. 「省略するな」（確認文言の必須化）という一文**単体**では、狙った箇所（グレーゾーンの項目）
   以外への副作用は出なかった（項目3は崩れなかった）。ところが、そこに**もう1つの直し
   （フォーマットの文言をそのまま使えという一文）を重ねると**、規程の書き方自体に曖昧さが
   ある別の項目（「原則」という表現）にも確認文言が波及し、分類が変わった。**効いている直しに
   別の直しを重ねるときは、単体では起きなかった副作用が出ないかを別途確かめること。**
4. 計測スクリプトが番号見出しの書式（`1.` と `**1**` の混在）を1通りしか想定しておらず、
   一部の回で「結論」を取り違えて誤った集計を出した（台帳★12の再発）。「結論:」の出現順で
   項目を割り当てる書式非依存の方式に直して再集計した。
