```python
import re

def extract_conclusions(text: str) -> dict:
    """本文に3パターンの語尾が言及されているか、見出し（冒頭220字）で宣言された総数は何か。"""
    has_a = "でしょう" in text
    has_b = "と思います" in text
    has_c = "のです" in text
    head = text[:220]
    m = re.search(r"(\d)\s*(?:か所|箇所|つ)", head)
    declared = int(m.group(1)) if m else None
    return {"全3パターン言及": has_a and has_b and has_c, "見出しの宣言数": declared}
```


## 指示文6（記事の節「応用・次の一手」・確認手順を聞く）

### 送った指示文（記事と同一文字列）

```
AIに「下書きの中で文末表現が不自然に連続している箇所を指摘して」と頼むと、見出しで言った件数(たとえば「2か所あります」)と、本文に実際に挙げている件数が食い違うことがあります。これを自分で見落とさずに確認するコツを教えてください。プログラミングはできません。
```

### 返ってきたもの（生・2回）

```
=== TRIAL 1 ===
良い着眼点です。これはAIの「要約の数」と「本文の列挙」が独立に生成されているため起きやすいズレで、プログラミング不要の確認法で十分対応できます。

**確認のコツ**

1. **見出しの数字は無視して、本文だけを独立に数える**
 AIが「2か所あります」と言っても、それは信用せず、本文に箇条書きされた具体的な指摘(①②③...)を自分で数え直す。見出しと本文、どちらが正しいかは本文の実物を数えた方が確実です。

2. **指摘された箇所を下書きに戻って一つずつ照合する**
 本文で挙げられた「〜だ。〜だ。〜だ。」のような引用部分を、元の下書きの該当箇所に自分で印(マーカーや丸)をつけながら突き合わせる。これにより「本当にその数だけあるか」「挙げ忘れがないか」が見える化されます。

3. **逆に、下書き全体を自分で文末だけ拾い読みする**
 下書きの各文の最後の数文字(「〜た。」「〜する。」「〜だ。」など)だけを目で追う。AIの指摘を見る前に自分で一度拾っておくと、AIの数との食い違いにすぐ気づけます。文章が長い場合は段落ごとに区切って確認すると漏れにくいです。

4. **AIに「本文に挙げた箇所の数」を聞き直す(ダブルチェック)**
 指摘をもらった直後に、別の質問として「今あなたが本文で実際に列挙した箇所は何か所ですか、番号を振って数えてください」と聞き直す。見出しの数字を再利用せず改めて数えさせることで、食い違いが露呈しやすくなります。

5. **「見落としがないか」を別途聞く**
 「文末表現の連続は他にもないか、本文で挙げた以外の箇所を全文チェックして」と念押しで聞く。AIは一度に全部を網羅しないことがあるため、再確認を頼むと新たに見つかることがあります。

**要点**: AIの出した「件数」という要約情報は鵜呑みにせず、本文の列挙そのものを自分の目で数える・下書きと照合する、という「数える作業だけ人間が担う」習慣をつけるのが最も確実です。

=== TRIAL 2 ===
良いコツを一つご紹介します。

**「見出しの件数」と「本文の箇条書き」を別々に数えて照合する**という単純な方法が確実です。手順は以下の通りです。

1. AIの回答の見出し部分(「〇か所あります」など)に出てきた**数字だけ**を先にメモする。
2. 本文を上から読みながら、箇条書きや指摘1つにつき「①②③…」のように自分で丸数字や連番を手書き(またはテキストで追記)して数える。
3. 最後に、メモした見出しの数字と、自分で数えた連番の最大値が一致するか確認する。

このとき大事なのは「AIが言った件数を信じて数える」のではなく、「本文を見てから自分で数え、それを見出しの数字と比べる」という順序です。先に件数を信じてしまうと、本文を読むときにその数に合わせて無意識に数えてしまう(確認バイアス)ため、ズレに気づきにくくなります。

さらに確実にしたい場合は、AIに対して次のように頼み方を変えるのも有効です。
- 「指摘箇所をすべて連番(1, 2, 3…)で箇条書きにし、最後に合計数を書いてください」
- 「見出しには件数を書かず、箇条書きの最後に『計〇件』とだけ書いてください」

こうすると、AI自身が箇条書きと件数を同じ場所で突き合わせる形になるため、食い違いが起きにくくなります。それでも食い違いが起きた場合は、「本文の箇条書きの個数」を正として扱い、見出しの数字は無視するのが安全です。
```
