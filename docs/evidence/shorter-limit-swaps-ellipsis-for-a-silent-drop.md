が残した未測定事項「字数指定を『100字』より短くした場合は試していません」を実測した。
材料は同記事と同じ、SNS監視（公式アカウント12件）・問い合わせ監視（受付フォーム12件）。
字数の上限だけを「100字以内」から「50字以内」に変更。計10回（★32＝材料2本×版2種×各2回＋追加2回）。

実測方法＝独立したサブエージェント（Agent tool, subagent_type省略=新規セッション。
事前知識なし・会話履歴なし）に、依頼文をそのまま渡し、「出力はこの12行の報告だけ」と
指示して応答させた。各回・各条件とも別々のエージェント呼び出し（コンテキストの共有無し）。

## 指示文6（複数の質問が埋め込まれた行を、自分で見分けさせる）

### 送った指示文（記事と同一文字列）

```
今渡した一覧のうち、1件の新着に2つ以上の質問や要件が含まれている行はどれですか。該当する行の番号だけを挙げてください。
```

実際にテストする際は、独立した新規セッションに事前の会話が無いため、
問い合わせ監視の12件一覧を「今渡した一覧は次の12件です。」として直前に渡したうえで、
この質問を続けて送った（記事中では、同じ一覧をすでに見せたあとの会話として自然に続く）。

### 返ってきたもの（生）

```
2, 10
```

### 照合（機械）

仕込みは「2番（返品・交換フォーム）」「10番（採用に関する問い合わせ）」の2行に、
原文の時点で2つ以上の質問・要件を埋め込んであった（教材の仕込み節を参照）。
返ってきた「2, 10」は、仕込んだ2行と**完全一致**。

### 判定

**採用**。1回のみの実測（この指示文は数値的な主張のための実験ではなく、
「複数の質問が埋め込まれた行を自分で見分けられるか」を確かめる補助的な使い方の提案のため、
記事本文でも「1回だけ試した」範囲の紹介に留め、割合や再現性は主張していない）。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 字数の上限を縮めると、崩れ方が「見える形（…）」から「見えない形（言い換えでの脱落）」へ
   移ることがある。「…」が0件という結果だけでは「中身が保たれた」と言えない。対策（「切らないで」）
   が効くのは見える崩れ方のほうだけで、見えない脱落には別の対策（質問数を数えてから要約）が要る。
2. ★32（2回転は材料を変えて2本・各2回）が再発＝この記事でも、同じ材料を2回だけでは
   「採用に関する問い合わせ」の脱落（4回中2回、しかも毎回違う点が消える）を見落とすところだった。
