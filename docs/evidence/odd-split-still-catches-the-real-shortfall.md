## 指示文1（材料①・端数を最終回に寄せた版・全額一致・5回）

3行を1行ずつ照合した表を示し、合計 33,333+33,333+33,335=100,001円が契約金額と一致することを
自分で計算して確認した。過不足なしと判定。

### 照合（機械）

```python
import re
texts = [open(f"last_{i}.txt", encoding="utf-8").read() for i in range(1, 6)]

    print(i, ok)
# => 1 True / 2 True / 3 True / 4 True / 5 True
```

### 判定

**採用**。5回とも「契約書どおりに入金されている」と正しく判定。誤って「不一致」と判定した回は0回。

## 指示文3（材料①の構造・中間金が本当に500円不足・3回）

**ここまでは「全額入金済み」という材料だった。**今度は、端数を最終回に寄せた構造のまま、


### 送った指示文（記事と同一文字列）

### 照合（機械）

## 指示文5（「端数は問題ない」と一言添えて、不足版を再確認・4回）

**端数という非丸い数字を「正常なもの」だと伝えると、本当の不足まで一緒に「正常」側へ
丸め込まれないかを確かめた。**材料は指示文3・4と同じ、本当に500円不足している2構造。

### 送った指示文（記事と同一文字列）

```
この契約は端数が出る分け方をしています。端数そのものは問題ありません。入金明細は契約書の金額どおりに入金されていますか。
```

（材料①の構造〈中間金500円不足〉に2回、材料②の構造〈残金500円不足〉に2回）

### 返ってきたもの（生・4回の結論）

**4回とも**「端数の分け方自体は問題ありません」と前置きしたうえで、「契約書どおりには
入金されていません」と500円の不足を正しく指摘した。1回（`hint_last_short_2`）は本文中で
いったん「300円不足」と書いた直後に「訂正します。不足額は300円ではなく500円です
（33,333 − 32,833 = 500）」と自分で計算し直して訂正し、最終的な結論は500円で正しかった。

### 照合（機械）

```python
texts = [open(f, encoding="utf-8").read() for f in
         ["hint_last_short_1.txt","hint_last_short_2.txt","hint_first_short_1.txt","hint_first_short_2.txt"]]
for i, t in enumerate(texts, 1):
    final_500 = "500円" in t.split("訂正")[-1] if "訂正" in t else "500円" in t
    print(i, final_500)
# => 1 True / 2 True（訂正後） / 3 True / 4 True
```

### 判定

**採用**。「端数は正常」と明示的に伝えても、本当の不足（500円）を正常の範囲に丸め込んで
見逃した回は0/4。1回だけ途中式で一時的な計算違い（300円）が出たが、同じ回答の中で
自分で検算し直して訂正していた（★24・12番の系列＝AI自身の計算も1回だけ揺れたが、
自己訂正まで含めて最終結論は正しかった）。
