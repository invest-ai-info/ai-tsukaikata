# 試した証拠 — monthly-check-from-last-findings

2026-08-19 実施。**架空の月次表を2か月ぶん・2本**（A＝部署別の経費集計／B＝店舗別・商品別の売上集計）作り、6個の指示文を **材料2本 × 各2回 ＝ 全24回** 通した。

判定はすべて Python。判定コード＝`gen.py`（表を作り、仕込みの成立を検算する）、`mk.py`（貼るメッセージの組み立て）、`check.py`（返りの照合）。

🔑 **測りたかったのは、公開記事 `odd-numbers-in-tables` の応用節の一文**＝「同じ表を毎月作っているなら、点検も毎月同じで済みます。**前回の指摘をそのまま渡すのが速いです**」。この一文には数字が1つも無い。もう1本の公開記事 `inbox-loop-new-since-yesterday` は「昨日の一覧を渡しても今日の仕分けは13件とも動かなかった。**渡しているのが判定の結果だけで、文章ではないためだと思われます**」と、検証していない推測で閉じている。**前回の指摘は文章**なので、その推測をここで当てられる。

🚨 **書き始める前の見立て（「前回の指摘を渡すと、新しい種類の異常が見えなくなる」）は外れた。**指摘を貼った版も貼らない版も、8月の6件を **4回とも 6/6**。見落としは0件。

🔑 **代わりに、別のところが落ちた。**前月の指摘を渡したうえで**「毎月この形で返してください」と返す形まで決めた版（指示文4）だけ**、**4回とも 5/6**。落ちたのは毎回同じ種類＝**ほかの異常と結び付かない、足し算だけの小計のズレ**。落ちる原因は「前月の指摘」ではなく**返す形を短く固定したこと**で、指示文5（足し直した値を並べて書かせる）で4回とも戻った。題は実測に合わせて変えてある（キュー15番）。

⚠️ 実測用のセッションは、このリポジトリのファイルを読まないよう指示したうえで走らせた。ただし**「事前知識なし」とは言えない**（台帳★20）。判定は機械照合できるものだけにしてある。

## この記事から出た教訓（`content/_lessons.md` へ）

1. **🆕 前回の指摘（文章）を渡しても、検査の視野は落ちなかった**＝貼った版・貼らない版とも4回とも6/6。★12c／★34（前回の出力を渡すと繰り越す）は、**渡すものが「指摘」で、作らせるものが「点検」なら起きない。**

2. **🆕 渡して増えるのは、検出ではなく仕分け**＝渡さない版も6/6なので、前回の指摘は検出を1件も増やしていない。増えるのは「直った3件／残った2件」の判定（12回とも5/5）で、これは渡さないと出てこない。

3. **🆕🚨 視野を狭めたのは「渡したもの」ではなく「返させる形」**＝前月の指摘を渡した3つの版のうち、**返す形まで固定した版だけ**が 4回とも 5/6。落ちたのは毎回**ほかの異常と結び付かない、足し算だけのズレ**で、代わりに**見つけた異常から派生した小計**を挙げている。**短く返させると、気づいた異常の周りしか計算しない。**

4. **🆕 落ちた検査は、その計算を「書かせる」ことで戻る**＝「足し直した値と表の値を並べて書いてください」を足した版は4回とも6/6。★1（禁止だけでなく受け皿）の、計算版。

5. **★47が再現した**＝異常の可否が表の中で機械的に決まるので、検出は崩れない。誤検知（直った3件を「まだある」と書く）は**24回とも0件**。

6. **🆕 頼まなくても書いてくる注意は、4回に1回は出ない**＝「小計は一致しているが、重複行や桁ミスを含んだままの一致なので検算になっていない」を、**頼まなかった20回では13回**しか書かなかった。**頼んだ4回では4回とも書いた。**自分から書いてくるからといって、書かせる一文を省かない。
