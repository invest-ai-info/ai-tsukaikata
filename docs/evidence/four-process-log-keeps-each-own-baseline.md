# 試した証拠 — four-process-log-keeps-each-own-baseline

キュー：`content/_recipe_queue.md`「自動化・ループ優先」節「監視している処理が3本・4本に増えても、
個別の「いつもの目安」の判定は崩れないか」。根拠は、公開済み`mixed-log-keeps-each-process-own-baseline.md`
が自分で残した未測定事項「処理は2本まで。3本以上を1本のログに混ぜる場合は試していません」
「頻度の差は最大5倍まで。それ以上に差が開く組み合わせは試していません」。実測日 2026-10-31。

実測に使ったAI＝`claude --print --safe-mode --tools ""`（Claude Code CLIを非対話モードで起動）。
`--safe-mode` は CLAUDE.md・skills・plugins・履歴を全部無効化する。1回の指示につき1つの新規
プロセスとして起動し、会話を継続しなかった（前の回の返りが次の回の判断に影響しないようにするため）。

先行記事 `mixed-log-keeps-each-process-own-baseline`（2026-10-20公開）は、頻度が5倍違う処理X
（1日4〜8回）・処理Y（1日1〜2回）の2本を1本のログに混ぜても、「処理ごとに計算して」と頼めば
どちらが止まっても見つかることを確かめた。この記事は、処理を4本（P1〜P4）に増やし、頻度差を
最大約17倍まで広げても同じ頼み方が崩れないかを測る。

## 教材（架空データ）

### ログの生成方法

Python（`random.Random` で乱数シードを固定・seed_base=42）で、21日分（2026-09-01〜09-21）の
日別実行回数から、1日の中でだいたい等間隔・わずかにずらした時刻（HH:MM）を機械的に割り振り、
処理名（process=P1〜process=P4）付きの行として日付・時刻順に並べた。日別回数の範囲は次の通り。

```
P1（1日1〜2回想定）
P2（1日4〜8回想定）
P3（1日10〜15回想定）
P4（1日20〜30回想定）
```

5つの構成を作った。「全処理が正常」はどの処理も全期間0件の日が無い版。残り4つは、指定した
1処理だけ09-10〜09-13の4日間を0件にし、他の3処理は全期間正常にした版。

```

🚨 **仕込みの検証**＝生成後、Pythonで日付ごと・処理ごとの行数を数え、仕込んだ日別回数と完全に
一致することを確認した（上の `counts=[...]` がその出力そのもの）。停止4日間（09-10〜09-13）が
指定した1処理だけ0になっていること、他の処理が全期間0件の日を持たないことも同時に確認した。

生成したログの先頭5行（stop-P1）：

```
2026-09-01 00:XX process=P1
2026-09-01 00:XX process=P2
2026-09-01 00:XX process=P3
2026-09-01 00:XX process=P4
2026-09-01 XX:XX process=P4
```

頻度差＝P4の平均（535/21≈25.5回/日）÷P1の平均（31/21≈1.48回/日）≈17.2倍。本文・題の「約17倍」はこの値。

## 指示文1〜3（処理ごとに計算・全5構成・各2回＝計10回）

### 記事に載せた指示文（記事と同一文字列）

```

処理ごとに、その処理自身の記録から「ふだんの1日あたりの実行回数」の目安を計算してください。そのうえで、その処理だけの目安と比べて極端に少ない日（0件の日を含む）があれば、処理名・日付・実行回数を挙げてください。該当する日が無ければ「該当なし」と答えてください。

### 照合（機械）

判定スクリプト（`check.py`）が、各返りの中の `| 処理名 | 2026-09-DD | 回数 |` 形式の表の行を

## 指示文4（日ごとに合算・stop-P1構成・2回）

### 記事に載せた指示文（記事と同一文字列）

```

### 返ってきたもの（生・2回）

**1回目**：「該当なし。」日別の合計表（9/1=46, 9/2=50, …, 9/10=37, …, 9/13=39, …）を提示し、

**2回目**：「該当なし。」同様の日別合計表を提示し、「ふだんは1日あたり45回前後で、多くの日は
37〜53回に収まっています。最も少ない9/10(37回)も、ほかの日と比べて極端に少ないとは言えません」。

### 照合（機械）

```
日付ごとの合計に、停止日(09-10〜09-13)を指して「該当あり」と答えた回: 0/2
日付ごとの合計の最小値(09-10=37)が本文に明記された回: 2/2（37という数値は、仕込みのP2〜P4の
  合算値 ＝ 126+268+535=929/21≈44.2回の日によるものと一致。P1の停止による影響は37という
  表の値そのものに正しく反映されている＝合算自体は正確。異常判定の基準だけが外れた）

### 判定

**採用（言い直し方の節に掲載。見逃しの実例として）。**合算では、P1の停止がログ全体の合計
（約45回/日）に埋もれて2回とも見逃された。先行記事（処理2本・頻度差5倍）でも同じ現象が
確認されており、処理を4本に増やし停止処理の割合を小さくしたことで、同じ見逃しが再現した。
