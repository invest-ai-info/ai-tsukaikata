# 試した証拠 — stop-when-material-is-missing

保存して使い回している指示文6本を、**材料を貼った回・1つも貼らない回・2つのうち1つだけ貼り忘れた回**で
走らせて、返りを機械で数えた。2026-08-16 実測。

- 実測用のセッションは、いずれも新規のエージェント（このサイトの記事を書いている会話とは別）。
  ⚠️ 台帳★20 のとおり「事前知識なし」ではない。実際 `d-P2-2` の返りは
  「このリポジトリの CLAUDE.md」に言及した＝**プロジェクトの文脈が一部伝わっている。**
  そのため結論は**機械照合できる結果だけ**に置いた（材料名の名指しの有無・埋め草の穴の数・
  行頭の「件名：」の有無・記録から計算した真値との一致）。
- ⚠️ **「わざと材料を外しました」とは一度も伝えていない**（伝えれば誘導になる）。
- 判定コードは `docs/evidence/stop-when-material-is-missing.check.py` 相当の内容を本文に転記した。

```
⑩ 保存版そのものを点検させた2回（e）の一致
  e-1: 挙げた件数 4件 / 「上の発注書」=True / 「いつもの様式」=True
  e-2: 挙げた件数 3件 / 「上の発注書」=True / 「いつもの様式」=True
```

### 判定

**採用。ただし件数は2回で割れる（4件と3件）。**
2回とも一致したのは「上の発注書」「いつもの様式」の2件で、
これは**指示文が参照語で名指ししているもの**そのもの。
3件目以降（案件名・数字）は数え方の違いで、2回目は自分から「実質2つ」とまとめた。
→ **参照語の一覧だけを物差しにする。件数は毎回同じにならない**（台帳★45の系列）。

## 計測コードの読み直し（台帳12番）

**この実測で 12番を5回踏んだ。**どれも「返りが悪く見える」方向の誤りだった。

| 回 | 何を間違えたか | どう直したか |
|---|---|---|
| 1 | 不在語を「〜ていません」で固定したので「入っていないため」を取りこぼした（b-P6-2） | 語幹で見る形へ |
| 2 | 今度は「〜ていな」に寄せたので「入っていません」を取りこぼした（b-P3-2・d-P2-2） | 2形を1つの正規表現へ |
| 3 | ひらがなの「ない」（「この会話にないため」）を取りこぼした（b-P2-1 の様式） | 語形を追うのをやめ、成立した窓を全部印字して目で確かめる形へ |
| 4 | **件名の一部**「【納品】記事1本…」を埋め草として数えた | 穴の中に材料名を含むものだけを数える形へ |
| 5 | 「件名」を素の文字列で見たので、本文中の説明「件名・本文・末尾のあいさつ」まで拾い、**止まった回を「メールを出した」と表示**した | 行頭の「件名：」だけを見る形へ |

🔑 **芯の結果（c-P2 の 0/2）は、4通りの不在語の当て方すべてで同じだった。**
計測器を4回作り直しても動かなかったので、この1件だけは検出の仕方に依存していない。

## この記事から出た教訓（`content/_lessons.md` へ）

1. **★12b／★18 とは逆の結果が出た**＝材料が**1つも無い**回は、12回とも
   「何が貼られていないか」を名指しして止まった。**埋めるのは、材料が
   「あるように見えて1つだけ欠けている」ときのほう。**
   さらに**欠けたものが「事実の中身」か「出す形（様式）」かで割れる**＝
   中身なら 4/4 気づき、様式なら **0/2**。
2. **12番が再発した（5回・同じ実測内）。**上の表のとおり。
   ⚠️ **ただし芯の結果は4通りの当て方すべてで同じ**だったので、
   「計測器を作り直しても動かない数字」を1つ作っておくと、
   12番を踏んでも結論が倒れない。
3. **★41（指示文が参照している材料を記事に載せ忘れる）の、AI側の姿がこれ。**
   ★41 は「書いた本人には見えない」で終わっていたが、
   **読む側（AI）にも見えない場合と、見えるのに黙って進む場合がある。**
