## 指示文9（応用・自動化の手順を聞く・材料なし・2回）

### 送った指示文（記事と同一文字列）

```
毎月、着手金と残金の2回払いになる請求と一括の請求が混ざります。入金明細と請求一覧を毎月同じ形で突き合わせたいです。プログラミングはできません。私が毎月やることを、番号を振って箇条書きで教えてください。
```

### 返ってきたもの（生・2回・先頭のみ抜粋）

**1回目（先頭4項目）:**
```
1. 請求一覧を最新化する:今月分の請求書を並べ、各行に「案件名」「請求区分(一括/着手金/残金)」
「請求金額」「請求日」を書き出す。着手金と残金は同じ案件でも別の行として2行に分ける。
2. 請求一覧に「消込状態」列を追加し、全行いったん「未確認」にする。
3. 入金明細(銀行やクレジットの入金履歴)を今月分だけ表示し、日付順に並べる。
4. 入金明細の1件ごとに、金額が請求一覧のどの行と一致するかを探す。一括請求は1件の入金と

```

**2回目（先頭4項目）:**
```
1. 入金明細（銀行の履歴）から、対象月に入った分だけを別のリスト（紙・メモ・表のどこでもいい）

2. 請求一覧から、対象月に「請求済み・未回収」になっている行をすべて書き出す。1行＝1件、
```

### 判定

**採用**。応用として、毎月繰り返す形の骨格を記事に書く。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 分割入金（着手金＋残金の2回払い）を「1件の完済」として結びつけられるかどうかを、
   通常の分割払い・本当に一部だけ未収のケース・残金と同額の別請求が衝突するケースの
   3条件・26回で試したが、未入金と誤判定した回・2回の入金を別々の請求として二重計上した
   回は、どちらも0回だった。[合算入金を見落とす記事](/recipes/combined-payment-missed-as-unpaid/)
   が検証した「多→1（複数の請求が1つの入金にまとめて振り込まれる）」方向では素朴な聞き方
   で見落としが9回中6回起きていたのに対し、その逆方向「1→多（1件の請求が複数回に分けて
   入金される）」では、同じ素朴な聞き方でも見落としが起きなかった。同じ「合算判定」という
   機構でも、方向によって崩れ方が対称ではないことが分かった。
2. 摘要（振込人名義）が会社名になっていない入金（「フリコミ」等）があると、金額が一致
   していても、3回中3回とも「要確認」と自分から注記した。これは★1系（受け皿を作る）の
   一種だが、こちらは指示していなくても自発的に出た点が異なる。ただし「要確認」という
   注記自体は判定の保証にはならないので、記事では「摘要が読み取れない入金は必ず自分の目で
   確認する」という人間側の手順として明記した。
