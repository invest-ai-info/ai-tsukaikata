```
| 情報源 | 判定 | 根拠 |

判定のポイント:
- 「新着件数が0の日がある」だけで停止と判断しない。B・Cのように周期的に更新される情報源は、0の日が続いても正常。
- 「停止」と呼ぶべきなのは、取得件数（ページへの到達可否）と新着件数（中身の動き）を分けて見た上で、長期間新着がゼロのEと、そもそも取得自体ができていないFの2種類。この2つは原因も直し方も違うので、ひとまとめに「停止」と呼ばず区別するのが実務的。
- Dのように観測回数が少なく周期性を確認できないものは、「停止」でも「正常」でもなく判定保留とし、もう数回分の記録を待つのが適切。拙速に停止と決めると、実は低頻度で正常なものを誤って停止扱いしてしまう。
```

### 照合（機械）

真値はA〜E正常・F停止。返りはA正常・B正常・C正常・D判定保留・E停止(stale)・F停止(dead)。
A〜Cは真値と一致。Dは誤判定（停止/正常のどちらにも倒していない＝判定保留）。Eは真値（正常）と不一致（停止扱い）。Fは真値と一致。
2値（正常/停止）には強制的に当てはめず、「正常・判定保留・停止(stale)・停止(dead)」という4つに自分で分けた。

### 判定

**採用**（言い直し方の節で、「両方見せても、こちらが期待した2値にきれいに収まるわけではない」の根拠として使う）。1回だけの結果。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 死活判定に渡す数字（取得件数か新着件数か）の選び方そのものが、閾値ルールが同じでも誤判定率を決める。AIの計数は2回とも正確で、崩れたのは計算ではなく「何の数字を渡したか」。
2. 新着件数だけで閾値を「賢く」（観測した最大間隔の3倍）しても直らない。健全な低頻度の相手への誤判定は減るが、代わりに本当に停止している相手まで「判定できない」に紛れ込み、見分けられなくなる。
3. 取得件数と新着件数を両方見せて自由に判定させても、こちらが想定した2値（正常/停止）には収まらない。AIは「正常・判定保留・停止（中身停止）・停止（取得失敗）」という4つに自分で分けた。
