# 試した証拠 — month-boundary-double-count

2026-08-18 実施。**架空の「月ごとに分けて置いてある記録」を2本**
（材料A＝勤怠の打刻ログ、材料B＝売上の記録）作り、**7月ぶんと8月ぶんを別々のログとして**
用意して、**月をまたぐことでだけ起きる境界の行を材料ごとに5件ずつ**仕込んだ。
5個の指示文を、**材料2本 × 各月2回 = 1つの指示文につき8回**通した。合わせて **40回**。

⚠️ 実測用のセッションは、このリポジトリのファイルを読まないよう指示したうえで、
1回ぶんにつき1つずつ新しく開いた（40セッション）。ただし**「事前知識なし」とは言えない**（台帳★20）。
判定は**機械照合できるものだけ**にしてある＝返ってきた合計の数値と、
仕込んだ行の文字列が返りに実在するかの数え上げ。

⚠️ 材料は、実測用セッションに**「利用者がチャットに貼ったメッセージそのもの」として
1つのファイルに入れて渡した**（指示文＋区切り線＋ログ）。チャットに直接貼った場合と
同じとは言い切れないので、ここに書いておく。

🚨 **実測用セッションは「今日」を 2026-08-18 として持っている。**
指示文にはどこにも今日の日付を書いていないのに、材料Aの8月ぶんで
**「本日は8/18ですが、ログは8/31まで埋まっています」**という指摘が返った回がある
（p1_A8_1・p1_A8_2・p3_A8_1）。**この指摘は、この実測の環境に固有のもの**なので、
判定には使っていない。記事にも書かない。

判定コード＝`gen.py`（仕込みの検算）、`mk.py`（貼ったメッセージの組み立て）、
`check.py`（返りとの突き合わせ）。
🚨 **`check.py` は4種類の誤りを出した**（末尾の「計測器の直し」。台帳12番）。
