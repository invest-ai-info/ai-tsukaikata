# 試した証拠 — how-far-back-changes-the-usual-number

記事＝`content/recipes/how-far-back-changes-the-usual-number.md`
（「いつもの目安は見せる日数で変わる——5.5倍にも7.6倍にもなる」）。

[ふだんは3〜5件です、と一言足すかどうかで急増の自己申告が0対5に分かれる](/recipes/surge-stays-quiet-without-a-baseline/)
の続き。あちらは「ふだんの目安」を**人間が数字で渡した**場合を測った。あちらの言い直し方
「そもそも、ふだんの件数が分からない」に、著者自身が「ふだんの目安を記録から出す形は、この記事では
試していません」と明記していた（`surge-stays-quiet-without-a-baseline.md:118`）。本記事はそこを埋める
＝**目安の計算そのものをAIにやらせる**場合を測った。

実測日 2026-10-03。実行方法は前回・前々回の担当と同じ＝`Agent`ツール（`general-purpose`／`model: sonnet`）で、
共有コンテキストの無い新規サブエージェントを毎回1回だけ呼び出した（★91＝答えを知らない者が答えることで
版の比較が成立する。材料を作った本人〈このセッション〉が返答も書くと比較が成立しないため、サブエージェントに
「ふつうの無料チャットAI」の役を演じさせ、ツール不使用・暗算で答えさせた）。

## 指示文1（8週間＝56日ぶん全部を渡す・材料A・2回）

### 送った指示文（記事と同一文字列）

```
これは問い合わせフォームに届いた件数の記録です。この記録から、ふだんの1日あたりの件数の目安を計算してください。そのうえで、本日の件数34件が、ふだんの目安の何倍にあたるかを書いてください。

（材料Aの56日ぶんを貼る）
```

### 返ってきたもの（生）

```
run1:
7/14〜9/7の56日間の記録から計算します。

【集計】
・7/14〜7/31（18日間）の合計：60件
・8/1〜8/31（31日間）の合計：148件
・9/1〜9/7（7日間）の合計：44件
・全体合計：60+148+44=252件
・日数：56日間

【ふだんの1日あたりの目安】
252件 ÷ 56日 = 4.5件/日

【本日との比較】
本日の件数34件は、ふだんの目安4.5件の
34 ÷ 4.5 ≈ 約7.6倍
にあたります。

ふだんの7〜8倍近い件数が来ている計算になるので、何か普段と違う出来事（キャンペーンや告知、障害、
SNSでの拡散など）が無かったか確認してみることをおすすめします。

なお、記録をよく見ると7月は1日3〜4件程度だったのが、8月後半〜9月にかけて5〜7件程度まで徐々に
増えてきている傾向があります。直近2週間（8/25〜9/7の14日間、合計85件）の平均は約6.1件/日で、
これと比べても本日の34件は約5.6倍となり、いずれにしても明らかに多い日だと言えそうです。

run2:
この記録（7/14〜9/7の56日間）の合計件数を計算すると252件になります。

【ふだんの1日あたりの目安】
252件 ÷ 56日 = 4.5件/日

【本日の34件との比較】
34件 ÷ 4.5件 ≈ 7.6倍

本日の34件は、ふだんの目安（1日あたり約4.5件）のおよそ7.6倍にあたります。

なお、この記録をよく見ると7月は1日3〜4件程度だったのが、8月後半から9月にかけて5〜7件程度まで
徐々に増える傾向があります。直近1週間（9/1〜9/7）だけで平均すると約6.4件/日なので、直近の感覚で
比べると34件は約5.3倍という見方もできます。目的に応じて、全期間の平均（4.5件）か直近の平均（6.4件）

```

### 照合（機械）

```
合計件数: run1=252, run2=252 → 真値252と2/2一致
ふだんの目安: run1=4.5件/日, run2=4.5件/日 → 真値4.5と2/2一致

　（真値34/6.142857=5.535…なので四捨五入は5.5が近いが、6.1を使うと34/6.1=5.57…で5.6も計算として成立。
　 丸め誤差の範囲）
※ run2はさらに直近7日（9/1〜9/7）の平均を自発的に計算（6.4件/日。真値（週8）=44/7=6.2857…なので
　 やや高めだが大きくは外れていない）、倍率5.3倍と自発的に申告
```

### 判定

**採用。**2回とも、56日全部を渡した場合の目安（4.5件/日）と倍率（7.6倍）は真値と一致した。
両方とも**頼んでいないのに**直近の傾向に自分から触れ、「全期間平均」と「直近平均」のどちらを

「直近」の範囲（run1は直近2週間、run2は直近1週間）は回によってバラついた＝**聞いていないことは、
聞いていない範囲で答えが割れる**（既知の台帳4番の系列）。

## この記事から出た教訓（`content/_lessons.md` へ）

1. **新しい教訓＝「ふだんの目安」をAI自身に記録から計算させると、計算の正確さは毎回そろうが
   （6条件×2回＝12回中12回が真値と一致）、“どこまでを「ふだん」とみなすか”という定義そのものが
   渡したログの長さで変わる。**同じ指示文・同じ「本日34件」でも、2週間ぶんだけ渡すと目安6.1件
   （倍率5.5〜5.6倍）、4週間で5.6件（6.0倍）、8週間全部で4.5件（7.6倍）と、目安が約36%・倍率が
   約2.1倍のあいだで動いた。原因は計算ミスではなく、**緩やかな増加傾向のある記録で「古い週を
   含めるほど目安が下がり、倍率が上がる」**という、渡すデータの範囲そのものの効果。
2. **★134が再発した（別記事での再確認）。**[ふだんの目安を人間が渡す記事](/recipes/surge-stays-quiet-without-a-baseline/)
   の指示文4（急増チェックを出す項目として名指しする＝絞っても消えない）は、目安を人間が渡す場合
   だけでなく、**目安の計算そのものをAIに委ねる、より難しい版でも同じく2/2で機能した。**
3. **4番（AIの自己申告は、本人が自覚した範囲しか含まない）の再発。**指示文1（56日全部を渡す）で、
   2回とも頼んでいないのに「直近の平均」を自発的に申告したが、run1は直近2週間・run2は直近1週間と、
   **自発的に選ぶ「直近」の範囲が回によって割れた。**聞いていないことを自発的に補う挙動は起きるが、
   その中身の粒度までは揃わない。
