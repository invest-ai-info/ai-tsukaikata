# 試した証拠 — ask-for-reasons-breaks-the-match

記事に載せた指示文すべてについて、この形式で残す。返ってきたものは生のまま。
判定は Python（正規表現でID・条文番号・記載なしを抜き出し、真値の辞書と突き合わせる集合演算）。
真値（各申請の該当条文または記載なし）は、規程の条文に沿ってこちらが決め、
走らせる前に「24件（材料A・B）／8件（材料C）ちょうど・IDの重複なし・ラベルが有効な集合の中」を
assertで確かめてある（★24＝真値を作るコードも計測器）。

⚠️ 実測に使ったAIは、このセッション内の新規サブエージェント（Agentツール `general-purpose`、
ツール不使用・ファイル読み書きなしを指示）。呼び出しごとに独立した会話。事前知識ゼロとは
言い切れない（★20）ため、「素のAIはこう返す」という一般化はしない。機械照合できる結果
（条文番号・記載なしの一致／不一致）だけを記事の根拠にしている。

⚠️ 記事の指示文中の「（ここに申請一覧24件を貼る）」「（ここに、あえて紛らわしくした申請8件を貼る）」は、

resume-from-last-not-clock-time.md と同じ、コピー用テンプレートとしての置き方。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 規程・チェックリストのように、除外条件まで含めて条文が明記されたルールに照らした
   判定は、単純な「該当条文を答えて」という指示文なら、新規の会話で3回ずつ・材料を
   変えて2本・わざと誤読しやすい罠を仕込んだ8件を含め、のべ168件の判定で1件も
   ブレなかった（3回の答えが割れた項目・真値と食い違った項目とも0件）。
2. ところが同じ規程・同じ申請一覧でも、「理由も一言添えて」と指示文に一文足しただけで、
   3回のうち2回に別々の誤りが混ざり、3回の答えが一致しなくなった（24件中2件）。
   縛りを足すと、足した先（理由の書き方）ではなく別の判定（条文そのものの当てはめ）が
   動く、という★93の系列。
3. 自信度の自己申告（「自信が無ければ印を付けて」）は、2回の実行で完全には一致せず
   （共通2件・差分2件）、しかも印の有無と正誤は無関係だった。自己申告だけを
   「外部確認が要る項目」の絞り込みに使うのは、この材料では裏付けが弱い（★4の系列）。
