# 試した証拠 — subtotal-ratio-1to6-still-one-spot

既存記事 `subtotal-still-correct-past-300-rows`（不均等さ「1対3」）が末尾に残した宿題
「不均等さは『1対3』の比率のみ（もっと極端な比率は試していません）」に答える実測（源0＝仮説キューH41）。

架空の店舗別売上表（東日本1エリア対西日本6エリア・570行）・部門別経費表（フロント1部署対
バックオフィス6部署・640行）を用意し、既存記事と同一の指示文を各材料5回ずつ、合計10回試した。
試した相手はClaude（独立したエージェント1本につき1会話・ツール不使用・チャット画面の自然文のみ
という条件を付けた10本の別セッション）。

⚠️ **判定は機械でやる。** 返ってきた最初の1つの数式を、同じ区分の他の全セルへ
「コピーダウン」した状態（Excelの相対参照の仕組みをPythonで再現）にしてから、
実際にLibreOffice Calcで再計算し、Pythonで直接集計した真値と比較した。
既存記事の `judge.py`（`shift_formula` / `build_and_check`）をそのまま使った。

🚨 **ground truthの計算に既存スクリプトのバグを見つけて直した。** `build_sheet.py` の
`ground_truth_store`/`ground_truth_dept` は、2つ目以降のブロックで `cur_block_sum`/`cur_unit_sum`

既存記事に同梱されていた `fix_gt.py`（詳細データから直接再集計する関数）をそのまま適用して解消した。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 新規：不均等な階層をコピーしたときに崩れる**場所の数**は、不均等の比率（1対3→1対6）を
   広げても増えなかった（どちらも1か所のまま）。ただし崩れた1か所に**残る金額の割合**は、
   比率にほぼ反比例して縮んだ（約1/3→約1/6、実測では約32〜34%→約17%）。
2. 新規：SUBTOTAL以外にも、位置だけで判定する方式（生データの範囲を階層の深さで割る）が
   見つかった。この方式は不均等な階層で2か所崩れ（大計・総合計）、SUBTOTAL自身が持つ
   「他のSUBTOTAL結果を自動で無視する」という自己修復力を持たないぶん、総合計まで連鎖した。
3. 新規：壊れた数式そのものを見せて「これは合っていますか」と聞き直すと、1回で誤りを検出し
   正しい修正式を返した。危険な階層を事前に聞く（追加確認1・2）のと同じ精度で、事後の検証にも効く。
4. 新規：検算の方法を聞くと、D列の文字列ベースの検算式（`SUMIF`の末尾一致）を自分から
   提示した。位置に依存しない検算式は、SUBTOTAL方式・SUM÷深さ方式のどちらの崩れも検出できる。
