# 試した証拠 — combined-payment-missed-as-unpaid

キュー「納品したのに入金の無い案件を出す」（`content/_recipe_queue.md`）の実測記録。

実行環境＝Agent ツール（`general-purpose`、会話の文脈を一切引き継がない独立呼び出し）。基本実験は
版a/b/c を各3回＝9回、追加検証4回（版d×2・単発の言い直し2種×各1）＝**計13回**。

⚠️ **見立てとの違いを先に書く。**キューの仮の題は「1件の取り違えが、2件の間違いになる」だったが、
実測では**同額の2件を取り違えて確定させた回は0回**だった。かわりに見つかったのは
**「1つの支払いが2件ぶんの合算だった」ケースの見落とし**。記事の題はこちらに差し替えた。

---

## 教材（架空データ）

Python で作成。真値は「(delivery, payment) の対応が一意に決まるか」を、金額・日付の窓（納品日から
-3〜+30日）で総当たりして確定させた（`build_truth3.py`、本ファイル末尾に全文）。

### 納品記録（12件）

```
1. ロゴA制作／甲社／30,000円／2026-07-02 納品済
2. バナー広告B／乙商事／20,000円／2026-07-05 納品済
3. 記事執筆C／丙出版／15,000円／2026-07-08 納品済
4. 名刺デザインD／丁工房／8,000円／2026-07-10 納品済
5. ロゴE制作／戊商店／30,000円／2026-07-12 納品済
6. LP制作F／辛デザイン／48,000円／2026-07-15 納品済
7. 動画編集G／壬映像／32,000円／2026-07-17 納品済
8. 資料作成H／子コンサル／41,300円／2026-07-20 納品済
9. LP修正I／丑企画／18,000円／2026-07-22 納品済
10. 動画撮影J／寅興業／28,000円／2026-07-24 納品済
11. 記事執筆K／卯出版／10,000円／2026-07-26 納品済
12. サイト修正L／辰システム／25,000円／2026-07-28 納品済
```

### 入金明細（10行）

```
行1　2026-07-08　摘要:オツシヨウジ　20,000円
行2　2026-07-11　摘要:ヘイシユツパン　15,000円
行3　2026-07-13　摘要:テイコウボウ　8,000円
行4　2026-07-15　摘要:フリコミ　30,000円
行5　2026-07-20　摘要:カ）ジユウシヨク　80,000円
行6　2026-08-03　摘要:コ）コンサル　41,300円
行7　2026-07-25　摘要:ウシキカク　17,500円
行8　2026-07-30　摘要:ヘンキン　6,500円
行9　2026-07-06　摘要:キユウリヨウ　3,000円
行10　2026-08-01　摘要:ゲツカイヒ　5,000円
```

### 仕込み（真値）

- **素直な一致（3件）**: #2→行1／#3→行2／#4→行3
- **同額で1行を取り合う（2件）**: #1（甲社30,000円）と#5（戊商店30,000円）は、どちらも行4（30,000円）
  としか一致しない。摘要「フリコミ」には社名の手がかりが無いので、**この情報だけではどちらか決められない**
- **合算入金（2件）**: #6（48,000円）＋#7（32,000円）＝80,000円＝行5。ただし摘要「カ）ジユウシヨク」は
  どちらの社名の読みとも一致しない
- **月をまたぐ入金（1件）**: #8（41,300円・7/20納品）は行6（41,300円・**8/3**入金）。金額は完全一致だが
  支払月が違う
- **差引のある入金（1件）**: #9（18,000円）に対し行7は17,500円（**500円少ない**＝振込手数料相当）
- **本当に未入金（3件）**: #10・#11・#12。入金明細のどの行（単独でも合算でも）とも一致しない
- **無関係の入金（4行）**: 行8・9・10と、あとで判明する行5の一部——いずれも12件のどの金額とも一致しない
  雑音（返金・給料・月会費のたぐい）

## 指示文1 — 素朴に聞く（版a・3回）

### 送った指示文（記事と同一文字列）

```
まだ入金されていない案件を挙げてください。
```

上に続けて、納品記録12件と入金明細10行を貼った。

### 返ってきたもの（生・3回とも要旨。生の全文は長いため、判定に関わる部分のみ）

- **a-run1**: 「明らかに入金が確認できないもの（5件）」＝#6,#7,#10,#11,#12。別枠で「要確認」に#1&#5
  （行4を取り合う）と#9（500円差）を自分から分けて記載（指示していないのに自発的に区分した）。
- **a-run2**: 表形式。#6,#7,#10,#11,#12を「未入金」、#1&#5と#9を「要確認」（自発的な区分）。
- **a-run3**: a-run2とほぼ同型。「確実に未入金なのは6・7・10・11・12の5件」＋「1か5のどちらか一方」
  ＋「9（500円不足）」を要確認として明示。

### 判定

**採用**。3回とも、頼んでいない「確かめる」に相当する区分を自発的に作った。**3回とも#1・#5を確定的に
どちらか一方へ割り振る誤りは無かった**（核心の①に対応）。**ただし3回とも、#6・#7（合算入金）を
単純に「未入金」へ入れてしまい、行5との合算関係には気づかなかった**——ここが見落とし。

## 指示文2 — 「確かめる」の受け皿を指定する（版b・3回）

### 送った指示文（記事と同一文字列）

```
まだ入金されていない案件を挙げてください。どの行と対応するか決められない案件は、「未入金」ではなく「確かめる」に分けてください。
```

### 返ってきたもの（生・3回・要旨）

- **b-run1**: 「未入金」に#6,#7,#10,#11,#12と**#5も含めてしまい**（「※行4と金額は一致しますが、下の
  『確かめる』で理由を説明します」という注記つき）、**同時に「確かめる」でも#1と#5を並べて論じている**。
  ⚠️ **#5が「未入金」と「確かめる」の両方に登場する自己矛盾**。#6・#7の合算には気づいていない。
- **b-run2**: 「確実な未入金：3件（10・11・12）」「対応関係を確認したい案件：5件（1・5・6・7・9）」。
  **#6・#7を「確かめる」に入れ、行5との合算（48,000+32,000=80,000）に自分から気づいた**うえで、
  摘要が一致しないため断定は避けた。真値に最も近い回。
- **b-run3**: #10,#11,#12を確実な未入金、#1&#5・#9を確かめる、として、**「参考（低確度）」の形で
  #6+#7=80,000=行5の一致に触れつつ「未入金」欄にも残す**（気づいてはいるが分類には未反映）。

### 判定

**採用**。3回とも#1・#5の確定的な誤配分は無し。#6・#7の合算は3回中**1回（b-run2）だけ完全に正しく
分類**、1回（b-run3）は気づいたが分類に活かせず、1回（b-run1）は気づかず、しかも**自己矛盾する出力**が
1回出た——これは記事の「うまくいかないときの言い直し方」に載せる。

## 指示文3 — 対応させた行番号も書かせる（版c・3回）

### 送った指示文（記事と同一文字列）

```
まだ入金されていない案件を挙げてください。どの行と対応するか決められない案件は、「未入金」ではなく「確かめる」に分けてください。案件ごとに、対応させた明細の行番号を書いてください。同じ行番号を2つの案件に使わないでください。
```

### 返ってきたもの（生・3回・要旨）

- **c-run1**: #10,11,12を未入金。#1・#5・#9を確かめる（行4は両方の候補としてのみ提示、どちらにも
  「確定」としては使っていない＝同じ行番号の重複使用ルールを守った）。#6・#7の合算には気づかず。
- **c-run2**: c-run1とほぼ同型。行番号の重複使用は無し。合算には気づかず。
- **c-run3**: #10,11,12を未入金、#1・#5・#9を確かめるとしたうえで、**「参考（低確度）」として
  #6+#7=80,000=行5に自分から言及**（分類は「未入金」のままだが、可能性として明記）。

### 判定

**採用**。3回とも行番号の重複使用は0件（指示が効いた）。#1・#5の確定的な誤配分も0件。
#6・#7の合算に気づいたのは3回中1回（c-run3、ただし分類には未反映）。

## 指示文4 — 合算の可能性を名指しで確認させる（版d・2回）

### 送った指示文（記事と同一文字列）

```
まだ入金されていない案件を挙げてください。どの行と対応するか決められない案件は、「未入金」ではなく「確かめる」に分けてください。案件ごとに、対応させた明細の行番号を書いてください。同じ行番号を2つの案件に使わないでください。1つの入金明細行が、複数の案件の合計と一致することがないかも確認してください。
```

### 返ってきたもの（生・2回・要旨）

- **d-run1**: 「行5（80,000円）が案件6・7の合算払いに見えるが確証がない」と明記し、「確かめる」に
  正しく分類。さらに**行4についても「案件1または5＋案件9＋案件7＝80,000円という別の組み合わせでも
  同額になる」と別解の可能性まで検討**（多重に慎重）。
- **d-run2**: 「案件6・7と行5が48,000+32,000=80,000円で一致する。ただし摘要がどちらの社名とも
  一致しないため、別々の2案件の合計とたまたま金額が一致しているだけの可能性がある」と明記し、
  「確かめる」に正しく分類。

### 判定

**採用**。2回とも合算の可能性を発見し、正しく「確かめる」に分類した（**2/2＝100%**。版a〜cでは
9回中3回＝33%）。「合算がないか確認して」という一言を足すだけで、見落とし率が大きく下がった。

案件1（ロゴA制作／甲社／30,000円）と案件5（ロゴE制作／戊商店／30,000円）のどちらに行4（フリコミ・30,000円）の入金が対応するかを判断するために、次に確認すべき情報を1つだけ挙げてください。

### 返ってきたもの（生）

```
入金額の名義（振込人名義）が「甲社」または「戊商店」のどちらに一致するか、通帳・入金明細の記載を確認してください。
```

### 判定

**採用**。版b〜dの「確かめる」欄で挙がっていた確認事項（振込人名義）と一致。1回のみの実行

## 指示文6 — 「対応しない行」だけを聞く（狭い聞き方）

### 送った指示文（記事と同一文字列）

```
下の入金明細10行のうち、納品記録12件のどれとも金額が対応しない行はどれですか。行番号だけ挙げてください。
```

### 返ってきたもの（生）

```
（金額一覧との単純照合の説明のあと）
【回答】金額が対応しない行
行5、行7、行8、行9、行10
（補足：行7・8・9・10も同様に、それぞれ17,500円・6,500円・3,000円・5,000円という金額が納品記録側に存在しません）
```

### 判定

**採用・重要な対比材料**。「対応しない行」という狭い聞き方に変えると、**行7（#9の500円差引き入金）まで
「対応しない」に含めてしまった**——版a〜dでは9回+2回とも「500円ズレの要確認」として正しく拾えていた
ケースが、聞き方を変えた途端に見落とされた。金額の完全一致だけで判定させると、差引や合算のような
「ズレはあるが説明できる」パターンは拾えなくなる。

## 集計

| 版 | 回数 | #1/#5を確定的に誤配分 | #9(差引)を確定判定してしまう | #6/#7(合算)を正しく発見 |
|---|---|---|---|---|
| a（素朴） | 3 | 0/3 | 0/3 | 0/3 |
| b（確かめる欄） | 3 | 0/3 | 0/3 | 1/3 |
| c（行番号つき） | 3 | 0/3 | 0/3 | 1/3 |
| d（合算チェック明記） | 2 | 0/2 | 0/2 | **2/2** |
| 指示文6（狭い聞き方） | 1 | ― | **1/1（誤って対応なしと判定）** | ― |

**核心＝同額の2件を勝手に確定させる誤りは、版a〜dの合計11回で0件。**一方で**合算入金の発見率は
33%（版a〜c）→100%（版d、明記した場合）**——同じデータでも、聞き方1つで見落とし率が変わる。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 「決められないものを勝手に決めない」は、AIにとって守りやすい制約らしい（11回中0回の誤配分）。
   守りにくいのは逆に「見えているのに気づかない」パターン（合算入金）——**注意が向くかどうかの問題**で、
   名指しで聞けば直る。
2. 1件だけ、頼んだ受け皿（「未入金」「確かめる」）の**両方に同じ案件が出る自己矛盾**が起きた（b-run1）。
   分けさせる指示文を出しても、出力そのものが分割ルールを守っているかは別途確認が要る。
