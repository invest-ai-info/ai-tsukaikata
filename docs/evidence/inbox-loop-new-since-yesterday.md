# 試した証拠 — inbox-loop-new-since-yesterday

2026-08-15 実施。**架空の受信箱3日ぶん**（13通・12通・13通）に、**同じ指示文をそれぞれ2回ずつ**通した。
受信箱には**未処理のまま残る5通（居座り）を、3日とも1文字も同じ文字列で**入れてある＝これが真値になる。

⚠️ 実測したのは**指示文だけ**。メールソフトとつなぐ仕掛けや、決まった時刻に走らせる仕掛けは
この記事の対象外で、既存記事に譲っている。

⚠️ 実測用のセッションには、このリポジトリのファイルを読まないよう指示したうえで走らせた。
ただし**「事前知識なし」とは言えない**（台帳★20）。そのため判定はすべて
**機械照合できるものだけ**にした＝件名の文字列の完全一致・欄の割り当ての一致・件数の数え上げ。

判定コード＝`check.py`（返りを読んで欄を取り出す／件名の丸めを検出する）、
`score_p4.py`（「前から残っているもの」の当たり外れを真値と突き合わせる）。
⚠️ **`check.py` は最初に1度あぶなかった**（下の「計測器の話」を見ること。台帳12番）。

## 計測器の話（台帳12番）

🚨 **`check.py` の見出しの正規表現を、最初は `^([ABC]):$` にしていた。**
そのままだと、`A`（コロンなし）で返ってきた3日目2回目だけが**空の結果**になり、
「居座り5通は5回とも同じ欄」と**取りこぼしに気づかないまま**表示されるところだった。
`^\s*(?:[#*\s]*)([ABC])\s*[:：]?\s*(?:[*\s]*)$` に緩めたうえで、
**拾えなかった行を必ず印字する**ようにしてある（上の照合出力に `[拾えなかった行]` が
1件も出ていないことが、拾い漏れが無いことの根拠）。

🚨 **`score_p4.py` は、返りの飾りを3種類落とさないと照合できなかった。**
①番号だけの行（`3, 5, 7`）②番号＋件名（`9 経費精算（…）`）③末尾の欄名（`（A）`）。
落としたあとに**受信箱の件名と完全一致するかを必ず印字する**形にしてある（「件名は受信箱の文字列と完全一致（丸め0件）」の行）。
飾りを落とす処理は、**落としすぎれば別のメールに化ける**ので、ここが最後の歯止めになる。
