記事「長い見本で文体は保てる——2本同時だと曖昧な頼み方は硬い側に偏る」の実測記録。

**実測方法**＝`claude` CLI の独立実行（`claude -p --model claude-sonnet-5 --tools "" --append-system-prompt "…"`）。
共有コンテキストの無い新規プロセスを毎回1回だけ呼び出した。台帳★287の教訓（作業ディレクトリ名が
記事の仮説を漏らす）を踏まえ、**実行ディレクトリは英数字5文字のランダム名**（`zq4lx`・`eegid`等、
意味を持たない）にした。system prompt は「あなたは汎用のアシスタントです。ツールを使わず、

## 判定コード

```python
import re

def sentences(text):
    return [p for p in re.split(r"。", text) if p.strip()]

def stats_a(text):
    """くだけた文体（んですよね系）の指標。"""
    sents = sentences(text)
    n = len(sents)
    avg = sum(len(s) for s in sents) / n
    target_end = sum(1 for s in sents if s.endswith("んですよね") or s.endswith("んです"))
    chinamini = text.count("ちなみに")
    return dict(n=n, avg=round(avg, 1), target_end=target_end, chinamini=chinamini)

KEITAI_RE = re.compile(r"のである$")

def stats_b(text):
    """硬い文体（のである調）の指標。"""
    sents = sentences(text)
    n = len(sents)
    avg = sum(len(s) for s in sents) / n
    plain = sum(1 for s in sents if KEITAI_RE.search(s))
    sosomo = text.count("そもそも")
    return dict(n=n, avg=round(avg, 1), plain=plain, sosomo=sosomo)
```

CLIの出力先頭には毎回 `Warning: no stdin data received in 3s, proceeding without it.` という
CLI自身のノイズ行が付く（stdinを渡していないため）。判定前にこの行だけを除去した。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 長い見本（約850字）でも、短い見本（約200〜400字）と同程度の高い比率（くだけた100%・硬い85%）
   で文体の文末パターンが再現された。見本の長さは、再現の良し悪しを大きく左右しなかった。
2. 【新規】2本の見本（文体が異なる）を同時に渡し「この文体で」と曖昧に頼むと、**出力は両方の
   中間（混ざる）ではなく、常に一方（この実測では硬い側）に完全に偏った**（6/6条件・計40文で
   くだけた側は0文）。見本の順番を入れ替えても結果は変わらなかった（74%→81%）。
3. 【新規・★100/★146の系列が再発】書く前に「どちらを使うか一言で確認して」と頼むと、**実際に
   書かせたときとは逆の側（くだけた）を使うと申告した**（2/2）。AIの自己申告は、同じ条件での
   実際の挙動の証明にならない。
