# 試した証拠 — free-text-tally-needs-row-ids

記事に載せる指示文すべてについて、実際に試した生の返りを残す。

実測方法：`claude --safe-mode --tools "" --session-id <uuid> -p "<指示文>"`。
`--safe-mode` でこのリポジトリの CLAUDE.md・skills・履歴を無効化し、新規の `--session-id` ごとに
完全に独立したセッションで実行した（★91対策＝材料を作った本人がそのまま答えも書く問題を避けるため）。
判定は Python ではなく、ID の集合を目で数え上げる機械的な対応づけ（本文に書いたとおりの単純な集計）で行った。

---

## この記事から出た教訓（`content/_lessons.md` へ）

1. 台帳6番（AIの集計・計数は当てにならない）は、この実測では**計数そのものは再現性が高かった**
   （同一の素朴な頼み方を独立セッションで2回試し、分類の内訳が完全一致）。崩れたのは計数ではなく、
   **入力の形**（IDが無いと空欄が貼った時点で消える）と、**逃げ道の有無**（1つに強制すると、
   内容の無い回答が実在カテゴリに紛れ込む）だった。
2. 台帳★112（合計と総行数の検算は自分から出てくる）の裏返しを観測した：合計の検算は**算術のズレ**
   しか検出できず、**内容の誤分類**（分類不能な回答が実在カテゴリに紛れ込むこと）は検出しない。
   「合計が合っている」は「内訳が正しい」を保証しない。
3. 結果をそのまま別のセッション・別の文脈（Slack報告）に渡すと、「ざっくりで」という指示だけでは
   数字がまるごと消える。会話を継続して同じ表を参照させた場合は、数字は丸まらずそのまま残った。
   **丸まるかどうかは、丸める指示そのものではなく「元のデータが見えているか」で決まる**可能性がある
   （1回だけの観測。一般化しない）。
