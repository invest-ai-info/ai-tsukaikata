# 試した証拠 — memo-chain-holds-until-it-summarizes-itself

[AIの引き継ぎメモで翌朝に続きができるか](https://ai-tsukaikata.com/recipes/memo-that-names-the-next-row/)
が末尾に残した宿題「止まったまま何日も続いた場合にメモがどうなるかは測っていません」に答える実測（2026-11-06）。

⚠️ 実測の仕方は `naming-today-does-not-cover-yesterday.md` と同じ形＝「材料を作った本人とは
別の、答えを知らない側に答えさせる」。Agent（general-purpose・毎回新規・前の回の文脈を共有しない
独立呼び出し）に、チャット応答のみを求める依頼として同じ文面を渡した。各エージェントには
「これはコード/ファイル操作ではなく、チャット画面での1回の会話応答である。ツールは使わず、
ユーザーへの返答のみを出力する」という前置きを付けた。

🔁 **自動化・ループ優先枠の2回転ルールに加え、この記事は「日」を跨ぐ連鎖そのものが核心**なので、
各チェーンを独立に複数本（2〜3本）走らせ、1本ずつ1日目→2日目→3日目と順番に進めた
（2日目のエージェントは1日目の出力だけを読み、1日目の待ち行列・資料は見ていない。3日目も同様）。

## 実測の構成

元記事（`memo-that-names-the-next-row`）は「資料集にある2行が止まる」という設計だったが、
今回は**1行だけが毎日同じ理由で止まり続ける**形に単純化した（複数行が混在すると、どの行の
情報が落ちたかの切り分けが難しくなるため）。⚠️ **これは元記事との違いであり、単純化したぶん
「止まる」以外の情報（他の行の処理結果など）に紛れて薄まる、という元記事が見つけた崩れ方は
今回は起こりにくい設計になっている。**この限定は下の「判定」にも明記する。

- **材料A（調べもの）**＝行 `R-07 北支店の来客数の月次推移 ／ 資料: kita-shiten-raikyaku.csv`。
  資料を開くと中身は北支店ではなく南支店の発注記録（品目コードKX-2200〜）で、来客数の数字が無い。
  **識別子3つ**＝`R-07` / `kita-shiten-raikyaku.csv` / `KX-2200`
- **材料B（請求書）**＝行 `S-07 東雲メンテナンス分の請求書確認 ／ 資料: seikyu-shinonome-06.txt`。
  資料を開くと宛先が東雲メンテナンスではなく「ひばり工房」。
  **識別子3つ**＝`S-07` / `seikyu-shinonome-06.txt` / `ひばり工房`
- どちらの資料も**2日目・3日目になっても中身は変わらない**（人間の差し替えが起きていない前提）。

比較する指示文は2つ。

1. **base**＝元記事の§1（素朴な「処理できなかった行はそのままにして、引き継ぎメモにその旨を
   書いてください」）
2. **winning**＝元記事が24/24で効いた最終版（「言い換えずにそのままコピーして貼って」＋
   「次はこの行から」に相当する、①行の文字列 ②資料のファイル名 ③画面の文言 を言い換えずに
   コピーする指示＋「これは何日目の失敗か」を書かせる1行）

**1日目**は待ち行列＋資料を渡し、メモを書かせる。**2日目・3日目**は「前日のメモだけが手元にある
（待ち行列も資料も前日の会話も無い）。今日も同じ理由で同じ行が止まった」と伝え、同じ指示文
（base／winning）で今日のメモを書かせる。前日のメモの**全文**を貼って渡した。

チェーン数＝材料A×base×2回／材料A×winning×3回／材料B×base×2回／材料B×winning×2回＝
**9本のチェーン**。各チェーン3日分なので、メモは合計27通。
