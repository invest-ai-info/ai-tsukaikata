# 試した証拠 — flat-log-keeps-the-benchmark-steady

記事＝`content/recipes/flat-log-keeps-the-benchmark-steady.md`
（「山も谷もない記録なら、目安は変わらない——動いたのは6%だけ」）。

[いつもの目安は見せる日数で変わる——5.5倍にも7.6倍にもなる](/recipes/how-far-back-changes-the-usual-number/)
の続き。あちらは**緩やかな増加傾向のある記録**で、渡す記録の長さ（2週/4週/8週）だけを
変えると「ふだんの目安」が約36%、倍率が約2.1倍の幅で動くことを確かめた。あちらの末尾は
「⚠️ この記事が実測していないこと」として「増減の傾向が無いフラットな記録で、窓の長さを
振った場合」を明記して残していた（台帳★225にも同じ限界が記録されている）。本記事はそこを
埋める＝**増減の無い（山も谷もない）架空の記録**で、同じ軸（窓の長さ）を振った。

実測日 2026-10-12。実行方法は前回・前々回の担当と同じ＝`Agent`ツール（`general-purpose`／
`model: sonnet`）で、共有コンテキストの無い新規サブエージェントを毎回1回だけ呼び出した
（★91＝答えを知らない者が答えることで版の比較が成立する。材料を作った本人〈このセッション〉が
返答も書くと比較が成立しないため、サブエージェントに「ふつうの無料チャットAI」の役を演じさせ、
ツール不使用・暗算で答えさせた）。6つの指示文を、それぞれ独立した新規呼び出しで**2回ずつ・
合計12回**試した（自動化ものの2回転の決まりに従う）。

真値（単純平均・週ごとの合計・標準偏差）はすべて Python `statistics`（固定シード・再現可能）
で算出した。

比べると、差は 5.29 − 5.00 = 約0.29件/日、相対的には約5.7%の差です。

判定: この差は実務上「同じ」とみなせる範囲だと思います。理由は以下の通りです。

- もともとの1日あたりの件数が3〜7件という小さな数で、日によってこの程度のばらつきが普通に出ます。0.3件ほどの差は、こうした自然なブレの範囲内です。

- 問い合わせ対応の人員配置やSLA（対応目標時間）の設計など、実務上の判断に使う場合、5.0件/日と5.3件/日の違いで結論が変わる場面はほとんどないはずです。どちらを使っても「1日あたりおおむね5件前後」という同じ目安になります。
