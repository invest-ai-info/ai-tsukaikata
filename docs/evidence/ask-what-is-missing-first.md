# 試した証拠 — ask-what-is-missing-first

2026-08-12 に実施。教材＝**21字の曖昧な依頼**1本。様式は `docs/evidence/TEMPLATE.md`。
判定はすべて Python（文字列照合）。

⚠️ **仕込み＝依頼を意図的に短くしたこと。**「取引先に謝るメールを書いて。納期が遅れた。」に
書いてある事実は**3件だけ**（相手・謝罪・遅延）。これで「AIが何件を勝手に決めるか」が
機械的に数えられる。

## 指示文A（そのまま書かせる）

### 送った指示文
取引先に謝るメールを書いて。納期が遅れた。

### 返ってきたもの（生・抜粋）

```
件名：納期遅延のお詫び（〇〇の件）

株式会社△△
ご担当者様

いつも大変お世話になっております。
株式会社□□の山田でございます。

このたびは、弊社製品の納期が遅延いたしましたこと、
誠に申し訳ございませんでした。心よりお詫び申し上げます。

今回の遅延は、弊社の生産工程における手配の不備が原因でございます。
本来であれば○月○日にお届けすべきところ、○月○日となる見込みです。

（…中略…）

つきましては、今後このようなことがないよう、
社内の進捗確認を週次から日次へと改めることといたしました。

株式会社□□
営業部 山田太郎
```

### 照合（Python）

```
出力の長さ: 333字
★AIが勝手に決めた設定: 4件
   ・遅延の原因（生産工程における手配の不備）
   ・自社の業種／部署（営業部）
   ・送信者の氏名（山田太郎）
   ・再発防止策の中身（進捗確認を週次から日次へ）
仮定であることの明示: ★なし
足りない情報の指摘: ★なし
```

### 判定
**記事の出発点。**日付は `○月○日` と伏せられているのに、**原因と再発防止策は伏せずに
断定されている**。伏せる／伏せないの基準が一貫していない。

## 指示文B（よく紹介される「頼み方を良くして」）

### 送った指示文
この頼み方を良くしてください。
「取引先に謝るメールを書いて。納期が遅れた。」

### 返ってきたもの（生・抜粋）

```
あなたは製造業の営業担当者です。取引先に対して、納期遅延のお詫びメールを
作成してください。以下の条件に従ってください。

■ 状況
・弊社の生産工程における手配ミスにより、納期が3日遅延しました
・取引先とは5年以上の取引実績があり、良好な関係を維持しています
・今回が初めての納期遅延です

■ メールの条件
・件名は簡潔に、遅延の事実が分かるものにしてください
・冒頭で謝罪し、原因、新しい納期、再発防止策の順で構成してください
・全体で400〜500字程度にまとめてください
・過度にへりくだりすぎず、誠実さが伝わる文体にしてください

（…以下、含めるべき要素5点・避けるべきこと3点…）
```

### 照合（Python）

```
出力の長さ: 426字
★AIが勝手に決めた設定: 7件（Aより3件増）
   ・遅延の原因 ・自社の業種／部署 ・遅延の日数（3日）
   ・取引の長さ（5年以上） ・初回かどうか（今回が初めて）
   ・文体の程度（へりくだりすぎず） ・文字数（400〜500字）
仮定であることの明示: ★なし
足りない情報の指摘: ★なし
```

### 判定
🚨 **記事の中心にした。「良くして」は逆効果だった。**

**設定が4件→7件に増えている。**しかも増えた3件（3日遅延・5年以上の取引・初めての遅延）は
**事実関係そのもの**で、違っていれば文面が嘘になる。
🔑 **改良版プロンプトは体裁が立派なので、そのまま使ってしまう。**使えば、AIが決めた
前提が固定されたまま本文が生成される。

⚠️ **「頼み方を良くして」は、材料がそろっているときだけ有効。**その場合も
**「これ以外の設定を足さないでください」**が必須（記事§7に、条件付きで載せた）。

## 指示文C（記事§1〜§3・採用した形）

### 送った指示文
この頼み方で、あなたが答えるために足りない情報を挙げてください。
まだ書き始めないでください。

足りない情報を、答えが変わる度合いの大きい順に並べてください。
それぞれ「埋まらないと何が起きるか」も1行で書いてください。

このうち、いくつ答えれば下書きを作れますか。
残りは「不明」のまま、触れない形で書いてください。

### 返ってきたもの（生・抜粋）

```
1. 何がどれだけ遅れたのか
   → 何日遅れるのか。すでに納期を過ぎているのか、これから遅れると伝えるのか。
     これで謝罪の重さが変わります
2. 遅れた原因
   → 自社の落ち度か、仕入先など外部要因か、災害など不可抗力か。
     原因を書かないお詫びは「隠している」と読まれることがあります
3. 新しい納期が決まっているか
   → 決まっているなら日付を、決まっていないなら「いつまでに連絡するか」が要ります
4. 相手が受ける影響
5. あなたの立場と、相手の役職
6. これが初めてか
7. 補償や値引きの話をするか
   → 社内で決まっていないことを書くと後で困ります

【いま分かっていること】
・相手は取引先 ・謝罪のメールである ・納期が遅れた
この3つだけでは、上の1〜3が埋まらないため、書いても仮の内容になります。

【いちばん急ぐなら】
1・2・3の3つだけ教えていただければ、下書きは作れます。
4〜7は「不明」のまま、触れない形で書きます。
```

### 照合（Python）

```
AIが勝手に決めた設定: 0件
足りない情報の指摘: 7件
仮定であることの明示: あり（「いま分かっていること」の節）
優先順位の提示: あり（「答えが変わる度合いの大きい順」「いちばん急ぐなら」）
```

### 判定
**採用。0件 / 7件。**
🔑 **「まだ書き始めないでください」が効きどころ**（無いと完成品が返る＝台帳★12bの再発）。
🔑 **質問が7件返るということは、Aでそのまま書かせていたら7件をAIが決めていたということ。**
Aで数えた「4件」は表に出たものだけで、実際にはもっと決められていた。

📌 **「3つで足りる」と返ってきたのが実用上いちばん大きい。**7つ全部答えるのは面倒だが、
3つなら答える。**質問の数ではなく「最低いくつで足りるか」を聞くのが型。**

## この記事から出た教訓（`content/_lessons.md` へ）

1. **★12b（成果物の前に「まだ作らないでください」）が再発。**これで**3回目**
   （献立・週報・この記事）。**質問を返させたいときは、止める一言が必ず要る**
2. **新規＝「頼み方を良くして」は、AIが決める設定を増やす。**実測 4件 → **7件**。
   増えた3件は事実関係（日数・取引年数・初回か）で、違えば文面が嘘になる。
   ⚠️ **改良版プロンプトは体裁が立派なので、そのまま使ってしまう**のが危ない。
   使うなら「これ以外の設定を足さないでください」を必ず添える
3. **新規＝AIは「伏せる／伏せない」の基準が一貫しない。**同じ返答の中で、
   日付は `○月○日` と伏せたのに、**原因と再発防止策は伏せずに断定した**。
   伏せてほしいものは名指しする
4. **新規＝質問させるときは「最低いくつ答えれば足りるか」まで聞く。**
   7件全部は答えないが、3件なら答える。**答えられる量に落とすのは相手にやらせる**
