## この記事から出た教訓（`content/_lessons.md` へ）

1. ★205番が再発した（振込手数料ぶんの差額という新しい欠け方で）。`three-way-split-does-not-
   break-the-match`（H23）・`four-and-five-way-split-does-not-break-the-match`（H27）は
   「本当に1回分だけ未入金」という欠け方での頑健性を確かめていたが、今回の欠け方は
   「1回分の金額が少しだけ（500円）ずれる」という、より見つけにくいはずの形。それでも10回中
   10回とも正しく名指しで検出され、健全な11件を巻き添えにした回も0回だった。
2. 台帳12番が再発した（計測スクリプトのほうを先に疑う、系列）。判定語が対象の名前より前に
   来る文（「未入金（不足あり）の工事は、木村様の…」）を、素朴な正規表現（名前の直後だけを
   見る判定）は拾えなかった。全10回を目視で確認し、実際の見逃しは0件であることを確定させた。
3. `combined-payment-missed-as-unpaid`（単発の入金明細1行と請求1件を直接比較する場面）は
   同じ振込手数料ぶんの差額を11/11拾えていたが、あれは1対1の比較だった。今回は複数回の
   分割入金をAI自身が合計してから過不足を見る場面（合算という一段階が挟まる）でも、同じ
   精度（10/10）が保たれることを確認した。
4. 新しい観察＝不足額を500円という丸い数字から437円という「振込手数料らしくない」額に
   変えても、検出は6/6で崩れなかった。また「合計額が…一致するかどうかも確認してください」
   という、照合を明示する一文を削っても、6/6とも自分から合計を照合して不足を検出した。
   この材料・この頼み方の範囲では、見逃しの入口になりそうな2つの条件（丸い数字への依存・
   明示的な照合指示への依存）のどちらも、崩れる原因にはならなかった。
