### 返ってきたもの（生・2回）

**1回目**：

```
**P3が最も異常です。**

理由は、2026-09-04 20:15:59 と 2026-09-04 20:16:11 に、わずか**12秒**の間隔で2回連続して実行されている点です。

P3は通常、短くても数分〜数十分、長いときは数時間おきに実行されています(ログ全体を通して見ても、P3同士の間隔が1分を切るケースは他に見当たりません)。それに対してこの2件は12秒しか離れておらず、他のどの処理・どの時間帯の間隔と比べても異常に短いです。

- 同じジョブが二重起動(二重トリガー)した
- 直前の実行が終わらないうちに次がキックされた(リトライ/タイムアウトによる多重実行)

といった、スケジューラやジョブ自体の不具合を疑わせる典型的なパターンです。

参考までに他プロセスの最短間隔も見ておくと、P2は約3分51秒(09-19 08:20:36→08:24:27)、P4は約2分(09-09 23:46:54→23:48:52)、P1は約1時間48分が最短で、いずれも12秒という極端な近さには及びません。したがって、この1件がログ全体の中で最も説明のつかない=異常な実行だと判断しました。

```

**2回目**：

```
**P1が最も異常です。**

理由は、P1だけが「1日に1回」程度の低頻度処理のはずなのに、実行間隔が全く一定していない点です。

P1の発生時刻を並べて間隔を見ると、

- 2026-09-01 02:33 → 06:56（約4時間23分後）
- 2026-09-03 01:37 → 2026-09-04 20:43（約43時間後）
- 2026-09-07 07:32 → 15:40（約8時間後、同日2回目）
- 2026-09-09 18:22 → 20:10（約1時間48分後、同日2回目）
- 2026-09-20 02:26 → 19:39（約17時間後、同日2回目）

のように、短いときは2時間足らず、長いときは40時間超と振れ幅が極端に大きく、実行時刻（早朝・昼・深夜）もバラバラです。本来「定期実行」であれば大体一定の間隔・時間帯に収まるはずですが、P1だけは「ほぼ1日おきに1回」という本来の周期から外れて、同日中に短時間で2回走ったり、2日近く間隔が開いたりを繰り返しています。

一方でP2・P3・P4は、1日の中で何度も（数十分〜数時間おきに）継続して発生しており、頻度は高いものの分布としては不自然さがありません（全処理が共通して2026-09-09 23:48から2026-09-14 00:05まで約4日間完全に止まっている期間はありますが、これは4処理すべてに共通する停止であり、特定の1処理の異常とは言えません）。
```

## この記事から出た教訓（`content/_lessons.md` へ）

1. **「いちばん異常な処理はどれですか」という単数形の問いは、監視対象の全部が同時に止まり、
   正常な基準点が記録に1本も残らない構成では、その停止そのものを答えの理由にしない。**
   2回とも「複数の処理が同時に止まった状態は、1つの処理の異常ではない」と自分から理由をつけて
   停止を除外し、代わりに別の、停止とは無関係な特徴（偶然の近接・間隔の不規則さ）を答えにした。
   **その代わりの答えは2回で一致しなかった**（1回目はP3、2回目はP1）——基準点が消えたときの
   単数形の答えは、再現性そのものが無い。
2. 複数形（「処理ごとに計算して」）は、正常な基準点が1本も残らない構成でも崩れなかった。
   4本すべてを2回とも漏れなく「該当あり」にした。比較の単位を処理名で区切っているため、
   「全体の中で何が目立つか」という単数形の罠に陥らない。
