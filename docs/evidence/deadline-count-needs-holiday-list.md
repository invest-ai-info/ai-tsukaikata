## 走らせる前の検算（Python）

```python
import datetime

HOLIDAYS = {
    datetime.date(2026,9,8): "けやき創業記念日",
    datetime.date(2026,9,21): "みなと感謝の日",
}

def is_business_day(d, holidays):
    return d.weekday() < 5 and d not in holidays

def next_business_day(d, holidays):
    d = d + datetime.timedelta(days=1)
    while not is_business_day(d, holidays):
        d = d + datetime.timedelta(days=1)
    return d

def nth_business_day(start, n, holidays):
    d = start
    count = 1
    while count < n:
        d = d + datetime.timedelta(days=1)
        if is_business_day(d, holidays):
            count += 1
    return d

orders = [
    datetime.date(2026,9,4),
    datetime.date(2026,9,7),
    datetime.date(2026,9,18),
    datetime.date(2026,9,28),
]

for od in orders:
    for holidays, label in [({}, "週末のみ(版a用)"), (HOLIDAYS, "休日表あり(版b/c用)")]:
        start = next_business_day(od, holidays)
        delivery = nth_business_day(start, 5, holidays)
        print(od, label, "->", start, "->", delivery)
```

```
2026-09-04 週末のみ(版a用) -> 起算 2026-09-07 -> 納期 2026-09-11
2026-09-04 休日表あり(版b/c用) -> 起算 2026-09-07 -> 納期 2026-09-14
2026-09-07 週末のみ(版a用) -> 起算 2026-09-08 -> 納期 2026-09-14
2026-09-07 休日表あり(版b/c用) -> 起算 2026-09-09 -> 納期 2026-09-15
2026-09-18 週末のみ(版a用) -> 起算 2026-09-21 -> 納期 2026-09-25
2026-09-18 休日表あり(版b/c用) -> 起算 2026-09-22 -> 納期 2026-09-28
2026-09-28 週末のみ(版a用) -> 起算 2026-09-29 -> 納期 2026-10-03
2026-09-28 休日表あり(版b/c用) -> 起算 2026-09-29 -> 納期 2026-10-05
```

## この記事から出た教訓（`content/_lessons.md` へ）

1. 【新規】「中5営業日」のような期間指定は、**休日情報を渡すだけで曖昧さの大半が解け、
   起算日の数え方まで文章で定義しても（この材料・n=4では）追加の効果は観測されなかった**。
   曖昧さの原因は「数え方の定義」より「休みという材料そのものが無いこと」だった。
2. 【新規】起算日が休日や週末と重なる誤りを**後から「確認して直して」と頼むと、
   直す過程で計算方法自体が変わり、別の誤りが混ざることがある**（n=1・再現検証はしていない）。
   最初から休日情報を渡すほうが、後から直させるより安定した。
