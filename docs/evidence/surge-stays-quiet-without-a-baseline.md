# 試した証拠 — surge-stays-quiet-without-a-baseline

記事＝`content/recipes/surge-stays-quiet-without-a-baseline.md`
（「「ふだんは3〜5件です」と一言足すかどうかで、急増に自分から気づく回数が0対5に分かれる」）。

実測日 2026-09-07。材料は架空の「今日ぶんの一覧」2本（社内ヘルプデスクの問い合わせ35件＝材料A、
通販サイトの返品申請35件＝材料B）。どちらも**中身は壊れていない**（重複・欠落・日付ずれは無い）。
「ふだんは1日3〜5件程度」のところ、今日だけ35件という**純粋な件数の急増だけ**を仕込んだ。

実行方法：`Agent` ツール（`general-purpose` / `model: sonnet`）で、共有コンテキストの無い新規サブエージェントを
毎回1回だけ呼び出した（★20＝実測環境にはプロジェクトの文脈が一部伝わることがあるので、
判定は機械照合できる項目（自己申告の件数・「ふだん」「通常」等の比較語の有無）だけに置いた）。

⚠️ **材料Bは当初、日付欄を09/01〜09/28にばらけさせて生成しており（生成スクリプトの粗）、
「本日の一覧」という前提と矛盾していた。**この状態で先に6回試したところ、基準ありの3回とも
日付のばらつき自体を指摘しており、急増の自己申告がどちらの手がかりで起きたか切り分けられなかった。
**この6回は使わず、日付を単一日の時刻表記に直した材料Bで6回撮り直した**（下に載せているのは撮り直した分）。
最初の6回の生ログは残していない（判定に使わなかったため）。この経緯は `content/_lessons.md` に追記した。

## この記事から出た教訓（`content/_lessons.md` へ）

1. **★20が再発した（間接的な形）**＝実測材料そのものの生成ミス（材料Bの日付欄が
   単一日になっていなかった）が、AIの「気づいたことにする」挙動を誤って底上げする形で
   紛れ込んだ。仕込みを作ったら、**その仕込みが前提と矛盾していないかも先に確認する**
   （台帳12番・★24と同じ「計測器（今回は教材そのもの）を先に疑う」の教材版）。
2. **新しい教訓＝「絞ってください」と「この項目を出してください」は逆の効果を持つ**。

   2/2とも残った。同じ「出力を絞る」操作でも、消したい情報を「除外」するか
   「必須項目として名指し」するかで結果が逆になる。
