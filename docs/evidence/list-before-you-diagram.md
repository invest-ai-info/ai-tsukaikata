# 試した証拠 — list-before-you-diagram

2026-10-19 に実施。架空の業務説明2本（材料1＝経費精算の流れ・材料2＝図書館の予約から貸出までの流れ）で、
一覧化→出典引用→漏れ確認→言葉の実在確認→図の構成案→突き合わせ、の6段階を各1回ずつ通した。
それぞれ独立した新規セッション（記事の方針や仕込みの意図を一切渡していない、素のAIアシスタント役）に、
同じ会話を6ターン続けて試した。判定はすべて機械（文字列の有無の照合）で行い、目視の「良くなった」判定はしていない。

⚠️ 両方の材料には、こちらが答えを知っている「真の関係」を先に決めてある（仕込み）。
AIにはこの仕込みを伝えていない。判定はこの仕込みと、返ってきた引用文そのものを読み直すことで行った。

---

## 教材1（架空データ・経費精算）

```
社員が経費を立て替えたときの流れです。社員は、立て替えた領収書を経費精算システムに登録します。経費精算システムは、登録された申請を上長に通知します。上長は、金額が3万円以下なら自分の承認だけで申請を確定させます。金額が3万円を超える場合は、上長が経理部に追加の確認を依頼します。経理部は、領収書の但し書きが「お品代」など内容不明なものを差し戻します。差し戻された申請は、社員が領収書を撮り直して再提出します。承認が確定すると、経理部が振込データを銀行システムに送ります。銀行システムは、申請の翌々営業日に社員の給与振込口座へ入金します。なお、法人カードで支払った経費は登録の対象外で、カード会社が毎月まとめて明細を経理部へ送ります。
```

この中に書かれている関係は9つ（登録・通知・確定・確認依頼・差し戻し・再提出・送金・入金・明細送付）。
上長と銀行システムの直接の関係・社員と経理部の直接の関係は、本文に書かれていない（仕込みの「無い関係」）。

## 教材2（架空データ・図書館の予約）

```
図書館の本の予約から貸出までの流れです。利用者は、図書館の蔵書検索システムで読みたい本を探し、貸出中の本であれば予約ボタンを押して予約します。蔵書検索システムは、予約の情報を該当する分館の返却待ちリストに追加します。本を借りていた利用者が本を返却すると、返却処理をした職員が返却待ちリストを確認します。返却待ちリストに予約が入っていれば、職員はその本を予約者のために取り置きし、予約者にメールで到着を知らせます。予約者は、メールを受け取ってから1週間以内に来館して本を受け取る必要があります。1週間以内に受け取りに来なければ、取り置きは自動的に解除され、次の予約者に回ります。なお、雑誌とAV資料（CD・DVD）は予約の対象外で、来館した人が直接棚から持っていく先着順になっています。
```

「予約者は来館して本を受け取る」とは書かれているが、来館先が「図書館」だと**その一文の中には書かれていない**
（文章全体の前提では明らかだが、一文単体では示していない＝仕込みの「無い関係」）。

## 基準（素朴に「図の構成案を作って」と直接頼むとどうなるか）

記事では紹介していない比較用の基準。教材1に、いきなり次の1文だけで頼んだ。

### 送った指示文
```
この説明文をもとに、関係図の構成案を作ってください。
```

### 返ってきたもの（生・一部）
```
**① 登場人物（レーン/ボックス)**
- 社員／経費精算システム／上長／経理部／銀行システム／（カード会社）※別経路として分離

**② 基本フロー(左→右、またはスイムレーン図)**
1. 社員 →（領収書を登録）→ 経費精算システム
...
4. 経理部で分岐
   - 但し書きが不明瞭(「お品代」等) → 差し戻し → 社員が撮り直して再提出（①に戻るループ）
   - 問題なし → 承認確定
...
**図の形式としては:**
- スイムレーン図（社員／システム／上長／経理部／銀行の5レーン)が一番わかりやすいです。
- 分岐点（3万円判定、但し書き判定）は◇（ひし形）で表現
...
```

### 判定
**不採用（記事で再現する元になった失敗）。**2つの問題がある。

1. **行ごとに照合できる形になっていない。**ノード・矢印・記号の使い方・配色の提案が1つの文章に混ざっていて、
   「この矢印はどの一文が根拠か」を1本ずつ機械で突き合わせられない
2. **「①に戻るループ」は本文に無い。**差し戻された申請が「最初の登録に戻る」とまでは書かれていない
   （再提出とだけ書かれている）。もっともらしいが確認できない推論が、確認できる事実と同じ調子で混ざっている

→ **先に一覧にしてから図を作らせる**ほうに切り替えた理由がこの2つ。

```
社員 → 経費精算システム → 立て替えた領収書を登録する
```

## 指示文6（突き合わせ）

### 送った指示文（記事と同一文字列）
```
いま作った図の構成案のノードと矢印を、ひとつずつ、さっきの一覧の行と照らし合わせてください。
一覧に無いのに図に入っているものがあれば挙げてください。
一覧にあるのに図から抜けているものがあれば挙げてください。
```

### 返ってきたもの（生・材料1）
```
図の構成案を一覧の9行と1つずつ照らし合わせました。
【ノードの照合】一覧に無いのに図にあるノードはありません。一覧にあるのに図から抜けているノードもありません。
【矢印の照合】一覧に無いのに図にある矢印はありません。一覧にあるのに図から抜けている矢印もありません。
結論: 不一致はありませんでした。
```

### 返ってきたもの（生・材料2）
```
→ 一致。一覧に無いのに図にあるノードは無し。一覧にあるのに図から抜けているノードも無し。
→ 一致。一覧に無いのに図にある矢印は無し。一覧にあるのに図から抜けている矢印も無し。
```

### 照合（機械）
```
両材料とも、ノード数・矢印数の目視再集計と自己申告が一致。指示文5で既に「一覧の言葉だけ」と
縛ってあるため、この段階で新たな不一致は出なかった（確認の工程としては機能したが、
今回は何も拾わなかった）。
```

### 判定
**採用。**今回は不一致ゼロだったが、「図を作らせたら必ず一覧と突き合わせる」という手順として、
縛りを忘れた回の保険になる。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 新規＝★277。一文を引用させても、その一文の中に実際に書かれているかまでは保証しない。
   関係に使った言葉そのものを引用文の中で確認しないと、架空の言葉が1つ混じる
   （「出典なし」は2本とも0件だったのに、言葉の実在確認では21行中3行が見つかった）。
