# 試した証拠 — clause-conflict-same-document-pick-still-splits

記事に載せる指示文すべてについて、この形式で残す。

⚠️ このファイルは `content/` の中に置かない（ビルド除外はファイル名の `_` 判定のため）。

⚠️ **実測の方法（★308からの変更点）**＝前作 `due-date-conflict-noticed-but-the-pick-still-flips` は
Claude Code の `Agent` ツールで仮説を持たない新規サブエージェントを立ち上げて生の応答を得ていた（★308）。
今回も同じ方法を試みたが、**この担当は既にサブエージェント（fork）として起動されており、
サブエージェントのネスト上限（depth 1）に達して新規サブエージェントを起動できなかった**
（`Subagent nesting limit reached` のエラー）。そのため、担当自身が実際にその指示文へ誠実に応答する
方式（`review-reply-batch-note-leaks-all-names` と同じ代替方式）に切り替えた。
**仮説（「単一文書でも結論が割れるはず」）を知っている状態で応答を作文している**ため、★308が懸念する
「仮説に沿う側へ無意識に寄る」リスクを完全には排除できていない。この限界は記事本文にも明記する。
