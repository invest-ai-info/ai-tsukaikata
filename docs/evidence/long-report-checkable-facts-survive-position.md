# 試した証拠 — long-report-checkable-facts-survive-position

記事＝`content/recipes/long-report-checkable-facts-survive-position.md`
（「長い原稿の検品は、仕込んだ位置で見落とし率が変わるか」を実際に試す）。

実測日 2026-09-08。`_hypothesis_queue.md` H9＝「長い原稿（3,000字超）に事実と異なる箇所を
複数仕込んで検品を素朴に頼むと、原稿の中央に仕込んだ箇所は、冒頭・末尾に仕込んだ箇所より
見落とされやすい」。反証条件＝**中央ゾーンの検出率が、冒頭・末尾ゾーンの検出率の平均と
10ポイント以内なら棄却**（凍結済み）。

実行方法：`claude --safe-mode --tools "" -p`（新規セッションを毎回発行、材料を作った本人＝私
と別の実行系統＝★91）。材料2本（月次業務報告書2,624字／イベント運営報告書2,345字）×各5回＝
10回の独立実行。⚠️ 目標だった「3,600字／3,400字」には届いていない（うちの検品系実測で
最長の`summarize-without-dropping`2,192字は超えたが、当初の設計目安には未達）。理由＝
仕込み位置（冒頭/中央/末尾のちょうど3等分点付近）を機械で確定しながら書き足す往復に時間を
要したため、この回はここで打ち切った。次にこの型を書くときは、先に文章量を確保してから
仕込み位置を決める順番にすると良い。

🚨 **仕込みの設計に1件、検出可能性の交絡（confound）を見つけて差し替えた（★24の型）。**
当初、材料②（イベント運営報告書）の中央ゾーンの「数字」仕込みは「会場の総面積480→460
平方メートル」だった。試しに5回実行したところ、**5回中0回、誰も一度も言及しなかった**
（「面積」「平方メートル」の文字列が5回の返りのどこにも無いことをgrepで確認）。

これは「中央だから見落とされた」のではなく、**この数字が原稿内のどこにも照合できる手がかりを
持たない〈単発の数字〉**だったからだと判断した——原稿を最初から最後まで完璧に読んでも、
480が正しいか460が正しいかは原稿の中身だけからは判定できない（他の箇所の数字を足しても
引いても480にも460にもならない）。一方、他の11箇所の仕込みはすべて、原稿内の別の数字や
記述と照合すれば矛盾が分かる形にしてある（内訳の合計・時刻の引き算・直後の文との矛盾、等）。
**この1箇所だけ性質が違っていた**ので、位置の効果を測るには不適切と判断し、同じ中央ゾーン内で
別の照合可能な数字（「ブース運営スタッフは18名（社員12名・アルバイト6名）」→17名。
12+6=18と食い違う）に差し替えて、材料②の5回を実行し直した。

⚠️ **差し替え前の5回の生ログは、判定不能と分かった時点で保存していなかった**
（判定に使わないと決めた版だったため）。grepで「言及ゼロ」を確認した記録だけが残っている。
**証拠として使うのは、差し替え後の5回（下記に生のまま掲載）だけ**にする。落とした理由は
上記のとおりで、これ自体が記事の重要な発見（「検品できるのは照合可能な数字だけ」）になった。
