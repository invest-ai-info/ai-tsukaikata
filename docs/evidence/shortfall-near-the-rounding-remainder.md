## 指示文1（材料1・本当の不足2円・全5回）

### 送った指示文（記事と同一文字列）

```
契約書どおりに入金されているか確認してください。
```

（続けて材料1の契約書・入金明細を貼った。残金が33,333円〈本来33,335円〉で着金。）

### 返ってきたもの（生）— p1_m1_main_1（全文）

```
**結論：契約書どおりには入金されていません。残金が2円不足しています。**

| 項目 | 契約書 | 入金 | 差額 |
|---|---|---|---|
| 着手金 | 33,333円 | 33,333円 | 0円 |
| 中間金 | 33,333円 | 33,333円 | 0円 |
| 残金 | 33,335円 | 33,333円 | **▲2円** |
| 合計 | 100,001円 | 99,999円 | **▲2円** |

**原因**
契約書は「端数は最終回」という取り決めで、100,001円を3等分した際の端数（33,333円×3＝99,999円、余り2円）を残金に上乗せし、残金を33,335円としています。一方、入金明細では残金が他の回と同じ33,333円になっており、端数の2円が反映されていません。

**補足**
- 契約書の内訳自体は正しく、33,333＋33,333＋33,335＝100,001円で合計と一致しています。
- 不足は2円なので、請求側は追加で2円を請求するか、少額として免除するかを判断することになります。
- 振込手数料を差し引いて入金された可能性もありますが、今回は手数料分（通常数百円）とは額が合わないため、端数の計算漏れとみるのが自然です。
```

### 照合（機械・`judge.py`）

```
p1_m1_main_1〜5: 期待不足額=2円 全て 金額記載=True・検出語=True・片付けた=False
```

| | 結果 |
|---|---|
| 2円の不足を「一致」で片付けず正しく検出した回数 | **5/5** |

```

| 着手金 | 33,333円 | 33,333円 | 0円 |
| 中間金 | 33,333円 | 33,333円 | 0円 |
```

## この記事から出た教訓（`content/_lessons.md` へ）

1. ★171・★205・★237の系列が再発した（不足額が端数の大きさと同じ、さらには端数の
   最小単位である1円ちょうどまで縮まる、という新しい欠け方で）。
   `odd-split-still-catches-the-real-shortfall`が残した宿題「もっと小さい差額が端数に
   埋もれるかは未検証」を22回試したが、見逃しは1件も起きなかった。
2. 新規＝1回だけ、冒頭の要約文（「1円合っていません」）と、直後の表の計算結果（「3円」）が
   食い違う回があった。最終的な結論・対応案はすべて正しい数字で一貫しており、実害は無かったが、
   **冒頭の要約文だけを読むと誤った金額を信じる可能性がある**。記事では「表や結論の数字まで
   必ず確認する」という注意として明記した。
3. 新規＝不足額が小さいほど（1円など）、AIは「振込手数料の可能性は低い（手数料なら通常
   もっと大きい額になる）」と自分から判断し、「端数の計算漏れ」という原因を推測する傾向が
   一貫して見られた。この推論自体の正しさは確認していないが、22回を通じて安定していた。
