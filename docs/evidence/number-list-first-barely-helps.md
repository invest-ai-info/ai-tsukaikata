# 試した証拠 — number-list-first-barely-helps

記事＝`content/recipes/number-list-first-barely-helps.md`
（「数字を先にリストアップさせる——それでも6割は見逃す」）。
キュー：`content/_recipe_queue.md`「副業」節「数字を先に全部リストアップしてから確認する2段階方式は、
キャプション内の文脈照合だけの素朴な一括確認より、自然な数字の誤りをどれだけ多く拾えるか」
（源0＝仮説キューH43）。先行記事 `natural-number-swap-hides-from-naive-check`
（2026-10-11公開）が「応用・次の一手」で残した宿題に答える。

実測日 2026-10-16。**全16回**＝材料2種（先行記事と同一のブレンダー・掃除機キャプション）に、
(1)2段階（まずリストアップ→続けて確認、2ターンの会話）×各5回＝10回
(2)2段階を1通のメッセージにまとめた版×ブレンダーのみ3回
(3)リストアップを省いて確認だけを直接頼む版×ブレンダーのみ3回。

⚠️ **実測に使ったAIについて。**このリポジトリの外の、会話の文脈を一切引き継がない独立した
`claude -p --model claude-sonnet-5 --tools "" --append-system-prompt "<汎用アシスタント人格>"` の
呼び出しとして、1セットごとに新しいプロセスで聞いている。2段階（1）は `--session-id <uuid>` で
発行し、続く指示は同じ `<uuid>` に `--resume` して送った（1回目のリストを踏まえて2回目を
答えさせるため）。(2)(3)は単発の呼び出し。人格を固定する一文
（「あなたは親切な汎用アシスタントです。ツールやファイルシステムへのアクセスはありません。
ユーザーの依頼に文章だけで答えてください。」）を毎回同じ `--append-system-prompt` で添えた。

判定は目視で分類。基準は先行記事と同じ＝**ある誤りを「拾った」と判定するのは、その具体的な値が
名指しで「確認した方がよい」「聞き間違いの可能性がある」等の理由つきで個別に挙げられた場合のみ**。
「それ以外の数字は不自然な点は見当たりません」のような一括パスのリストに含まれる場合は
「拾わなかった」とする。実行スクリプト＝`docs/evidence/_raw/number-list-first-barely-helps/`
（教材2本・指示文4種・生の返り全26件を `raw/` に保存）。

## この記事から出た教訓（`content/_lessons.md` へ）

1. **★267が新しい形で再発した**（単独の材料・単発の呼び出しでは崩れなかったものが、
   複数の情報を1回でまとめて処理させると崩れる）。2回の会話に分けたときは10回中0回だった
   「正しい値を誤って疑う」誤りが、1通のメッセージにまとめる・確認だけを単独で頼むと
   6回中4回に増えた。AIが項目どうしの整合性を探しにいく範囲が、作業を1つの依頼にまとめるほど
   広がり、仕込んでいない組み合わせにまで疑いを向けることがある。
2. **「数字を先に全部リストアップする」工程自体には、小さいが実在する効果がある。**
   同じ確認の指示文でも、事前にリストアップさせた版（30%）のほうが、直接確認させた版（20.8%）
   より検出率が高かった。ただし効果は先行記事の「数値に注意して」という言い方（約40%）を
   超えるものではなく、2段階にすること自体が優れた解決策というわけではない。
