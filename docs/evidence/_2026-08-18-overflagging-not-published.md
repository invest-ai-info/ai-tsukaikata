# 測ったが公開しなかった記録 — 「気になるところを全部挙げて」と誤検出

⚠️ **これは公開した記事の証拠ではない。**`content/_recipe_queue.md` の
「納品前の検品で『気になるところを全部挙げて』と頼むと、直さなくていい箇所まで増える」を
2026-08-18 の夜に実測したが、**キューが立てた見立て（拾いすぎが増える）が再現しなかった**ので
公開しなかった。次に同じ題材を採る人が、同じところからやり直さないために残す。

ファイル名を `_` で始めてあるのは、公開記事の証拠ファイル（`<slug>.md`）と取り違えないため。

## 何をやったか

架空の発注書と納品前の原稿を**2組**（A＝家計簿アプリの記事／B＝電動自転車の商品ページ）作り、
**本当の違反8件**と**紛らわしいが発注書と素材に照らすと○になるもの8件**を同数ずつ仕込んで、
7個の指示文を**22回**通した（指示文1〜4は材料2本×各2回、5〜7は材料2本×各1回）。

## 何が起きたか（結論）

1. 🔑 **紛らわしい8件は、ほとんど誤検出されなかった。**返りは自分から
   「引用の中の『絶対』は発注書5でそのまま残すよう明記されているので触らないでください」
   「見出しの体言止めは可ですが、これは本文なのでNGです」と**正しく線を引いた**。
   つまり**「強める一言を足すと誤検出が増える」という見立ては、この仕込みでは成り立たなかった。**
2. 🚨 **かわりに割れたのは、本当の違反のほうの検出数**＝同じ指示文の2回で **4/8〜8/8**。
   ただしこれは `compare-two-runs-yourself`（2回転の割れ）と
   `writing-check-against-spec`（発注書との突き合わせ）で既に書いてある型で、
   **この題材を独立した1本にするだけの新しさが無い。**
3. 📌 **拾いすぎが起きたのは、こちらが仕込んだ紛らわしいものではなく、
   「素材から導いた文」のほう**＝「月に4回に満たないので、読み取りの速さより
   直しやすさのほうが効いてきます」のような、素材の数字から書き手が導いた解釈。
   返り自身が「3.7回＝月4回未満は算術なのでセーフ。後半は素材に無い」と割った回もある。
   **ここを仕込みに据え直せば、別の記事として立つ可能性はある**（下記）。
