## 教材（架空データ）

### ログの生成方法

Python（`random.Random` で乱数シードを固定）で、21日分（2026-09-01〜09-21）の日別実行回数
から、1日の中でだいたい等間隔・わずかにずらした時刻（HH:MM）を機械的に割り振り、処理名
（process=X / process=Y）付きの行として日付・時刻順に並べた。日別回数の仕込みは次の通り。

**セット1（多数派の処理Xが停止・131行）**

```
処理X（1日4〜8回想定）: 09-01〜09-21の日別回数
  5,7,6,4,8,5,6,7,5, 0,0,0,0 ,6,5,7,4,6,8,5,6
  （09-10〜09-13の4日間だけ0。合計100回）
処理Y（1日1〜2回想定）: 09-01〜09-21の日別回数
  1,2,1,2,1,2,1,1,2,1,2,1,2,1,2,1,2,1,2,1,2
  （全期間1〜2回・0件の日なし。合計31回）
```

**セット2（少数派の処理Yが停止・147行、役割を入れ替え）**

```
処理X（1日4〜8回想定）: 09-01〜09-21の日別回数
  5,7,6,4,8,5,6,7,5,5,6,7,4,6,5,7,4,6,8,5,6
  （全期間4〜8回・0件の日なし。合計122回）
処理Y（1日1〜2回想定）: 09-01〜09-21の日別回数
  1,2,1,2,1,2,1,1,2, 0,0,0,0 ,1,2,1,2,1,2,1,2
  （09-10〜09-13の4日間だけ0。合計25回）
```

生成したログの先頭5行（セット1）：

```
2026-09-01 00:06 process=X
2026-09-01 00:08 process=Y
2026-09-01 04:49 process=X
2026-09-01 09:28 process=X
2026-09-01 14:04 process=X
```

🚨 **仕込みの検証**＝生成後、Pythonで日付ごと・処理ごとに行数を数え、仕込んだ日別回数と完全に
一致することを確認した（`sum(X)==100, sum(Y)==31`（セット1）／`sum(X)==122, sum(Y)==25`
（セット2））。実際にAIがセット2の合算を数えた結果（指示文3の2回目の返り）も、09-01から
09-21まで同じ日別合計（6,9,7,6,9,7,7,8,7,5,6,7,4,7,7,8,6,7,10,6,8）を示し、こちらの仕込みと
一致することも確認した。

## この記事から出た教訓（`content/_lessons.md` へ）

1. **複数の監視対象を1つの指示文にまとめるとき、「全体で見る」と「対象ごとに見る」のどちらで
   頼むかで、見逃しの起きやすさが非対称に変わる。**今回は、多数派の停止は合算でも見える
   （合計自体が落ちるため）が、少数派の停止は合算すると多数派の数字に埋もれて消える。
   頻度の差が大きい対象を1本の記録にまとめるときは、「対象ごとに」と名指しすることが必須で、
   「全体で見て」も一部は偶然当たるので、少数のお試しでは問題に気づきにくい。
2. **「気づいてはいるが、主たる判定は変えない」という返りが起きる。**セット2の合算・2回目は、
   本文末尾でYの不在に触れながら、設問への一次的な回答は「該当なし」のままだった。機械判定は
   「言及があったか」ではなく「設問への一次的な回答が何だったか」で見る必要がある。
