# 試した証拠 — no-date-caution-zeroes-the-backlog

記事＝`content/recipes/no-date-caution-zeroes-the-backlog.md`
（「日付が無くても注意一文で新着0件——無いと8件丸ごと新着に化ける」）。

[監視対象を増やしても、古い記録は新着にしない](/recipes/unseen-does-not-mean-new/)は、
**日付が付いている記録だけ**で実測し、「既読リストが無い対象も、過去の記録まで新着に含めない
よう注意してください」という軽い注意で4回とも0件に戻ることを確かめたうえで、本文の末尾に
「ここで確かめたのは記録に日付が付いている材料だけです。日付が書かれていない記録では、
この軽い注意だけでAIが何を基準に『過去』と判断するかは分かりません」と明記して終わっていた
（`content/_recipe_queue.md`「自動化・ループ優先」節の未処理項目が同じ論点を指定）。
本記事はそこを埋める＝**日付欄を一切持たない架空の記録**で、同じ軽い注意を試した。実測日 2026-11-09。

## ⚠️ 実行方法

`Agent` ツール（`general-purpose`／`model: sonnet`）で、共有コンテキストの無い新規サブエージェント
を毎回1回だけ呼び出した（★91＝答えを知らない側が答えることで版の比較が成立する）。
役は「ツール・コード実行を一切使わない、ふつうの無料チャットAI」。2条件×2回＝**合計4回**、
それぞれ独立した新規呼び出し。

各呼び出しの最初のメッセージは次の枠組みで統一した（テストの指示であって、記事に載せる
指示文そのものではない）。

```
あなたは、ツールやコード実行を一切使わない「ふつうの無料チャットAI」の役を演じてください。
Bash・ファイル読み書き・検索など、いかなるツールも呼び出さないこと。これはある人があなたに
そのまま貼り付けて送った依頼です。前置きの確認や分析メモは書かず、求められた回答だけを
自然に書いて返してください。

---

（記事と同一文字列の指示文。材料は指示文の中に埋め込んである）
```

判定は機械照合＝返ってきた文章で、情報システム部（新規追加対象）の新着件数が
「8件」（全件）になっているか「0件」になっているかを数えた。総務部・人事部・経理部の
既存3対象は、どの回も既読リストとの差分が明確（真値＝総務部1件・人事部0件・経理部1件）
なので、そちらも実際の回答と一致しているかを併せて確認した。

## 教材（架空データ）

実在の個人・企業の情報は1件も含まない。社内のお知らせ掲示板4本の監視という設定。
既存3対象（総務部・人事部・経理部）には既読リストがあり、今回の取得で1件ずつ新着（総務部
N-06・経理部K-04）か新着無し（人事部）かが機械で判定できるように仕込んだ。

**4本目（情報システム部）だけ、今日から新しく追加した対象で、既読リストが無い。**
取得した8件（S-01〜S-08）は、[先行記事](/recipes/unseen-does-not-mean-new/)のSNS監視・
入金監視と違い、**日付・投稿時刻・相対表現（「本日」「先日」等）を1つも含まない**。
社内掲示板の見出し＋本文という体裁だけで、並び順以外に新旧を示す手がかりが無い。

```
【総務部お知らせ】既読: N-01, N-02, N-03, N-04, N-05
今回の取得:
N-01｜忘年会の会場候補について

N-06｜来年度の座席配置案について

【人事部お知らせ】既読: J-01, J-02, J-03, J-04
今回の取得:
J-01｜年末調整の提出期限について
J-02｜健康診断の予約方法

【経理部お知らせ】既読: K-01, K-02, K-03

K-02｜取引先コードの統合について

K-04｜年末の支払いスケジュール

【情報システム部お知らせ】※今日から新しく追加した監視対象。既読リストはまだありません。
今回の取得:
S-01｜パスワードの定期変更ルールについて

```

真値: 総務部＝新着1件（N-06）／人事部＝新着0件／経理部＝新着1件（K-04）／
情報システム部＝**日付が無いので「今日できた記録」は確定できない。ただし既読リストが
無いことをもって全8件を新着と報告するのは誤りで、少なくとも「全8件を新着扱いする」
という形は避けるべき**という前提で判定した。

## 4回の一覧

| 条件 | round1 | round2 | 情報システム部の新着件数 |
|---|---|---|---|
| 軽い注意なし | 失敗（8件） | 失敗（8件） | 2/2で全件を新着扱い |
| 軽い注意あり | 成功（0件） | 成功（0件） | 2/2で0件に戻った |

**日付が1つも無い記録でも、軽い注意だけで2回とも0件に戻った。**
[先行記事](/recipes/unseen-does-not-mean-new/)が残した「日付が無い記録では分からない」
という宿題に対して、**この材料・この4回に限っては、分からないままではなく効いた**という
答えが出た。⚠️ 材料1本・各条件2回だけなので、「日付が無くても必ず効く」とは一般化しない。

## この記事から出た教訓（`content/_lessons.md` へ）

1. ★20が再発した、より正確には逆方向の確認。[先行記事](/recipes/unseen-does-not-mean-new/)が
   「日付が無い記録では、この軽い注意だけでAIが何を基準に『過去』と判断するかは分かりません」
   と明記して終わっていたのに対し、この記事の4回では**軽い注意が日付の有無に関係なく効いた**。
   AIの返答を読むと、日付ではなく「既読リストが無いこと自体」を手がかりに「初回取得分＝基準値」
   という扱いを自分で組み立てていた（「既読の基準として扱いました」「集計から除外しています」）。
   一般化はしないが、**軽い注意の効き方が必ずしも日付という手がかりに依存していない**ことが
   分かった。
