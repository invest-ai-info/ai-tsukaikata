# 試した証拠 — no-date-line-holds-until-forced
すべて **claude CLIを `--safe-mode --tools ""` で新規サブプロセス起動**し、送ったのは
指示文＋教材の文字列だけ（この会話の文脈は一切渡していない＝答える側は真値を知らない）。
指示文1（①外しただけ）・指示文2（②強制）は各6回。指示文3（③強制+推測明記）は3回。
指示文4（下流の質問）は、指示文2の直後に**同じセッションIDで`--resume`し**独立3チェーン。
指示文5（②の末尾に元のガード文を書き戻した版）は3回。指示文6（保存版テンプレート）は2回。
のべ23回＋下流3回＝26回。

⚠️ このプロジェクトの `create_session`（別セッション起動）は `scheduled_trigger` 起点の
セッションで `permission_mode` が記録されず使えなかった（台帳★91が過去に記録した既知の詰まり）。
この担当のツールセットには Agent（サブエージェント）ツールも無かった。かわりに、
**この環境に用意されている `claude` CLI を `--safe-mode`（CLAUDE.md・skills・plugins・
hooks・過去の会話を全部無効化）で直接サブプロセス起動**したところ、本物の独立応答が取れた
（`date-decides-which-note-wins` の証拠ファイルと同じ手口）。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 「決めない」という禁止の一文は、単体で試して安全に見えても、それは「誰も決めろと
   迫っていない」という前提の上で安全なだけである。別の指示（「必ず決めて」）と組み合わせると、
   同じ材料・同じAIでも0/6から6/6へ反転する。ガードの一文の有無は、単独では試さず、
   競合する指示と組み合わせた状態でも試さないと、効いているかどうか分からない。
2. 強制されて確定した「推測」は、下流の会話に引き継がれても半分の回（3/6）でしか
   「推測だった」という事実が残らない。決めさせないことが可能な場面では、下流で
   正直さを期待するより、確定させる時点で止めるほうが確実。
