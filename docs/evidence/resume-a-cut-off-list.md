# 試した証拠 — resume-a-cut-off-list

記事に載せた指示文すべてについて、この形式で残す。返ってきたものは生のまま。
判定は Python（正規表現でID・日付・金額・区分を抽出し、集合演算で欠落・重複・
紛らわしい組の取りこぼしを数える）。仕込み（紛らわしい3組・連番）自体は
`gen.py` で機械的に生成し、走らせる前に「意図した3組以外に偶然の一致が無いこと」を
assert で確かめてある（★24＝真値を作るコードも計測器）。

⚠️ 実測に使ったAIは、このセッション内の新規サブエージェント（Agentツール
`general-purpose`）。事前知識ゼロとは言い切れない（★20＝サイトの文脈が
一部伝わっている可能性がある）ため、「素のAIはこう返す」という一般化はしない。
機械照合できる結果（ID・件数・書式）だけを記事の根拠にしている。

## この記事から出た教訓（`content/_lessons.md` へ）

1. 「続きを書いて」も「すでに出したIDは書かないで」も、材料に元の名簿が残ったままの
   会話の中では、行の欠落・重複・紛らわしい組の取りこぼしを起こさなかった（2本×各2回、
   計12回で0件）。定説（番号で区切れ）が正しいかどうか以前に、「続き」という言い方だけでも
   崩れなかった——これは既存記事（`tidy-files-without-deleting`）の実測（前半／残りで頼むと
   境目がずれる）とは条件が違う（あちらは会話を切って別の頼み方をした）ので、上書きではなく
   条件の違いとして両方を残す。
2. 崩れたのは中身ではなく書式（見出し行の有無）で、しかも「◯件目から◯件目まで」という
   番号指定の言い方だけで起きた。「続きを書いて」系は見出しを繰り返さないという振る舞いで
   一貫していたのに対し、番号だけを指定する言い方は「新しい表の依頼」として扱われることが
   あるらしい。★40（形を固定しても行が消える）の親戚だが、今回は行ではなく見出しが対象。
