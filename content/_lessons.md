# 書き方の台帳（まだコードになっていない教訓だけを置く）

毎晩の担当は**書く前にここを全部読む**。学んだことがあれば足す（**ノルマではない**）。
形式＝「日付／出た記事／事実／次からどう書くか」。証拠は `docs/evidence/<slug>.md`。

⚠️ **ここは待合室であって住所録ではない。**2回出た教訓・全題材に効く教訓は
週次（月曜）で `src/validate.py`・記事の型・`tools/make_figures.py` へ昇格し、
下の「昇格済み」へ移す。**生きている教訓が15件を超えたら週次で整理する**
（長い台帳は読まれなくなって死ぬ）。

⚠️ 夜の担当は**追記のみ**。既存の教訓と「昇格済み」欄を書き換えない。

---

## 生きている教訓

### ★1. 禁止は、受け皿と対で渡す

**4本で出た（最多）。**「〜するな」だけを渡すと、止めたくないものまで一緒に止まる。

| 出た記事 | 何が起きたか |
|---|---|
| `quiz-yourself-with-ai` | 「教材に無いことを出すな」だけだと**問題そのものが作れなくなる**。「代わりに『記載がない』が正解になる問題にして」で直った |
| `fix-typos-not-voice` | 「誤字だけ。他は一切変えるな」だと守りは4/4だが**直ったのは3/6**（重複表現が「書き換え」側に入って止まる） |
| `slides-outline-first` | 「反対意見を1枚立てて」だけだと「ご指摘は当たりません」調の**反論**になる。「その通りかもしれないので、こう確かめます、の形で」で直った |
| `summarize-without-dropping` | 「要約は書き直さないで」が無いと、**指摘の代わりに直った要約**が返り、何が足りなかったかが消える |

→ **禁止を書いたら、必ず「代わりに何をするか」を隣に書く。**
🔥 **昇格候補（最優先）。**記事の型か `validate.py` のどちらで効かせるかは週次で決める。

### 2. 範囲は「名前」ではなく「種類の一覧」で渡す

「校正」「整理」「改善」「要約」のような**名前の範囲は相手が決める**。AIは広いほうで取る。

- `fix-typos-not-voice`＝「校正して」で社内用語が**0/4**しか残らない。直す種類（誤字・重複・表記ゆれ）を並べると6/6・4/4
- `summarize-without-dropping`＝「要約して」で**4/14**。残す種類を名指しすると**14/14**

→ **やってほしいことを、種類の一覧で渡す。**

### 3. 量の制約は「長さ・時間」で渡す。「個数」で渡すと1件が重くなる

- `translate-for-internal-use`＝「2文に割って」は3文で返る。「60字以内」なら守る
- `slides-outline-first`＝「10枚で」だと1枚が重くなる。「15分・1枚1分半」だと枚数が動いて9枚
- `fix-typos-not-voice`＝「短くして」は効かない。「30字以内」で平均17字

⚠️ ただし**上限として当てにはできない**＝`summarize-without-dropping` で「400字以内」が
**417字（4%超過）**になった。**方向は動くが、守られる保証はない。**

### 4. AIの自己申告は、本人が自覚した範囲しか含まない

- `fix-typos-not-voice`＝「直した箇所」の申告**7件**に対し、実際の差分は**13件**。
  無申告の6件に、守りたかった語（本件・別紙・稟議・体言止め）が**そっくり入っていた**
- `tidy-files-without-deleting`＝**件数はどの回も合っている**のに、名前を突き合わせると違う

→ **件数の一致で安心しない。**中身（名前・文字列）を突き合わせる。
🔑 良かれと思ってやった変更ほど、申告に出てこない。

### 5. 単一条件で抜かせると、隣接するものが静かに落ちる

- `mail-needs-reply`＝「返信が要るものだけ」で経費精算・アンケート督促が消える
- `summarize-without-dropping`＝「ただし・対象外・〜しないでください」を含む**10文が0文**しか残らない
- `tidy-files-without-deleting`＝9件が「スクリーンショット5点」に**丸められて**一覧から消える

→ **全件をどれかに割り当てる分類にする。**「判断できない」という行き先を1つ作ると、
落ちたものが見える（`tidy` では45件が「決まった26件＋自分で見る19件」に割れた）。

### 6. AIの集計・計数は当てにならない。照合できる形で出させる

- `translate-for-internal-use`＝用語の出現回数（workspace 4回を5回、connector 5回を6回）
- `slides-outline-first`＝手順の中で数えた「作るフォルダ9個」が実際は15個

→ **数ではなく、原文の一文をそのまま引用させる。**引用なら読者がその場で検索して確かめられる。

### 7. 「丸める」癖は、1回守らせても次の指示文で戻る

`tidy-files-without-deleting` で**同じ晩に3回**起きた（9件→6件→4件）。
指示文を変えるたびに再発する。→ **各指示文で毎回、明示的に止める。**

### 8. AIは「名前・ラベル」を根拠に言い切る

`tidy-files-without-deleting`＝ファイル名の「最終_確定」を信じて、
**更新日時で12日17時間ぶん新しいファイルを「旧版なので削除」と判定**した。
根拠が名前しか無いのに、断定で返る。

→ **「名前を根拠にしないでください」まで言う。**根拠の種類を制限し、根拠を書かせる。

### 9. 換算・計算をさせるときは、使った前提を並記させる

`translate-for-internal-use`＝時差の換算を**実際に1時間間違えた**
（2026年の米国夏時間は3月8日開始）。前提（時差・夏時間の有無）を書かせると、
誤りが結果の上で見える。

### 10. 相反しうる指示は、優先順位と「印の形」まで指定する

`translate-for-internal-use`＝「原文に無いことを足さない」と「専門用語に言い換えを添える」は
正面衝突する。両方渡すと、言い換えが消えるか、印の無いまま混ざる。→ 〔 〕まで指定する。

### 11. 統計っぽい指示は、少数データで破綻する

`odd-numbers-in-tables`＝「平均から3.5倍離れた数字」は、**誤入力自体が平均を動かす**うえ
12個の数字では届かず0件になる。「中央値の3倍以上か3分の1以下」で仕込んだ3件ちょうど。

→ **閾値は、実データに当てて確かめてから記事に載せる。**

### 12. 計測スクリプトのほうを、先に疑う

記事に載る数字は、生成物ではなく**計測器**が間違っていることがある。

- `slides-outline-first`＝末尾ブロックの取りこぼしで「画面の最大175字」（正しくは24字）
- `tidy-files-without-deleting`＝素朴な部分一致で削除提案を15件（`在庫表.xlsx` が
  `コピー ～ 在庫表.xlsx` に誤ヒット。正しくは14件）

→ **数字を出したら、その数字を出したコードを1回読み直す。**

### ★12d. 「頼み方を良くして」は、AIが決める設定を増やす

`ask-what-is-missing-first`＝21字の依頼（書いてある事実は3件）に対し、
**そのまま書かせると4件、「この頼み方を良くして」と頼むと7件**をAIが勝手に決めた。
増えた3件は「3日遅延」「5年以上の取引」「今回が初めて」——**事実関係そのもの**で、
違っていれば文面が嘘になる。

🚨 **改良版プロンプトは体裁が立派なので、そのまま使ってしまう。**使えば、
AIが決めた前提が固定されたまま本文が作られる。

→ 正しい形は **「足りない情報を挙げてください。まだ書き始めないでください」**
（決めた設定 **0件**・質問 **7件**）。
→ さらに **「いくつ答えれば下書きを作れますか」**まで聞く。7件全部は答えないが、
3件なら答える。**答えられる量に落とす作業も相手にやらせる。**
→ 「良くして」を使うなら**材料がそろっているときだけ**。その場合も
**「これ以外の設定を足さないでください」**が必須。

📌 **AIは「伏せる／伏せない」の基準が一貫しない。**同じ返答の中で日付は `○月○日` と
伏せたのに、**原因と再発防止策は伏せずに断定した**。伏せてほしいものは名指しする。

### ★12c. 前回のものを「型」として渡すと、型が中身を上書きする

`weekly-report-from-memo`＝先週の週報を渡して「この形式で今週ぶんを」と頼んだら、
**今週のメモにあった9件の事実のうち2件しか残らなかった**。しかも
**消えた場所は空欄にならず、先週の言葉で埋まる**。

| 今週のメモ（本当のこと） | 週報に出てきた文 |
|---|---|
| 返事なし・担当が出張 | 検討が進んでいます |
| 今週は動きなし | 順調に進行中 |
| 研修が延期・日程未定 | 日程を調整中 |
| **値引きの可否を相談したい** | **特になし**（先週のまま） |
| （メモに進捗の数字なし） | **進捗85%**（先週70%からの補間） |

🚨 **消えた7件は全部「進んでいない」情報だった。**報告書としていちばん
伝えなければいけないところが、まとめて型に吸収される。
🚨 **返ってきた文は読んでも一切おかしくない。**元の材料と1行ずつ並べるまで分からない。

→ **「参考にして」ではなく「本文は1文字も流用しないで」まで言う。**
いちばん確実なのは**中身を消した空の見出しだけを渡すこと**。
→ **「前回の数字を今週ぶんに使い回さないで」を明示する**（数字は補間される）。
→ **対応表を出させるときは「使わなかった行も挙げて」を必ず付ける**
（付けないと使った行の一覧しか返らず、落ちた行は自己申告に出てこない＝4番の親戚）。
これで 2/9 → 9/9、メモに無い断定 4件 → 0件になった。

### ★12b. 成果物を作らせる前に、「まだ作らないでください」で条件確認を挟む

`weekly-menu-from-fridge`＝AIは**成果物を先に出したがる**。条件を渡しても、
確認工程そのものを飛ばして献立を出す。⚠️ **「まだ作らないでください」を付けると
条件の復唱だけが返り、そこで抜けを足せる。**これを挟むだけで、実測では
7項目（アレルギー・金額・予算・調理時間・未使用の明示・残量表・使い切り）が
**0/7 → 7/7 に反転した。**

📌 **安全に関わる条件は、他の条件と並べない。**同じ実測で、
「妻がえびアレルギー」を条件リストの1行として渡したら**えび料理が入った**
（冷凍室にむきえびが実在する状態だった）。**「絶対に使ってはいけない食材：えび。
これは他のどの条件よりも優先してください」**と単独で渡して守られた。
⚠️ 条件を並べると、同じ重みで扱われる。

### ★13. PowerShell でファイルを書き換えない（日本語が壊れる）

2026-08-12 未明、`SESSION_HANDOFF.md` を**全文文字化けさせて push した**。原因は

```powershell
(Get-Content ファイル -Raw) -replace '旧', '新' | Set-Content ファイル -Encoding utf8
```

Windows PowerShell 5.1 の `Get-Content` は**既定が cp932**なので、UTF-8 の日本語を
壊して読む。それを UTF-8 で書き戻すと全部化ける。しかも
**`-replace` の検索文字列も化けているので、狙った置換は起きない**（失敗にすら見えない）。

→ **ファイルの書き換えは Edit ツールか Python でやる。**PowerShell は実行と確認だけ。
⚠️ **テストもビルドも通る**（`SESSION_HANDOFF.md` は検査対象外）。**機械は気づかない。**
🔑 この型は「静かな欠落」の親戚＝**成功したように見えて、中身だけ壊れている。**

### 14. claude.ai のルーティン設定は、プログラムから書き換えられない

2026-08-12 朝、プロンプトの貼り替えを自動でやろうとして**2回とも失敗した**。

| 試した方法 | 結果 |
|---|---|
| フォームの値を直接設定 → 保存 | 画面側の状態に伝わらず、**古い値のまま保存された**（成功したように見える） |
| 全選択して自動入力 | 入力はできたが、**保存前にダイアログが閉じた** |

→ **ルーティンの指示欄は、人が実際にクリップボードから貼るしかない。**
こちらでやるのは「貼るテキストを用意する」「貼った後に読み直して確認する」の2つ。
⚠️ **2回失敗したら3回目を当てずっぽうで試さない**（設定を壊すリスクのほうが大きい）。

📌 **確認は必ず「保存後に読み直す」でやる。**1回目の失敗は、保存操作までは成功して
いたので**画面上は何も問題が無かった**。読み直して初めて古いままだと分かった。

### 15. 試した結果、題材の切り口が間違いと分かったら、組み替えてよい

`mail-needs-reply`＝「返信が要るものだけ」で試したら静かな欠落が見つかり、
**3分類（返信/自分の作業/読むだけ）へ題材ごと組み替えた**。キューの題を変えて、
変えた理由をキューに記録する。**これは逸脱ではなく、正しい仕事。**

### ★16. 批評は「指させる文」がある欠陥に偏る。欠落は話題にすらならない

`critique-not-rewrite`＝下書きに欠陥を10件、**文の中にある欠陥5件**と
**一度も書かれていない欠陥5件**に分けて仕込み、8通りに批評させた。

| 頼み方 | 文の中にある欠陥 | 書かれていない欠陥 |
|---|---|---|
| 「批評してください」 | **4/5** | **1/5** |
| 「直さずに批評して（＋受け皿）」 | 5/5 | 2/5 |
| 「書かれていないことを挙げて」 | 1/5 | 3/5 |
| **「読み手を名指し＋何が分からないまま残るか」** | **0/5** | **5/5** |
| 「段落ごとに割り当て（＋対応しない指摘は別に）」 | 5/5 | 4/5 |

🚨 **素朴な批評でも指摘は6件出る。**読むと十分な批評に見えるので、
**足りないことに気づけない。**指させる文が無い欠陥（期限・連絡先・主管・工数）は
話題にすらならない。

→ **「書かれていないこと」は独立した1回として聞く。**
→ **さらに読み手を名指しして、その席から聞く。**「なぜ自分に来たのか」「自分が何時間
取られるのか」は、8通り試して**読み手を名指しした1通りでしか出なかった**。
🚨 **ただし引き換えに、文の中の欠陥が 0/5 になる。視点を1つに決めると、もう一方が
見えなくなる。**→ **2回に分けて聞く。**

### ★17. 「添削して」は、間違いを指摘ではなく削除で処理する

同じ実測。「この下書きを添削してください」の返りは完成度の高い文面だったが、

- **根拠のない断定「大幅にコストが下がります」は、申告にも出ないまま本文から消えた**
  → 書いた本人は、自分の断定に根拠が無かったことを**知らないまま**、その一文だけ落ちた文面を受け取る
- **原文10行のうち、そのまま残ったのは2行**（宛名と名乗り）。申告された変更点は3件（4番の再発）
- **原文に根拠のない記述が5件足された**（「申請者・確認者の双方に負担」など）。
  そのまま送れば、自分が決めていない内容を自分の名前で送ることになる（12d・12c の系列）
- **書かれていない欠陥は0/5**。添削は文を整える作業なので、もともと無いものは対象外

→ 🔑 **完成度が上がるほど、何が消えたかが見えなくなる。**検査は
**「原文の行が何行そのまま残ったか」を数えるのがいちばん早い。**

📌 **7番が再発した**＝「私が直してと言うまで書き直さないで」は直後の返答では守られたが、
**その次の返答で修正案が1件戻った**。⚠️ 形が少し違い、
**「書き直しはしません」と書き添えながら、書き換え文そのものを出す。**宣言があるぶん読み流す。
📌 **12番が再発した**＝1回目の計測で、添削版の「書き直した本文」ごと数えていた。
本文に原文の語が残っているので、**指摘していないのに指摘したことになっていた。**

### ★18. AIの既定は「決めて進む」。やらせるだけでは、穴は1件も出ない

`try-the-runbook`＝架空の手順書（8手順）に「やると進めない穴」を8件仕込んで、
頼み方を変えて実行させた。

| 頼み方 | 見つかった穴 |
|---|---|
| 「レビューして」（読ませて批評） | 5/8 |
| **「そのとおりにやってみて」（実行・受け皿なし）** | **0/8** |
| 「やってみて」＋「できない所で止まって」＋「自分で決めて進まないで」 | **8/8** |
| 「各手順の開始時点で手元に要るものを出させる」 | 7/8 |

🚨 **受け皿なしで実行させると、止まった報告0件・8手順とも「完了」で終わる。**
そのあいだに**書かれていない値を14件、自分で決めていた**。
🚨 **穴のあった場所ほど、丁寧に埋められる**（明細表を作る手順が無い所では、
列まで決めて「作成しました」と書いた）。**埋めた箇所は実行記録の中で他の行と見分けがつかない。**

→ **差は「実行させたこと」ではなく「止まってよいと伝えたこと」。**
→ 🔑 **止まる許可だけでは足りない。**「分からないことを自分で決めて先へ進まないでください」
まで書く（＝1番の系列だが、**禁止のほうが後から要る**という順番が逆の例）。
→ **読ませて批評させると 5/8 で頭打ち。**落ちる3件は
**前の手順の成果物が無い・分岐の戻り先・初回だけ要る準備**＝**1から順に追わないと出ない。**

📌 **手順書は、書いた本人にとっては足りている。**「初めてやる人／毎月やっている人」で
分けさせると、初回にだけ必要なもの（権限・窓口・様式）が初回側に固まって出た。
**手順書を書くのは毎月やっている人なので、ここが構造的に抜ける。**

📌 **4番が再発（3本目）**＝あとから「自分で決めたことを挙げて」と聞くと、
実際の**14件のうち12件**しか出ない。**漏れた2件は、値を書かずに黙って進んだ判断。**
→ **決めさせてから聞くのではなく、決めるその場で「仮置き」と印を付けさせる**と、
本文の印と最後の一覧が12件で一致した。
📌 **12番が再発（同じ晩に2本目）**＝判定語を素の文字列でしか見ておらず3件取りこぼした
（「「不備」の基準」がかぎ括弧で分断されていた等）。**正規表現に直し、
一致した実文字列を印字して目で確かめる形にした。**

### ★19. 他人の発言の記録を「整えさせる」と、発言そのものが書き換わる

`tidy-transcript-without-rewriting`＝架空の通話の文字起こし28行に、誤変換5件・
食い違い2組・変えてはいけない言い切りの度合い4件を仕込んで「読みやすく整えて」と頼んだ。

- **賢さは問題なかった**＝誤変換5/5修正・食い違い（40台/50台・加藤/佐藤）を自発的に指摘
- 🚨 その同じ返答で、**フィラー除去では説明できない変化が25/28行**。言い切りの度合いは
  **4件とも書き換わり**、「遅れたはずです」が「遅れました」の**断定**になった
