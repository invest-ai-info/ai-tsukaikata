# 書き方の台帳（まだコードになっていない教訓だけを置く）

毎晩の担当は**書く前にここを全部読む**。学んだことがあれば足す（**ノルマではない**）。
形式＝「日付／出た記事／事実／次からどう書くか」。証拠は `docs/evidence/<slug>.md`。

⚠️ **ここは待合室であって住所録ではない。**2回出た教訓・全題材に効く教訓は
週次（月曜）で `src/validate.py`・記事の型・`tools/make_figures.py` へ昇格し、
下の「昇格済み」へ移す。**生きている教訓が15件を超えたら週次で整理する**
（長い台帳は読まれなくなって死ぬ）。

📌 **同じ型の教訓は1つの節に束ねてある**（2026-08-15 に束ね直した）。
節の見出し（`###`）は**その家族に共通する型**で、中の教訓は `####` の小見出しとして
**もとの番号と題のまま**入っている。各節の先頭に
**「この節に入っている番号」を全部並べてある**ので、`★25` のような古い番号で探しても
そこへ着く。番号でこの節を指してよい。

🚨 **番号は振り直さない。減らさない。**番号は `content/_recipe_queue.md`・
`content/_review_log.md`・`docs/evidence/*.md`・記事本文から名指しで参照されている。
番号が引けなくなると、参照している側は**黙って壊れる**（誰にも見えない＝このサイトが
いちばん警戒している型）。

⚠️ 夜の担当は**追記のみ**。既存の教訓と「昇格済み」欄を書き換えない。
足すときは、当てはまる節の**末尾に `#### <新しい番号>. <題>` で足す**。
当てはまる節が無ければ `###` で新しく立てる（節が15を超えたら週次で束ね直す）。

📌 **この節に入っている番号: ★1・★37。**

**いま昇格候補の上位。**

### 2. 範囲・量・優先順位は、「名前」ではなく数えられる形で渡す

🔑 **名前で渡した範囲・量は、相手が決める。**「校正」「整理」「短く」「5分」はどれも
解釈に開いていて、AIは広いほう・楽なほうで取る。
→ **種類の一覧・字数・順位・印の形——こちらで数えられる形に翻訳してから渡す。**

📌 **この節に入っている番号: 2・3・10・★28。**
以前の番号でこの節を指してよい（2 のもとの題＝『範囲は「名前」ではなく「種類の一覧」で渡す』）。

「校正」「整理」「改善」「要約」のような**名前の範囲は相手が決める**。AIは広いほうで取る。

- `fix-typos-not-voice`＝「校正して」で社内用語が**0/4**しか残らない。直す種類（誤字・重複・表記ゆれ）を並べると6/6・4/4
- `summarize-without-dropping`＝「要約して」で**4/14**。残す種類を名指しすると**14/14**

→ **やってほしいことを、種類の一覧で渡す。**

#### 3. 量の制約は「長さ・時間」で渡す。「個数」で渡すと1件が重くなる

- `translate-for-internal-use`＝「2文に割って」は3文で返る。「60字以内」なら守る
- `slides-outline-first`＝「10枚で」だと1枚が重くなる。「15分・1枚1分半」だと枚数が動いて9枚
- `fix-typos-not-voice`＝「短くして」は効かない。「30字以内」で平均17字

⚠️ ただし**上限として当てにはできない**＝`summarize-without-dropping` で「400字以内」が
**417字（4%超過）**になった。**方向は動くが、守られる保証はない。**

#### 10. 相反しうる指示は、優先順位と「印の形」まで指定する

`translate-for-internal-use`＝「原文に無いことを足さない」と「専門用語に言い換えを添える」は
正面衝突する。両方渡すと、言い換えが消えるか、印の無いまま混ざる。→ 〔 〕まで指定する。

#### ★28. 「5分の動画」と言っても5分にならない。時間は字数に翻訳して渡す

`video-script-by-the-clock`＝架空の走り書き14行から、5分の動画の台本を作らせた。
台詞の字数は Python で実測（抜き出しの規則は証拠ファイルに書いた）。

| 頼み方 | 台詞の字数 | 1分300字なら |
|---|---|---|
| 「5分くらいの台本を書いて」 | **2,320字** | **7分44秒**（＋2分44秒） |
| 「1分300字・5分なので1,500字」1回目 | 1,449字 | 4分50秒 |
| 同じ指示文 2回目 | 1,489字 | 4分58秒 |
| ＋1文40字・書き言葉禁止・足さない | **969字** | **3分14秒**（−1分46秒） |

**その時間と字数が合っていない。**しかも**自分が何字書いたかは書かない**ので、
数えないかぎり画面上は「5分の台本」に見える。

→ **時間しか決まっていない仕事は、自分で字数に直してから渡す**（台帳3番の新しい形）。
→ ⚠️ **逆向きの事故もある**＝縛り（1文40字・書き言葉の禁止・材料の外を足さない）を重ねると
**尺が足りなくなる**。足りないぶんは「材料が足りていない」ということなので、
**そこでAIに埋めさせない**（埋めると材料の外の話が入る）。
📌 申告した字数は、道具を使えた回も使えなかった回も**実測と一致した**。
「AIは数えられない」とは、この題材では言えなかった。

### 5. 加工・整形させると、指定していないものが静かに落ちる

🔑 **「整える」系の仕事（抜き出す・丸める・添削する・読みやすくする・短くする・丁寧にする）は、

🚨 落ちても**返りは整っている**ので、画面を見ているかぎり気づけない。
**完成度が上がるほど、何が消えたかは見えなくなる**（★17）。
→ 共通の検査は1つ——**渡した材料の何行・何件・何文字列がそのまま残ったかを数える。**

📌 **この節に入っている番号: 5・7・★17・★19・★21・★36・★38。**
以前の番号でこの節を指してよい（5 のもとの題＝『単一条件で抜かせると、隣接するものが静かに落ちる』）。

- `mail-needs-reply`＝「返信が要るものだけ」で経費精算・アンケート督促が消える
- `summarize-without-dropping`＝「ただし・対象外・〜しないでください」を含む**10文が0文**しか残らない
- `tidy-files-without-deleting`＝9件が「スクリーンショット5点」に**丸められて**一覧から消える

→ **全件をどれかに割り当てる分類にする。**「判断できない」という行き先を1つ作ると、
落ちたものが見える（`tidy` では45件が「決まった26件＋自分で見る19件」に割れた）。

#### ★17. 「添削して」は、間違いを指摘ではなく削除で処理する

同じ実測。「この下書きを添削してください」の返りは完成度の高い文面だったが、

- **原文に根拠のない記述が5件足された**（「申請者・確認者の双方に負担」など）。

→ 🔑 **完成度が上がるほど、何が消えたかが見えなくなる。**検査は
**「原文の行が何行そのまま残ったか」を数えるのがいちばん早い。**

#### ★19. 他人の発言の記録を「整えさせる」と、発言そのものが書き換わる

`tidy-transcript-without-rewriting`＝架空の通話の文字起こし28行に、誤変換5件・
食い違い2組・変えてはいけない言い切りの度合い4件を仕込んで「読みやすく整えて」と頼んだ。

- **賢さは問題なかった**＝誤変換5/5修正・食い違い（40台/50台・加藤/佐藤）を自発的に指摘
- 🚨 その同じ返答で、**フィラー除去では説明できない変化が25/28行**。言い切りの度合いは
  **4件とも書き換わり**、「遅れたはずです」が「遅れました」の**断定**になった
- 🚨 **返ってきた文はビジネス文書として自然**なので、読み直しても気づけない

→ **「読みやすく」は文体の注文として解釈される**（2番の親戚）。ただし対象が
**他人の発言の記録**だと、書き換えは品質の問題ではなく**記録の破壊**になる——ここが新しい。
→ 取り除いてよい種類と、**変えてはいけない種類（言い切りの度合いを名指し）**を並べると、
同じ賢さのまま置き換え0行になった。
→ 文脈から確定できない誤り（数字・人名）は「直さない＋〔要確認〕と付けて一覧に」の
**受け皿つき禁止**で、食い違いが両側とも残った（1番の系列）。
→ 話の中に食い違いを作らない聞き間違い（「4日」＝真値14日）は、**どの頼み方でも
テキストからは見つからない**。数字と名前はタイムスタンプ付きで全部一覧にさせ、
音源で確かめる（一覧の引用29/29が原文に実在＝一覧自体の捏造も機械で照合できる）。

📌 **4番が再発（4本目）**＝直した箇所の申告は最初**5件だけ**（実変化25行）。
「すべて一覧にして」と聞き直すと言い切り化を**自己検出して差し戻しまで推奨**したが、
それでも**5行は最後まで一覧に出なかった**。申告の質は聞き方で変わる。網羅はしない。
検査は自己申告ではなく、**別の新しい会話**に原文と並べて渡すほうが拾った
（申告が漏らした行を検査は3番目に挙げた）。

#### ★36. 盛りが入ったぶんだけ、事実のほうが落ちている

`listing-only-what-you-checked`＝架空のフリマ出品メモ（19行・事実だけ）から23項目を取り出し、

「水濡れは試していない」「金具の耐久は試していない」「追跡なし」——**買う人に不利な側**。

「小さい」は買う人が決めること。**丸めた瞬間に、根拠がそこだけ消える。**

### ★31. 自動化するなら、材料を変えて2本・各2回。割れたら割れたまま出す

#### ★43. 自動化には形が3つある。3つ目は「前回の入力が今回にも残る」

`inbox-loop-new-since-yesterday`＝架空の受信箱3日ぶん（13通・12通・13通）に、
**未処理のまま残る5通を3日とも1文字も同じ文字列で**入れて、各日2回ずつ走らせた。

| 形 | 何が起きるか | 出た記事 |
|---|---|---|
| 1回ごとに独立 | 形はそろうのに、中身の方針が回ごとに割れる | `transcript-auto-same-every-time`（★31） |
| 前回の**出力**が次回の入力 | AIが1度足した文が世代を越えて残る | `weekly-report-loop-without-drift`（★34） |
| 前回の**入力**が今回にも残る | **一覧の中身が毎回ほとんど同じ。新しいぶんが埋もれる** | この記事 |

🔑 **仕分けそのものはまったく崩れなかった**＝居座り5通は3日×2回＝6回とも同じ欄、
件名も6回とも受信箱の文字列と完全一致、取りこぼし0件。**それでも2日目A欄は4件中3件、
3日目A欄は5件中3件が昨日と同じ欄にいたもの**で、返りのどこにもそうは書かれていない。
**この節の物差し（2回転して割れを見る）では、この事故は見つからない。**割れていないため。

→ **「毎回ぜんぶ入れ替わる」つもりで作ると、毎朝ほとんど同じ一覧を読むことになる。**
受信箱・未処理の申請・未解決の問い合わせ・在庫の欠品リストは全部この形。
→ **作る前に、前回の入力が今回にも残るかを確かめる。**残るなら、
**昨日の出力を保存して、こちら側で突き合わせる**ところまでが自動化の範囲。

📌 **★35が再発した（2本目）**＝手動版（`mail-needs-reply`）の症状は「単一条件で抜かせると
隣接が落ちる」だったが、**自動化では落ちなかった**。かわりに
「落ちないから毎日出続ける」が問題になった。**手動版の結論を前提に書き始めない。**
📌 **★12c／★34は、この形では出なかった**＝昨日の一覧を渡しても今日の仕分けは13件とも
動かない（渡さない版と欄の割り当てが完全一致）。渡しているのが
**判定の結果だけで、文章ではない**ため。⚠️ **「前回のものを渡すな」を一般則にしない。**
📌 **12番が再発した（11本目）**＝返りの見出しを拾う正規表現を `^([ABC]):$` にしていたため、
`A`（コロンなし）で返ってきた回だけ**結果が空**になり、**「5回とも同じ欄」と
取りこぼしに気づかないまま表示するところだった。**緩めたうえで
**拾えなかった行を必ず印字する**形に直した。
