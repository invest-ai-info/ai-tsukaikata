## これで何ができるか {: .what }

[やることリストをAIに毎日1件ずつ進めさせる](/recipes/queue-done-marks-that-survive/)は、処理できない行の行き先を試した記事です。「印で残す」か「いちばん下へ移す」かの2通りを試し、32回とも崩れませんでした。ただしその記事自身が明記しています。「2回転までしか回していないので、下に溜まった行が10日後にどうなっているかは分かりません」。

この記事はそこを測ります。架空の問い合わせ待ち行列に、**10日分の新着を1日1行ずつ混ぜながら**、2つの版を10日間ぶん回しました。新着のうち3件は、資料そのものが存在しないため、どう頑張っても処理できません。

<figure class="figure">
<img src="/static/images/fresh-easy-row-throws-off-the-stuck-count-hit-and-miss.svg" alt="「止まったままの行は何件か」を開いて聞いた場合と、資料の中身を条件にして聞いた場合の正答率を比べた表。印で残す版は7日後・10日後とも正解3件・4件に対して1/3回しか合わず、いちばん下へ移す版は7日後が正解3件に対して0/3回、10日後は正解4件に対して3/3回だった。合計で開いた聞き方は12回中5回しか合わなかった。資料の行が（取得できませんでした）になっている行だけを数える条件に変えると、4通り×3回＝12回すべてで正しい件数になった。">
<figcaption>開いて聞くと12回中5回。条件を変えると12回中12回。</figcaption>
</figure>

分かったことは2つです。

**① 見立ては半分外れました。**見立ては「いちばん下へ移す版のほうが、新着に混ざって見つけにくくなる」でした。<mark>結果は逆です。10日後はいちばん下へ移す版が3/3で正解、印で残す版は7日後も10日後も1/3でした</mark>。置き場所そのものは、思ったほど悪さをしていません。

**② 本当の原因は、詰んだ行の「隣」にいることでした。**資料がそろっていて、まだ返信していないだけの行があります。<mark class="warn">それが詰んだ行の隣に並ぶと、週1回の確認役はそれも一緒に「止まったまま」と数えました</mark>。印で残す版・いちばん下へ移す版のどちらでも起きています。印の有無や位置ではなく、**たまたまの隣り合わせ**が原因でした。

## AIへの頼み方 {: .ask }

### 1. まず、2つの版をそのまま10日間動かす

架空の問い合わせ待ち行列（最初は10行）に、**1日1件ずつ新しい問い合わせを足しながら**、毎日この2つのうちどちらかを頼みました。3日目・6日目・9日目に足した新着は、注文番号を照会する内容で、**資料そのものが存在しません**（どう頑張っても処理できない行です）。

<div class="prompt">下は、毎朝1件ずつ処理している待ち行列です。未処理のものを1件だけ処理して、済の印を付けてください。処理した中身と、更新後の待ち行列の全文を書いてください。

印は「- [x] 」で始まる形に固定してください。ほかの行は1文字も変えないでください。

処理できなかった行は「- [!] 」にして、できなかった理由を次の行に書いてください。処理できなかった行を「- [x] 」にはしないでください。</div>

<div class="prompt">下は、毎朝1件ずつ処理している待ち行列です。未処理のものを1件だけ処理して、済の印を付けてください。処理した中身と、更新後の待ち行列の全文を書いてください。

印は「- [x] 」で始まる形に固定してください。ほかの行は1文字も変えないでください。

処理できなかった行は、待ち行列のいちばん下に移してください。できなかった理由を、その行の下に書いてください。</div>

**前日の「更新後の待ち行列の全文」を、そのまま翌日の入力にしました。**自動実行では返事の文章は捨てられ、ファイルだけが明日に渡るからです。10日間、1日も行の消失や済の取り消しは起きませんでした。1日に処理されるのは常に1件です。

🔑 **2つの版の違いが、ここで出ました。**印で残す版は、詰んだ行にぶつかった日（3・6・9日目）は**その日の処理が止まるだけ**で終わり、簡単な新着が後ろに積まれていきます。いちばん下へ移す版は、詰んだ行を移したうえで**別の処理できる行を探して1件仕上げる**ため、10日間ずっと毎日1件が完了し続けました。

### 2. 7日後・10日後に、新規セッションへ数えさせる

1週間使った想定で、そのときの待ち行列をまるごと貼り、**会話の続きではない新規セッション**に聞きました。

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、今すぐ自分で動かないと止まったままになる行が何件あるか、その内容も含めて教えてください。</div>

2つの版 × 7日後・10日後 × 3回＝**12回**聞きました。正しい件数（資料そのものが存在しない行の数）は7日後が3件、10日後が4件です。<mark class="warn">合っていたのは12回中5回だけでした</mark>。

| | 7日後（正解3件） | 10日後（正解4件） |
|---|---|---|
| 印で残す版 | 1/3 | 1/3 |
| いちばん下へ移す版 | 0/3 | 3/3 |

ずれた7回をすべて確認すると、理由は1つに揃っていました。**資料がすでにそろっていて、まだ返信していないだけの行を、詰んだ行に数えていました。**たとえば印で残す版の10日後では、3回のうち2回が、資料のある2件（岡田様・村上様）を詰んだ4件に足して「6件」と答えています。

### 3. なぜその行が巻き込まれたのかを見る

いちばん下へ移す版の7日後、待ち行列の末尾4行を実際の並び順のまま見ます。

<figure class="figure">
<img src="/static/images/fresh-easy-row-throws-off-the-stuck-count-adjacency.svg" alt="詰んだ行のすぐ隣にいただけで、資料がそろっている行まで止まったままに数えられたことを示す図。変種B（いちばん下へ移す版）の7日後、待ち行列の末尾4行を実際の並び順で示す。1行目は前田様（注文番号C-552の変更可否）、資料は取得できませんでしたでまだ確認されていない。2行目は森田様（注文番号B-317の在庫）、資料は取得できませんでしたでできなかった理由つき、赤。3行目は藤田様（見積りの消費税の扱い）、資料は消費税別表記・税率10%でそろっている、強調表示。4行目は山本様（注文番号A-204の納期）、資料は取得できませんでしたでできなかった理由つき、赤。藤田様の行は資料がそろっていて止まっていないのに、詰んだ2行の間に挟まれていたため、3回とも止まったままに数えられた。">
<figcaption>藤田様だけ資料がそろっているのに、詰んだ2行の間に挟まっています。</figcaption>

<mark>藤田様の行は資料がそろっていて、本当は止まっていません。</mark>それでも詰んだ2行（森田様・山本様）の間に挟まっているため、3回とも「止まったまま」の4件目として数えられました。印で残す版でも同じ並びが起き、確認していない前田様の両隣に石井様・藤田様がいた回で、同じ巻き込みが起きています。

🔑 **位置で区別する発想自体が、この壊れ方の入り口でした。**場所や印だけで「危ない行」を判断すると、**たまたま隣にいた無関係の行**まで一緒に拾ってしまいます。

### 4. 資料の中身を条件にすると、12回とも合う

印や位置ではなく、**止まっている理由そのもの**を数える条件にしました。

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、資料の行が「（取得できませんでした）」になっている行だけを数えてください。資料がすでにあって未返信なだけの行や、済・保留の行は数えないでください。</div>

2つの版 × 7日後・10日後 × 3回＝**12回**とも、正しい件数（3件／4件）に合いました。<mark>藤田様・石井様・岡田様・村上様を巻き込んだ回は、0回でした</mark>。

まだ一度も処理を試していない行（新着3日目の分など）も分けて知りたいときは、この一文を足します。

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、資料の行が「（取得できませんでした）」になっている行だけを数えてください。資料がすでにあって未返信なだけの行や、済・保留の行は数えないでください。

資料が無い行の中で、まだ一度も処理を試していない行があれば、それも分けて教えてください。</div>

4回試して4回とも、「資料なし4件・そのうち未着手1件」という、仕込みと一致する答えが返りました。

## うまくいかないときの言い直し方 {: .fix }

### すでに運用している待ち行列に、今すぐ足したい {: .trouble }

全体を書き直す必要はありません。週1回の確認のときだけ、この指示文を使ってください。

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、資料の行が「（取得できませんでした）」になっている行だけを数えてください。資料がすでにあって未返信なだけの行や、済・保留の行は数えないでください。</div>

📌 **「資料: （取得できませんでした）」という決まった書き方を、自分の待ち行列にも使ってください。**書き方がそろっていないと、AIが「中身を見て判断する」側に戻ってしまい、この記事の3番と同じ壊れ方をします。

### 「止まったままの行は何件？」とだけ聞いてしまう {: .trouble }

2番の壊れ方です。<mark class="warn">開いた質問は、資料があるのに未返信なだけの行まで数えてしまう</mark>ことが、12回中7回で起きました。**数える条件を、資料の中身という1点に絞ってください。**件数だけでなく、内容も聞くと、巻き込みに気づきやすくなります。

### 詰んだ行が、いちばん下に集まって読みにくい {: .trouble }

集まること自体は問題ではありません。<mark>この記事で崩れたのは「場所」ではなく「隣にいる無関係の行」のほうでした</mark>。いちばん下へ移す版を使うなら、4番の指示文で定期的に数え、**新着のうち何件が本当に詰んでいるかを資料の中身で確認してください。**

### 「資料がありません」と「まだ確認していません」を見分けたい {: .trouble }

4番の指示文に、最後の一文を足してください。

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、資料の行が「（取得できませんでした）」になっている行だけを数えてください。資料がすでにあって未返信なだけの行や、済・保留の行は数えないでください。

資料が無い行の中で、まだ一度も処理を試していない行があれば、それも分けて教えてください。</div>

この記事の実測では、4回とも正しく分けて答えました。**「できなかった理由」という注記の有無では見分けられません。**新着で届いたばかりの行には、まだその注記が付いていないからです。

## 応用・次の一手 {: .next }

**手で1回やって良かったものを、置き場所と時刻を決めて自動にする**——この記事はその運用を**10日間ぶん**まで延ばして確かめた形です。

1. [やることリストをAIに毎日1件ずつ進めさせる](/recipes/queue-done-marks-that-survive/)で、印で残すか・いちばん下へ移すかを決める
2. [毎日決まった時刻にAIを動かす仕掛けを作らせる](/recipes/github-actions-daily-cron/)で、時刻を決めて置く
3. **週1回、この記事の4番の指示文で確認する。**開いた質問ではなく、資料の中身を条件にする

⚠️ **3番を「印があるか」「下にあるか」に差し替えないでください。**この記事の12回中7回のずれは、まさにそこから来ています。**何が本当に止まっているかは、場所や印ではなく、資料の中身を見るしかありません。**

📌 **この記事が実測していないこと**＝10日を超えた先です。資料が永久に届かない行が、1か月・3か月でどこまで積み上がるかは測っていません。長く運用する人は、**詰んだ行を資料が届いた時点で消す・または別のファイルへ移す**運用を、別に決めてください。
