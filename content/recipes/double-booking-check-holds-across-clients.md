## これで何ができるか {: .what }

オンライン秘書・バーチャルアシスタントの仕事では、<mark>複数クライアントの予定を同時に抱えて、新しい依頼の候補時間が誰かと重なっていないかを確認する作業</mark>があります。クライアントが増えるほど、頭の中だけで全員の予定を突き合わせるのは大変になります。

この記事は、架空のクライアント3〜4名ぶんの予定と、新しい依頼の候補時間をAIに渡して、<mark>ダブルブッキング(予定の重複)に気づくか</mark>を試した結果です。合計17回試して、見落としは0件でした。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 各クライアントの予定が分かるメモ（日付・開始時刻・終了時刻） |
| プログラミング | **不要**。この記事の指示文をコピーして貼るだけです |

<mark class="warn">実在のクライアント名・実際の予定は貼らないでください。</mark>この記事は架空の名前・時刻を使っています。AIの回答は必ず自分でも一度見比べてから、来客への返信を確定してください。

## AIへの頼み方 {: .ask }

### 1. 複数クライアントの予定と、候補時間をまとめて渡す

<div class="prompt">下記は3名のクライアントの、2026年11月10日（火）の既存の予定です。

クライアントA: 10:00-11:00 会議
クライアントB: 13:00-14:30 会議
クライアントC: 15:00-15:30 会議

新しい来客対応の依頼が来ました。候補の時間は次の5つです。

候補1: 09:00-10:00
候補2: 10:30-11:30
候補3: 13:30-14:00
候補4: 14:30-15:00
候補5: 16:00-17:00

既存の予定と重ならない候補だけを教えてください。</div>

**3回とも「候補1・候補4・候補5が空いている」と正しく判定しました。**候補2はクライアントAの会議と、候補3はクライアントBの会議と重なることも、3回とも自分から説明しました。

### 2. 見落としを防ぐため、候補を1つずつ理由付きで判定させる

同じ3名の予定・同じ候補5つに続けて、聞き方を変えます。

<div class="prompt">下記は3名のクライアントの、2026年11月10日（火）の既存の予定です。

クライアントA: 10:00-11:00 会議
クライアントB: 13:00-14:30 会議
クライアントC: 15:00-15:30 会議

新しい来客対応の依頼が来ました。候補の時間は次の5つです。

候補1: 09:00-10:00
候補2: 10:30-11:30
候補3: 13:30-14:00
候補4: 14:30-15:00
候補5: 16:00-17:00

候補1〜5について、それぞれ『空いている』か『重複している』かを1つずつ判定してください。重複している場合は、どの予定と重なっているかも書いてください。</div>

**5候補×3回=15件の判定すべてが正しい結果でした。**まとめて聞いたときと同じ結論でしたが、<mark>1件ずつ理由を書かせると、後から見返したときにどこで判断したかが追いやすくなります</mark>。

### 3. 候補を渡さず、AI自身に空き時間を提案させる

ここまでは「渡した候補が空いているか」を判定させていました。今度は逆に、候補を渡さず、AI自身に空き時間を考えさせます。

同じ3名の予定に続けて、今度は候補を渡さずに頼みます。

<div class="prompt">下記は3名のクライアントの、2026年11月10日（火）の既存の予定です。

クライアントA: 10:00-11:00 会議
クライアントB: 13:00-14:30 会議
クライアントC: 15:00-15:30 会議

既存の予定を避けて、来客対応に使える1時間の空き時間帯を、営業時間9:00-18:00の中から3つ提案してください。</div>

**3回とも、提案した3件とも既存の予定と重複していませんでした。**1回目・2回目は「9:00-10:00」「11:00-12:00」「16:00-17:00」、3回目は2件目だけ「11:30-12:30」でしたが、どちらも空いている時間帯の範囲内でした。

## うまくいかないときの言い直し方 {: .fix }

### 隙間のない2件の予定にまたがる候補でも、両方との重複に気づくか {: .trouble }

<mark class="warn">最も見落としやすいのは、2件の予定が隙間なく連続していて、候補がその境目をまたぐケースです。</mark>片方だけ気づいて、もう片方を見落とさないかを確かめます。

<div class="prompt">下記は3名のクライアントの、2026年11月12日（木）の既存の予定です。

クライアントD: 09:00-09:30 会議
クライアントE: 11:00-12:00 会議
クライアントF: 12:00-13:00 会議

新しい来客対応の依頼が来ました。候補の時間は次の5つです。

候補1: 08:30-09:00
候補2: 09:30-10:00
候補3: 10:45-11:15
候補4: 11:45-12:15
候補5: 13:00-13:30

既存の予定と重ならない候補だけを教えてください。重複する候補については、どの予定と重なっているかも書いてください。</div>

クライアントEとFの予定は12:00で隙間なく連続しています。候補4（11:45-12:15）は、Eの終わり際とFの始まり際の両方にかかります。<mark>3回とも「候補4はEとも、Fとも重複する」と、両方を正しく指摘しました。</mark>片方だけで判定を止めた回は0件でした。

### 後から4人目の予定を追記しても、前半の判定を正しく更新するか {: .trouble }

実際の仕事では、確認を始めた後で「あ、もう1件忘れていた」と予定が追加されることがあります。<mark>先に出した候補への判定が、後から追記された情報で更新されないまま残ってしまわないか</mark>を確かめます。

<div class="prompt">下記は3名のクライアントの、2026年11月10日（火）の既存の予定です。

クライアントA: 10:00-11:00 会議
クライアントB: 13:00-14:30 会議
クライアントC: 15:00-15:30 会議

新しい来客対応の依頼が来ました。候補の時間は次の5つです。

候補1: 09:00-10:00
候補2: 10:30-11:30
候補3: 13:30-14:00
候補4: 14:30-15:00
候補5: 16:00-17:00

既存の予定と重ならない候補だけを教えてください。

追記：クライアントDの予定も確認に入れてください。クライアントD: 16:00-16:30 会議</div>

候補5（16:00-17:00）は、先に出た3名の予定とは重なりませんが、追記されたクライアントDの予定（16:00-16:30）とは重なります。<mark>3回とも「候補1と候補4だけが空いている」と正しく答え、候補5をクライアントDとの重複として指摘しました。</mark>追記前の判定（候補5は空き）がそのまま残った回は0件でした。

## 応用・次の一手 {: .next }

**クライアントが増えてきたら、毎回の頼み方を手順にしておくと安定します。**

<div class="prompt">複数のクライアントの予定を抱えるオンライン秘書の仕事をしています。新しい来客対応の依頼が来るたびに、既存の全クライアントの予定と重なっていないかをAIに確認してもらいたいです。プログラミングはできません。私がAIに渡すものと、頼み方の手順を、番号を振って箇条書きで教えてください。</div>

2回試したところ、項目の数や順番は少し違いましたが、骨格は共通していました。

- 全クライアントの予定一覧を、同じ形式（クライアント名・日付・開始時刻・終了時刻）で渡す
- 新しい依頼の詳細を、既存の一覧とは別に分けて伝える
- 「1分でも重なったら重複」のように、判断の基準を数字で具体的に指定する
- **出力形式を指定する**（重複の有無・どの予定と・何分重なっているか）
- **判断に使った予定の行を引用させる**、または自分でも一度見比べる（AIの見落としに自分で気づけるようにする）

[案件の取り違えを防ぐ記事](/recipes/wrong-client-material/)や[営業日計算で納期を逆算する記事](/recipes/deadline-count-needs-holiday-list/)と同じく、**複数の情報源を扱う作業では、判断の基準と出力形式を先に決めておく**と、見落としに自分で気づきやすくなります。

<mark class="warn">この結果は、この6種類の聞き方・計17回の実測です。</mark>「クライアントの人数や予定の件数が増えても必ず見落とさない」と一般化しないでください。試したのは、次の範囲までです。

- クライアント数は3〜4名、候補時間は5つまでです。もっと多い人数・件数は未検証です
- 境界をまたぐケースは1種類（隙間のない2件に候補がまたがる形）のみ試しました
- 時刻の表記はすべて24時間表記で統一しています。表記がクライアントごとに違う場合は未検証です

今回の生の返りと判定は `docs/evidence/double-booking-check-holds-across-clients.md` に全文置いてあります。
