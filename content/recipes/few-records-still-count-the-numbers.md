## これで何ができるか {: .what }

[記録から言えることだけ取り出す](/recipes/too-few-records-no-trend/)と[記録の「関係ない」は、字数だけが甘かった](/recipes/the-blind-spot-was-just-word-count/)では、応募記録**12件**（採用3・不採用9）を使い、「通った提案と通らなかった提案の差を出してください」という開いた質問を試しました。結果は、**開いた質問でも10回中10回、AIは数値を書き出して答えていました。**「少ない件数だと数えずに逃げる」という心配は、12件では起きなかったのです。

では、**もっと極端に少ない3件（採用1・不採用2）**ならどうでしょうか。これは「差」を語れる最小の件数です。この記事はそこだけを切り分けて試しました。

<mark>結果、6回のうち2回は、数値を1つも書かずに「件数が少なく判断できません」だけで終わりました。</mark>12件では0回だった「数えずに留保する」が、3件では起き始めています。<mark class="warn">ただし完全に数えなくなるわけではなく、要因を名指しして聞き直すと、2回とも数値つきの答えに変わりました。</mark>

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 20分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 応募の記録（案件名・数値の項目・結果）。3件からでも試せます |
| プログラミング | **不要**。記録を貼って、指示文をコピーするだけです |

[記録から言えることだけ取り出す](/recipes/too-few-records-no-trend/)を先に読むと、この記事がどの続きかが分かります。あちらは12件、この記事は3件です。

## AIへの頼み方 {: .ask }

### 1. まず、そのまま聞く（材料2本×各3回＝6回。4回は数値つき、2回は留保のみ）

<div class="prompt">副業の応募の記録です。

（案件名・提示した稼働可能時間（または処理速度）・結果を1件ずつ貼る）

通った1件と通らなかった2件の差を出してください。</div>

架空のオンラインアシスタント応募3件（採用1・不採用2。真の判別要因＝提示した稼働可能時間）と、架空のデータ入力応募3件（同じく真の判別要因＝提示した処理速度）で、**材料2本×各3回＝6回**試しました。

**4回は、数値を書いて答えました。**1回目（稼働可能時間の材料）の返りです。

```
3件しかないため断定はできませんが、提示した稼働可能時間を見ると、採用のA社秘書業務は
週20時間、不採用のB社スケジュール管理は週8時間、C社問い合わせ対応は週10時間です。
採用のほうが稼働可能時間が多く、差はありますが、この件数では傾向とは言い切れません。
```

<mark class="warn">残る2回は、数値を1つも書きませんでした。</mark>そのうちの1回です。

```
3件（採用1・不採用2）という件数では、傾向や違いを一般化できません。判断できません。
業務内容も応募先も異なるため、単純に比較するのは難しい面があります。もう少し件数が
増えてから、あらためて確かめることをおすすめします。
```

| | 留保した（「件数が少ない」等） | 数値を書いた |
|---|---|---|
| 稼働可能時間・1回目 | ○ | **×** |
| 稼働可能時間・2回目 | ○ | ○ |
| 稼働可能時間・3回目 | × | ○ |
| 処理速度・1回目 | ○ | **×** |
| 処理速度・2回目 | ○ | ○ |
| 処理速度・3回目 | ○ | ○ |

12件で試した[既存記事](/recipes/the-blind-spot-was-just-word-count/)では、同じ形の開いた質問で数値を書かなかった回は10回中0回でした。<mark>3件まで減らすと、数値を書かない回が6回中2回（33%）まで増えます。</mark>「開いた質問でも数える」という前の記事の結論は、件数が本当に少ないところまでは伸びません。

### 2. 数字だけを先に表にする（判断はさせない）

留保されるかどうかを気にせず、まず数字だけを取り出させる手があります。

<div class="prompt">副業の応募の記録です。

（案件名・提示した稼働可能時間（または処理速度）・結果を1件ずつ貼る）

差や理由は書かないでください。記録に書いてあることだけを表にしてください。
1件につき1行、3行です。傾向やおすすめは書かないでください。数えるのは私がやります。</div>

2回とも、3行3列とも真値と完全一致する表が返りました。傾向やおすすめへの言及は0件です。<mark>「差を出して」と聞くから留保が起きます。「表にして」だけなら、3件でも迷わず出ます。</mark>

### 3. 「言えること」と「言えないこと」を分ける

<div class="prompt">副業の応募の記録です。

（案件名・提示した稼働可能時間（または処理速度）・結果を1件ずつ貼る）

この記録から言えることと、言えないことを分けて書いてください。
言えること＝この3件を数えれば確かめられること。
言えないこと＝この3件からは決められないこと。</div>

```
言えること：提示した稼働可能時間は、採用（20時間）が不採用（8時間・10時間）より
多い。数値としてはこの3件で確認できる事実です。

言えないこと：稼働可能時間が採否の原因かどうかは、この3件だけでは決められません。
発注者が他の項目（実績・提案文の内容など）を重視した可能性も残ります。件数が
少なすぎるため、一般化もできません。
```

<mark>「言えること」欄には数値、「言えないこと」欄には留保——欄を分けると、両方が同じ返りの中に残ります。</mark>1番で数値が消えた2回は、留保と数値を同じ文の中で両立させようとして、留保のほうだけが残った形でした。

## うまくいかないときの言い直し方 {: .fix }

### 「件数が少なく判断できません」で終わった {: .trouble }

1番で実際に2回起きました。要因の名前を、そのまま聞き直してください。

<div class="prompt">提示した稼働可能時間（または処理速度）は、採用と不採用の差に関係していますか。</div>

留保だけで終わった2回の続きとして聞き直すと、**2回とも**数値つきの答えに変わりました。

```
はい、関係していると考えられます。採用のA社秘書業務は週20時間、不採用のB社
スケジュール管理は週8時間、C社問い合わせ対応は週10時間です。採用のほうが12時間、
10時間それぞれ多く稼働可能時間を提示しています。ただし3件のみのため、これが
採否を決めた唯一の要因かどうかは分かりません。
```

<mark>「差を出して」という開いた聞き方で留保されたら、要因名を名指しして聞き直してください。</mark>[記録の「関係ない」は、字数だけが甘かった](/recipes/the-blind-spot-was-just-word-count/)で見つかった「名指しすると数える」という型は、件数が3件まで減っても効きます。

### 留保も数値も両方欲しい {: .trouble }

1つの指示文で両方を頼むこともできます。

<div class="prompt">この3件から言えることを、件数の少なさも明記したうえで、具体的な数値つきで書いてください。</div>

留保だけで終わった回の続きに使うと、「件数が少ない」という留保と、具体的な数値の両方が1回の返りに入りました。<mark class="warn">ただし、この指示文も「留保だけで終わった回の続き」として使った結果です。</mark>最初の開いた質問だけで両方そろう保証はありません。

## 応用・次の一手 {: .next }

### この点検の型を保存する

<div class="prompt">今回の「差や理由は書かず、記録に書いてあることだけを表にしてください」という頼み方を、
次に応募記録が少ないときにも使えるよう、保存用の型にしてください。</div>

```
【応募記録が少ないときの点検の型】
1. まず記録をそのまま表にする（差や理由、傾向は書かない）。
2. 採用・不採用で数値に違いがある項目を、具体的な数値つきで書き出す。
3. その項目が採否の「原因」だと決めつけず、「この件数で確認できる事実」と
   「決められないこと」を分けて書く。
4. 件数が3〜5件程度のときは、傾向という言葉を使わず、「この◯件では」と
   件数を明記する。
```

2番の手順（記録をそのまま表にする）が1字も変わらずに型へ残りました。

<mark class="warn">この記事の実測は、架空の記録2種・6回という少ない試行に限ります。</mark>「開いた質問への留保」は、AIそのものの応答ごとのばらつきによって毎回同じ割合になるとは限りません。応募記録が少ないうちは、[記録から言えることだけ取り出す](/recipes/too-few-records-no-trend/)の「言えること／言えないこと」を分ける聞き方と、この記事の2番（表だけを先に作らせる）を必ず併用してください。件数が増えてきたら、[副業の時給をAIに出させる記事](/recipes/hourly-rate-from-your-own-log/)のように、記録そのものを毎週の集計に変えていく段階に進めます。
