## これで何ができるか {: .what }

<mark>AIが出してきた数字を、そのまま使えるようになります。</mark>

AIに調べ物をさせて表を作らせると、出典つきの立派な表が返ってきます。URLも付いています。押せば実在するページが開きます。

それでも<mark class="warn">その数字が、そのページに書かれていないことがあります</mark>。

そして<mark class="warn">一番危ないのは、確認する作業までAIに頼むことです</mark>。

実際にあった例を1つ。AIに各社のAI料金を比較させて表ができました。数字には全部、出典URLが付いています。念のため確かめようと思って、**確認もAIに頼みました。**「このページに `gpt-5.5-pro` の長い入力の料金は載っているか」と。

返ってきたのは、こうです。

> 長い入力の行はありません。「272Kトークン未満」という但し書きだけが付いています

これを信じて、正しく書かれていた $60 と $270 を記事から削除しました。**どちらの答えも事実ではありませんでした。**

<img src="/static/images/summary-vs-raw.svg" alt="要約された確認結果と生ページを比べた図。生ページには gpt-5.5-pro の行が実際にあり、短い入力が30ドルと180ドル、長い入力が60ドルと270ドルと書かれていた。見出しは Short context と Long context の8列。ところがAIが返してきた確認結果は「長い入力の行はありません。272Kトークン未満という但し書きだけです」というもので、行は実在し、272Kという文字列はページに1度も出てこない。確認をAIに要約させると、確認そのものが作り話になる。">

生ページを開けば、その行は普通に存在します。見出しは「Short context（短い入力）／ Long context（長い入力）」の8列で、`gpt-5.5-pro` の行には $60.00 と $270.00 が並んでいます。そして「272K」という文字列は、**そのページに1度も出てきません**。

### どうやって気づいたか

**生のページを、要約させずに自分で眺めたときです。**別の作業でこのページの中身をそのまま表示したところ、次の1行が目に入りました。

```
gpt-5.5-pro $30.00 - - $180.00 $60.00 - - $270.00
```

要約を1回はさむだけで、この行は「存在しないもの」に変わっていました。<mark>要約は、書いていないことを書くだけでなく、書いてあることを消すこともあります。</mark>

## AIへの頼み方 {: .ask }

### 1. 「書いてあるものだけを写して」と言う

これが本体です。調べ物を頼むとき、最初に置きます。

<div class="prompt">そのページに実際に書かれている数字だけを写してください。

他の行や他の項目から計算して求めないでください。規則性がありそうでも、当てはめないでください。</div>

<mark>「正確に」「間違えないで」では防げません。AIは間違えているつもりが無いからです。</mark>だから**計算して埋める、という具体的な動作を名指しで禁じます**。

### 2. 空欄を許可する

1だけだと、AIは板挟みになります。**埋めなくていい、と先に言ってください。**

<div class="prompt">見つからない項目は、空欄のまま「公表されていない」と書いてください。

表のすべてのマスを埋める必要はありません。空欄があるほうが、埋まっているより役に立ちます。</div>

<mark class="warn">「表を作って」と頼んだ時点で、埋めるべき枠が生まれています。</mark>枠があると、書くことが無くても埋めにきます。これは要約でも同じことが起きます（[AIに「注目されています」と書かせない](/recipes/stop-filler-sentences/)）。

### 3. 数字の「周りの文」ごと引用させる

一番よく効く一文です。

<div class="prompt">それぞれの数字について、出典ページのどこに書いてあったか、その前後の文を1〜2行そのまま引用してください。</div>

<mark>URLだけでなく、周りの文を求めるのがコツです。</mark>ページに無い数字は、周りの文を引用できません。**引用しようとした時点で手が止まる**ので、そこで「見つかりませんでした」に変わります。

URLを求めるだけでは止まりません。URLは正しいものを付けられてしまうからです。

### 4. まとめ記事を使わせない

数字が壊れるもう1つの原因は、二次情報です。

<div class="prompt">数字は、その会社の公式ページからだけ取ってください。

まとめ記事・ニュースサイト・個人ブログの数字は使わないでください。</div>

まとめ記事は、条件ごと写し間違えます。「Q1の営業利益」と「Q2の純利益」を取り違えたまま各社に転載されている、というようなことが実際に起きます。<mark>AIはその間違いを、間違いだと気づかずに引き継ぎます。</mark>

### 5. 書いたあとに、自分で見直させる

書き終わってから、もう一度確かめさせます。

<div class="prompt">いま書いた数字を1つずつ、出典ページに戻って確認してください。

「このページに、この数字が本当に書かれているか」だけを見てください。無かったものは削って、代わりに「公表されていない」と書いてください。</div>

書く作業と、確かめる作業を分けるのがコツです。同時にやらせると、書いている勢いのまま通ります。

### 6. 条件が違うものを、並べさせない

数字が正しくても、比較として壊れることがあります。

<div class="prompt">同じ名前の指標でも、測った条件が違うなら「単純比較できない」と書いてください。

条件が書かれていない場合も、書かれていないと明記してください。</div>

各社が同じ名前のテストで違う条件を測っていることは珍しくありません。**数字を並べた表は、それだけで「比較できる」という主張になります。**

## うまくいかないときの言い直し方 {: .fix }

### 出典は合っているのに、数字が違う {: .trouble }

<div class="prompt">この数字が、出典ページのどこに書いてあるか、前後の文ごと引用してください。

引用できない場合は、ページに無いということなので、そう言ってください。</div>

<mark>「合っていますか」と聞くと「合っています」と返ります。</mark>引用を求めると、無い場合は物理的に書けません。

### 「確認しました」と言うが、本当か分からない {: .trouble }

<div class="prompt">確認したとのことですが、どうやって確認しましたか。

開いたURLと、そこで見つけた文をそのまま見せてください。</div>

### 表に空欄を作りたがらない {: .trouble }

<div class="prompt">空欄を埋めようとしなくて構いません。

いまの表で、出典に書かれていない数字がどれか教えてください。それは全部消して、「公表されていない」に置き換えてください。</div>

**消す作業として頼む**と素直に応じます。「埋めるな」より「消せ」のほうが具体的です。

### 単位や桁が混ざる {: .trouble }

<div class="prompt">単位を揃えてください。出典ページに書かれている単位と、表に書いた単位が同じか1つずつ確認してください。

換算した場合は、換算前の値も併記してください。</div>

換算はそれ自体が計算なので、間違いが混ざります。換算前を残させると、後から検算できます。

### 毎回言うのが面倒になった {: .trouble }

<div class="prompt">「出典に書いてある数字だけを写す。無ければ空欄にする」を、この先ずっと守ってほしいです。毎回言わなくて済むように、理由も含めて覚えておいてください。</div>

やり方は [AIに「記憶」を持たせる](/recipes/claude-code-memory/) に書きました。

## 応用・次の一手 {: .next }

**まず1と3を試してください。**「計算して埋めないで」と「周りの文ごと引用して」の2つで、大半は防げます。

慣れてきたら、**言葉ではなく仕組みで止める**ほうへ移してください。数字は機械的に照合できます。

<div class="prompt">記事に書いた数字が、出典ページに文字列として存在するかを機械的に照合する仕組みを作れますか。

存在しない数字があったら、公開せずに止めてください。</div>

言葉での指示は「お願い」なので破れますが、照合は「保証」です。[静かに壊れたのを見つけさせる](/recipes/auto-health-check/) と同じ考え方です。

最後に、冒頭の例の続きを。消してしまった $60 と $270 は、あとで元に戻しました。気づけたのは、**生のページをそのまま眺めたから**です。もう一度AIに確認させていたら、たぶん同じ答えが返ってきて、間違いは残ったままでした。

<mark class="warn">確認をAIに要約させると、確認そのものが作り話になります。</mark>数字を確かめるときは、要約ではなく**その数字が載っている行そのもの**を見てください。1行なら、目で見るのは数秒です。
