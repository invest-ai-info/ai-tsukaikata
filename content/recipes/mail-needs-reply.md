## これで何ができるか {: .what }

朝、受信箱に未読が30通ある。<mark>全部読まないと、どれが自分の番なのか分からない</mark>——この「読むために読む」時間が、いちばん削りやすい時間です。

ただし、いきなり「返信が要るものだけ抜き出して」と頼むと落とし穴があります。**返信は要らないけれど締切のある作業が、まるごと消えます。**経費精算の督促、回答期限つきの社内アンケート、パスワードの有効期限。どれも返事はしませんが、放っておくと困ります。

<img src="/static/images/mail-triage.svg" alt="受信箱の未読をAIに渡して3つに仕分ける図。A＝返信しないと相手が止まるもの（可否の回答待ち、実装が止まっている問い合わせ）。B＝返信は要らないが自分の作業があるもの（経費精算、回答期限つきの社内アンケート）。「返信が要るものだけ」と頼むとBが落ちる。C＝読むだけでよいもの（返信は不要ですと本文に書いてある周知、メールマガジン）。AとBの両方に当てはまる1通は、急ぐほうに入れてもう片方を同じ行に書かせる。">
<figcaption>枠を2つで頼むと、真ん中が消えます。3つにするだけで取りこぼしがなくなります。</figcaption>

この記事は、受信箱を3つに仕分けさせて、締切順ではなく**「相手が止まっている順」に並べ直すまで**の頼み方を載せます。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 10分 |
| 費用 | 無料。無料のチャットAIで足ります |
| 必要なもの | ブラウザで使えるAI（ChatGPT・Claude・Geminiなど） |
| プログラミング | **不要**。メールを貼って、指示文をコピーするだけです |

メールソフトとAIをつなぐ必要はありません。件名と本文をコピーして貼るだけで動きます。会社の規則で本文をそのまま貼れない場合は、後半の「メールを貼ること自体が不安」を先に読んでください。

## AIへの頼み方 {: .ask }

### 1. 「返信が要る」ではなく、3つに仕分けさせる

最初の一手がここです。**枠の数を2つにしないでください。**

<div class="prompt">受信箱のメールを下に貼ります。次の3つに仕分けてください。

A. 私が返信しないと、相手の作業が止まるもの
B. 返信は要らないが、私が何か作業をしないといけないもの
C. 読むだけでよいもの

1通ずつ、番号・差出人・件名・分類・そう分類した理由（1行）を表にしてください。

（ここに、件名と本文をまとめて貼る）</div>

Bという枠を作るかどうかだけで、結果が変わります。<mark>「返信が要るものだけ」と頼むと、経費精算やアンケートの督促は「返信不要」なので静かに消えます</mark>。消えたことに気づけないのが厄介なところです。

### 2. 両方に当てはまる1通を、消えないようにする

実際に仕分けさせると、必ずAとBの両方に当てはまるメールが出てきます。取引先からの「請求書の送付先を変えてください、確認できたら一報を」のような依頼です。返事もするし、社内の登録変更もします。**このとき、片方に押し込まれてもう片方が消えます。**

<div class="prompt">AとBの両方に当てはまるものは、急ぐほうの分類に入れてください。

そのうえで、同じ行に「もう片方でやること」も書いてください。片方だけ書いて、もう片方を省略しないでください。</div>

「省略しないでください」まで書きます。これが無いと、分類は1つに決めるものだと解釈されて、返信のほうだけが残ります。

### 3. 判定の理由を、本文の言葉で引用させる

理由を書かせるところまではすぐ思いつきますが、その理由が本文に根拠を持っているかは別の話です。

<div class="prompt">分類の理由は、あなたの解釈ではなく、本文にある言葉をそのまま引用してください。

引用できる言葉が本文に無いものは、理由の欄に「本文に手がかりなし」と書いてください。それらしい理由を作らないでください。</div>

引用させると、判定の質が目で見えるようになります。「確認をお願いします」「17時までに共有してください」「返信は不要です」——<mark>依頼の言葉は、たいてい本文にそのまま書いてあります</mark>。逆に、引用できないものが「読むだけ」に入っていたら、それは差出人の見た目で分類されたということです。そこだけ自分の目で確かめれば足ります。

### 4. 締切は、書いてあるものだけ書かせる

ここが、この記事でいちばん事故りやすいところです。

<div class="prompt">Aに分類したものを、締切の早い順に並べ直してください。

・締切が本文に書かれているものは、その日時をそのまま書いてください
・書かれていないものは「記載なし」と書いてください。推測で埋めないでください
・本文にある日付が、返信の期限なのか、それとは別の予定の日付なのかを区別してください</div>

3行目が要ります。これが無いと、<mark class="warn">「至急」「なるべく早く」が「本日中」という日時に化けます</mark>。本文に日時は書かれていないのに、締切の欄に日付が入ります。

3つ目の条件も実物で効きます。「9月請求分より送付先を変更してください」というメールには9月という日付がありますが、それは変更が始まる時期であって、返事の期限ではありません。<mark>日付が本文にあるだけで締切として拾われるので、区別を先に指示しておきます</mark>。

### 5. 「相手が止まっているか」で並べ直させる

締切順は、実は最良の順番ではありません。締切が書かれていない緊急案件が後ろに回るからです。

<div class="prompt">Aのうち、私の返事を待って相手の作業が止まっているものだけを選んでください。

止まっていない（私が返さなくても相手は進められる）ものは、別のリストにしてください。それぞれ、なぜそう判断したかを1行で書いてください。</div>

この軸に変えると順番が入れ替わります。「顧客がログインできない」という締切の書かれていないメールが先頭に来て、「来週どこかで30分お時間を」という営業の依頼が後ろに下がります。<mark>締切の有無と、緊急かどうかは別のものです</mark>。

### 6. 今日・明日のぶんだけ、下書きを作らせる

仕分けが終わったら、そのまま返信の材料まで作らせられます。ただし条件が要ります。

<div class="prompt">Aのうち、締切が今日・明日のものだけ、返信の下書きを作ってください。

私がまだ判断していないこと（可否・日程・原因）は、（ここに入れる）のように空欄にしてください。空欄を埋めた文章を作らないでください。</div>

空欄の指定を落とすと、<mark class="warn">「工場に確認しましたところ問題ございません」のような、起きていないことが書かれた下書きが出てきます</mark>。読み流して送ると嘘になります。空欄にさせておけば、埋めるときに必ず目が通ります。空欄を嫌がるときの言い直し方は[「たぶん動きます」と言わせないための頼み方](/recipes/verify-before-report/)と同じ考え方です。

### 7. 「読むだけ」に落としたぶんを、もう一度見せさせる

最後にこれをやってください。仕分けで危ないのは、Aの判定ミスではなくCへの取りこぼしです。

<div class="prompt">Cに分類したものを、件名だけ一覧にしてください。

そのうち「実は私が見落とすと困る可能性があるもの」があれば、印を付けて理由を書いてください。無ければ「なし」と書いてください。</div>

これが効きます。たとえば「返信は不要です」と明記された停電の周知に、<mark>「作業中のデータは事前に保存してください」という自分の作業が混ざっている</mark>ことがあります。返信不要という言葉に引っ張られてCに入りますが、本当はBです。**自分で仕分けても同じ間違いをするので、機械のせいではありません。**

### 8. 今回の基準を、次回そのまま使える形にさせる

毎朝これを繰り返すなら、指示文を育てます。

<div class="prompt">いま使った分類の基準を、私が次回そのまま貼れる1つの指示文にまとめてください。

今回、判断に迷ったものを2つだけ選んで、「こういう場合はこちらに入れる」という例として指示文の中に入れてください。</div>

迷った実例を2つ入れさせるのがコツです。抽象的な基準だけだと次回また同じところで迷います。同じ処理を繰り返す作業をまとめて渡す型は[同じ指示を何回もコピペしているなら、まとめて1回で頼める](/recipes/batch-instead-of-repeat/)にまとめてあります。

## うまくいかないときの言い直し方 {: .fix }

### ほとんど全部が「返信が要る」に入る {: .trouble }

判定が甘いと、仕分ける意味がなくなります。条件を厳しくします。

<div class="prompt">分類が偏っています。Aに入れる条件を厳しくしてください。

Aは「私が返信しないと、相手の作業が今日・明日のうちに止まるもの」だけにしてください。それ以外は、私の作業が要ればB、要らなければCにしてください。

条件を変えた結果、Aから外れたものを一覧にしてください。</div>

**「外れたものを一覧にして」が要ります。**これが無いと、厳しくした結果どれが降格したのかが分からず、締め直しが正しかったのか判断できません。

### 返信したはずのものが、また上がってくる {: .trouble }

長いスレッドを貼ると、過去の依頼まで未対応として拾われます。

<div class="prompt">スレッドの中で、いちばん新しい発言が誰のものかを見てください。

私の発言で終わっているものは「返信済み」として分けてください。判断できないものは「判断できない」と書いてください。</div>

ただし、自分が返信したあとに相手が新しい依頼を足していることがあります。その場合は返信済みではありません。<mark>「最後の発言が誰か」で見ると、この区別が機械的にできます</mark>。

### 長いスレッドで、いま何を求められているのか分からない {: .trouble }

往復が10回を超えたスレッドは、経緯をまとめさせないほうが正確になります。

<div class="prompt">このスレッドは長いので、最後の1往復だけを見て「いま私に求められていること」を書いてください。

過去の経緯はまとめなくてよいです。求められていることが複数あれば、番号を振ってください。

そのうえで、最後の1往復では触れられていないが、まだ私が答えていない依頼があれば、それも番号を振って足してください。</div>

経緯をまとめさせると、すでに解決したことまで宿題として並びます。**最後の1往復に絞ると、解決済みのものが自然に落ちます。**最後の一文は保険です。相手が積み残しを言い直していないときだけ効きます。

🆕 **追記（2026-08-28）：上の指示文を、架空の案件スレッド2本・のべ16機会で測り直しました。**心配していた「経緯をまとめると解決済みが混ざる」という副作用は、実際には8機会中0件でした。むしろ「最後の1往復だけ」に絞ったことで、古い宿題を大きく取りこぼす（16機会中6件しか拾えない）という、この記事では測っていなかった代償が出ています。詳しい実測は[長いスレッドの宿題を漏らさず出す](/recipes/long-thread-pending-items/)にまとめました。長いスレッドの宿題出しは、そちらの頼み方（まず経緯を要約させる）を先に試してください。

### メールを貼ること自体が不安 {: .trouble }

会社の規則で本文をそのまま渡せないことがあります。渡す前に、渡す量を減らせます。

<div class="prompt">メールの本文をそのまま渡さずに仕分けたいです。

私が貼る前に、伏せるべき情報の種類を挙げてください。そのうえで、伏せたまま仕分けできる形（どこを残せば判定できるか）を教えてください。</div>

やってみると分かりますが、<mark>返信が要るかどうかの判定に、氏名も会社名も金額も要りません</mark>。差出人が社内か社外か、依頼の言葉、期限。この3つが残っていれば仕分けはできます。<mark class="warn">判断がつかないまま社外秘や個人情報を貼るのは、あとから取り消せません</mark>。渡す範囲を先に区切る話は[「ついでに整理しておきました」と言わせない頼み方](/recipes/limit-what-ai-touches/)にまとめました。

### 仕分けはできたが、結局ぜんぶ本文を読み直している {: .trouble }

分類だけでは、次の動きが決まりません。動詞まで出させます。

<div class="prompt">分類結果に、私が本文を開かずに済む情報を足してください。

各行に「私がやること」を動詞ひとつで書いてください。本文を読まないと決められないものは「本文を読む必要あり」と書いて、その理由を1行で書いてください。</div>

これをやると、<mark>「本文を読む必要あり」に残るのは、判断そのものを求められているメールだけになります</mark>。上司からの「来期の体制について率直な意見を聞きたい」のような一通です。そこは読むべきところなので、残ってよい残り方です。

## 応用・次の一手 {: .next }

仕分けに慣れたら、逆から聞けます。

<div class="prompt">この1週間ぶんの受信箱を渡します。私に届くメールのうち、そもそも私宛でなくてよかったものはありますか。

差出人と種類でまとめて、届かないようにする方法（配信停止・転送設定・依頼先の変更）も書いてください。</div>

<mark>仕分けを速くするより、届く量を減らすほうが効きます</mark>。毎朝仕分けている種類のメールが、実は別の人が受けるべきものだった、ということがあります。

もう1つ、返信の型そのものを作らせられます。

<div class="prompt">私がよく返している返信を3種類、型として作ってください。

型には、私が毎回書き換える場所だけを空欄にしてください。毎回同じ文は固定してください。</div>

自分の仕事の中でこの型が他にどこで使えるかを探すなら、[渡せる作業の見つけ方](/recipes/find-what-to-delegate/)の「チェック」の型がそのまま入口になります。受信箱の仕分けは、抜けや誤りを目で探している作業の代表例です。
