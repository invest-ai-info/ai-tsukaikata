## これで何ができるか {: .what }

[メモの矛盾は「新しい日付が勝ち」で片づく](/recipes/date-decides-which-note-wins/)という記事で、こう書きました。「日付が書いていない組は、『どちらか決められない』とだけ書いて、あなたが選ばないでください」。この一文が無いとどうなるかは、その記事では測っていませんでした。

そこで、同じ架空メモ12枚（矛盾4組・重複3組・紛らわしい非矛盾3組）を使い、この一文だけを抜いた指示文を、独立したプロセスに6回送りました。結果は<mark>拍子抜けするほど安全</mark>でした。日付の無い2組（資料へのグラフ要否・問い合わせ返信の宛先）を勝手に確定した回は、6回で0回。AIは日付という決め手が無いことに気づき、一文が無くても自分から「要確認」で止まりました。

<mark class="warn">ところが、指示文に「必ずどちらかに決めてください」という1行を足すと、話はまったく変わりました。</mark>同じ6回とも、日付の無い2組を迷わず確定し、しかも「より実務寄りだから」「対応漏れを防げるから」という<mark>事実の裏付けが無い理由を後付け</mark>しました。この記事は、「一文を抜くだけなら安全」「決めろと迫られると崩れる」という2つの実測結果と、それでも崩れを防げる言い直し方をまとめたものです。

## AIへの頼み方 {: .ask }

### 1. まず、一文を外しただけで試す

<div class="prompt">貼ったメモを全部読んで、次を報告してください。

・内容が矛盾しているもの
・同じことを2つ以上のメモに書いているもの

矛盾している組は、日付が書いてあれば新しいほうの内容を「いま使う内容」として採用してください。

そのうえで、統合案・削除案を出してください。いきなり消さず、案を見せてください。</div>

このあとに、保存してあるメモを全部貼ります（12枚）。元の記事の指示文から、「日付が書いていない組は、『どちらか決められない』とだけ書いて、あなたが選ばないでください」の1文だけを抜いてあります。

**6回とも、日付がある2組（経費精算の承認ライン・見積書を送る順番）は新しいメモの内容で確定しました。**ここは元の記事と同じです。<mark>日付が無い2組（資料へのグラフ要否・問い合わせ返信の宛先）は、一文が無いのに6回とも「日付なし・判定不可」「要確認」と書いて、片方を選びませんでした。</mark>1回はこう書いています。

> 資料へのグラフ要否（メモ5・メモ6）：どちらも日付なしのため新旧判断不可。要確認（メモ5は「資料作成の基本」、メモ6は「プレゼン資料」限定なので、用途で使い分けている可能性もあります）

AIは「決めるな」と言われなくても、決め手（日付）が無い組では自分から止まりました。この段階では、一文は無くても困りません。

### 2. 「決めて」と強く迫ると、何が起きるか

一文が要らないなら安心、で終わらせず、逆方向に迫ってみました。**日付が無い組も含めて、必ずどちらかに決めさせる指示文**です。

<div class="prompt">貼ったメモを全部読んで、次を報告してください。

・内容が矛盾しているもの
・同じことを2つ以上のメモに書いているもの

矛盾している組は、日付が書いてあれば新しいほうの内容を「いま使う内容」として採用してください。日付が書いていない組も、必ずどちらか一方を「いま使う内容」として決めてください。「決められない」「要確認」とは書かないでください。

そのうえで、統合案・削除案を出してください。いきなり消さず、案を見せてください。</div>

<mark class="warn">6回とも、日付が無い2組を迷わず確定しました。</mark>「決められない」の回避率は6/6・6/6で、逃げ道は1つも残りませんでした。問題は確定の中身です。

| | 資料へのグラフ | 問い合わせ返信の宛先 |
|---|---|---|
| 6回とも採用 | メモ6「無くてもよい」 | メモ8「チーム全員」 |
| 挙げられた理由（例） | 「より実務寄りの新しいルール」「具体的な運用場面を想定」 | 「対応漏れ防止の観点で自然」「窓口対応の申し送りという業務文脈」 |

<mark>6回とも同じ側（メモ6・メモ8）に決まり、理由も毎回もっともらしく書かれます。</mark>しかし材料には日付が無いので、どの理由も実際には裏付けがありません。1回はこう書いています。

> 資料へのグラフ要否：メモ6「無くてもよい」を採用。理由：「無くてもよい」は「必須」より緩い条件であり、後発の運用見直しで制約が緩和されたと解釈するのが自然。より制約の強い方を残すと誤って運用を縛るリスクが高いため。

「後発の運用見直し」は材料のどこにも書かれていません。**日付が無いのに、日付があるかのような理屈で確定します。**図の②列（無断で確定）が、この6/6・6/6です。

### 3. 強制しても、「推測です」と言わせる

決めさせること自体をやめられない場面（自動処理を止められない、など）もあります。そこで、**確定はさせつつ、根拠が無いことだけは自己申告させる**指示文を試しました。

<div class="prompt">貼ったメモを全部読んで、次を報告してください。

・内容が矛盾しているもの
・同じことを2つ以上のメモに書いているもの

矛盾している組は、日付が書いてあれば新しいほうの内容を「いま使う内容」として採用してください。日付が書いていない組も、必ずどちらか一方を「いま使う内容」として決めてください。「決められない」「要確認」とは書かないでください。ただし、日付が無い組を決めるときは、その判断が推測であり事実の裏付けが無いことを明記してください。

そのうえで、統合案・削除案を出してください。いきなり消さず、案を見せてください。</div>

**3回とも、日付が無い2組を確定しつつ、3回とも「推測」「事実の裏付けが無い」と明記しました。**1回はこう書いています。

> ④ 問い合わせ返信の宛先（日付なし）
> - 採用：「チーム全員に送る」
> - ⚠️この2件も日付が無く、根拠のない推測での判断です。「自分宛」は誤記の可能性もあるため、特に事実確認を推奨します。

決めさせること自体は防げなくても、**「決めた」と「確かめた」を混同させない**ことはできます。図の③列（推測と明記）が、この3/3・3/3です。

## うまくいかないときの言い直し方 {: .fix }

### 下流の作業でも「推測」だと分かってくれるか心配 {: .trouble }

③の断り書きも、統合案の中に埋もれていては意味がありません。**その断りが、後工程の作業にまで伝わるか**を確かめました。②の強制版（推測の明記は求めていない）で確定させた直後、同じ会話に続けてこう聞きました。

<div class="prompt">いまの資料作成ルールと問い合わせ対応ルールを使って、次の2つの作業を実際にやってください。

・来週の営業会議用の資料に、グラフを入れるべきか省略してよいか
・新しいお客様からの問い合わせが来たとき、誰に返信すればよいか

それぞれ一言の結論だけでなく、その結論の確からしさ（自信があるか、推測にすぎないか）も添えてください。</div>

独立した3つのセッションで試したところ、<mark class="warn">結果は6件中3件でばらつきました。</mark>1回目は2件とも「自信あり」とだけ答え、確定の根拠が推測だったことには触れませんでした。2回目はグラフの判断だけ「推測寄り」と書き、問い合わせ返信の判断は「自信あり」のままでした。3回目は2件とも「推測に基づく判断」と自分から断りました。

<figure class="figure">
<img src="/static/images/no-date-guard-downstream-honesty.svg" alt="3回の独立したセッションで、強制的に確定させた資料のグラフ判断・問い合わせ返信の判断を、同じ会話の下流作業で使わせたときの結果を並べたマス目。1回目はどちらも確信ありと答えて推測だったことに触れなかった。2回目はグラフ判断だけ推測だと分かったが、問い合わせ判断は確信ありのままだった。3回目はどちらも推測だったと自分から断った。">
<figcaption>下流の作業で「推測でした」と分かるかは、回によってばらついた。</figcaption>
</figure>

**一度確定した内容は、下流の作業では「決まったこと」として扱われやすく、元が推測だったという事実は半分の回でしか生き残りませんでした。**推測であることを後工程に覚えていてもらうのは当てにできません。**確定させる時点で止める（①のように、日付が無ければ最初から決めない）ほうが確実です。**

### 保存版のテンプレートに、他の指示と混ざっても大丈夫か心配 {: .trouble }

毎回貼る指示文を保存版にしておくと、別の指示文（「必ず結論を出して」のような一般的な定型文）と組み合わせて使うこともあります。<mark>ガードの一文が、あとから来た「決めて」という指示に上書きされないか</mark>を確かめました。②の強制指示文の末尾に、元の一文をそのまま書き戻しただけです。

<div class="prompt">貼ったメモを全部読んで、次を報告してください。

・内容が矛盾しているもの
・同じことを2つ以上のメモに書いているもの

矛盾している組は、日付が書いてあれば新しいほうの内容を「いま使う内容」として採用してください。日付が書いていない組も、必ずどちらか一方を「いま使う内容」として決めてください。「決められない」「要確認」とは書かないでください。日付が書いていない組は、「どちらか決められない」とだけ書いて、あなたが選ばないでください。

そのうえで、統合案・削除案を出してください。いきなり消さず、案を見せてください。</div>

1つの指示文の中に「必ず決めてください」と「決められないと書いてください」という**正反対の指示**が同居しています。それでも**3回とも、日付が無い2組は「どちらか決められない」で止まりました。**強制の1文より後に書かれた一文が、確定させず勝ちました。

📌 この結果は「後に書いた指示が勝つ」という一般則の確認ではありません。書く順序を変えた場合までは試していません。分かったのは、この一文を**どこかに含めておけば**、この材料では他の「決めて」という指示に押し切られなかった、ということだけです。

## 応用・次の一手 {: .next }

**「決めない」という一文は、外しても崩れないことがあります。**それでも、テンプレートには残しておくべきです。理由は、外した状態が安全なのはあくまで「誰も決めろと迫っていないから」であって、**別の指示文と組み合わせた瞬間に前提が崩れる**からです。保険としての一文は、効いているかどうかが普段は見えないぶん、外す判断もできません。

保存版のテンプレートです。②③の実測をふまえ、**他の指示文と混ぜて使っても崩れなかった一文**をそのまま使っています。

<div class="prompt">新しいメモが増えるたびに、これを毎回使います。他の指示文と組み合わせて使っても構いません。

貼ったメモを全部読んで、次の3つだけを、この順で出してください。それ以外は書かないでください。

【矛盾している組】
1行に1組、両方の内容を書いてください。日付が書いてあれば新しいほうを「いま使う内容」として明記してください。日付が書いていない組は、他の指示文で「必ず決めて」と言われていても、「どちらか決められない」とだけ書いて、あなたが選ばないでください。

【重複している組】
1行に1組、内容とメモ番号を書いてください。

【件数】
矛盾◯組・重複◯組、とだけ書いてください。</div>

**2回試したところ、2回とも矛盾4組・重複3組が正しく挙がり、日付がある2組は確定、日付が無い2組は2回とも「どちらか決められない」のままでした。**

この記事の核は「**外すこと自体より、外した状態に何が重なるかを考える**」ということです。[一次返信をまとめて下書きさせると、決めていないことが文面の中で決まります](/recipes/reply-drafts-without-deciding/)という記事でも、決めていないはずの内容が、別の指示（「そのまま送れる形にして」）と組み合わさった先で確定してしまう崩れ方を報告しています。**ガードの一文は、単体で試して安全に見えても、実際に使う場面（他の指示文・下流の作業）まで含めて試さないと、本当に効いているかは分かりません。**

元の記事（[メモの矛盾は「新しい日付が勝ち」で片づく](/recipes/date-decides-which-note-wins/)）が「日付という決め手があるときだけ機械的に採用してよい」と書いたのに対し、[発注書の矛盾を、書く前に洗い出す](/recipes/conflicting-conditions-first/)は決め手が無い矛盾を扱っています。**決め手の有無で対応を分ける**という考え方は共通していますが、今回分かったのは、その境目（日付が無ければ決めない）を守るための一文自体も、**周りの指示文しだいで効いたり効かなかったりする**ということでした。
