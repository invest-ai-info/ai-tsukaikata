## これで何ができるか {: .what }

抽出→分類→まとめのような複数ステップの定期自動化を、工程6個・7個・8個とさらに長くつなげられるかを確かめる頼み方です。途中の工程で欠けた情報（期限が分からない、本文が届いていない）を抱えたまま先へ渡しても、その欠けが途中で消えないかを見ます。プログラミングは要りません。

材料は[後の工程ほど欠けを見逃さない](/recipes/later-stages-skip-the-gap-and-stay-clean/)が実際に5工程目まで走らせた出力です。これをそのまま工程6〜8の入力に使いました。

<mark>工程3で期限の日付が本工程に届かなかった版（材料A-1）は、工程6でも工程7でも止まりました。</mark>2回とも「データが本当にありますか」と聞き直しています。勝手に日付を作ることも、全件を「分かっている」とみなして進めることもしませんでした。

<mark class="warn">一方で、期限が「今週中」「今週金曜まで」のような言い回しだった材料（材料A-2）は違いました。</mark>**基準の「具体的な日付」という言葉を文字どおりに読んだ結果、12件のうち9件が「期限が分かっていない」側に回りました。**2回とも同じ結果です。読む人には実質的な期限でも、日付の形をしていないと「分からない」と同じ扱いになります。

## AIへの頼み方 {: .ask }

### 1. 工程6で「期限が分かっている／分かっていない」に仕分ける

まず、部署まで振り分けた一覧を渡し、期限の有無で仕分けて部署ごとに並べ替えさせます。

<div class="prompt">はじめに、受け取った件数を「受け取った件数: ◯件」の形で書いてください。前の工程から件数が増えたり減ったりしている場合は、その理由も書いてください。
下は、担当部署まで振り分けた問い合わせの一覧です。1件ずつ、期限の具体的な日付が本文に書かれているものを「期限が分かっている」、書かれていないものを「期限が分かっていない」に分けてください。部署ごとに、期限が分かっているものを先に並べ直してください。4行はそのまま残し、順番だけ変えてください。</div>

（この下に、工程4の出力をそのまま貼ります。4つの材料それぞれで独立した新規会話に渡し、各2回試しました）

結果は材料ごとにはっきり割れました。

- **材料A-1**（期限欄が全件「記載あり・日付未着」）：2回とも仕分けに進みませんでした。「具体的な日付がどこにも書かれていない」と理由を述べ、本文データの追加共有を求めています
- **材料A-2**（日付と「今週中」等が混在）：2回とも同じ結果でした。「期限が分かっている」になったのは、「8月28日（金）まで」のように暦の日付を含む3件だけです。残り9件（「今週中」「今週金曜まで」など）は「分かっていない」に回りました
- **材料B-1・B-2**（期限は本文に記載なし）：2材料×各2回＝4回とも12件全件が「分かっていない」になりました。B-2にあるM-11の「希望日は9月5日・6日」という記載も、4回とも見抜いています。「回答の期限ではなく希望する利用日」だと判断し、期限が分かっているには含めませんでした

**なぜこの結果になるか。**指示文の「期限の**具体的な日付**が本文に書かれているもの」という言葉を、AIは文字どおりに読みます。「今週中」は、人が読めば今週金曜までに答えるべき期限です。それでも暦の日付（◯月◯日）という形をしていないので、この基準では「分かっている」に入りません。材料A-1のように、期限が存在するらしいという申し送りだけで実際の文言が渡っていない場合もあります。その場合は、推測で埋めずに止まって聞き直しました。

### 2. 工程7で部署別レポートにまとめる

工程6の出力をそのまま工程7に渡し、上司向けの1枚レポートを作らせます。

<div class="prompt">はじめに、受け取った件数を「受け取った件数: ◯件」の形で書いてください。前の工程から件数が増えたり減ったりしている場合は、その理由も書いてください。
下は、部署ごとに期限が分かっているものを先に並べ替えた問い合わせの一覧です。これをもとに、上司に送る1枚のレポートを作ってください。部署（営業部・サポート部・総務部）ごとに「期限が分かっている件数」「期限が分かっていない件数」「合計」を表にし、表の下に一言の総括文を添えてください。</div>

工程6の4つの出力を、それぞれ独立した新規会話に渡して各2回試しました。

- **材料A-1の出力**（工程6で止まった「質問」そのもの）を渡すと、2回とも「部署ごとの件数表を含むレポートを作れません。実際の一覧データ自体がまだ共有されていません」と気づいて、同じく止まりました
- **材料A-2の出力**を渡すと、2回とも表を正しく作りました。営業部1／3、サポート部1／4、総務部1／2、合計3／9です（期限が分かっている／分かっていない）
- **材料B-1・B-2の出力**を渡すと、4回とも3部署とも0件・合計0／12の表を正しく作りました

**なぜこの結果になるか。**工程6が「質問」で止まったときの文面には、部署名や件数など表に使える材料がありません。工程7はそれを検知し、前段の停止をそのまま引き継ぎました。一方、工程6が実際に数字を出せていた3つの材料では、工程7はその数字をそのまま数え直すだけで済みました。7工程目まで食い違いは出ませんでした。

### 3. 工程8まで伸ばして、優先順位付きタスクリストにする

工程7のレポート（材料A-2・B-1の出力）を、さらに工程8へ渡します。

<div class="prompt">はじめに、受け取った件数を「受け取った件数: ◯件」の形で書いてください。前の工程から件数が増えたり減ったりしている場合は、その理由も書いてください。
下は、部署別の件数表を含むレポートです。これをもとに、今日中に対応すべき担当者向けの優先順位付きタスクリストを作ってください。期限が分かっている件は優先度高、期限が分かっていない件は「確認が先」という別枠にしてください。件数の表はそのまま残し、その下にタスクリストを追加してください。</div>

材料A-2・B-1それぞれで各2回試しました。

- **材料A-2の出力**（3件／9件）を渡すと、4回とも表の数字をそのまま残し、優先度高に3件・確認が先に9件を正しく振り分けました
- **材料B-1の出力**（0件／12件）を渡すと、4回とも「優先度高」の枠に**該当なしと明記**しました。0件を無理に埋めることはありませんでした

**なぜこの結果になるか。**件数表という、すでに数字だけに絞られた材料を渡しているので、工程8は数え直す以外の仕事をしていません。8工程目まで鎖を伸ばしても、表の数字自体は1件も動きませんでした。

## うまくいかないときの言い直し方 {: .fix }

### 「今週中」も期限扱いにすると、材料によっては希望日を拾ってしまう {: .trouble }

「具体的な日付」という基準が狭すぎるなら、言い回しも含めるよう言い直せば直ります。

<div class="prompt">はじめに、受け取った件数を「受け取った件数: ◯件」の形で書いてください。前の工程から件数が増えたり減ったりしている場合は、その理由も書いてください。
下は、担当部署まで振り分けた問い合わせの一覧です。1件ずつ、回答の目安になる時期が本文に何らかの形で書かれているものを「期限が分かっている」、何も書かれていないものを「期限が分かっていない」に分けてください。「8月28日」のような日付だけでなく、「今週中」「今週金曜まで」のような言い回しも「期限が分かっている」に含めてください。部署ごとに、期限が分かっているものを先に並べ直してください。4行はそのまま残し、順番だけ変えてください。</div>

同じ4材料に、それぞれ各2回試しました。

- **材料A-2**：2回とも12件全件が「期限が分かっている」に回復しました。「今週中」「今週金曜まで」も正しく拾いました
- **材料A-1**：言い直し後も2回とも止まりました。「記載あり・日付未着」という申し送りだけでは、暦の日付も「今週中」のような言い回しも実際には1つも渡っていません。全件を「分かっている」とみなすのは不自然だと、自分から指摘しています
- **材料B-1**：2回とも変わらず0件。期限に関する言い回しが本文に一切無いため、安全なままでした
- <mark class="warn">**材料B-2**：2回とも、M-11の「希望日は9月5日・6日」を誤って拾いました。</mark>「回答の目安になる時期」の一種とみなし、「期限が分かっている」に含めています。総務部の先頭に繰り上がったのもこの1件です

<figcaption>「今週中」を救う言い直しは、材料A-2を直す代わりに材料B-2で罠を1件だけ開けた。</figcaption>

**なぜこの結果になるか。**材料B-1の期限欄は「本文に記載なし」だけです。時期を示す言葉が本文のどこにも無いので、基準を広げても拾うものがありません。ところが材料B-2は違います。期限欄そのものに「記載なし（希望日は9月5日・6日）」という注記があります。**日付らしい文字列が、期限欄の中に既に存在しているのです。**そのため、「回答の目安になる時期」という広い基準に引っかかりました。狭い基準（「具体的な日付」のみ）のときは、同じ注記があっても取り違えませんでした。基準を広げた途端に取り違えが起きています。**基準を広げるほど安全になるとは限りません。**広げた基準がどの情報に触れるかで、結果が変わります。

### 見る欄を名指しすると、広げた基準でも罠に乗らない {: .trouble }

「期限欄の中にある日付」と「本文の用件にある日付（希望する利用日など）」を区別する一文を足して、材料B-2で試し直しました。

<div class="prompt">はじめに、受け取った件数を「受け取った件数: ◯件」の形で書いてください。前の工程から件数が増えたり減ったりしている場合は、その理由も書いてください。
下は、担当部署まで振り分けた問い合わせの一覧です。1件ずつ、回答の目安になる時期が本文に何らかの形で書かれているものを「期限が分かっている」、何も書かれていないものを「期限が分かっていない」に分けてください。「8月28日」のような日付だけでなく、「今週中」「今週金曜まで」のような言い回しも「期限が分かっている」に含めてください。ただし、期限欄に書かれた時期だけを見てください。希望する利用日や予約日は期限ではありません。部署ごとに、期限が分かっているものを先に並べ直してください。4行はそのまま残し、順番だけ変えてください。</div>

<mark>材料B-2に2回試し、2回とも0／12に戻りました。</mark>「M-11の『9月5日・6日』は希望する利用日であり、期限ではない」と、理由まで明記して除外しています。**どの欄を見るかを1文で名指しするだけで、基準を広げたことによる取り違えは直りました。**

### 推測させたくない工程に、進めてよい条件を渡す {: .trouble }

材料A-1は、どう言い直しても止まって質問してきます。**止まるのは正しい挙動ですが、自動化の中では人の確認を待てない場面もあります。**その場合は、進めてよい条件をあらかじめ渡します。

<div class="prompt">はじめに、受け取った件数を「受け取った件数: ◯件」の形で書いてください。前の工程から件数が増えたり減ったりしている場合は、その理由も書いてください。
下は、担当部署まで振り分けた問い合わせの一覧です。1件ずつ、期限の具体的な日付が本文に書かれているものを「期限が分かっている」、書かれていないものを「期限が分かっていない」に分けてください。「日付は本工程に未着」の件はすべて「期限が分かっていない」として扱ってよいです。部署ごとに、期限が分かっているものを先に並べ直してください。4行はそのまま残し、順番だけ変えてください。</div>

<mark>材料A-1に2回試し、2回とも止まらずに進み、12件を正しく「期限が分かっていない」に分類しました。</mark>**「分からなければどちらに倒すか」を先に渡しておけば、止まらずに進めつつ、作り話も起きません。**止めるか進めるかは、どちらも正しい挙動のまま選べます。

## 応用・次の一手 {: .next }

**この記事の値打ちは2つです。**

1. 前工程が欠けを抱えたまま止まった場合、その停止は工程6・7・8まで鎖を伸ばしても誤魔化されずに続くこと
2. 「期限が分かっている」の基準を広げて1つの穴（相対表現の見逃し）を塞ぐと、別の穴（希望日との取り違え）が開くことがあること

**基準を広げるだけでは、安全側に動くとは限りません。**

**毎日・毎週この鎖を自動で回すなら、**[毎日決まった時刻にAIを動かす](/recipes/github-actions-daily-cron/)**の形に載せてください。**欠けた項目をどう使う工程を足すかは[欠けていた期限を実際に使う工程を足す](/recipes/later-stage-needs-the-missing-deadline/)で扱っています。保存版にするのは、この記事の指示文3（「今週中」も含めつつ、期限欄だけを見る一文を足す拡張版）です。

⚠️ **今回確かめたのは工程8までです。**工程9・10とさらに増やした場合や、期限以外の項目（担当部署・件名）が途中で欠けた場合に同じ結果になるかは確かめていません。実測に使ったのは`claude --safe-mode`という実測環境1つだけです。別のAIサービスでは結果が異なる可能性があります。
