## これで何ができるか {: .what }

[工程2に確認させると誤りは直る——健全なときほど、正しい項目を巻き添えにする](/recipes/doubt-fixes-added-not-dropped/)には、著者自身が試していない対策が書いてありました。「対策の候補は『除外する基準は、工程1と同じ語（至急・今すぐ・本日中）の有無だけにしてください。業務停止の有無などの別の基準を作らないでください』のように、基準をこちらで固定することです。この一文も今回の8回のどこにも試していません」。

試しました。架空の社内ヘルプデスクへの問い合わせを使い、[前の記事](/recipes/doubt-fixes-added-not-dropped/)と同じ2つの場面——**健全な5件だけを渡す条件**と、**「もう解決した至急」という誤りを1件混ぜた6件を渡す条件**——の両方で、基準を固定する一文を足して材料2本×各2回ずつ試しました。

結果は、条件によってはっきり分かれました。<mark>誤りを混ぜた6件では、基準を固定した版が4回とも誤りだけを正しく検出・除外しました。</mark>健全な項目は一度も巻き込まれていません。<mark class="warn">ところが健全な5件だけの条件では、基準を固定しても巻き添えは消えませんでした。4回とも、これまでとは別の1件（1回は2件）が新たに除外されました。</mark>全部で24回、材料2本ぶんの記録は `docs/evidence/narrowed-criteria-fixes-dirty-not-clean.md` に生のまま置いてあります。

### 6. 誤りを混ぜた6件で、除外の根拠を引用させる

自動実行では、除外された理由の文章はどうせ読まれません。せめて、除外の根拠になった本文の語句をそのまま引用させれば、あとで人が数秒で検算できます。

## うまくいかないときの言い直し方 {: .fix }

### 対策を足したのに、健全な項目が除外され続ける {: .trouble }

指示文3の症状です。除外された項目名を、工程1の実際の判定（記事や証拠にある一覧）と突き合わせてください。工程1が「意味で」含めていた項目（この記事ではHD-2206）が、確認版では「語そのものの有無」で除外されていないかを確認します。<mark>「〜のように」という言い方は、確認する工程では「〜そのもの」に狭まることがあります。</mark>

📌 **この記事では、この崩れを直す言い方を見つけられませんでした。**「〜のような語の有無」という表現を「〜に限らず、同じ意味を持つ表現も含めてください」に変える案は考えられますが、試していません。次に測るなら、そこから始めてください。

### 誤りが実際にあるときは対策が効くのに、無いときは巻き添えが出る {: .trouble }

これは指示文3・4の対比そのものです。<mark>対策を「常に足す」のではなく、「実際に誤りが混ざっていそうなとき」と「健全だと分かっているとき」で使い分ける手があります。</mark>ただし、自動実行では事前にどちらか分からないのが普通なので、実務的には次のどちらかになります。

- **確認そのものをやめる**（[前の記事](/recipes/doubt-fixes-added-not-dropped/)の指示文2＝確認なし版。矛盾には気づくが行は消えない）
- **確認はするが、除外はせず「要確認」の印だけ付けさせ、消すかどうかは人が決める**（次の一手）

### 除外の理由が信用できるか確かめたい {: .trouble }

指示文6のように、除外の根拠にした語句を一字一句そのまま引用させてください。<mark>引用が本文に実在しない、または文脈と違う語句を指していたら、その除外は疑ってください。</mark>この記事の4回では、引用はすべて本文と一致していましたが、n=4なので過信はできません。

## 応用・次の一手 {: .next }

**基準を固定する対策は、万能薬ではありませんでした。**誤りが実際に混ざっているときは検出率を保ったまま巻き添えを消しましたが、健全なときの巻き添えは、対策を足しても消えず、除外される項目が変わっただけでした。[前の記事](/recipes/doubt-fixes-added-not-dropped/)の結論（「確認は、間違いを見つける力は強いが、間違いが無いときにも何かを見つけようとする」）は、この対策を足しても変わりませんでした。

⚠️ **自動実行に確認の一言を足すなら、「本当に健全な日」がどれくらいの頻度であるかを先に考えてください。**誤りが混ざっている日が多いなら、この記事の対策（基準を固定する）は有効です。健全な日のほうが多いなら、対策を足しても巻き添えは消えないので、[確認なしで気づきだけを残す](/recipes/doubt-fixes-added-not-dropped/)ほうが、この記事の材料では安全でした。

📌 **除外ではなく印を付けるだけにする手は**[毎日同じ警告に、新しい1件だけ拾わせる](/recipes/stop-one-false-alarm/)の考え方と同じです。除外は取り消しがききませんが、印は人が見てから消せます。

📌 **工程を分けたときに何が壊れるかの土台は**[「AIには工程を分けて頼め」を測った記事](/recipes/split-into-stages-what-breaks/)にあります。この記事と[前の記事](/recipes/doubt-fixes-added-not-dropped/)は、その続きです。

⚠️ **この記事が実測していないことは3つあります。**

- 「〜のような語」という言い方を「〜に限らず同じ意味の表現も含む」に言い直した場合
- 健全・誤り以外の3つ目の条件（誤りが2件以上混ざる場合）
- 対策の一文を2回に分けて聞く（先に基準だけを確認させてから除外させる）場合
