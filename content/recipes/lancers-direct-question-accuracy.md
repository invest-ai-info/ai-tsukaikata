## これで何ができるか {: .what }

<mark>ランサーズの「生成AIの使用許可・制限を選べる制度」の有無を直接尋ねると、答えは聞き方で大きく割れました。</mark>独立した新規の会話にそれぞれ4回、4つの聞き方を試した結果です。

- **広く聞く（場面指定なし）**——4回とも「確証がない」という慎重な答え
- **場面を指定して聞く（先行記事と同じ聞き方の再実行）**——<mark>4回中1回しか先行記事に近い内容になりませんでした</mark>
- **「わからなければ分からないと書いて」と足す**——4回とも正直に「分かりません」
- **「推測でもいいから具体的に」と求める**——<mark class="warn">4回とも正しい導入時期（2024年3月）には届かず、1回は対象範囲を全形式に広げて誤りました</mark>

既存の2本があります。[ランサーズのAI可否は「要確認」](/recipes/lancers-ai-policy-needs-confirmation/)と[ランサーズのライティングも「要確認」](/recipes/lancers-writing-contest-still-needs-confirmation/)です。どちらも「制度の有無を直接尋ねた3回も、正確さまでは検証していません」という宿題を残していました。その宿題を、実際に機械で判定したのが今回です。

<mark class="warn">先行記事が見つけた「3回とも近い内容が出てくる」という結果は、同じ文言を新しい日に試したこの記事の4回では再現しませんでした。</mark>同じ聞き方でも、別の機会に試すと結果が変わります。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 特にありません |
| プログラミング | **不要**。この記事の指示文をコピーして貼るだけです |

この記事の真値（制度名・対象範囲・導入時期）は、ランサーズ公式プレスリリース「生成AIの『使用許可・制限』の選択機能」（<a href="https://www.lancers.co.jp/news/pr/23074/">https://www.lancers.co.jp/news/pr/23074/</a>・2024/03/07・2026-09-16確認）に基づきます。要点は3つです。発注者が**コンペ方式**で依頼を募集する際に、生成AIの使用許可・制限を選択できる機能があること。使用した場合は提案に【AIで生成】のラベルが付くこと。この機能は現在**「デザイン」「ライティング」業務の依頼のみ**に適用されていることです。

## AIへの頼み方 {: .ask }

### 1. 制度の有無を、場面を指定せず広く聞く

まず、どの依頼形式・業務かを指定せず、制度の有無だけを聞きました。

<div class="prompt">ランサーズには、AI利用の許可・制限を選べる制度がありますか。知っていることを教えてください。</div>

**4回とも「確証がない」「分かりません」に近い慎重な答えでした。**例えば1回目はこう答えました。「選択項目が追加されている可能性もありますが、具体的な項目名や仕様を正確に説明できる自信はありません」。制度の存在そのものを断定した回は0件です。

### 2. 先行記事と同じ場面指定の聞き方を再実行する

次に、先行記事が実際に3回試して「近い内容が出てくる」と報告した文言を、まったく同じ文字列で、新しい日に4回試しました。

<div class="prompt">ランサーズには、コンペ方式のデザイン依頼で、発注者が生成AIの「使用許可・制限」を選べる制度がありますか。知っていることを教えてください。</div>

**4回中1回しか、先行記事に近い内容になりませんでした。**その1回は「発注者が案件ごとに生成AIの利用を許可するかどうかを選べる枠を用意しています」と踏み込んで答えました。残り3回は違います。「システム化されているのか…正確な仕様までは断言できません」のように、確証が無いという言い回しのほうが強く出ました。<mark>同じ文言・同じ場面指定でも、先行記事の「3回とも近い内容」という結果は再現しませんでした。</mark>

## うまくいかないときの言い直し方 {: .fix }

### 「わからなければ分からないと書いて」を足す {: .trouble }

制度の有無を断定させず、分からない部分は正直に書かせたいときの言い直しです。

<div class="prompt">ランサーズには、AI利用の許可・制限を選べる制度がありますか。制度の名称・対象になる依頼形式や業務・導入時期について、分からないことがあれば、無理に答えず「分かりません」と書いてください。</div>

**4回とも「分かりません」と正直に答えました。**具体的な制度名や導入時期を作り話として出した回は0件です。

### 「推測でもいいから具体的に」と求めると {: .trouble }

「分からない」という答えが、具体性を求める一言でどう変わるかを確かめました。

<div class="prompt">ランサーズには、AI利用の許可・制限を選べる制度がありますか。制度の名称・対象になる依頼形式や業務・導入時期について、分からなくても、最も可能性が高い推測でかまわないので具体的に教えてください。</div>

**4回とも「推測です」と断ったうえで、具体的な名前・範囲・時期を出しました。**正しい導入時期（2024年3月）に届いた回は4回中**0回**でした。4回とも「2023年」を中心に推測し、2024年に触れたのは2回だけで、どちらも範囲の片端としてです。<mark class="warn">さらに1回は、対象範囲を「タスク形式・プロジェクト形式・コンペ方式いずれにも関係しうる」と誤りました。</mark>実際はコンペ方式限定のはずの制度を、全形式に広げたのです。残り3回はコンペ方式を優先する方向には傾いていましたが、「コンペ方式のみ」とはっきり言い切ったのは1回でした。

## 応用・次の一手 {: .next }

**AIの答えをそのまま信じず、確認する手順を決めておくと安心です。**

<div class="prompt">プラットフォームの規約や制度について、AIに聞いた答えをそのまま信じずに確認する手順を作りたいです。プログラミングはできません。私が毎回確認することを、番号を振って箇条書きで教えてください。</div>

2回とも10項目でしたが、次の骨格は共通していました。

- AIに「出典のURL」を聞き直し、そのURLを自分のブラウザで実際に開く
- 開いたページが、そのプラットフォームの公式ドメインかどうかを確認する
- ページ内検索で、AIが言った数字・条件が実際にそのページに書かれているか確認する
- ページの更新日を確認し、AIの答えと食い違えばページの原文を優先する
- 確認できなかった項目は「未確認」として分けて残す

確認したい点が決まっていれば、サポートへの問い合わせ文もそのまま作らせられます。

<div class="prompt">ランサーズのサポートに問い合わせる、短い質問文を1つ作ってください。AI利用の許可・制限を選べる制度の名称や、対象になる依頼形式・導入時期を具体的に確認したいです。</div>

2回とも、そのまま送れる短い質問文ができました。既存の2記事も含めて[案件のAI利用ルールを確かめる](/recipes/job-ai-policy-check/)と合わせて読んでください。プラットフォームが変わっても、「自分から規約を語り出す」現象と「確証がないまま推測で答える」現象の両方に注意が要ることが分かります。

⚠️ **この結果は、この1つのプラットフォーム（ランサーズ）・1種類の制度・合計20回（次の一手4回を含む）の実測です。**「AIはいつもこう答える」と一般化しないでください。試したのは、次の範囲までです。

- 聞いたのはランサーズの「使用許可・制限」の選択機能1つだけです。他社の類似制度や、ランサーズの他の制度は試していません
- 各聞き方はそれぞれ4回のみです。先行記事の3回との食い違いが、聞き方の違いか、試行回数の少なさによる揺れかは、この記事だけでは切り分けられません
- ランサーズの制度そのものが今も同じ内容かは、応募のたびに公式ヘルプで確認してください。制度は2024年3月時点のプレスリリースが根拠で、更新されている可能性があります
