## これで何ができるか {: .what }

[ふだんは3〜5件です、と一言足すかどうかで急増の自己申告が0対5に分かれる](/recipes/surge-stays-quiet-without-a-baseline/)は、「ふだんの目安」を**人間が数字で渡した**場合を確かめました。その記事はこう締めていました——「そもそも、ふだんの件数が分からない場合は、この記事では試していません」。

毎日の記録が積み上がっていけば、目安は人間が決め打ちしなくても、**記録そのものから計算させられる**はずです。今回はそこを確かめました。結論は3つです。

1. **目安の計算そのものは崩れません。**渡した記録の合計・平均を自分で計算させた12回すべてが、真値（単純平均）と一致しました
2. **ただし「ふだん」とみなす数字は、渡す記録の長さだけで変わります。**同じ本日の件数（34件）でも、直近2週間ぶんだけ渡すと目安は1日6.1件、4週間で5.6件、8週間全部で4.5件と変わりました
3. **その結果、「ふだんの何倍か」も5.5倍から7.6倍まで動きます。**どちらも計算としては正しいので、**どちらが「正しい倍率」かはAIには決められません**

原因は計算ミスではありません。今回の材料は**緩やかな増加傾向のある記録**です（7月は1日3〜4件、9月は1日6〜7件）。**古い週を含めるほど目安は下がるので、本日との倍率は見かけ上大きくなります**。<mark>同じ本日の件数・同じ指示文でも、渡すログの長さを変えただけで「何倍か」の答えが変わります</mark>。これが本記事の芯です。

📌 **この記事の数字はすべて架空データでの実測です。**問い合わせフォームの受信件数ログ（材料A・8週間）と来店予約の件数ログ（材料B・6週間）の2本に、実在の個人情報は1件も入れていません。同じ指示文を、独立した新規会話（毎回ゼロから起動・前の会話の記憶なし）で**合計12回**試しました。生の返りと機械照合は `docs/evidence/how-far-back-changes-the-usual-number.md` に全文置いてあります。

この記事は[ふだんの目安を人間が渡す記事](/recipes/surge-stays-quiet-without-a-baseline/)の続きです。あちらは目安を「ふだんは1日3〜5件程度です」と人間が決めて渡しましたが、こちらは**目安の計算そのものをAIに任せます**。指示文は全部で6つです。振ったのは次の2点だけです。

- **渡す記録の長さ**（2週間／4週間／8週間）
- **計算のさせ方**（そのまま／週ごとに区切る／項目を絞る／祝日を除く）

## AIへの頼み方 {: .ask }

### 1. まず、8週間ぶん全部を渡す

7/14〜9/7の56日分を、1日も欠かさず貼ります。

<div class="prompt">これは問い合わせフォームに届いた件数の記録です。この記録から、ふだんの1日あたりの件数の目安を計算してください。そのうえで、本日の件数34件が、ふだんの目安の何倍にあたるかを書いてください。</div>

この下に56日分の記録（日付｜件数）を貼ります。**2回とも、目安は4.5件/日、倍率は約7.6倍**でした。56日の合計（252件）も2回とも正しく計算できています。

<mark>2回とも、頼んでいないのに「直近のほうが件数は多い」と自分から言及しました</mark>。ただし自発的に計算した「直近」の範囲は、1回目は直近2週間、2回目は直近1週間と回によって割れました。**聞いていないことへの気づきは起きますが、その中身の粒度までは揃いません。**

### 2. 渡す記録を4週間に絞る

指示文は1番と一字一句同じです。貼る記録だけを、直近28日（8/11〜9/7）に絞ります。

<div class="prompt">これは問い合わせフォームに届いた件数の記録です。この記録から、ふだんの1日あたりの件数の目安を計算してください。そのうえで、本日の件数34件が、ふだんの目安の何倍にあたるかを書いてください。</div>

**2回とも、目安は5.6件/日、倍率は約6.0倍でした。**指示文も本日の件数（34件）も1番と同じです。<mark>渡すログを56日から28日に短くしただけで、目安は4.5件から5.6件に、倍率は7.6倍から6.0倍に変わりました</mark>。

### 3. さらに2週間に絞る

同じ指示文のまま、貼る記録を直近14日（8/25〜9/7）だけにします。

<div class="prompt">これは問い合わせフォームに届いた件数の記録です。この記録から、ふだんの1日あたりの件数の目安を計算してください。そのうえで、本日の件数34件が、ふだんの目安の何倍にあたるかを書いてください。</div>

**目安は2回とも6.1件/日、倍率は約5.5〜5.6倍でした**（最後の1桁は、目安を先に丸めてから割るかどうかで回によって割れています）。<mark class="warn">同じ本日・同じ指示文なのに、見せた記録を8週間→4週間→2週間と短くするだけで、目安も倍率も向きをそろえて動きます</mark>。目安は4.5→5.6→6.1件、倍率は7.6→6.0→5.5倍という順です。

### 4. 週ごとの小計を先に出させる

計算の中身を検算できるようにする言い方です。材料は1番と同じ8週間ぶんです。

<div class="prompt">これは問い合わせフォームに届いた件数の記録です。まず1週間ごとの合計を出し、次にそれぞれを7で割って週ごとの平均を出してください。そのうえで、全体のふだんの1日あたりの件数の目安を計算し、本日の件数34件がふだんの目安の何倍にあたるかを書いてください。</div>

2回とも、8週ぶんの週合計（23・24・23・24・35・37・42・44件）がすべて正しく出ました。そのうえで、最終的な目安（4.5件）・倍率（約7.6倍）は1番とまったく同じでした。<mark>週ごとの小計を見せても見せなくても、最終的な答えは変わりません</mark>。ただし小計があれば、「どの週から増え始めたか」を人間が後から目で確かめられます。これは次の「言い直し方」で使います。

### 5. 保存版——出す項目を3つに絞って、急増チェックを必須にする

[ふだんの目安を人間が渡す記事](/recipes/surge-stays-quiet-without-a-baseline/)の指示文4（急増チェックを「出す項目」の1つとして名指しする）を、**目安の計算そのものをAIに任せる版**に応用します。材料は変えて、来店予約の件数ログ（6週間・42日、本日29件）を使います。

<div class="prompt">これは来店予約の件数の記録です。毎回この形で処理してください。

①この記録から、ふだんの1日あたりの件数の目安を計算して書く
②本日の件数29件が、ふだんの目安の何倍にあたるかを書く
③②が5倍を超えているかどうかを1行で

この3つ以外は書かないでください。</div>

2回とも、こう返ってきました。

> ①ふだんの1日あたりの件数の目安は、記録のある42日間の合計166件を日数で割った、約3.95件です。
> ②本日の29件は、ふだんの目安（約3.95件)の約7.34倍にあたります。
> ③はい、5倍を超えています。

<mark>指定した①②③の3項目だけがそろい、前置きや補足は付きませんでした（2回とも）</mark>。目安の数字（約3.95件）も倍率（約7.3倍）も真値と一致しています。**目安を人間が渡す場合に効いた「絞っても急増チェックは消えない」という型は、目安の計算ごとAIに任せても同じく機能しました。**

### 6. 祝日など特殊な日を、目安の計算から除く

直近2週間の記録に、祝日で件数が0件だった日を1日混ぜます。

<div class="prompt">これは問い合わせフォームに届いた件数の記録です。祝日で臨時休業だった日は、ふだんの目安の計算に含めないでください。この記録から、ふだんの1日あたりの件数の目安を計算してください。そのうえで、本日の件数34件が、ふだんの目安の何倍にあたるかを書いてください。</div>

この下に、9/3だけ「0件（祝日のため臨時休業）」と書いた14日分を貼ります。2回とも、9/3を自分から除外し、残り13日の合計（79件）を13で割った約6.1件/日を目安にしました。倍率も2回とも約5.6倍で一致しています。祝日を含めたまま計算すると、目安は5.6件・倍率は6.0倍になるはずです。ですが2回とも、その数字は出てきませんでした。<mark>祝日を「含めないでください」という指示は、2回とも正しく効きました。</mark>

## うまくいかないときの言い直し方 {: .fix }

### 日によって「ふだんの何倍」の答えが違う気がする {: .trouble }

<mark class="warn">これはAIの気まぐれではなく、渡す記録の長さが毎回違うために起きます。</mark>記録が1日増えるたびに古い記録も一緒に渡していると、増加・減少の傾向がある記録では目安がじわじわ動きます。**毎回同じ「直近◯週間」を切り出して渡す**よう、渡す範囲を固定してください。指示文3番（2週間）・指示文2番（4週間）のように「直近2週間」「直近4週間」のどちらかに決めて、途中で変えないことが大事です。

### どの期間を「ふだん」とすべきか決められない {: .trouble }

機械的な正解はありません。ただし目安にできる考え方はあります。**件数が増え続けている・減り続けている記録なら、短い期間（2〜4週間）のほうが「今」に近い目安になります。**件数が波打つだけで方向性が無い記録なら、長い期間のほうが1日1日のブレに振り回されません。指示文4番の「週ごとの小計を先に出させる」形にしておくと、増減の傾向そのものを毎回の出力から目で確認できます。

### 祝日やイベントの日を、目安の計算に混ぜたくない {: .trouble }

指示文6番のように、「◯◯だった日は目安の計算に含めないでください」と**理由と一緒に名指し**してください。この実測では2回とも正しく除外されました。名指しせずに「特殊な日を除いて」とだけ頼むと、どの日が特殊かをAIが自分で判断することになり、この記事では確かめていません。

## 応用・次の一手 {: .next }

**「ふだんの目安」は、人間が渡しても（[前の記事](/recipes/surge-stays-quiet-without-a-baseline/)）、AIに記録から計算させても（この記事）、どちらも成立します。**ただし計算させる場合は、**何週間分を渡すかという、もう1つの決め事が増えます。**

- 人間が目安を渡す：基準がぶれない代わりに、目安そのものを自分で決めて更新する手間がある
- AIに記録から計算させる：手間は減るが、渡す記録の長さを固定しないと、同じ日でも倍率が変わる

<div class="prompt">これは来店予約の件数の記録です。毎回この形で処理してください。

①この記録から、ふだんの1日あたりの件数の目安を計算して書く
②本日の件数29件が、ふだんの目安の何倍にあたるかを書く
③②が5倍を超えているかどうかを1行で

この3つ以外は書かないでください。</div>

この指示文は、[毎日決まった時刻にAIを動かす仕掛けを作らせる](/recipes/github-actions-daily-cron/)にそのまま組み込めます。ただし**「直近◯週間」は、指示文か記録の作り方のどちらかで固定してください。**固定しないまま記録が育っていくと、半年後には今日とは違う「ふだん」で急増が判定されることになります。

⚠️ **この記事が実測していないこと**は3つです。

- 増減の傾向が無いフラットな記録で、窓の長さを振った場合
- 記録が数百日まで育った場合
- 年単位の季節変動がある記録

材料Bはフラットな記録でしたが、窓の長さを振る実測には使っていません（保存版の確認だけに使いました）。次に測るならここからです。[材料が壊れた日にAIが気づくか](/recipes/count-the-material-every-run/)とあわせて読むと、「中身が壊れた日」「量だけ多い日」「目安の定義そのものが動く日」の3つを見分けられます。
