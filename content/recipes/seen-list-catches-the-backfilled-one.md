## これで何ができるか {: .what }

[300件のログは分割して渡せる](/recipes/split-across-chunks-keeps-the-edge-row/)は「既読リストに無い項目を新着として」という指示文で新着を32件とも見逃さないと書いていました。ただし、その実測は**既読リストそのものを一度も渡していなかった**ことが後から分かっています。証拠の生の返り8回中5回が「既読リストが提示されていないため、本日付けの投稿を新着として扱いました」と自分から告白していました。つまり測れていたのは日付基準で、記事が主張する既読リスト基準ではありません。

この記事は、既読ID一覧を**実際に**渡して同じ場面を測り直します。<mark>さらに、新着2件のうち1件を一覧の中ほどの古い日付にしました。</mark>「遡って取得し直した分」という想定で、日付だけ見ていると新着だと気づけません。プログラミングは要りません。

結論は3つです。

1. 既読ID一覧298件を実際に渡すと、新着2件の**両方**を正しく検出しました。1件は一覧の中ほどに紛れた古い日付、もう1件は一覧中最新の日付です。材料2本（お知らせ一覧・メンテナンス履歴）×2回転＝**4回とも見逃し0件・誤検知0件**です。
2. 300件を1つのメッセージで渡した場合と、100件ごと3分割で渡した場合を比べても、結果は同じでした。分割そのものは既読リスト方式を崩しませんでした。
3. <mark>チャンクを送るたびに、AIは自分から既読ID一覧とそのチャンクを照合し、見つけた新着を名指しで報告しました。</mark>**日付ではなくID一覧のギャップ**で気づいていることが、返り自体に書かれています。「ANN-0099の次がANN-0101で、ANN-0100だけ抜けている」という言い方です。

この記事の進め方は2段です。まず既読ID一覧と全件を一括で渡して基準を取り、次に同じものを3分割で渡して差が出るかを確かめます。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 20分 |
| 費用 | 無料。無料のチャットAIで足ります |
| 必要なもの | ブラウザで使えるAI（ChatGPT・Claude・Geminiなど）と、既読ID一覧・監視対象の一覧 |
| プログラミング | **不要** |

- **この記事は[300件のログは分割して渡せる](/recipes/split-across-chunks-keeps-the-edge-row/)の実測し直しです。**あの記事の指示文を1字も変えていません。既読リストを実際に渡す点だけを変えています。
- **既読リスト方式そのものの崩れ方は[監視対象を増やしても、古い記録は新着にしない](/recipes/unseen-does-not-mean-new/)にあります。**この記事はその方式を、分割という別の軸で確かめます。

## AIへの頼み方 {: .ask }

### 1. まず、既読ID一覧と全件を一括で渡す

今回の材料は300件の一覧です。既読ID一覧は298件（全体から新着2件を除いたもの）です。

<div class="prompt">既読リスト（これまでに確認済みのID一覧）は次のとおりです。

（ここに、既読ID一覧をそのまま貼ります）

投稿一覧は次のとおりです（全300件）。

（ここに、投稿一覧をそのまま貼ります）

既読リストに無い項目を新着として、該当する投稿のIDだけを列挙してください。説明や前置きは不要です。該当が無ければ「新着なし」とだけ書いてください。</div>

**2系列（お知らせ一覧・メンテナンス履歴）×2回転＝4回とも、2件とも正しく検出されました。**うち1件は一覧の中ほど（2024-03-29付け）、もう1件は一覧中最新（2026-10-01付け）です。これが基準になります。

### 2. 同じものを100件ごと3分割で渡す

1件目のチャンクに、既読ID一覧も一緒に渡します。

<div class="prompt">既読リスト（これまでに確認済みのID一覧）は次のとおりです。

（ここに、既読ID一覧をそのまま貼ります）

投稿一覧を3回に分けて送ります。まず1件目から100件目です。

（ここに、1件目から100件目までの投稿一覧をそのまま貼ります）</div>

まだ新着を聞いていませんが、<mark>AIは自分から既読ID一覧と照合し、こう返しました。</mark>

```
1件目（ANN-0001〜ANN-0100）を既読リストと照合しました。

未読は1件だけです
- 2024-03-29: 「定例メンテナンスのお知らせ（遡って取得し直した分）」(ID: ANN-0100)

ANN-0001〜ANN-0099 の99件はすべて既読リストに含まれています。既読リストはANN-0099の次がANN-0101で、ANN-0100だけ抜けています。この投稿は遡って取得し直した分なので、最初の確認時に漏れたものと思われます。

2件目と3件目も送ってください。届いた分から順に、既読リストにないIDを洗い出します。
```

<mark>日付ではなく、ID一覧のギャップで気づいています。</mark>2件目を続けます。

<div class="prompt">続き（101件目から200件目）です。

（ここに、101件目から200件目までの投稿一覧をそのまま貼ります）</div>

このチャンクには新着が無いので、「未読はありませんでした」という返事だけが続きます。

### 3. 最後のチャンクで、新着をまとめて聞く

<div class="prompt">続き（201件目から300件目）です。これで全部（300件）届きました。

（ここに、201件目から300件目までの投稿一覧をそのまま貼ります）

既読リストに無い項目を新着として、該当する投稿のIDだけを列挙してください。説明や前置きは不要です。該当が無ければ「新着なし」とだけ書いてください。</div>

**2系列×2回転＝4回とも、一括のときと同じ2件が正しく列挙されました。**分割の有無で結果は変わりません。

## うまくいかないときの言い直し方 {: .fix }

### 一括でもう一度、同じ結果か確かめたいとき {: .trouble }

<div class="prompt">既読リスト（これまでに確認済みのID一覧）は次のとおりです。

（ここに、既読ID一覧をそのまま貼ります）

投稿一覧は次のとおりです（全300件）。

（ここに、投稿一覧をそのまま貼ります）

既読リストに無い項目を新着として、該当する投稿のIDだけを列挙してください。説明や前置きは不要です。該当が無ければ「新着なし」とだけ書いてください。</div>

1番と同じ指示文です。分割の有無で結果が変わっていないか心配なときに使います。一括でも分割でも、同じ既読ID一覧・同じ一覧を渡して、両方の答えを突き合わせてください。

### 分割する回数・件数が増えたとき {: .trouble }

<div class="prompt">続き（201件目から300件目）です。これで全部（300件）届きました。

（ここに、201件目から300件目までの投稿一覧をそのまま貼ります）

既読リストに無い項目を新着として、該当する投稿のIDだけを列挙してください。説明や前置きは不要です。該当が無ければ「新着なし」とだけ書いてください。</div>

最後のチャンクで使う指示文は3番と同じです。分割の数が3つより増えても、最後のチャンクでこの文面を使えば、それまでのチャンクの分も含めて新着を列挙してくれます。今回確かめたのは3分割までです。

### IDが連番ではないとき {: .trouble }

今回の仕込みは、既読ID一覧のIDが連番で、新着1件だけがちょうど1つ抜けている形でした。この連番という性質が、気づきやすさの手がかりになった可能性があります。IDが連番ではない・抜けが複数あるシステムでは未測定です。

心配なら、1番の指示文の後にもう一つ聞いてください。

<div class="prompt">今の判断は、日付とIDの照合のどちらを手がかりにしましたか。教えてください。</div>

日付ではなくIDの照合で答えているかを、ここで確認できます。

<div class="prompt">既読リスト（これまでに確認済みのID一覧）は次のとおりです。

（ここに、既読ID一覧をそのまま貼ります）

投稿一覧を3回に分けて送ります。まず1件目から100件目です。

（ここに、1件目から100件目までの投稿一覧をそのまま貼ります）</div>

## 応用・次の一手 {: .next }

[300件のログは分割して渡せる](/recipes/split-across-chunks-keeps-the-edge-row/)には穴がありました。「既読リストに無い項目を新着として」と書きながら、実際には既読リストを渡していませんでした。今回は既読ID一覧を実際に渡して、答えを付け直しました。<mark>既読リスト方式は、分割そのものには崩れませんでした。</mark>

崩れる原因があるとすれば別の場面です。[監視対象を増やしても、古い記録は新着にしない](/recipes/unseen-does-not-mean-new/)が示した場面（新しい監視対象を追加した直後、既読リストがまだ無い状態）がそれです。

同じ形の監視は、点検のたびに起きます。誤報を条ごとに直す話は[2つの誤報、1回の依頼で両方直る](/recipes/same-week-two-fixes-stay-separate/)にあります。

⚠️ **この記事が実測していないこと**は3つです。

- IDが連番ではない・抜けが複数あるシステムでの検出精度
- 4分割より多い分割や、300件より大きい規模
- 新着が3件以上、同じチャンクに重なって仕込まれた場合

📌 **試行回数。**`claude --safe-mode --tools "" --system-prompt "あなたは親切な汎用アシスタントです。ツールやファイルシステムへのアクセスはありません。ユーザーの依頼に文章だけで答えてください。"` で、**合わせて18回**の独立呼び出しをしました。

- 一括4回（2系列×2回転）
- 3分割4回（2系列×2回転。各3ターンの多ターン会話）
- 言い直し方の自己申告確認1回（系列ANNのみ。2回のやり取り＝基準メッセージ+確認の質問）
