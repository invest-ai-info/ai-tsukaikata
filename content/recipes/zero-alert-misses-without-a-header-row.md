## これで何ができるか {: .what }

[定期実行させたAIが「本当に動いたか」を、自分で確かめる形にする](/recipes/count-the-material-every-run/)には、著者自身が書いた未測定事項がありました。「点検の5項目と『0件の警告』を同じ指示文に入れるのは自然ですが、この記事の実測はそれぞれ別に走らせたものです」。

試しました。結論は3つです。

1. **表形式の記録（列に「種類」という見出しがある）なら、1本にまとめても両方の役目が壊れません。**材料点検・0件警告・件数・未対応一覧の4つとも、2回とも真値と一致しました。
2. **見出しのない走り書きの記録では、0件警告だけが4回とも外れました。**まとめても、まとめずに単独で聞いても同じです。<mark>0件警告が外れる原因は、「まとめたこと」ではありません。</mark>
3. <mark>0件警告が外れる原因は、リストの項目数でもありません。</mark>同じ走り書きの記録で、実際にある種類（設備）を聞くと2回とも正しく「なし」と答えました。崩れるのは「0件になる種類を、見出しのない材料から確定する」ところだけです。

材料は前作と同じ2本（表形式の受付ログ＝材料A、走り書きの現場メモ＝材料B）を流用しました。同じ材料で比べることで、「まとめたこと」だけを変数にできます。

この記事の進め方は3段です。まず「まとめても壊れないか」を確かめます。次に、壊れた箇所の原因を1つずつ切り分けます。最後に、両方の役目を保つ言い直しまで実測します。

## AIへの頼み方 {: .ask }

### 1. まず、2つの点検を1本の指示文にまとめる

まとめるのは2つです。点検の5項目（行数・最新の日付・昨日判定・重複の組数・崩れた行）と、0件警告（毎日ある種類が今日は0件か）です。両方を、出す順番の中に並べて1本にします。

<div class="prompt">今日は2026年8月16日です。下は「昨日ぶん」として置かれた記録です。下の種類は、この記録に毎日1件以上あるものです。

請求、納期

次の4つだけを、この順番で出してください。

1. 材料の点検（下の5つを1行ずつ）
   - 受け取った行数（見出しの行を除く）
   - 記録に出てくる日付のうち、いちばん新しいもの
   - その日付は昨日（2026-08-15）ですか。「昨日／昨日ではない／判断できない」で書いてください
   - 中身が完全に同じ行が何組あるか
   - 列や書き方が途中で崩れている行があれば、その行をそのままコピー（無ければ「なし」）
2. 上に挙げた種類のうち、今日の記録に1件も無かったものの名前と「0件」（すべてあれば「なし」）
3. 種類ごとの件数（多い順）。中身が完全に同じ行は、1件として数えてください
4. まだ対応が終わっていないものの一覧（記録の文言をそのままコピーしてください）

無いものを推測で埋めたり、似た種類に振り替えたりしないでください。この4つ以外は何も書かないでください。前置き・感想・提案・注記・確認事項・補足は書かないでください。そのままファイルに保存します。</div>

表形式の材料（受付ログ）に、壊れた日の記録を貼って2回、正常な日の記録を貼って1回試しました。<mark>表形式の記録では、壊れた日の2回とも4項目すべてが真値と一致しました。</mark>一致したのは次の5点です。

- 行数13、日付2026-08-14（昨日ではない）
- 重複3組、崩れた行あり
- 0件警告（請求0件・納期0件）
- 件数（仕様3・返品3・その他3）
- 未対応3件

正常な日も誤検知は0件でした。

⚠️ **ただし項目3「種類ごとの件数」に、項目2で出した0件情報が重複して付け加わりました。**頼んだのは別の項目として分けることで、0件の種類を3番でも書けとは指示していません。実害はありませんが、まとめたことで項目のあいだに情報が漏れた一例です。

### 3. まとめたのが原因か、別々でも確かめる

## うまくいかないときの言い直し方 {: .fix }

### 「見出しがないから」と教えても、言い直すと別の項目が消える {: .trouble }

「推測せず、1件ずつ数えてから0件なら0件と断定して」と足すと、0件警告は直ります。

<div class="prompt">今日は2026年8月16日です。下は「昨日ぶん」として置かれた記録です。下の種類について、それぞれ記録の中に何件あるかを1件ずつ数えてください。記録に1件も無い種類は、推測せずに「0件」と断定してください。

在庫

1. 上で数えた種類ごとの件数（0件だったものも含めて全部）
2. 種類ごとの件数（多い順）。中身が完全に同じ行は、1件として数えてください
3. まだ対応が終わっていないものの一覧（記録の文言をそのままコピーしてください）

この3つ以外は何も書かないでください。前置き・感想・提案・注記・確認事項・補足は書かないでください。そのままファイルに保存します。</div>

2回試すと、<mark>項目1「在庫：0件」は2回とも正解でした。</mark>ところが<mark class="warn">項目2「種類ごとの件数（多い順）」が、2回とも「在庫：0件」だけになりました。</mark>本来出るはずの設備3・問い合わせ3・清掃2・その他2が、丸ごと消えています。0件警告を直す言い直しが、件数の内訳を壊したことになります。

   - 列や書き方が途中で崩れている行があれば、その行をそのままコピー（無ければ「なし」）
2. 上で数えた種類の件数（0件だったものも含めて全部）
3. 記録に実際に出てきたすべての種類を、2の種類にかぎらず、件数の多い順にもれなく挙げてください。中身が完全に同じ行は、1件として数えてください

### 自分の記録が「見出しのある形」か分からない {: .trouble }

表の先頭行に、列の名前（「種類」「状態」など）が1行として書かれていれば「見出しのある形」です。

- 見出しあり：Excelやスプレッドシートからそのままコピーした表
- 見出しなし：メモ帳・チャットのログ・音声の文字起こしのような走り書き

迷ったら、2番の最終形（「数えた種類に限らず全部挙げて」まで入れた指示文）を既定にしてください。見出しがある記録でも崩れませんでした。

## 応用・次の一手 {: .next }

**この記事が答えたのは[前の記事](/recipes/count-the-material-every-run/)の未測定事項「6番と7番を1つの指示文にまとめた形」です。**まとめること自体は崩れの原因ではなく、崩れていたのは走り書きの記録で0件を確定する部分でした。

📌 **この記事が実測していないこと**は3つです。

- 3個以上の種類を一度に渡した場合
- 列見出しが「種類」以外の言葉（「区分」「カテゴリ」など）だった場合
- 見出しの一部だけが欠けた記録

実際に使う前に、ご自身の記録の形で一度だけ試してください。

⚠️ **「見出しのある形に直す」のも手です。**走り書きの記録そのものを、送る前に「種類」の列を1行足した表に整えてしまえば、この記事の崩れを避けられます。ただし、その変換自体が新しい作業になるので、まずは最終形の指示文（数えた種類に限らず全部挙げる一文つき）を試すほうが早いはずです。

📌 **試行回数。**指示文は8個で、走らせた回数は上から順に、頼み方が3・3・2・2・2回（計12回）、言い直し方が2・3回（計5回）、**合わせて17回**です。材料は[前の記事](/recipes/count-the-material-every-run/)から流用した架空のもので、真値はコードで再計算して元記事の集計と一致することを確認しました。指示文ごとの生の返りは `docs/evidence/zero-alert-misses-without-a-header-row.md` にあります。
