## これで何ができるか {: .what }

[基準を固定しても、健全な5件の巻き添えは消えない](/recipes/narrowed-criteria-fixes-dirty-not-clean/)は、対策を1つ試していませんでした。著者自身がこう書いています。「『〜のような語の有無』という表現を『〜に限らず、同じ意味を持つ表現も含めてください』に変える案は考えられますが、試していません。次に測るなら、そこから始めてください」。

試しました。架空の社内ヘルプデスクへの問い合わせを使い、言い換えた一文を材料2本×各2回ずつ試しています。条件は6つです。

- [前の記事](/recipes/narrowed-criteria-fixes-dirty-not-clean/)と同じ**健全な5件だけを渡す条件**
- 同じく**誤りを1件混ぜた6件を渡す条件**
- 今回新しく足した、**「急ぎではない」と自分で書いている依頼を紛れ込ませた条件**
- 誤りと紛らわしい語の**両方を同時に混ぜた条件**
- 誤り混入・紛らわしい語混入それぞれに、**除外の根拠を引用させる指定を足した条件**

## うまくいかないときの言い直し方 {: .fix }

### 巻き添えが消えても、除外の判断が信用できるか確かめたい {: .trouble }

指示文5・6のように、除外の根拠にした本文の語句を一字一句そのまま引用させてください。<mark>「類義語・言い換え」を許す基準は、語そのものの基準より判断の幅が広いぶん、根拠の引用がいっそう役立ちます。</mark>この記事の4回では、引用はすべて本文と一致していましたが、条件ごとにn=4なので過信はできません。

### この言い換えを、他の場面にそのまま持ち込みたい {: .trouble }

📌 **この記事が確かめたのは6条件×4回＝24回だけです。**題材は架空の社内ヘルプデスク問い合わせ1つ、材料は2つの言い回しに限られます。<mark class="warn">この言い換えを、別の分類作業（経費の勘定科目・問い合わせの製品カテゴリなど）にそのまま持ち込んでよいとは言えません。</mark>持ち込む前に、自分の材料で同じように2回転（材料を変えて2本、各2回）試してください。

### 紛らわしい語をもっと難しくしたら、どこかで崩れるはず {: .trouble }

今回の紛らわしい語（HD-2225／HD-3320）は、「急ぎではない」「来週」という否定の言葉を自分から含んでいました。<mark class="warn">否定の言葉すら含まない、もっと巧妙な紛らわしさは試していません。</mark>例えば、緊急に見える言葉と緊急でない言葉が同じ文に混ざる依頼です。次に測るなら、そこから始めてください。

## 応用・次の一手 {: .next }

**これで、[「AIには工程を分けて頼め」を測った記事](/recipes/split-into-stages-what-breaks/)から始まった3本の連作が、いったん決着しました。**

1. 工程を分けると、上流の誤りは下流で直るか。答え＝「確認は効くが、健全なときほど巻き添えを生む」（[doubt-fixes-added-not-dropped](/recipes/doubt-fixes-added-not-dropped/)）
2. 基準を固定すれば直るか。答え＝「誤りには効くが、健全な巻き添えは消えない」（[narrowed-criteria-fixes-dirty-not-clean](/recipes/narrowed-criteria-fixes-dirty-not-clean/)）
3. 基準を緩めて類義語も含めれば直るか。答え＝**この記事。24回中24回、直った**

⚠️ **自動実行に確認の一言を足すなら、まず「のように」を使わず、範囲を明示的に広げる言い方にしてください。**「〜のような語の有無」という限定は、確認する工程では字義どおりに縮みます。範囲を広げる側の言葉で書くほうが、意味で判断する工程1の挙動に近づきました。

📌 **除外ではなく印を付けるだけにする手は**[毎日同じ警告に、新しい1件だけ拾わせる](/recipes/stop-one-false-alarm/)の考え方と同じです。今回のように対策で巻き添えを消せた場合でも、自動実行の初日は「除外」ではなく「印を付けるだけ」にして、しばらく人が見てから消す運用のほうが安全です。
