## これで何ができるか {: .what }

AIに「読みやすく整えて」と頼んだあと、返ってきた文を全部読み直すのは大変です。<mark>読み直す場所を先に絞れれば、そのぶん速く出せます。</mark>

欄が二つに分かれた架空の下書きを**2本**作りました。片方は応募文（【これまでの実績】と【これから取り組みたいこと】）、もう片方は謝罪文（【経緯】と【今後の対応】）です。**前半が確かめられる欄、後半が確かめられない欄**になっています。

数えるものは、走らせる前に決めました。**約束の言葉24語**（必ず／徹底／再発防止／二度と／全力／…）と**詫びの言葉9語**（申し訳／お詫び／ご迷惑／…）で、<mark>どちらも原稿に1語も出てこないことをコードで確かめてあります</mark>。あわせて、原稿に無い数字が出たかどうかも数えました。

「読みやすく整えてください。」だけを、**材料2本 × 各5回 ＝ 10回**通した結果です。

- ✅ **事実の欄は、10回とも追加0件でした。**原稿に無い数字が入った回は0回です
- ✅ **原稿の数字が消えた回も、10回とも0回**でした。日付も件数も字数も、そのまま残ります
- 🚨 <mark>増えたのは約束の欄だけで、合わせて7件</mark>（再発防止4回・徹底1回・申し訳1回・ご迷惑1回）
- 🚨 <mark>しかも足されたのは謝罪文の側だけで、応募文は5回とも0件</mark>でした。同じ一文でも、材料が変われば起きません

⚠️ **これはこの2本・この回数での話です。**「事実は絶対に動かない」という話ではありません。数字が書き換わる材料は別にあり、[提案文を、実績を盛らずに書く](/recipes/proposal-without-inflating/)では**素材に無い約束**が、[発注者への返事を、条件を薄めずに書く](/recipes/client-reply-without-softening/)では**条件そのもの**が消えました。この記事が言えるのは、**欄が分かれている下書きでは、増える場所が偏った**というところまでです。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 欄が2つ以上に分かれている下書き（実績と抱負、経緯と今後、など） |
| プログラミング | **不要**。貼って、指示文をコピーするだけです |

実測に使った材料は、次の架空の下書きです。指示文の「原稿」はこれを指します。

```
【経緯】
・7月14日の納品分で、見出しの2か所に誤字がありました。
・こちらの確認は、書き上げてから1回だけでした。
・指摘をいただいたのは翌15日の朝で、差し替えは同じ日の12時に済んでいます。
・同じ月に納品した12本のうち、誤字が出たのはこの1本です。

【今後の対応】
・確認を、書き上げた直後と翌朝の2回に分けます。
・見出しだけを声に出して読む手順を1つ足します。
・次の納品分から、この2つを使います。
```

もう1本は応募文で、【これまでの実績】に5行（2年3か月・月8本・3000字・24時間以内など）、【これから取り組みたいこと】に3行を入れてあります。

## AIへの頼み方 {: .ask }

### 1. まず、そのまま整えさせる

<div class="prompt">読みやすく整えてください。</div>

**10回とも、読みやすくはなりました。**箇条書きが文になり、見出しが `##` に変わり、「済んでいます」が「完了しております」になります。

<mark>それでも、事実の欄の数字は10回とも1つも動きませんでした。</mark>7月14日も、2か所も、12本のうち1本も、そのままです。応募文のほうも、2年3か月・月8本・3000字・24時間以内が5回とも残りました。

🚨 **増えたのは約束の欄です。**謝罪文の5回で、こう入りました。

> 再発防止のため、以下の2点を次回納品分より実施いたします。

> この度はご迷惑をおかけし、申し訳ございませんでした。今後はこの2点を徹底し、再発防止に努めます。

<mark class="warn">「再発防止」も「徹底」も「申し訳」も「ご迷惑」も、原稿には1語もありません。</mark>原稿にあるのは「確認を2回に分けます」「手順を1つ足します」という手順だけです。

### 2. 応募文では、5回とも何も足されなかった

同じ指示文を応募文に当てた5回は、**約束の欄への追加が0件**でした。抱負の欄の「〜したいです」が「〜できるようになりたい」に整うだけで、決意の言葉は入りません。

🔑 **書類の種類で起きたり起きなかったりします。**謝罪文には「詫びて、決意を述べる」という世間の型があり、原稿がそれを書いていないぶんを埋めた、という読み方ができます。⚠️ **2本で試したから見えたことです。**1本だけなら「起きなかった」で終わっていました。

### 3. 「書いていないことは足さないで」を1行足す

<div class="prompt">読みやすく整えてください。
原稿に書いていないことは足さないでください。</div>

**4回とも、追加は0件**になりました。謝罪文の側でも、詫びの一文も決意の言葉も入りません。

📌 **この材料では、禁止だけで足りました。**当サイトの記事は「禁止には受け皿を対で」と書くことが多いのですが、ここでは受け皿なしでも0件です。<mark>止めたいものが「無くても文が成り立つもの」なら、禁止だけで止まる</mark>ということだと見ています。

### 4. 〔足した文〕の欄を作らせる

それでも心配なら、足したものを自己申告させます。

<div class="prompt">読みやすく整えてください。
原稿に無い文を足した場合は、整えた本文の下に〔足した文〕として1行ずつ並べてください。</div>

**4回とも追加は0件で、〔足した文〕の欄には「（原稿にない文の追加はありません）」と書かれました。**§3と数字は同じです。

⚠️ **自己申告だけを信じないでください。**この記事の判定は、AIの申告ではなく**先に決めた語の一覧との照合**でやっています。申告と実際がずれる例は[AIに任せた作業は、報告ではなく現物で確かめる](/recipes/verify-before-report/)にあります。

### 5. 整える前に、いま何を約束しているかを確定させる

いちばん効いたのは、整える前の一手でした。

<div class="prompt">この原稿の中で、私が相手に約束していることを1行ずつそのまま抜き出してください。
まだ整えないでください。</div>

謝罪文の2回とも、**原稿の3行を一字一句そのまま**返しました（機械照合で3/3・3/3）。「確認を、書き上げた直後と翌朝の2回に分けます。」など、**自分が何を引き受けたのかが、整える前に画面に出ます。**

### 6. 事実の欄を、名指しで凍らせる

<div class="prompt">【経緯】の欄は1文字も変えないでください。
【今後の対応】の欄だけを、読みやすく整えてください。</div>

**4回とも、事実の欄の行が一字一句そのまま残りました**（謝罪文4/4行・応募文5/5行）。追加も0件です。<mark>読み直す場所が、後ろの欄だけになります。</mark>

### 7. 毎回やるなら、確かめる欄を様式に入れる

<div class="prompt">毎回この形で返してください。
【整えた本文】欄の見出しと順番はそのまま。行を足さない。
【私が確かめること】原稿から決まらないので私が決める必要がある点。1行ずつ。
この2つの見出し以外には、何も書かないでください。</div>

**4回とも追加は0件**で、【私が確かめること】には原稿から決まらない点が5〜6行ずつ返りました。「『翌朝』の確認を何時ごろに行うか」「誤字だった具体的な語句を本文に書くかどうか」——**足されなかった代わりに、足すべきかどうかの判断がこちらへ戻ってきます。**

## うまくいかないときの言い直し方 {: .fix }

### 何が「約束」なのかで、回ごとに答えが割れる {: .trouble }

⚠️ **§5を応募文に当てた2回は、答えが割れました。**1回目は「約束として読める行は**ありません**」と答え、語尾が「たいです」「考えています」なので願望だと説明しました。2回目は**4行を約束として抜き出し**、そのうえで「後半3行は希望・意向に近い書き方です。この4行のうちどれを『約束』として扱うか、判断が必要そうであれば教えてください」と添えました。

🔑 <mark>どちらも間違っていません。線を引いていないのはこちらです。</mark>迷ったら、語尾で決めてしまうのが早いです。

<div class="prompt">語尾が「します」「いたします」で終わっている行だけを、約束として抜き出してください。
「したいです」「考えています」で終わる行は、約束に入れないでください。</div>

**この形を4回通したところ、割れは消えました。**応募文の2回とも「該当する行は**ありません**」、謝罪文の2回とも同じ3行です。⚠️ ただし応募文の2回は<mark>「〜ました」（実績の過去形）も拾うかを聞き返してきました</mark>。線を1本引くと、その線のすぐ外にあるものが次の質問になります。

### 保存版にしたら、欄の見出しが消えた {: .trouble }

⚠️ **これは実測で起きました。**§7の保存版を応募文に当てた1回で、【これまでの実績】と【これから取り組みたいこと】の見出しが両方とも消え、**8行が【整えた本文】の下に1つの箇条書きとして並びました**（指示文には「欄の見出しと順番はそのまま」と書いてあります）。

<mark class="warn">欄が消えると、この記事のやり方そのものが使えなくなります。</mark>読む場所を欄で絞る前提が崩れるからです。同じことが別の題材でも起きるのは[出す形を決めて2回走らせる](/recipes/transcript-auto-same-every-time/)にあります。**保存版にしたら、材料を替えてもう1回**通してください。

### 事実の欄も、本当に動いていないのか心配 {: .trouble }

この記事の判定は「数字が増えたか・消えたか」だけです。**言い回しの変化は数えていません。**気になるなら、別の会話に原文と整えた文を並べて渡します。

📌 数字が動かなくても、**書いていない約束が足されることはある**というのが§1の結果です。逆に、数字はそのままでも**条件が反転する**例は[発注者への返事を、条件を薄めずに書く](/recipes/client-reply-without-softening/)にあります。**「数字が合っているから大丈夫」は、この2つの壊れ方には効きません。**

## 応用・次の一手 {: .next }

**下書きの欄を、先に2つに割っておく。**この記事のやり方は、原稿が「確かめられる欄」と「確かめられない欄」に分かれていることが前提です。分かれていない下書きなら、まず§5で約束の行だけを抜き出させて、そこから欄を作ってください。

**納品前の検品と組み合わせる。**発注書の条件との突き合わせは[発注書と自分の原稿を、AIに突き合わせさせる](/recipes/writing-check-against-spec/)が担当です。**あちらは「条件を満たしたか」、この記事は「書いていないことが増えていないか」**で、見ている向きが逆です。

**毎回同じ様式で回すなら、§7の2見出しをそのまま置く。**【私が確かめること】に返ってきた行は、そのまま自分の作業リストになります。

**今回の数字はすべて架空データでの実測**（本体＝材料2本 × 各5回 ＝ 10回、後半の指示文＝材料2本 × 各2回 ＝ 各4回、合わせて30回）です。生の返りと判定コードは `docs/evidence/edited-draft-check-the-promise-column.md` に全文置いてあります。
