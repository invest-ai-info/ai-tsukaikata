## これで何ができるか {: .what }

[監視の対策は100件でも効く](/recipes/backlog-scale-holds-brevity-breaks-it/)には、著者自身が書いた
未測定事項がありました。「過去分がもっと多い場合（数百件・数千件）は、そもそも一覧を丸ごと貼れなく
なり、材料を分割して渡す必要が出てきます。分割したときにどちらの側で崩れるかは、この記事では扱って
いません」。

測りました。監視対象の過去ログを**300件**まで育て、1つのメッセージに貼りきれない前提で、
**100件ごと3分割・150件ごと2分割**の2通りに分けてAIに渡しました。

<figure class="figure">
<img src="/static/images/split-across-chunks-keeps-the-edge-row-boundary.svg" alt="300件のログに仕込んだ2件の新着（100件目・201件目）の位置を固定したまま、分け方を100件ごと3分割と150件ごと2分割の2通りに変えた図。100件ごと3分割では、100件目はちょうど1つ目の境界線の上に、201件目はちょうど2つ目の境界線の直後に乗る。150件ごと2分割では、同じ100件目・201件目はどちらも境界から離れたチャンクの中ほどに収まる。件数と中身は300件とも同じで、分け方だけを変えて境界の位置をずらしていることを示す。">
<figcaption>同じ2件でも、分け方次第で境界の上に乗ったり中ほどに収まったりする。</figcaption>
</figure>

新着2件の位置は固定し、仕込んだのは「本日付けの投稿（または受付）」です。100件ごと3分割では、
この2件がちょうど境界線の上（1つ目の境界の直前・2つ目の境界の直後）に乗ります。150件ごと2分割
では、同じ2件がチャンクの中ほどに収まります。中身は変えず、分け方だけを変えて境界の位置をずらし
ました。

<mark>材料2本（SNS監視・問い合わせ監視）×分け方2通り×各2回、さらに聞き方を2通り加えて計16回試した
結果、境界の上でも中ほどでも、仕込んだ新着2件×16回＝32件は32件とも見逃されませんでした。</mark>
無関係な過去の投稿を新着と誤って数えた回も0件でした。

## AIへの頼み方 {: .ask }

### 1. まず素朴な指示文を、分割して渡す

1つ目の進め方は「全部届くまで分析しない」と伝え、最後にまとめて聞くやり方です。下はSNS監視
（@pottery_studio_tsuchi）の例です。問い合わせ監視でも、対象名の部分を入れ替えただけで指示文の
構造は同じにしました。

<div class="prompt">毎朝、監視対象の新着をまとめて報告する担当です。今日は2026-10-05です。

@pottery_studio_tsuchiの過去の投稿一覧が育って全部で300件になり、1つのメッセージに貼りきれないため、3回に分けて貼ります。全部貼り終えるまでは、分析や件数の集計はせず「次をお願いします」とだけ返してください。

1回目（1件目から100件目）です。

（ここに、1件目から100件目までの投稿一覧をそのまま貼ります）</div>

2回目は「続き」とだけ告げて次のチャンクを貼ります。

<div class="prompt">続き（101件目から200件目）です。

（ここに、101件目から200件目までの投稿一覧をそのまま貼ります）</div>

最後のチャンクで、初めて新着を聞きます。

<div class="prompt">続き（201件目から300件目）です。これで@pottery_studio_tsuchiの過去分は全部（300件）届きました。

（ここに、201件目から300件目までの投稿一覧をそのまま貼ります）

既読リストに無い項目を新着として、該当する投稿のIDだけを列挙してください。説明や前置きは不要です。該当が無ければ「新着なし」とだけ書いてください。</div>

材料2本×分け方2通り（100件ごと3分割・150件ごと2分割）×各2回、計8回試しました。
<mark>8回とも、仕込んだ新着2件を1件も欠かさず、他の投稿を巻き込むこともなく正しく列挙しました。</mark>
境界線のちょうど上に乗っていた3分割の回でも、結果は変わりませんでした。

### 2. 毎回「新着はある？」と聞きながら進めても崩れないか

実際の使い方により近いのは、チャンクを貼るたびに「ここまでで新着はある？」と聞いてしまうやり方
です。都度の答えが、最後の「全部まとめて」で食い違わないかを確かめました。

<div class="prompt">毎朝、監視対象の新着をまとめて報告する担当です。今日は2026-10-05です。

@pottery_studio_tsuchiの過去の投稿一覧が育って全部で300件になり、1つのメッセージに貼りきれないため、3回に分けて貼ります。

1回目（1件目から100件目）です。この中に本日（2026-10-05）付けの新着があれば、IDを教えてください。無ければ「新着なし」と答えてください。

（ここに、1件目から100件目までの投稿一覧をそのまま貼ります）</div>

<div class="prompt">続き（101件目から200件目）です。この中に本日（2026-10-05）付けの新着があれば、IDを教えてください。無ければ「新着なし」と答えてください。

（ここに、101件目から200件目までの投稿一覧をそのまま貼ります）</div>

全部貼り終えたところで、今度は過去のやり取り全体を振り返らせます。

<div class="prompt">これで@pottery_studio_tsuchiの過去分は全部（300件）届きました。ここまでのやり取りを振り返って、本日（2026-10-05）付けの新着をすべて、IDで列挙してください。説明や前置きは不要です。見つからなければ「新着なし」とだけ書いてください。</div>

こちらも材料2本×分け方2通り×各2回、計8回試しました。<mark>都度の判定でも、境界をまたいで数ターン前
に貼った新着を、最後の振り返りでも2件とも正しく挙げ続けました。</mark>「もう答えたから」と、
前に見つけた新着を最後の一覧から落とす回は0件でした。

### 3. わざと紛らわしい日付を仕込んでも拾われたか

300件を機械的に生成する過程で、過去分の中に**同じ月日で年だけ違う投稿**（例: 2025年の同じ
月日の投稿）が偶然混ざりました。これは「日付の下4桁だけ見て判定していないか」を確かめる自然な
ひっかけになりました。

```
2026-10-05: 「クーポンの使い方が分からない」(受付ID: LN-261005-1)  ← 本日付け（新着）
2025-10-05: 「メルマガ解除の依頼」(受付ID: LN-251005-1)            ← 1年前（新着ではない）
```

<mark>このひっかけを誤って新着に数えた回は、16回中0回でした。</mark>返ってきた文章の中でも
「年が違うため新着ではありません」と自分から言及した回が複数ありました。年まで含めて日付を
照合していたことがうかがえます。

## うまくいかないときの言い直し方 {: .fix }

### 境界で崩れると思っていたのに崩れなかった {: .trouble }

この実測の範囲では、分割そのものは崩れる原因になりませんでした。もし実際の自動化で新着の
見落としが起きているなら、疑う順番を変えてください。[監視の対策は100件でも効く](/recipes/backlog-scale-holds-brevity-breaks-it/)
で分かっているとおり、崩れるのは件数でも分割でもなく「簡潔にしてください」のような**書式の
指定**を対策の一文に重ねたときでした。まず書式の指定を外し、崩れが消えるかを確かめてください。

### チャンクの区切り方が分からない {: .trouble }

この記事では100件・150件という区切りを使いましたが、区切りの大きさそのものは結果を左右しません
でした。目安は「チャットの入力欄に貼って、折り返しや省略が起きない量」です。貼ってみて途中で
切れるようなら、もう少し小さい区切りに変えてください。

### 件数がもっと多い場合（1,000件・10,000件）は {: .trouble }

この記事が試したのは300件・最大3分割までです。1,000件・10,000件規模になると、チャンクの
本数そのものが増え、会話が長くなります。会話が長くなるほど、最初のほうのチャンクを正しく
覚えていられるかは、この記事では確かめていません。その規模で使う場合は、最初の1回だけ、
報告された件数と元の一覧を自分の目で見比べてください。

## 応用・次の一手 {: .next }

**この記事の結論は2つです。**①監視ログが数百件まで育ち、分割して渡す必要が出ても、境界の位置
そのものは新着の見落としを増やしませんでした。②チャンクごとに都度「新着はある？」と聞いても、
最後にまとめて振り返らせれば、数ターン前に見つけた新着を2件とも拾い続けました。

📌 **この記事が答えたのは[前の記事](/recipes/backlog-scale-holds-brevity-breaks-it/)の未測定事項の
うち「分割したときに境界で崩れるか」だけです。**件数そのものをさらに増やす話（1,000件超）、
分割の回数をさらに増やす話（5分割・10分割）は、この記事では扱っていません。

📌 **「新着が無いことの確認」に使うなら**[定期実行させたAIが「本当に動いたか」を、自分で確かめる形にする](/recipes/count-the-material-every-run/)
と組み合わせると、分割して渡した回数と、実際にAIが応答した回数が一致しているかまで確認できます。

⚠️ **この記事が実測していないこと**＝1,000件を超える規模、4分割以上の分け方、書式の指定を
分割と同時に重ねた場合の3つです。実際に監視ログを分割して渡す人は、最初の1回だけ、報告された
件数と元の一覧を自分の目で見比べてください。
