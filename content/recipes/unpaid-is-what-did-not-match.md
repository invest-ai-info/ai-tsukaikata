## これで何ができるか {: .what }

納品は済んだ。請求も出した。**では、まだ入金されていないのはどれか。**

当サイトの[作業記録から時給と偏りを出す](/recipes/hourly-rate-from-your-own-log/)は、材料の中に「納品済・未入金」という状態があることを前提にしています。**その状態がどこから来るのかは、これまで1本も書いていませんでした。**答えは単純で、**口座の明細と突き合わせて、どの明細行も付かなかった案件が「未入金」**です。<mark>未入金は名簿ではなく、突き合わせの残りです。</mark>

架空の納品記録**12件**と入金明細**9行**を**2組**作り、次の5つを仕込みました。

| 仕込み | 中身 |
|---|---|
| 同じ金額の2件 | 同じ取引先・同じ金額の案件が2件。その金額の入金は明細に1行だけ |
| 合算入金 | 2案件ぶんが1行にまとまっている（55,000＋18,000＝73,000円） |
| 差引のある入金 | 40,000円の案件に対して39,780円（差220円） |
| 月をまたぐ入金 | 6月に納品して7月に入金 |
| 本当に入金の無い1件 | その金額の入金が明細のどこにも無い |

**真値は手で書いていません。**「金額が同じ・名義が同じ・入金日が納品日より後」で整合する案件の集合をコードが総当たりで作り、1件に決まれば確定、2件以上なら決められない、どの行も付かなければ明細なし、と機械に分けさせています。頼み方を3通り、材料2組 × 各3回、**全18回**通しました。

- **材料に無い案件番号が返りに出た回は、18回とも0件**でした。作り話は起きていません
- **差220円の行に触れたのは18回とも。**合算の行に触れたのは17回
- 🚨 <mark>素で頼んだ6回は、同じ金額の2件が6回とも「未入金」の一覧の中に入りました</mark>
- 🚨 <mark class="warn">うち1回は、片方だけを未入金の表に載せて、もう片方には何も書きませんでした</mark>
- ✅ 「決められない案件は『確かめる』に分けてください」を1行足した12回は、**12回ともその2件が確かめる欄へ移り**、未入金の一覧には**入金が1行も無い1件だけ**が残りました

<mark class="warn">明細は、口座番号を伏せて「日付・摘要・金額」の3列だけ貼ってください。</mark>書類の中の口座番号やカード番号を渡さない線は[役所や保険の書類をAIに読ませる](/recipes/life-paperwork/)と同じです。この記事は**督促の文面を作る話ではありません**。出すのは一覧までで、文面は[発注者への返事を、条件を薄めずに書く](/recipes/client-reply-without-softening/)へ渡してください。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 20分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 納品の記録（案件・取引先・金額・納品日）と、口座の入金明細 |
| プログラミング | **不要**。2つの表を貼るだけです |

実測に使った材料は、次の架空の2つの表です。指示文の「下の納品の記録と、口座の入金明細」はこれを指します。

## AIへの頼み方 {: .ask }

### 1. まず素のまま頼む——判別できないことは、頼まなくても書かれる

<div class="prompt">下の納品の記録と、口座の入金明細を突き合わせます。
まだ入金されていない案件を挙げてください。</div>

**6回とも突き合わせ自体はできていました。**合算の行（73,000円）を「J-05とJ-06の合計と一致」と読んだ回、差220円を「振込手数料が差し引かれた可能性」と書いた回が、それぞれ複数あります。

🔑 **同じ金額の2件についても、6回中5回は自分から「どちらに対応するか特定できない」と書きました。**材料の中だけで決まらないことは、頼まなくても指摘されます。

🚨 <mark>同じ「特定できない」でも、それがどの欄に書かれるかは回ごとに変わります。</mark>5回は「J-02またはJ-03のどちらか」という**1行として、未入金の一覧の中**に入りました。取引先へ渡す表を作るなら、どちらの案件を書けばよいのか、この行だけでは決まりません。

### 2. 断りを書かなかった1回で、片方が表から消えた

本体の18回のうち1回だけ、「特定できない」と書かずに突き合わせを進めた回がありました。その回はこう書いています。

> みなみ工房の入金は6/10に30,000円のみ。J-02（30,000円）と同額で相殺すると、以下の2件が未入金として残ります。

そして未入金の表に並んだのは **J-03 と J-12 の2件**でした。<mark class="warn">J-02 は、表にも本文にも出てきません。</mark>

🔑 **1件の取り違えが、2件の間違いになります。**行2の入金を J-02 に当てた瞬間、J-03 は「未入金」になり、J-02 は「入金済み」になります。**どちらが正しいかは材料からは決まらないのに、表の上では決まって見えます。**

### 3. 「決められない案件は『確かめる』に」の一行を足す

<div class="prompt">下の納品の記録と、口座の入金明細を突き合わせます。
まだ入金されていない案件を挙げてください。

どの行と対応するか決められない案件は、「未入金」ではなく「確かめる」に分けてください。</div>

<mark>この一行だけで、6回とも同じ金額の2件が「確かめる」の欄へ移りました。</mark>未入金の一覧に残ったのは、**入金が1行も無い1件だけ**です（6回とも）。

📌 **合算の2件と、差220円の1件も「確かめる」へ移った回があります。**返り自身がこう書きました——「行4の73,000円が両案件の合計と一致しているため恐らく両方入金済みと思われますが、明細上は合算されており個別の消込ができません」。**入っているかどうかと、どの案件に入ったかは別の話**だと分けています。

### 4. 対応させた行番号まで書かせる

<div class="prompt">下の納品の記録と、口座の入金明細を突き合わせます。
まだ入金されていない案件を挙げてください。

どの行と対応するか決められない案件は、「未入金」ではなく「確かめる」に分けてください。

案件ごとに、対応させた明細の行番号を書いてください。同じ行番号を2つの案件に使わないでください。</div>

**6回とも、§3と同じ振り分けになりました。**加えて、1行を2案件に使った箇所を自分から断ります——「行1〜9をすべて使い切っており、同じ行番号を2案件に重複使用していません。行4のみJ-05とJ-06の合算入金として1行を2案件に対応させています」。

### 5. 明細の側から見る——付かない行を、行ごと残させる

案件の側から見ると、宙に浮いた明細行は画面から消えます。**向きを逆にします。**

<div class="prompt">下の納品の記録と、口座の入金明細を突き合わせます。

明細の各行について、対応させた案件番号を書いてください。
どの案件にも対応しない行があれば、その行の文字列をそのままコピーして最後に並べてください。</div>

**4回とも、明細9行が全部並んだ対応表が返りました。**合算の行には「2件分の合計と一致」、差220円の行には「差220円」が付きます。

⚠️ **ただし受け皿に何か入ったのは4回中1回だけ**でした。その1回は差220円の行を行ごとコピーして末尾に並べ、残る3回は「どの案件にも対応しない行：なし」と書いて、差220円の行を案件に対応させています。<mark>「対応しない行」の判定が、金額が一致しない行を含むかどうかで割れます。</mark>

🚨 <mark class="warn">向きを逆にしても、同じ金額の2件の問題は消えません。</mark>この4回のうち1回は、対応表の下の補足で片方（S-02）だけを名指しで未入金にしました。**行の側から見ても、1行を2案件のどちらに当てるかは決まらないからです。**§3の一行は、この形と一緒に使ってください。

### 6. 金額が合わない行は、差額だけ書かせる

<div class="prompt">下の納品の記録と、口座の入金明細を突き合わせます。

金額が完全に一致しない行があれば、案件の金額・明細の金額・差額の3つをそのまま書いてください。
差額が何によるものかは推測しないでください。</div>

**4回とも、差額の数字だけが返りました。**「振込手数料でしょう」と書かれた回は0回です。⚠️ 手数料なのか、値引きなのか、こちらの請求違いなのかは、**明細からは決まりません**。決めるのは自分です。

### 7. 毎月やるなら、3つの見出しに固定する

<div class="prompt">下の納品の記録と、口座の入金明細を突き合わせます。毎月この形で返してください。

【未入金】対応する明細の行が1つも無い案件。案件番号と金額だけ。
【確かめる】対応する行を1つに絞れない案件。案件番号と、候補になった行番号。
【対応表】案件番号と、対応させた行番号。

この3つの見出し以外には、何も書かないでください。</div>

**4回とも3つの見出しだけで返り、未入金は4回とも「入金が1行も無い1件」でした。**表計算ソフトへそのまま貼れます。

## うまくいかないときの言い直し方 {: .fix }

### 保存版にしたら、合算と手数料の断りが消えた {: .trouble }

⚠️ **これは実測で起きました。**§7の保存版で、片方の材料の2回は合算の2件と差220円の1件を【確かめる】に置いたのに、**もう片方の材料の2回は同じ3件を【対応表】に確定として置きました**（行4・行7）。

<mark class="warn">形を短くすると、断りを書く場所ごと無くなります。</mark>毎月の形にする前に、**別の材料でもう1回**通してください。同じことが別の題材でも起きるのは[数式を書かせると、渡した表でしか合わない](/recipes/formula-that-survives-new-rows/)にあります。

### 「未入金」に、たぶん入っている案件まで並ぶ {: .trouble }

素で頼むと起きます。§3の一行を足すか、それでも混ざるなら§5の向き（明細の側から見る）に変えてください。**どちらも、判定をやめさせて置き場所を作る形**です。

### 明細に、この一覧に無い入金が混じっている {: .trouble }

先月ぶんの入金や、副業以外の振り込みが同じ口座に入ることがあります。§5の「どの案件にも対応しない行を、行ごと並べて」がそのまま受け皿になります。<mark>付かない行が出るのは異常ではありません。</mark>付かない理由を自分で1行ずつ書き足していけば、翌月からはそこが減ります。

## 応用・次の一手 {: .next }

**毎月1回、同じ2つの表を貼るだけの形にする。**§7の指示文は中身が変わっても形が変わりません。決まった時刻に走らせる仕組みは[GitHub Actionsで、毎日決まった時刻に動かす](/recipes/github-actions-daily-cron/)にまとめてあります。

**入金の月と納品の月がずれる件は、集計の側でも起きます。**同じ行が7月と8月のどちらに入るかで数字が変わる話は[月をまたぐ集計を自動で回す](/recipes/month-boundary-double-count/)にあります。**あちらは1回の集計にどの行を入れるかで、こちらは1行が1案件にしか使えないという制約の話**です。

**手取りで見るなら、契約額ではなく振り込まれた額から始める。**差引の行をどう扱うかは[契約額から手取りを出す](/recipes/take-home-from-the-contract-amount/)と同じ問題です。

**今回の数字はすべて架空データでの実測**（材料2組 × 3通り × 各3回 ＝ 18回、後半の指示文は材料2組 × 各2回）です。⚠️ 「同じ金額の2件がどの欄に置かれたか」は、見出しの書き方が回ごとに変わるため機械では1通りに決まりません。**18回の全文を読んで分類しました。**生の返りと判定コードは `docs/evidence/unpaid-is-what-did-not-match.md` に全文置いてあります。
