## これで何ができるか {: .what }

打ち合わせのメモや業務の説明文を、AIに頼んで関係図にしてもらう——これはよくやる使い方です。ただ、できあがった図を見ても判断できないことがあります。<mark>本当に文章に書いてあった関係なのか、AIが分かりやすくするために足した関係なのか</mark>です。

この記事でやるのは、<mark>いきなり図にさせず、先に「何が → 何に → 何をする」の一覧を作らせる</mark>頼み方です。一覧なら1行ずつ、根拠になる一文を照合できます。架空の業務説明2本（経費精算の流れ・図書館の予約の流れ）で実際に試しました。すると<mark class="warn">出典の一文を引用させるだけでは、本文に無い言葉が1つ混じっていることに気づけませんでした</mark>。合計21行のうち3行（14%）で、関係に使った言葉そのものが、引用した一文の中には存在していませんでした。

<figcaption>一覧にしてから図にすると、途中の2段階（出典・言葉の確認）で機械的に照合できます。</figcaption>

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。無料のチャットAIで足ります |
| 必要なもの | ブラウザで使えるAI（ChatGPT・Claude・Geminiなど）だけ |
| プログラミング | **不要**。この記事の指示文を順番にコピーして貼るだけです |

図を描く手段（Canvas・画像生成・矢印つきの図解機能）はツールごとに違うので、この記事では主役にしません。<mark>主役は図にする前の「何と何が、どう繋がるか」という構造</mark>です。ここを一覧の形で確認してから、最後に図の構成案を作らせます。

## AIへの頼み方 {: .ask }

### 1. いきなり図にさせず、関係の一覧を作らせる

元の説明文を貼って、まず一覧化だけを頼みます。

<div class="prompt">次の説明文に出てくる関係を、1行1組の一覧にしてください。
形式は「何が → 何に → 何をする」です。
説明文に書かれていない関係は、絶対に作らないでください。

（ここに説明文を貼る）</div>

架空の経費精算の説明文（9つの関係を含む）で試すと、9行とも元の文章と対応する、筋の通った一覧が返ってきました。この段階では悪くありません。問題は、この一覧を<mark>そのまま信じてよいかどうか</mark>です。

### 2. 行ごとに、根拠の一文を引用させる

一覧の行それぞれに、裏付けとなる一文を付けさせます。

<div class="prompt">さっき作った一覧の行それぞれについて、どの一文が根拠になっているかを、説明文からそのまま引用してください。
根拠になる一文が見つからない行があれば、消さずに「出典なし」と書いてください。</div>

これを2つの架空データ（経費精算9行・図書館の予約12行）で試したところ、<mark>「出典なし」と書かれた行は合計21行のうち0件</mark>でした。AIは必ず、それらしい一文を見つけて引用してきます。ここで「全部根拠があるなら安心」と思うと、次の落とし穴に気づけません。

### 3. 一覧に入っていない関係を、自分で見つけさせる

一覧が元の説明文の全部をカバーしているかも、AIに確認させます。

<div class="prompt">説明文に出てくる関係のうち、まだ一覧に入っていないものがあれば、同じ形式で追加してください。
追加した行にも、根拠になる一文を付けてください。</div>

経費精算の材料では「説明文に含まれる関係は、既にすべて一覧に入っています」という回答でした。1回目の一覧化で、すでに完全だったということです。確かめずに「完全です」と書かず、この指示文で裏付けを取ってから次に進みます。

### 4. 引用した一文に、その言葉が本当にあるかを確認させる

ここがこの記事のいちばんの発見です。指示文2で「出典なし」は0件でしたが、<mark class="warn">引用した一文そのものを読み直すと、関係に使った言葉が実際には書かれていない行がありました</mark>。

図書館の例で見てみます。一覧の1行は「予約者 → 図書館 → 来館する」でした。根拠として引用した一文は「予約者は、メールを受け取ってから1週間以内に来館して本を受け取る必要があります。」です。

この一文のどこにも「図書館」という言葉はありません。来館先が図書館であることは文章全体を読めば明らかです。ですが<mark>この一文単体には書かれていません</mark>。

<div class="prompt">一覧の行ごとに、矢印でつないだ言葉が、引用した一文の中に実際に書かれているかを確認してください。
書かれていない言葉を使っている行があれば、その言葉を一文の中にある言葉に直すか、直せなければ行ごと削除してください。</div>

この指示文を2つの材料に試しました。経費精算では9行中2行が「申請」という、根拠文に無い言葉を使っていたため修正されました。図書館では12行中1行（「図書館」の行）が、直せる言葉が無いため削除されました。合わせて<mark>21行中3行（14%）</mark>です。「出典を引用する」工程と、「その引用に本当に書かれているかを確認する」工程は別物だと分かります。

### 5. 検品済みの一覧だけから、図の構成案を作らせる

言葉の確認が済んだ一覧を渡して、ここで初めて図にします。

<div class="prompt">この一覧だけをもとに、図の構成案を作ってください。
ノードには一覧に出てきた言葉だけを使い、矢印も一覧にある行だけにしてください。
一覧に無いノードや矢印を、新しく足さないでください。</div>

「一覧の言葉だけを使う」と縛りを明示すると、2つの材料ともノードの数・矢印の数が、検品後の一覧の行数とぴったり一致しました。経費精算は9個・9本、図書館は11個・11本です。

縛りを入れずに素朴に「図の構成案を作って」と頼んだ比較では、1本ずつ照合できる形になりませんでした。理由は3つあります。

- 分岐の記号（◇など）の提案が、関係そのものと同じ文章に混ざる
- 矢印の色分け・線の種類といった見た目の提案まで一緒に返ってくる
- 「差し戻された申請は最初の登録に戻る」という、元の説明文には無い補足が、確認できる事実と同じ調子で付いてくる

### 6. 図と一覧を、最後にもう一度突き合わせる

<div class="prompt">いま作った図の構成案のノードと矢印を、ひとつずつ、さっきの一覧の行と照らし合わせてください。
一覧に無いのに図に入っているものがあれば挙げてください。
一覧にあるのに図から抜けているものがあれば挙げてください。</div>

今回の2つの材料は、どちらも不一致ゼロでした。手順5で縛りを明示できていたからです。それでも、<mark>縛りを忘れた回の保険として、図を作らせたら必ずこの確認を挟む</mark>のが安全です。

## うまくいかないときの言い直し方 {: .fix }

### 「出典があるから正しい」と思い込んでしまう {: .trouble }

指示文2だけで止めると、「根拠の一文が付いている＝正しい」と見えてしまいます。実測ではどちらの材料も「出典なし」は0件でした。<mark class="warn">引用文が実在する一文であることと、その中に使った言葉が実在することは別です</mark>。指示文4を必ず続けてください。

### 図から直接、間違いを探そうとしてしまう {: .trouble }

図（ノードと矢印の構成案）の段階で誤りを探すのは、一覧の段階で探すより難しくなります。矢印のラベルが長くなったり、配置の都合で言葉が省略されたりするためです。<mark>照合は一覧の段階で済ませ、図は「検品済みの一覧をそのまま絵にする」だけの工程にする</mark>のが安全です。

素朴に「図の構成案を作って」と直接頼むと、分岐の記号や矢印の色分けまで1つの回答に混ざります。本文に無い推測（「差し戻しは最初の工程に戻る」など）も、同じ調子で混ざってきました。

### 一覧が長すぎて、照合が大変になる

説明文が長いと一覧も長くなります。その場合は指示文4を一度に全部ではなく、<mark>10〜20行ずつに区切って確認させる</mark>ほうが安定します。まとめて渡すほど結果が雑になることは、[同じ指示を何回もコピペしているなら、まとめて1回で頼める](/recipes/batch-instead-of-repeat/)でも触れています。

## 応用・次の一手 {: .next }

**毎回同じ種類の説明文を図にしているなら、一覧の列をテンプレート化できます。**「何が／何に／何をする／根拠の一文」の4列を決めます。説明文を貼るだけでこの4列が埋まる指示文にしておけば、次回からコピーして貼るだけです。

毎週同じ形式の報告書や議事録を図にしているなら、自動化の余地もあります。[「毎日決まった時刻に自動でやっておいて」をAIに作らせる](/recipes/github-actions-daily-cron/)と組み合わせれば、一覧の生成と検品まで自動で回せます。

この記事で使った「引用させた一文に、使った言葉が本当にあるか確認する」という考え方は、数字の確認にも応用できます。出典のURLは正しいのに、そのページにその数字が書かれていないことがあります。この別の落とし穴は[AIに数字を「それっぽく」埋めさせないための頼み方](/recipes/numbers-not-in-the-source/)にまとめました。

なお、この記事が検査しているのは**図の中身（関係が本当にあったか）**です。図の**見た目の崩れ**（文字が線を貫く・枠からはみ出す）は別の問題で、[AIに図を作らせると崩れる、を検査で止める](/recipes/catch-broken-figures/)で扱っています。軸が違うので、両方を別に確認してください。
