## これで何ができるか {: .what }

[返信待ちの仕分けは毎日そろう——新しい受け皿が1人取り違える](/recipes/sort-holds-new-bucket-slips-once/)は、受け皿を足した仕分けの指示文が「同じ材料の繰り返し」に崩れないかを調べた記事でした。その記事はこう締めくくっています——「材料そのものが毎日少しずつ更新される運用でも同じ結果になるかは、この18回では試していません」。今回はそこだけを引き継ぎました。

やったことは2つです。

- 同じ架空材料（会社の総務課）を、実際の運用のように**3日分育てた**
- 育てた材料に、**同じ受け皿分類の指示文を新規セッションで各日2回・計6回**通した

材料を育てる内容は3つです。新しい用件を足す。前日まで未解決だった行の一部に、回答が来た形へ更新する。返信不要の周知メールも日ごとに足す。結論は3つです。

1. **本体の催促一覧（6件）は、3日分のどの日も、その日の真値と6回とも完全に一致しました。**古い行が解決して消え、新しい行が未解決として増える——という日々の入れ替わりも、6回とも正しく反映されています
2. **受け皿〔一次返信のみ・本回答待ち〕も、6回とも真値と完全に一致しました。**2日目に古い1件が解決して抜け、新しい1件が入り、3日目にはその新しい1件だけが残る——という入れ替わりも、正しく追えていました
3. **ただし3日目の1回だけ、〔決められない〕に無関係の行が紛れ込みました。**紛れ込んだのは、**その日に初めて増えた「返信不要」の周知メール**です。同じ型の古い周知メールは、1日目からある2件、2日目に増えた1件とも、6回とも一度も紛れ込みませんでした

## うまくいかないときの言い直し方 {: .fix }

### 「その日に初めて増えた行」だけが、別枠に迷い込む {: .trouble }

[返信待ちの仕分けは毎日そろう](/recipes/sort-holds-new-bucket-slips-once/)は「受け皿を作ることは、仕分けを完成させることとイコールではない」ことを扱いました。今回分かったのは、別の側面です。材料が日々育つ運用では、その「別の受け皿」が増えたばかりの行をいちばん拾いやすいという側面です。

古い行の判定は、何度もやり直されたかのように安定します。増えたばかりの行には比較対象がありません。AIが型を見誤る余地が、そのぶん広くなるようです。<mark>同じ「返信は不要と書いた」という一文を持つ全社宛メールで、違いが出ました。古い3件は6回とも素通りしました。増えたばかりの1件だけ、2回中1回つまずきました。</mark>

🔑 **自動実行に置くなら、「前日までは無かった行」だけを別枠で目立たせる運用が安全です。**多くの自動化は差分（前回との違い）を既に扱っているはずです。〔決められない〕に出た行のうち、増えたばかりのものには一段高い注意を払う価値があります。

### 本体・受け皿の入れ替わりは、3日間を通じて1件も崩れなかった {: .trouble }

ここまでは崩れた話でした。<mark>本体の催促一覧と受け皿〔一次返信のみ〕は、3日分・6回を通じて、その日ごとの真値と完全に一致し続けました。</mark>

今回起きた変化は3つです。古い行が解決して消える。新しい行が未解決のまま増える。件名の違う返信が元の用件と結びつく。個別の変化は、[返信待ちの仕分けは毎日そろう](/recipes/sort-holds-new-bucket-slips-once/)や[記録の更新日を自動で書き換える](/recipes/record-date-does-not-roll-back/)で、すでに確かめられていました。**3日分を積み重ねて同時に起こしても、崩れ方が増幅することはありませんでした。**

📌 **この記事も、取り違えを完全に0にする指示文には行き着いていません。**[迷ったときの倒れ方をそろえる](/recipes/tilt-direction-per-judgment/)が扱ったのと同じです。〔決められない〕に入った行だけは、人が毎朝さっと目を通す運用にしておくのが安全です。

## 応用・次の一手 {: .next }

材料が毎日少しずつ育つ運用でも、受け皿分類の指示文は崩れにくいとわかりました。ただし「増えたばかりの行」だけは、古い行より注意が必要です。

自動実行に置くなら、[定期実行させたAIが「本当に動いたか」を自分で確かめる形にする](/recipes/count-the-material-every-run/)が使えます。材料の件数を記録し、前日からの増分だけを抜き出す仕組みです。抜き出した増分を、〔決められない〕に出た行と照らし合わせる運用が組みやすくなります。毎朝決まった時刻に走らせる仕掛けそのものは[毎日決まった時刻にAIを動かす仕掛けを作らせる](/recipes/github-actions-daily-cron/)にあります。

📌 **この記事は3日・材料A1本・各日2回（計6回）だけを測りました。**4日目以降も同じ結果になるかは、この6回では試していません。もう一方の材料（地域のお祭りの事務局）でも同じ「増えたばかりの行」問題が起きるかも、試していません。
