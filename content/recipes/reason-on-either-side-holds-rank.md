## これで何ができるか {: .what }

[先行記事](/recipes/priority-needs-a-reason-not-a-label/)で分かったことがあります。AIにタスクの優先順位づけを頼むとき、「理由の一文（なぜ重要か）」を全タスクに書けば、重大な仕事が軽い仕事より必ず先に並びます。<mark>この記事は、その理由の一文を「重大な側だけ」「軽い側だけ」に削っても同じ結果になるかを試したものです。</mark>プログラミングは要りません。

<mark>結論は「片方だけで足りた」です。</mark>試したのは2方向です。

- 重大4件だけに理由を書いて、軽い4件はラベルだけにする
- 逆に、軽い4件だけに理由を書いて、重大4件はラベルだけにする

どちらの方向も、材料2本×各2回＝4回・16組×4回＝64組ずつ、64／64（100%）で重大側が先に並びました。

| やること | 材料 | 結果（重大4件が先だった組数） |
|---|---|---|
| 全タスクに理由を書く（基準・再検証） | A・B×各2回 | 64／64（100%） |
| **重大4件だけ**理由を書き、軽い4件はラベルのみ | A・B×各2回 | 64／64（100%） |
| **軽い4件だけ**理由を書き、重大4件はラベルのみ | A・B×各2回 | 64／64（100%） |

**この記事は、AIに実際にタスクを並べ替えさせた実測の記録です。**架空のタスク一覧を使っており、特定の会社の実例ではありません。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料 |
| 必要なもの | 特にありません。チャットAIに一覧を貼るだけです |
| プログラミング | **不要** |

この記事は、[先行記事](/recipes/priority-needs-a-reason-not-a-label/)の続きです。先行記事は「理由文がある材料」と「全タスクをラベルだけにした材料」の2つを比べ、後者で順位が完全に逆転すると示しました。<mark class="warn">ただし先行記事は、理由文を全部残すか全部消すかの二択でした。</mark>「重大な4件にだけ理由を書けば十分では」という疑問に、先行記事の本文は答えを残していません。

この記事が試すのはその1点だけです。**中間12件の理由文はどの条件でも変えていません。**動かしたのは、重大4件・軽い4件のうちどちらに理由を残すかだけです。

## AIへの頼み方 {: .ask }

材料は先行記事と同じ架空タスク一覧2種類です（材料A＝総務・経理、材料B＝ネットショップ運営）。各20件の内訳は次のとおりです。

- **重大4件**（TB系／SB系）: 締切は先だが、遅れると重大な影響が出ると本文に書いた仕事
- **軽い4件**（TA系／SA系）: 締切は近いが、遅れても実害がないと本文に書いた仕事
- **中間12件**（TF系／SF系）: 締切・重要度とも中間的な仕事

指示文は先行記事とまったく同じ文字列を使いました。**変えたのは材料側だけです。**各回は独立した新規セッション（`claude --safe-mode --tools ""`）で実行しました。前の回の結果は参照できません。

## うまくいかないときの言い直し方 {: .fix }

### この実測は「全部ラベル」までは試していない {: .trouble }

この記事が動かしたのは、重大4件と軽い4件のうち**どちらか一方だけ**です。中間12件は、どの条件でも理由文を残したままでした。<mark class="warn">先行記事の「両方ともラベルだけにすると逆転する」という結果は、中間12件までラベルに変えた材料で出たものです。</mark>この記事の結果から「中間12件も含めて全部ラベルにしてよい」とは言えません。全部をラベルにする場合は、先行記事の結果（逆転する）のほうが当てはまります。

### 4件のうち一部だけに理由を書いたらどうなるか {: .trouble }

これも、この記事では試していません。<mark class="warn">重大4件のうち2件だけに理由を書き、残り2件はラベルのままにしたらどうなるかは未確認です。</mark>理由を書く手間を「オール・オア・ナッシング」からどこまで削れるかは、次に試すことの1つとして残します。
