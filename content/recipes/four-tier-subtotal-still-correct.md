## これで何ができるか {: .what }

<mark>集計欄が小計・中計・大計・総合計の4段になっても、今回の実測では数式が崩れませんでした。</mark>材料は2つです。店舗別売上表（地域ブロック→エリア→店舗の3階層）と、部門別経費表（事業部→部署→担当者の3階層）です。それぞれに4段の数式を作らせました。

- **自由に数式を選ばせた場合**——材料2種×5回=10回とも、小計・中計・大計・総合計の4段すべてが正しい数式でした
- **SUBTOTAL関数を禁じても**——2回とも崩れませんでした
- **「自分自身を含めない」という注意書きを外しても**——2回とも自分から二重計上を避ける形を選びました
- <mark>**同じ指示文でも、選んだ数式の方式は材料によって割れました**</mark>——店舗別売上表はSUMIFS系が5回中4回、部門別経費表はSUBTOTALが5回中5回でした
- **参考**——同じ問いを3段構造で試した[既存記事](/recipes/three-tier-subtotal-still-correct/)でも、最下位の段は10回中10回正しい数式でした

<mark class="warn">「4段にしても絶対に崩れない」という意味ではありません。</mark>試したのは架空データの2種・合計14回の範囲です。段数の深さそのものより、**その回にAIがどの方式を選ぶか**のほうが結果を左右すると考えられます。

この記事は[集計欄が3段でも数式は全問正解](/recipes/three-tier-subtotal-still-correct/)の続きです。あちらは2階層＋3段で、本文が自ら「階層は3段まで(4段以上は試していません)」と書いて終わっていました。その4段を実際に作って試したのが今回です。関連する実測に[集計表の合計欄は、データの右に置く](/recipes/formula-subtotal-goes-beside-not-below/)・[集計欄が2段でも、危ういのは小計欄](/recipes/grand-total-survives-subtotal-does-not/)もあります。

## AIへの頼み方 {: .ask }

### 1. 全国チェーンの店舗別売上表で試す（地域ブロック→エリア→店舗の4段）

架空の店舗別売上表を用意しました。既存記事の3階層（関東・関西・中部の3エリア×各2店舗×3日分）に、もう1段「地域ブロック」を足しています。東日本ブロックには関東エリアだけが入ります。西日本ブロックには関西・中部の2エリアが入ります。空欄は4種類あります。店舗の小計欄（6か所）・エリアの中計欄（3か所）・地域ブロックの大計欄（2か所）・全社の総合計欄（1か所）です。

<div class="prompt">小計欄・中計欄・大計欄・総合計欄のどれも、それぞれ自分自身を範囲に含めない形で、かつ行が増えても直さなくていい数式にしてください。</div>

**5回のうち4回は、SUBTOTALを使わずに「ラベル名で作り直す」方式を選びました。**仕組みは次の2点です。

- キー列（店舗名・エリア名・地域ブロック名）と区分列（「売上」「〇〇店小計」「〇〇中計」のような末尾）を、ワイルドカードで絞り込む
- `SUMIFS(E$1:INDEX(E:E,ROW()-1), キー列, キー値, 区分列, "条件")` という形で、各階層を直下の階層だけから作り直す

**残り1回はSUBTOTALの累積範囲**（`=SUBTOTAL(9,E2:E10)` のように、終点を自分の1行上に揃えて重ねていく形）でした。5回とも、店舗の小計6個・エリアの中計3個・地域ブロックの大計2個・全社の総合計1個、計12個の数式が正しいことを確認しました。判定はPythonによる機械判定です。

### 2. 同じ指示文を、部門別経費表でも試す（事業部→部署→担当者の4段）

材料を部門別経費表に替えました。フロント事業部・バックオフィス事業部の2事業部、3部署×各2担当者、担当者ごとに3費目です。同じ指示文を試しました。

<div class="prompt">小計欄・中計欄・大計欄・総合計欄のどれも、それぞれ自分自身を範囲に含めない形で、かつ行が増えても直さなくていい数式にしてください。</div>

**今回は5回とも、SUBTOTALの累積範囲を選びました。**店舗別売上表とは逆の結果です。店舗別売上表と合わせると、材料2種×5回=10回・計120個の数式チェックです。すべて正しい一方で、**どちらの方式を選ぶかは材料によって割れました**。この記事の仮説（4段にすると最下位の段がさらに崩れやすくなる）は棄却します。

## うまくいかないときの言い直し方 {: .fix }

### SUBTOTAL関数を使わせたくないとき {: .trouble }

部門別経費表では5回ともSUBTOTALを選んでいたので、その関数を封じても同じ結果になるか確かめました。

<div class="prompt">SUBTOTAL関数は使わずに、SUM関数とSUMIF関数（またはSUMIFS関数）だけで、小計欄・中計欄・大計欄・総合計欄のどれも自分自身を範囲に含めない形で、行が増えても直さなくていい数式にしてください。</div>

**2回とも、値としては正しい数式にたどり着きました。**明細の絞り方は2回で違いました。

- 1回目：区分名が「〇〇計」で終わらない行だけを拾う条件（`"<>*計"`）
- 2回目：キー列（事業部・部署・担当者）の一致だけ

どちらも、上位の階層はラベル名のワイルドカードで下位の計だけを足す形でした。<mark>SUBTOTALという便利な関数を封じても、この2回では崩れませんでした。</mark>

### 「自分自身を含めない」の一文を外したいとき {: .trouble }

縛りの一文自体が結果を左右しているのか、外して確かめました。

<div class="prompt">小計欄・中計欄・大計欄・総合計欄に入れる数式を作ってください。</div>

**2回とも、明細行はSUM、上位の階層は「下位の計のセルをそのまま足す」形**を自分から選び、崩れませんでした（例：`営業部中計=田中小計+佐藤小計`、`フロント事業部大計=営業部中計`）。1つしかない階層（東日本ブロックのエリアは関東のみ）では、足すのではなく1つのセルをそのまま参照する形でした。この材料では、注意書きの一文が無くても結果は変わりませんでした。

## 応用・次の一手 {: .next }

**地域ブロックに含まれるエリアの数が1つと2つで違うことが、数式の作り方に影響するかも聞いてみました。**

<div class="prompt">この表では、地域ブロック「東日本」にはエリアが「関東」の1つしかなく、地域ブロック「西日本」にはエリアが「関西」「中部」の2つあります。大計の数式を作るとき、ブロックに含まれるエリアの数が1つと2つで違うことは、数式の作り方に影響しますか。理由も教えてください。</div>

1回だけ試した結果ですが、**SUBTOTAL方式ではエリア数の違いは式の形に影響せず、範囲が変わるだけ**だと正確に説明しました。一方で「中計のセルを直接足し合わせる方式」だとエリア数がそのまま項数になり、エリアが増えると式の修正が要ると自分から指摘しました。SUBTOTALを推奨する理由として筋が通っています。

**地域ブロックやエリアの増減があっても崩れない保守の手順も聞きました。**

<div class="prompt">毎月、新しい地域ブロックが追加されたり、既存の地域ブロックに新しいエリアが追加されたりします。集計表の小計・中計・大計・総合計の数式を、そのたびに直さなくていいように保守したいです。プログラミングはできません。私が新しいエリアや地域ブロックを追加するときにやることを、番号を振って箇条書きで教えてください。</div>

骨格は3段構造の既存記事と同じでした。各合計行の直上に空白の「余白行」を置き、挿入はその余白行の上で行います。新しく出てきたのは、**表の外で別の合計（例：区分が「売上」の行だけをSUMIFで合計）を作り、全社総合計と一致するか確かめる**という検算の手順です。段数が増えるほど、どこで崩れたかを目で追いにくくなることへの対策として筋が通っています。

⚠️ **この結果は、この2種類の架空データ・合計14回の実測です。**「AIは集計表を何段にしても絶対に崩れない」と一般化しないでください。試したのは、次の範囲までです。

- 階層は4段まで（5段以上は試していません）
- 各段の呼び方（小計・中計・大計・総合計）を指示文にそのまま書いた場合だけ
- 材料はいずれも18明細・30行程度の小さな表（数百行規模の実データは試していません）
- 1つの地域ブロックに1エリアしかない・もう一方に2エリアあるという、意図的に不均等な構造

3段構造でも2段構造でも試した同じ指示文で、今回もすべて正しいという結果でした。この事実を踏まえると、**別の日・別のセッションで試したら違う結果になる可能性があります。**返ってきた数式は、行を1つ足して合計が動くかを自分の目で確かめてください。
