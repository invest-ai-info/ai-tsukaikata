## これで何ができるか {: .what }

[待ち行列の止まった行を週1回で数える](/recipes/fresh-easy-row-throws-off-the-stuck-count/)は、資料が届かない行（詰んだ行）を週1回数える実験でした。ただし測ったのは10日後まで。記事自身が「資料が永久に届かない行が、1か月・3か月でどこまで積み上がるかは測っていません」と明記しています。

この記事はそこを測ります。架空の問い合わせ待ち行列を**30日後・90日後**まで伸ばし、詰んだ行が**11件・31件**に増えた状態を作りました。前作と**まったく同じ2つの聞き方**を、新規セッションに2回転×3回＝6回ずつ試しました。

<img src="/static/images/stuck-rows-hold-the-count-at-scale-hit-and-miss.svg" alt="資料の中身を条件にした聞き方と、開いた聞き方の正答率を、30日後と90日後で比べた表。資料の中身を条件にした聞き方は30日後（正解11件）・90日後（正解31件）とも6/6で緑。開いた聞き方は30日後・90日後とも0/6で赤。下の枠には、資料の中身を条件にした聞き方は詰んだ行が11件から31件に増えても6回とも正しい件数に合ったこと、開いた聞き方は規模が変わっても6回とも資料はあるが未着手の行を詰んだ行と同じ数に数え、答えが真値より常に5件・15件多かった（16件・46件）ことが書かれている。">
<figcaption>資料条件の聞き方は6/6のまま。開いた聞き方は0/6のまま。</figcaption>
</figure>

分かったことは2つです。

**① 正しい聞き方は、規模が3〜8倍になっても崩れませんでした。**<mark>詰んだ行が11件→31件に増えても、「資料の行が『（取得できませんでした）』になっている行だけを数えて」という聞き方は6回とも正しい件数に合いました</mark>。前作の10日後（正解3〜4件）と合わせると、3件→4件→11件→31件の4水準すべてで崩れていません。

**② 外れ方のクセが変わりました。**前作（10日後）は、開いた質問が**12回中5回しか合わない**という、位置によって当たり外れが分かれる不安定な壊れ方でした。規模が大きくなると様子が変わります。<mark class="warn">開いた聞き方は30日後・90日後とも6回中6回、毎回同じ分だけ多く数えました</mark>（30日後は真値11件に対し16件、90日後は真値31件に対し46件）。たまたまの巻き込みではなく、「資料はあるが未対応の行」も含めて数えるという一貫した解釈に落ち着いたためです。

## AIへの頼み方 {: .ask }

### 1. 30日後・90日後の待ち行列を用意する

前作と同じ到着パターン（3日に1回・資料なしの問い合わせが届く）を、30日・90日ぶんまで延ばしました。

| | 全行数 | 詰んだ行（資料なし） | 資料あり・未対応 | 済・保留 |
|---|---|---|---|---|
| 30日後 | 40行 | **11件** | 5件 | 24件 |
| 90日後 | 100行 | **31件** | 15件 | 54件 |

「詰んだ行」とは、資料そのものが届かず、どう頑張っても処理できない行です。「資料あり・未対応」は、回答の材料はそろっているのに、まだ返信していないだけの行です。この2つを混同しないことが、この記事の核心です。

### 2. 開いた質問をそのまま聞くと、やっぱり外れる

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、今すぐ自分で動かないと止まったままになる行が何件あるか、その内容も含めて教えてください。</div>

30日後・90日後それぞれの待ち行列全文を、**新規セッション**に2回転×3回＝6回ずつ渡しました。

| | 30日後（正解11件） | 90日後（正解31件） |
|---|---|---|
| 報告された件数 | 16件（6回とも） | 46件（6回とも） |

<mark class="warn">開いた質問は、6回とも同じ数で外れました。</mark>内訳を見ると、どの返りも2種類の行を区別していました。「資料が取得できず回答の材料がない行」と「資料はあるが未対応の行」を、それぞれ正しく分けて数えています。それでも見出しの先頭では、その合計を「今すぐ動かないと止まる件数」として報告していました。**つまりAIは数え間違えていません。質問の言葉自体が、2種類の行をどちらも「止まったまま」に含めてよい形になっています。**

<figure class="figure">
<img src="/static/images/stuck-rows-hold-the-count-at-scale-gap.svg" alt="詰んだ行の真値が30日後11件・90日後31件に増えても、開いた聞き方のはみ出しが資料ありの未着手行の数と常に一致することを示す積み上げ棒グラフ。30日後は資料の中身を条件にした聞き方が11件、開いた聞き方は11件＋はみ出し5件で16件。90日後は資料の中身を条件にした聞き方が31件、開いた聞き方は31件＋はみ出し15件で46件。はみ出しは、資料はあるがまだ処理していない行の数と常に一致し、規模が3倍になっても0件や2件に固定されるわけではなかった。">
<figcaption>はみ出しは「資料あり・未対応」の行の数と、常にぴたり一致します。</figcaption>
</figure>

### 3. 資料の中身を条件にすると、規模が変わっても狂わない

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、資料の行が「（取得できませんでした）」になっている行だけを数えてください。資料がすでにあって未返信なだけの行や、済・保留の行は数えないでください。</div>

同じ2つの規模・同じ6回ずつで試しました。

| | 30日後（正解11件） | 90日後（正解31件） |
|---|---|---|
| 正答率 | **6/6** | **6/6** |

詰んだ行は11件→31件に増えました。<mark>それでも資料の中身を条件にしたこの聞き方は、6回とも正しい件数に合いました。</mark>前作の10日後（12回中12回）と合わせると、3〜4件から31件まで、どの規模でも崩れていません。

### 4. 詰んだ行だけを、別の一覧に抜き出す

90日分も貯め込んでしまうと、週1回の確認は「件数」だけでは足りません。詰んだ行がどれなのか**実際の内容**を知りたくなります。

<div class="prompt">下は、問い合わせ対応の待ち行列です。資料が「（取得できませんでした）」になっている行だけを、同じ書式のまま別の一覧として書き出してください。それ以外の行は、今回は書き出さなくてよいです。</div>

90日後（詰んだ行31件／全100行）の状態に、2回転×3回＝6回試しました。

書式は「- [!] ◯◯様：...」とその次の行の「資料: ...」です。<mark>6回とも、31件を1件の欠落・1件の誤混入もなく、もとの書式のまま抜き出しました。</mark>100行の中から31件だけを選び出す作業でも、崩れは起きませんでした。

## うまくいかないときの言い直し方 {: .fix }

### すでに運用している待ち行列に、今すぐ足したい {: .trouble }

全体を書き直す必要はありません。週1回の確認のときだけ、3番の指示文を使ってください。

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、資料の行が「（取得できませんでした）」になっている行だけを数えてください。資料がすでにあって未返信なだけの行や、済・保留の行は数えないでください。</div>

📌 **「資料: （取得できませんでした）」という決まった書き方を、自分の待ち行列にも使ってください。**書き方がそろっていないと、AIが「中身を見て判断する」側に戻ってしまいます。

### 「止まったままの行は何件？」とだけ聞いてしまう {: .trouble }

2番の壊れ方です。

<div class="prompt">下は、問い合わせ対応の待ち行列です。週に1回だけ目を通すとして、今すぐ自分で動かないと止まったままになる行が何件あるか、その内容も含めて教えてください。</div>

<mark class="warn">開いた質問は、規模が大きくなるほど「外れ方が安定する」だけで、正しくはなりません。</mark>件数だけ見ると「毎回16件・46件だから、むしろ安定していて使える」と思いたくなりますが、それは真値に対して常に5件・15件多い数字です。**数える条件を、資料の中身という1点に絞ってください。**

### 詰んだ行が多すぎて、一覧が読みにくい {: .trouble }

4番の指示文で、詰んだ行だけを別出しできます。

<div class="prompt">下は、問い合わせ対応の待ち行列です。資料が「（取得できませんでした）」になっている行だけを、同じ書式のまま別の一覧として書き出してください。それ以外の行は、今回は書き出さなくてよいです。</div>

📌 **抜き出した一覧は、資料が実際に届いた時点で元の待ち行列へ戻す運用に向きます。**毎週の確認で「新しく詰んだ行」と「前から詰んでいる行」を分けたいときは、抜き出した一覧に日付を添えてください。

## 応用・次の一手 {: .next }

**手で1回やって良かったものを、置き場所と時刻を決めて自動にする**——この記事はその運用を**90日ぶん**まで延ばして確かめた形です。

1. [やることリストをAIに毎日1件ずつ進めさせる](/recipes/queue-done-marks-that-survive/)で、待ち行列を毎日1件ずつ進める形を決める
2. [毎日決まった時刻にAIを動かす仕掛けを作らせる](/recipes/github-actions-daily-cron/)で、時刻を決めて置く
3. **週1回、この記事の3番の指示文で確認する。**開いた質問ではなく、資料の中身を条件にする
4. **詰んだ行が目に見えて増えてきたら、4番の指示文で別の一覧に抜き出す**

⚠️ **3番を「件数だけ毎回同じだから、開いた質問でもいい」に差し替えないでください。**規模が大きくなるほど外れ方が安定して見えますが、それは真値ではありません。**何が本当に止まっているかは、資料の中身を見るしかありません。**

📌 **この記事が実測していないこと**＝90日を超えた先と、連鎖実行そのものの90日ぶんの再実測です。

- 30日後・90日後の待ち行列そのものは、前作が10日間の実際の連鎖実行で確かめた挙動（毎日1件ずつ処理し、処理できない行は資料なしのまま残る）をもとに、同じ到着パターンをそのまま延ばして作りました
- 週1回の確認は、どちらの規模も実際にAIへ6回ずつ試しています
- 100日を大きく超えて育て続ける場合や、詰んだ行を別出しする運用を何度も繰り返した場合までは、この記事では測っていません
