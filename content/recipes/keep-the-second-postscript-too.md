## これで何ができるか {: .what }

<mark>募集文の追記欄に、本題に近い話題と遠い話題の2つが並んでいるとき、提案文に残るのはどちらかを見分けられるようになります。</mark>[前作](/recipes/postscript-lands-only-if-topic-is-close/)は、追記を1つだけ仕込んで、話題が近いか遠いかで拾われ方が変わることを確かめました。今回はその2つを同じ追記欄に並べたらどうなるかを試しました。

架空の募集文2種（①サイトのリニューアル②動画ナレーション）の追記欄に、次の2文を同じ括弧の中に並べました。

- **近い話題**：サイトのフォーム不具合／動画の字幕の不具合
- **遠い話題**：展示会での対応が分かりにくい（両材料でそろえた）

**近い話題は2材料とも10/10が本文に残りました。遠い話題は2材料とも10/10が本文から消えました。**消えた遠い話題は、書き手向けの申し送り（相手に送る本文の外）にだけ「範囲外のため触れていません」と残っていました。本文だけをコピーして送れば、遠い話題は影も形もありません。

<mark class="warn">前作では遠い話題だけを単独で追記すると、材料2（動画ナレーション）は6回中3回拾っていました。</mark>今回、近い話題と同じ追記欄に並べただけで、その3/6が0/5まで落ちました。この2つの架空の募集文・全20回での実測です。確かめていないことは、記事の最後にまとめます。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 特にありません。募集文を読んで提案文を書かせる場面の話です |
| プログラミング | **不要**。この記事の指示文をコピーして貼るだけです |

<mark class="warn">この記事は「採用率が上がるか」を測ったものではありません。</mark>測ったのは「AIが追記欄の2つの話題を、どちらも拾うかどうか」だけです。実際に提案文を送るときは、拾われた内容が事実として正しいか、相手に失礼にならないかを必ず自分で確認してください。

[前作](/recipes/postscript-lands-only-if-topic-is-close/)は「話題が近ければ拾い、遠いと拾わない」という結果でした。本文はこう締めくくっていました。「追記が2つ以上ある場合（今回は1つだけ）」は確かめていない、と。この記事はその宿題に答えます。応募文づくり全般は[実績を盛らずに提案文を組む記事](/recipes/proposal-without-inflating/)も参考にしてください。

## AIへの頼み方 {: .ask }

### 1. サイトのリニューアル募集に、2つの追記を並べて頼む

前作と同じ架空の募集文（会社紹介ページのリニューアル、医療用検査機器の輸入卸業という設定）を使います。末尾の追記欄に、近い話題と遠い話題を同じ括弧の中に2文として並べました。

> （追記：話は変わりますが、前回のサイトは、お問い合わせフォームを送信しても完了画面が表示されないという声が社内からありました。前回参加した展示会では、案内係の対応が分かりにくいという声もお客様からありました。）

<div class="prompt">次の募集文を読み、この募集に応募する提案文を書いてください。

【募集文】
（ここに募集文を貼る）</div>

**5回試して、5回とも近い話題（フォームの不具合）は提案文の本文に組み込まれました。**確認事項や対応内容のひとつとして、自分から取り込んでいます。

> 以前のサイトで、送信後に完了画面が表示されないというお声があったと拝見しました。フォームを扱う場合は、送信完了の画面表示と、送信後の動作確認も作業に含めたいと考えています。

**一方、遠い話題（案内係の対応）は5回とも本文には一語も出ませんでした。**5回とも、本文のあと（相手に送らない前提の「補足」や注記）でだけ触れていました。

> 募集文末尾の追記のうち、お問い合わせフォームの件は今回の制作に関わるため、確認事項2に入れました。展示会での案内係の件は、サイト制作とは関係が薄いので触れていません。

**本文をそのままコピーして送れば、この除外の説明ごと相手には届きません。**遠い話題は、黙って消えたように見えます。

### 2. 動画ナレーションの募集でも、同じ形になるか確かめる

> （追記：話は変わりますが、前回の動画は、字幕の表示が速すぎて読み切れないという声がありました。前回参加した展示会では、受付の対応が分かりにくいという声もお客様からありました。）

【募集文】
（ここに募集文を貼る）</div>

**近い話題（字幕の不具合）は5回とも本文に組み込まれました。**見出しを立てて対応を列挙した回もありました。

> 前回の動画で字幕が速すぎたとのことでしたので、今回は詰め込みすぎず、ナレーターが余裕をもって読める分量とテンポにします。

<mark class="warn">**遠い話題（受付の対応）は5回とも本文から消えました。**</mark>材料1と同じ形です。4回は本文のあとで「依頼範囲外のため触れていません」と明示し、**残る1回は言及そのものがどこにも出ませんでした**（除外の説明すら書かれませんでした）。

🔑 **前作との違いはここです。**前作で材料2（動画ナレーション）は遠い話題を単独で追記すると6回中3回拾っていました。今回、近い話題と同じ追記欄に並べただけで、その3/6が**0/5**まで落ちています。材料によって強さが違っていた「拾う/拾わない」が、2つを束ねると材料によらず一律ゼロになりました。

### なぜこの言い方が効くのか

**AIは追記の2つの話題を見比べ、近いほうだけを本題の一部として扱い、遠いほうを「書き手への申し送り」に格下げしていました。**除外した理由も自分から正しく言語化しています——「サイト制作とは関係が薄い」「依頼範囲外」。判断そのものは的確です。問題は**その判断の置き場所**です。

このサイトでは[AIが自分から付けた警告は、本文の外に付くと届かない](/recipes/reply-drafts-without-deciding/)という現象を何度か確かめてきました。今回も同じ構図です。遠い話題への言及は消えたのではなく、**本文の外（相手が読まない場所）に移動していました。**本文だけを読む人には、最初から話題が無かったように見えます。

## うまくいかないときの言い直し方 {: .fix }

### 遠い話題を、本文の中に戻したいとき {: .trouble }

<mark>効いたのは「依頼主が本当に困っていそうなことも考えてください」と1文足すことでした。</mark>前作の言い直し方と同じ一文を、2文入りの追記欄のまま足します。材料1（サイトのリニューアル）で3回試しました。

【募集文】
（ここに募集文を貼る）</div>

**3回とも、遠い話題（案内係の対応）が本文の中に出てくるようになりました。**0/5から3/3への変化です。

> 展示会で案内が分かりにくかったというお話も、お客様にとっての「分かりにくさ」という点で同じ課題だと感じました。サイトの制作範囲外ですが、ご希望があれば、展示会で配れるQRコード付きの案内や、来場者向けの簡単な案内ページを追加でご提案できます。

<mark class="warn">**ただし、3回とも「範囲外ですが」という留保がつきました。**</mark>近い話題のように無条件で作業に含めた回は、3回のうち0回でした。

同じ一文を、材料2（動画ナレーション）にも3回試します。

<div class="prompt">次の募集文を読み、この募集に応募する提案文を書いてください。依頼主が本当に困っていそうなことも考えてください。

【募集文】
（ここに募集文を貼る）</div>

**こちらも3回とも、遠い話題（受付の対応）が本文に戻りました。**しかし3回とも「依頼範囲外」「任意」の留保つきです。

> また、受付の対応が分かりにくかったというお声については、動画の最後に「ご来場のお客様へ」の一言を入れる案も出せます。

合わせて**6回とも、遠い話題は無条件の作業ではなく、任意の付帯提案の形に収まりました。**🚨 **「本文に戻った」と「近い話題と同格になった」は別のことです。**この一文は遠い話題を相手の目に触れる場所まで引き戻しましたが、依頼として受けるかどうかの判断は読者に残ったままです。見積りに含めるかどうかは、結局こちらが確認して決める必要があります。

【募集文】
（ここに募集文を貼る）</div>

**2回とも、遠い話題は近い話題とまったく同じ見出し・箇条書きの形式で本文に入りました。**「① お問い合わせフォームの完了画面」「② 展示会での案内係の対応」のように番号も形もそろえています。<mark>それでも、2回とも「こちらはウェブデザインの範囲外の課題と理解していますが」という留保は残りました。</mark>

> 追記の2点は、どちらも本文で同じ分量・見出しの扱いにしました。ただし②の展示会の案内係の件は、サイト制作の範囲外です。

同じ一文を、材料2にも2回試します。

【募集文】

**2回とも、形式がそろうだけでなく、留保語が完全に消えました。**「範囲外」「任意」という語は一度も出ず、こう書いた回もありました。

> この2点は、どちらも原稿の完成度に関わると考え、同じ優先度で取り組みます。

🔑 **同じ指示文・同じ強さの言い直しでも、材料によって留保が消えるかどうかが割れました。**考えられる理由は、話題どうしの実際の近さです。材料2の遠い話題（展示会の受付対応）は、動画そのものが流れる展示会の一部なので、ナレーション原稿の仕事と地続きに見えます。材料1の遠い話題（展示会の案内係）は、サイト制作という仕事とはやはり別物です。<mark class="warn">担当が「近い／遠い」と決めたラベルと、AIが実際に感じ取る業務の近さは、同じではありませんでした。</mark>

## 応用・次の一手 {: .next }

**自分が募集文・依頼文を書く側でも応用できます。**本当に伝えたい前提が2つ以上あるなら、ひとつの追記にまとめて済ませないでください。今回の実測では、近い話題と同じ括弧に入れただけで、遠い話題は単独のときより拾われにくくなりました。[本題に近い話題だけを拾う前作](/recipes/postscript-lands-only-if-topic-is-close/)と合わせて読むと、**追記は「ついでに書く」場所ではなく、「本題に近い1件だけを書く」場所だと分かります。**他に伝えたいことがあるなら、別の文として本題と同じ位置に書くか、「以下も必ず確認してください」と名指しで頼んでください。

情報の「置き場所」が結果を左右するという同じ性質は、[材料に無い情報を先に挙げさせる記事](/recipes/ask-what-is-missing-first/)でも確かめています。

⚠️ **この結果は、この2つの架空の募集文・のべ20回での実測です。**次の範囲は確かめていません。

- 追記が3つ以上ある場合（今回は2つまで）
- 近い話題どうし・遠い話題どうしを2つ並べた場合（今回は近い1つ・遠い1つの組み合わせだけ）
- 「同じ重みで反映して」でも留保が残るかどうかは、話題の実際の近さ次第で変わるらしいという観察までで、どんな話題の組み合わせでも同じになるとは確かめていません

伝えたいことが複数あるなら、「2つとも追記にまとめれば両方届く」とは考えず、本当に大事なことは本題の近くか、名指しの一文で渡してください。それでも確実に同格で扱わせたいなら、「同じ重みで」まで書いたうえで、返ってきた文面に留保が残っていないかを自分の目で確認してください。

今回の生の返り20回ぶんと判定コードは `docs/evidence/keep-the-second-postscript-too.md` に全文置いてあります。
