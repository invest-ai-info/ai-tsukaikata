## これで何ができるか {: .what }

<mark>分割払いの入金照合は、分割の回数が2回から3回に増えても崩れませんでした。</mark>架空のリフォーム工事12件・結婚式場12組を用意しました。どちらも一括6件・2回払い3件・3回払い3件が混在しています。同じ指示文を材料2種×5回＝10回試しましたが、2回払い・3回払いのどちらを誤って「未入金」扱いした回も0回でした。

<mark class="warn">ただし「3回払いなら絶対に崩れない」という意味ではありません。</mark>この材料・この回数（合計21回）で試した範囲の結果です。本文の最後に、確かめていないことも書いておきます。

## 前提 {: .need }

|---|---|
| かかる時間 | 20分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 請求（契約）一覧と、入金明細の2つの表 |
| プログラミング | **不要**。この記事の指示文をコピーして貼るだけです |

<mark class="warn">口座番号や実在の顧客名は貼らないでください。</mark>入金明細は日付・氏名・金額の3列だけにしてください。この記事は架空の氏名・金額を使っています。実在の人物・団体とは関係ありません。

分割払いの入金照合そのものの基本的な挙動は[分割払いの入金照合を実測した記事](/recipes/installment-payments-add-up-correctly/)にあります（本当に一部だけ未収のケース・摘要が読み取れない入金の扱いなど）。件数が増えたときの精度は[予約件数を3倍にした実測](/recipes/installment-scale-does-not-increase-misses/)にあります。この記事が見ているのは「1件あたりの分割回数が2回から3回に増える」という、そのどちらとも違う軸です。

## AIへの頼み方 {: .ask }

### 1. まずリフォーム工事の請求データで素朴に聞く

架空のリフォーム工事12件（一括6件・2回払い3件・3回払い3件、**全件入金済み**）を用意しました。

<div class="prompt">まだ入金されていない工事はどれですか。1件が複数回に分けて入金されることがあります。合計額が工事金額と一致するかどうかも確認してください。</div>

上に続けて、請求一覧と入金明細を貼ります。

**5回とも「未入金の工事はありません」と正しく答えました。**2回払いの3件（渡辺様・伊藤様・山本様）も、3回払いの3件（鈴木様・田中様・木村様）も、誤って未入金扱いした回は0回です。3回払いの案件では、着手金・中間金・完成金の3回ぶんをすべて拾って合計する必要がありましたが、5回とも過不足なく計算していました。

### 2. 同じ指示文を、結婚式場のデータでも試す

業種が変わっても同じ結果になるかを見るため、架空の結婚式場（申込金・中間金・最終金の分割）でも同じ実験をしました。指示文だけ言葉を合わせています。

<div class="prompt">まだ入金されていないご家族はどれですか。1件が複数回に分けて入金されることがあります。合計額が請求額と一致するかどうかも確認してください。</div>

**こちらも5回とも「未入金のご家族はありません」と正しく答えました。**リフォーム工事の実験と合わせて、2種類の材料・合計10回を通じて、分割が3回に増えても誤判定は出ていません。

### 3. 対応する入金明細まで書かせる

根拠まで書かせる言い方も試しました。3回払いの案件では、3件の明細を1件も取りこぼさずに対応づけられるかが焦点です。

<div class="prompt">まだ入金されていない工事はどれですか。どの入金明細（日付・金額）が対応するかを、工事ごとに書いてください。同じ入金明細を2つの工事に使い回さないでください。</div>

**3回とも、3回払いの3件それぞれに着手金・中間金・完成金の3行を正しく対応させました。**2件だけ拾って「完了」と早合点した回や、明細を使い回した回は0回です。2回は入金明細の総数（21件）と必要件数（一括6＋2回払い3×2＋3回払い3×3＝21）が一致することまで自分から検算していました。

## うまくいかないときの言い直し方 {: .fix }

### 本当に1回分だけ足りないとき {: .trouble }

ここまでは「全員入金済み」という材料でした。今度は、3回払いの1件だけ本当に最後の1回（完成金）が届いていない状態を作りました。指示文は1文字も変えていません。

<div class="prompt">まだ入金されていない工事はどれですか。1件が複数回に分けて入金されることがあります。合計額が工事金額と一致するかどうかも確認してください。</div>

**3回とも、未入金の1件（木村様・完成金1,280,000円）だけを正しく指摘しました。**他の11件を誤って未入金扱いした回は0回です。着手金・中間金の2回分（合計1,920,000円）が届いている状態を「もう完了した」と早合点した回もありませんでした。

### 真ん中の回だけ抜けているとき {: .trouble }

最後の回が抜けるケースだけでは足りないと考え、結婚式場のデータで**中間金（3回のうち2回目）だけ**が届いていない状態も試しました。着手金と完成金という「両端」は入金済みです。

<div class="prompt">まだ入金されていないご家族はどれですか。1件が複数回に分けて入金されることがあります。合計額が請求額と一致するかどうかも確認してください。</div>

**3回とも、未入金の1組（山口家・中間金585,000円）だけを正しく指摘しました。**「着手金と完成金は入っていますが、間の中間金が抜けている状態です」のように、両端が入金済みであることまで自分から言語化した回もあります。<mark>最初と最後だけを見て判定しているのではなく、内訳の各回を個別に照合していると考えられます。</mark>

## 応用・次の一手 {: .next }

**毎月やるなら、分割回数が何回でも同じ手順で回せる形にしておくと安心です。**

<div class="prompt">毎月、着手金・中間金・完成金の3回に分けて入金される契約と、着手金・完成金の2回だけの契約、一括払いの契約が混ざります。件数は月によって10件のときも40件のときもあります。入金明細と請求一覧を毎月同じ形で突き合わせたいです。プログラミングはできません。私が毎月やることを、番号を振って箇条書きで教えてください。</div>

2回試したところ、手順の数（12個と10個）は違いました。それでも、次の骨格は共通していました。

- 請求一覧と入金明細を、毎月同じ形で並べる
- 契約ごとに、何回目の入金かを記録する
- 金額を突き合わせて、済んだところに印を付ける
- 未入金・不明入金を、別枠に洗い出す
- ファイル名に年月を入れて、翌月に引き継ぐ

⚠️ **この結果は、この2種類の架空データ・合計21回の実測です。**「AIは分割が何回に増えても絶対に間違えない」と一般化しないでください。試したのは、次の範囲までです。

- 分割は最大3回払いまで（4回以上の分割は試していません）
- 割合は30%＋30%＋40%または50%＋50%という、きれいに割り切れる形だけ
- 入金額は予定額どおり（振込手数料の差引などで少しずれるケースは試していません）

督促や確定申告の判断も、この記事の外に置いています。
