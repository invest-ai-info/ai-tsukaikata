## これで何ができるか {: .what }

自分の自動化が、毎朝ダイジェストをメールやSlackに送ってくる。項目が多くて読みにくいので、要約する一言を足したくなる——「初心者にもわかるように」「やさしく」のような言い方です。[長い文書の要約から「ただし書き」だけが静かに消えるのを防ぐ](/recipes/summarize-without-dropping/)は、**字数を絞ったとき**に何が落ちるかを測った記事でした。今回の変数は字数ではなく、**読者レベルの指定**です。

架空の自動監視ダイジェスト2本に、数字・条件・例外を先に決めて仕込みました。

- **材料A**＝15項目（AIモデルの発表・価格・停止警告・移行措置など）
- **材料B**＝13項目（新しい連携先・停止警告・料率変更・終了予定など）

同じ材料に「そのまま要約して」と「初心者にもわかるように要約して」を各2回当て、残った項目数を数えました。結果は次の3つです。

1. **材料Aは、そのまま要約だと2回とも15項目全部が残りました（15/15・15/15）。**
2. **わかりやすく要約させると、2回とも同じ2項目だけが消えました。**消えたのは発表の正確な時刻（2027-02-09 18:40）と、停止の正確な回数（52回連続）です。他の13項目（価格・移行措置・対象外条件・終了日など）は2回とも残りました。
3. **材料Bは、そのまま要約の時点で既に1項目（新連携先の追加日時）が2回とも欠けていました**（12/13・12/13）。わかりやすく要約させても、同じ1項目のままでした。追加の欠落はありません。
4. <mark>「日付・時刻・回数を含む数字は一切省略せず、原文のまま書いてください」と名指しすると、全項目が戻りました</mark>（材料A: 15/15・15/15／材料B: 13/13・13/13）。

<mark class="warn">「わかりやすく」は数字を全般的に削る指示ではありません</mark>。価格・料率・移行措置の期限・対象外条件のような「本体の数字」は、材料A・Bとも2回ずつ全部残りました。消えたのは、見出しの事実に添えられた**時刻・回数という二次的な精度の数字**だけです。

📌 **この記事の数字はすべて架空データでの実測です。**実在の個人・企業の情報は含みません。材料や仮説を知らない独立した新規会話で、**合計12回**試しました。生の返りと機械照合は `docs/evidence/easy-summary-drops-time-and-count.md` に全文置いてあります。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。無料のチャットAIで足ります |
| 必要なもの | 自動化が送ってくるダイジェスト・通知文のテキスト |
| プログラミング | **不要**。文章を貼って指示文を添えるだけです |

材料Aは、AIモデルの発表・価格変更・停止警告・移行措置を含む架空の自動監視ダイジェストです。

```
おはようございます。本日の自動監視ダイジェストです(2027-02-10 07:00 JST生成)。

【即時通知】
・ことのはAIが新モデル「ことのは3.2」を発表しました(2027-02-09 18:40)。入力価格は1,000トークンあたり0.8円、出力価格は1,000トークンあたり2.4円です。

【停止警告】
・「つむぎ速報」は34日間取得できていません(52回連続失敗)。※URLが変わったかフィードが廃止された可能性があります。
・「はこぶねログ」は28日間、新着データがありません(取得自体は成功しています。中身が止まっているだけです)。
・「ことのは公式ブログ」は21日間新着がありませんが、このフィードは通常の更新間隔が45日なので、まだ警告の対象ではありません。

【価格変更】
・クラウドノート社の月額プランは、1,200円から1,500円に変更されます。ただし、2027-02-10より前に契約した利用者は、2027-05-31まで旧価格の1,200円が維持されます(移行措置)。
・この価格変更は新規契約者のみに適用され、既存の年間契約者には影響しません。
・なお、上記の0.8円/2.4円は少なくとも2027-04-30までのプレビュー価格であり、正式価格は未定です。

【終了予定】
・旧API「v1」は2027-03-01をもって提供終了です。v2への移行が必要です。
・祝日・休日は実行の遅延を異常として数えません。

【実行状況】
・今週の定時実行は24回のうち、90分以上の遅延が18回(75%)ありました。
・担当者による手動の再認証が必要です(期限: 2027-02-20)。

以上です。
```

もう1本（材料B）は、受注の自動監視レポートです。新しい連携先・在庫フィードの停止・決済手数料の変更を含みます。全文は `docs/evidence/easy-summary-drops-time-and-count.md` にあります。

⚠️ 仕込みに使った会社名・サービス名はすべて造語です。実在のブランド名を使うと、AIの事前知識が判定に混ざり、何が原因で気づいたのかを切り分けられなくなります。

## AIへの頼み方 {: .ask }

### 1. まず「そのまま要約して」の基準値を取る

<div class="prompt">次の文章を要約してください。</div>

（このあとに、上の材料Aをそのまま貼ります）

2回試しても、15項目全部が残りました。1回目・2回目とも文中に出ていたのは次の4つです。

- 発表の日時（2027-02-09 18:40）
- 停止の回数（52回連続失敗）
- 価格のプレビュー期限
- 移行措置の対象条件

### 2. 「初心者にもわかるように要約して」で、2項目だけ消える

言い方を1か所だけ変えます。

<div class="prompt">次の文章を、初心者にもわかるように要約してください。</div>

（このあとに、同じ材料Aを貼ります）

2回とも、同じ2項目が消えました。1回目は「ことのは3.2が発表されました」とだけ書かれ、発表日時がありません。2回目は「34日間データが取れていません」とだけ書かれ、52回という失敗回数がありません。

一方、価格・移行措置・対象外条件・終了日・遅延実績・再認証期限は、2回とも文中に残っていました。

<mark>材料Aでわかりやすく要約させたときに消えた2項目に共通するのは、どちらも「見出しの事実」に添えられた、もう1段細かい数字だということです</mark>。「発表された」「取得できていない」という主張そのものは残り、「いつ」「何回」という精度だけが落ちます。

⚠️ 2回目の返りでは、価格の単位も「1,000トークンあたり」から「1,000文字あたり」に書き換わっていました。これは省略ではなく数字の中身の書き換えです。わかりやすく要約させた4回中1回だけの観測なので、ここでは「起こりうる」とだけ書き、法則として扱いません。

### 3. 材料を変えても同じ化け方をするか

材料Aだけの偶然ではないか確かめます。情報の種類をまるごと変えた材料B（受注監視レポート・13項目）で、同じ2つの指示文を試しました。

<div class="prompt">次の文章を要約してください。</div>

（このあとに、材料Bを貼ります）

<div class="prompt">次の文章を、初心者にもわかるように要約してください。</div>

（このあとに、同じ材料Bを貼ります）

ここで**材料Aとは違う形が出ました**。「そのまま要約して」の時点で、新しい連携先の追加日時（2027-03-04 21:15）が、2回とも最初から消えていたのです。「わかりやすく」に変えても、欠ける項目は同じ1件のままで、増えませんでした。

| | 材料A（15項目） | 材料B（13項目） |
|---|---|---|
| そのまま | 15/15・15/15 | 12/13・12/13 |
| わかりやすく | 13/15・13/15 | 12/13・12/13 |

<mark class="warn">「わかりやすく」で項目が減ったのは材料Aだけで、材料Bでは増えませんでした</mark>。材料Bの欠落は、読者レベルの指定とは別の理由で起きていたと見ています。この1件だけが本文の見出し扱いで、添えられた日時の重みが軽く見積もられたためです。**「わかりやすく」が必ず数字を削るとは言えません。**削るのは、材料Aのように、わかりやすさの指示が追加で落とした項目がある場合だけです。

## うまくいかないときの言い直し方 {: .fix }

### 「省略しない」と名指しすれば戻るか {: .trouble }

消えた2項目を、読者レベルの指定を残したまま取り戻します。

<div class="prompt">次の文章を、初心者にもわかるように要約してください。ただし、日付・時刻・回数を含む数字は一切省略せず、原文のまま書いてください。</div>

（このあとに、材料Aを貼ります）

2回とも、15項目全部が戻りました。発表日時も失敗回数も、原文の表記のまま文中に出ています。前の単位の書き換え（トークン→文字）も、この2回では起きませんでした。

### 材料Bの「そのまま」からの欠落も戻るか {: .trouble }

材料Bの欠落は、わかりやすさの指定とは無関係に起きていました。同じ一文を足しても戻るか、別に確かめます。

<div class="prompt">次の文章を、初心者にもわかるように要約してください。ただし、日付・時刻・回数を含む数字は一切省略せず、原文のまま書いてください。</div>

（このあとに、材料Bを貼ります）

2回とも、13項目全部が戻りました。「そのまま」の時点から消えていた追加日時（2027-03-04 21:15）も、文中に出ています。<mark>「数字・日付・時刻・回数は省略しない」という一文は、わかりやすさの指示が原因の欠落だけでなく、そのまま要約でも起きていた欠落まで戻します</mark>。狙い撃ちではなく、数字を残すこと自体を強く指定する一文だと見たほうが筋が通ります。

## 応用・次の一手 {: .next }

自分の自動化が、ダイジェストの前に「読みやすく」という一言を足しているなら、同じ指示文で何が消えるかを一度確かめてください。消える項目は材料ごとに違う可能性があります。**見出しの主張に添えた時刻・回数・識別子のような「2段目の数字」は、まず疑う場所**です。

既にある要約をあとから検査する頼み方は、[長い文書の要約から「ただし書き」だけが静かに消えるのを防ぐ](/recipes/summarize-without-dropping/)の「すでにある要約を、あとから検査する」にまとめてあります。要約を書き直させず、検査だけを頼む形です。

毎回自動で送る形にするなら、「省略しない」の一文を**要約の指示の最後**に置いてください。この記事の実測では、先に置いても後に置いても全項目が戻りました。ただし[自動実行の形に短くする工程で、拾い漏れを止める一文が真っ先に落ちる](/recipes/backlog-scale-holds-brevity-breaks-it/)という教訓があります。体裁を整える指示を後から重ねると、先に書いた「省略しない」のほうが埋もれることがあります。

⚠️ **この記事が実測していないこと**は2つです。

- 読者レベルの指定を「やさしく」「子ども向けに」のようにさらに強めたとき、消える項目が増えるかどうか
- 3本目以上の材料でも、材料Bのような「そのまま」から欠けるパターンが同じ頻度で出るかどうか

次に測るなら、**自分の自動化が実際に送っている通知文**で同じ照合をかけることから始められます。考え方は[死活判定は数字の選び方で変わる](/recipes/raw-count-catches-it-new-count-misses-it/)や[更新停止の異常判定は一律にしない](/recipes/flat-threshold-misfires/)と同じです。
