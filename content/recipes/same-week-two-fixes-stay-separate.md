## これで何ができるか {: .what }

[除外の書き方で来年また鳴るか決まる](/recipes/exclusion-wording-decides-the-repeat/)は、条ごとの誤報を週をまたいで1つずつ直す形を実測しました。ただしその記事は、最後に「誤報が同じ週に複数の条で同時に起きた場合は未測定」と書いて終わっていました。この記事はその先です。<mark>2つの条の誤報が同じ週に重なっても、1回の依頼で両方を正しく直せるかを実測します。</mark>プログラミングは要りません。

結論は3つです。

1. 条1（金額超過）と条3（数量異常）の誤報が同じ週に同時に起きても、1回の依頼で両方の除外が正しく反映されました。材料2本（系列C・系列D）×2回転＝**4回の独立呼び出しすべて**で、誤報2件が消え、本物の異常5件はそのまま残りました。
2. 触っていない条2（ID重複）・条4（日付未来）・条5（担当者欄空欄）の文章は、4回とも**1文字も変わりませんでした**。目視ではなく、機械で文字列を比較して確認しています。
3. 直したルールについて「条2・4・5は変えていないか」とAI自身にも確認させました。<mark>自己申告でも機械照合と同じ結論が返りましたが、主役はあくまで機械照合です。</mark>AIの自己申告は自覚した範囲しか含まないので、確認の足し算として使っています。

この記事の進め方は3段です。まず基準を取り、同じ週に2条の誤報を1回の依頼で直させ、同じ記録でもう一度確かめます。これを材料を変えて2回繰り返しました。

### 4. 材料を変えて、もう一度確かめる（2回転目）

同じ指示文・同じ材料で、新規プロセスからもう一度試しました。**結果は系列C・系列Dとも1回目と完全に一致しました。**誤報2件の除外・本物5件の維持・条2〜5の文字どおりの不変、すべて4回とも同じです。2回転の値打ちは「割れたら、それが見える」ことにありますが、今回は割れた回がありませんでした。

## うまくいかないときの言い直し方 {: .fix }

### 直した条2・4・5が本当に変わっていないか心配なとき {: .trouble }

AI自身に聞いても確認できます。<mark class="warn">ただし自己申告だけを根拠にしないでください。</mark>主役は、直す前と直した後のルールをテキストで比較する機械照合です。

<div class="prompt">直す前の点検ルールは次のとおりでした。

条1（金額超過）: 金額が50万円を超える行
条2（ID重複）: 受注IDが同じ行が2行以上ある場合、その全ての行
条3（数量異常）: 数量が0以下の行
条4（日付未来）: 受注日が2026-10-18より後の行
条5（担当者欄空欄）: 担当者名が空欄の行

直したあとのルールは次のとおりです。

条1（金額超過）: 金額が50万円を超える行。ただし、取引先が北斗フーズで商品が年末特需セットの行（毎年恒例の季節性大口注文）は除く。
条2（ID重複）: 受注IDが同じ行が2行以上ある場合、その全ての行
条3（数量異常）: 数量が0以下の行。ただし、取引先が白川紙業で数量が0、金額が0円の行（正規の注文取消行）は除く。
条4（日付未来）: 受注日が2026-10-18より後の行
条5（担当者欄空欄）: 担当者名が空欄の行

このルールのうち、条2（ID重複）・条4（日付未来）・条5（担当者欄空欄）の文章は、直す前と比べて一文字も変えていませんか。変わっている場合は、どこがどう変わったかも教えてください。</div>

**系列Cはこう答えました。**「変わっていません。条2・条4・条5は、直す前と直した後で一文字も違いません。」のあとに、条1・条3の変更箇所を正しく名指ししました。**系列Dも同じ結論でした。**どちらも機械照合の結果と一致しています。

⚠️ **AIの自己申告は、本人が自覚した範囲しか含みません。**直す前のルール文を渡さずに「変わっていませんか」と聞くと、比較のしようがなくAIが止まってしまうこともあります。比較を頼むときは、**直す前と直した後の両方を同じメッセージに入れてください。**

### 3条以上が同時に重なったとき {: .trouble }

今回確かめたのは、条1と条3の**2条**が同時に重なった場面だけです。3条以上が同時に重なった場合や、条の組み合わせが違う場合は未測定です。心配なら、2番の指示文の形で該当する件数ぶんの誤報を全部書き並べてから送り、3番の指示文で同じ記録を再点検してください。

### 条の数が増えても、確認の指示文は変えなくてよい {: .trouble }

<div class="prompt">条ごとに、当てはまる受注IDだけを挙げてください。
第◯条: 受注ID,受注ID,...（無ければ「なし」）
の形で、ルールにある条の数だけ行を、やり直さず一度だけ出力してください。理由も対処も書かないでください。</div>

基準点検・再点検に使う指示文は、1番・3番と同じこの1つだけです。条の数が5より増えても、文面を変える必要はありません。

## 応用・次の一手 {: .next }

同じ形は、点検のたびに起きます。誤報を1件だけ止める基本は[誤報を1件だけ止める](/recipes/stop-one-false-alarm/)に、作った検査が本当に鳴るかを試す話は[自分で作った検査を、わざと壊して確かめる](/recipes/try-breaking-your-own-checks/)にあります。

⚠️ **この記事が実測していないこと**は4つです。

- 3条以上が同時に重なった場合
- 条1・条3以外の組み合わせ（例: 条2のID重複と条4の日付未来が同時に重なる場合）
- 除外の書き方そのもの（一般化型か行specific型か）の違い。これは[除外の書き方で来年また鳴るか決まる](/recipes/exclusion-wording-decides-the-repeat/)が確かめた軸で、今回は踏襲していません
- 本物の異常の内容を系列間で変えた場合（今回は系列C・Dで本物5件の内容をあえて揃え、誤報の内容だけを変えています）

📌 **試行回数。**`claude --safe-mode --tools "" -p` で毎回新規プロセスを起動し、**合わせて14回**の独立呼び出しをしました。
