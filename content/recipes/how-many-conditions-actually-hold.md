## これで何ができるか {: .what }

「AIには条件を細かく指定するとよい」——これも[役割を与える](/recipes/role-prompt-same-answer/)と並んでよく見かける定説です。ただし裏側には別の心配もあります。**条件を積みすぎると、後のほうから守られなくなるのでは**という不安です。

そこで実際に試しました。架空の会社の社内お知らせ（経費精算システムの切り替え）を書かせるタスクを1つ用意し、機械で○×が決まる条件を12個先に決めます。それを**3個・6個・9個・12個**と積んだ4版に、**同じ12個を逆の順番で並べた版**、**条件ごとに○×を出させる版**を加えて、<mark>6版×各2回＝12回・102問を通しました</mark>。

先に結果を書きます。

- 🔑 <mark>102問中102問（100%）が条件を満たしました</mark>。12個まで積んでも、逆順に並べても、崩れは1件も起きませんでした
- **9個版も12個版も、2回とも全条件を満たしています。**条件を増やすほど崩れる、という単純な話にはなりませんでした
- AIの自己申告（「すべて満たしています」）は12回とも、実際の判定と一致していました
- 🚨 <mark class="warn">ただし、これは「今回崩れが1件も起きなかった」からです。</mark>自己申告が本当に崩れを見つけられるかどうかは、崩れた回で試さないと分かりません。この実測だけでは確かめられていない、というのが正直なところです

**この記事は「条件はいくつ積んでも大丈夫」とは言いません。**測ったのはこの1つの材料・この12回だけです。ただ、少なくともこの実測では、条件を12個まで積んでも崩れませんでした。**崩れなかったことと、自己申告を信じてよいことは別問題**——ここが本題です。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 箇条書き・文字数など、○×が機械で決まる条件のリスト |
| プログラミング | **不要**。指示文をコピーして貼るだけです |

この記事でやるのは、条件を全部覚えて手で数える作業ではありません。**条件を渡したときに、実際どこまで守られるか**を確かめる場面の話です。「読みやすく」のような機械で決まらない条件は、この記事のやり方では判定できません（後述）。

## AIへの頼み方 {: .ask }

## うまくいかないときの言い直し方 {: .fix }

### 一言の自己申告を信じてよいか不安 {: .trouble }

不安は正しいものです。今回の実測では崩れが1件も起きなかったので、自己申告が実際とすべて一致しました。しかし<mark class="warn">これは「たまたま崩れなかったから一致した」だけで、「自己申告が崩れを見つけられる」ことを示したわけではありません</mark>。

条件ごとに○×を1行ずつ出させる、より丁寧な自己申告も試しました。

<div class="prompt">以下の情報をもとに、社内向けのお知らせ文を作成してください。

【伝える内容】
・対象：全社員
・経費精算システムを2026年9月15日から新しいシステムに切り替える
・旧システムは2026年9月30日まで並行稼働し、2026年10月1日以降は使用できなくなる
・申請時はシングルサインオン（SSO）でログインする
・問い合わせ先：システム部（内線1234）

【文章の条件】次の9個の条件をすべて満たしてください。
①本文全体を400字以内におさめる
②箇条書き（「・」または「-」で始まる行）をちょうど5行使う
③本文中に次の3語を必ず1回以上入れる：「移行」「ご協力」「余裕を持って」
④次の2語は使わない：「バグ」「エラー」
⑤日付はすべて「2026年9月15日」のように「年」「月」「日」を使った形式で統一する（「9/15」のようなスラッシュ表記は使わない）
⑥文末は敬体（です・ます調）で統一する（「である」調を混ぜない）
⑦見出し（1行目）に「重要」という語を使わない
⑧問い合わせ先は本文の最後の行に置く
⑨見出し（1行目）は20字以内にする

書き終えたら、①〜⑨のすべての条件について、番号ごとに「○（満たした）」か「×（満たしていない）」を1行ずつ書いて提出してください。×が1つでもあれば、文章を直してから、直した文章とチェック結果をあらためて出してください。</div>

2回とも実際に9/9で、①〜⑨の自己申告もすべて○で一致しました。⚠️ ただし**この2回もそもそも崩れなかった**ので、自己申告が崩れを実際に見つけられるかは、今回の実測だけでは確かめられていません。**「一言より丁寧」ではあっても、「自己申告であること」は変わっていません。**

事実、[「400字以内で要約して」を試した記事](/recipes/summarize-without-dropping/)では、字数の上限指定が417字（4%超過）で守られていませんでした。**条件の種類によっては、この記事のような満点にならないことが、他の実測ですでに分かっています。**「今回は崩れなかった」を「AIの自己申告は当てになる」に広げないでください。

### 本当に守られたかを、自分で確かめたい {: .trouble }

いちばん確実なのは、[AIに任せた作業は、報告ではなく現物で確かめる](/recipes/verify-before-report/)のとおり、**自分の目と手で数える**ことです。字数・行数・必須語の有無くらいなら、貼り付けた文章を見ながら数分で数えられます。

<div class="prompt">いま書いてもらった文章について、以下を1つずつ数えて報告してください。数えるだけで、直さないでください。

・文字数（記号・改行も含めた全体の文字数）
・箇条書きの行数
・「移行」「ご協力」「余裕を持って」がそれぞれ何回出てくるか
・最後の1行に何が書かれているか、そのまま引用する</div>

これは「守られているか」の判定をAIに頼むのではなく、**数える作業だけ**をAIにやらせて、判定は自分でする頼み方です。機械で決まる条件ほど、この形が向いています。

### 条件が「機械で決まらないもの」だった {: .trouble }

「読みやすく」「丁寧な印象で」のような条件は、この記事のやり方では判定できません。**この記事が扱ったのは、字数・行数・必須語・禁止語・表記の統一・位置など、○×が機械で決まる12個だけ**です。

機械で決まらない条件は、[使えるコピー案だけを数える](/recipes/count-copy-ideas-that-pass/)でも触れているとおり、AIに判定させても回ごとに答えが割れます。**割れる条件は数で確かめず、人が読んで判断してください。**

## 応用・次の一手 {: .next }

**条件を積むこと自体を怖がる必要はなさそうです。**今回の実測では、12個まで積んでも、逆順に並べても、崩れは1件も起きませんでした。

**その代わり、「守られているはずだ」と信じて終わらせないでください。**崩れなかったのは今回の材料・今回の回数の話で、条件の種類が変われば守られない例はすでにあります（[400字以内が417字になった実測](/recipes/summarize-without-dropping/)）。条件が機械で数えられるものなら、上の頼み方のように**数えるところまではAIに任せ、判定は自分の目でする**のが確実です。
