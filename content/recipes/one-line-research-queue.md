## これで何ができるか {: .what }

<mark>あとで調べたいと思ったURLを、1行足すだけで預けられます。</mark>

ニュースを見ていて「これ気になるけど、いま読む時間がない」と思うことがあります。ブックマークに入れても、たいてい二度と開きません。

代わりに、**テキストファイルに1行足しておくと、AIが翌朝までに調べて下書きを書いておいてくれる**形にします。

<figure class="figure">
<img src="/static/images/queue-flow.svg" alt="待ち行列の流れを示した図。あなたがスマホでURLを1行足す、AIが毎朝きまった時刻に起動する、AIが出典の本文を実際に開いて読む、AIが公開されない場所に下書きを置く、最後にあなたが読む、の5段階。AIが担当するのは真ん中の3つで、人がやるのは最初の1行と最後に読むところだけ。途中で公開されることはない。">
<figcaption>人がやるのは、最初の1行と最後に読むところだけ</figcaption>
</figure>

実際に動かした結果を先に書きます。2件預けて、**1件は下書きができ、1件は「書けません」と言って止まりました。**

<mark>書けたことより、書かずに止まれたことのほうが重要です。</mark>2件目は、そのAIモデルの公式情報がまだどこにも公開されていませんでした。まとめ記事の数字を使えば表は埋まりますが、それをやらせなかったので、下書きを作らずに理由だけ書いて終わっています。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 30分（最初の1回だけ） |
| 費用 | 無料（AIの利用料は別） |
| 必要なもの | **決まった時刻に自分で動けるAI** と、スマホから編集できるファイル置き場 |
| プログラミング | **不要** |

チャット画面だけのAIでは作れません。時間が来たら自分で起き上がって作業する形が要ります。やり方は [「毎日決まった時刻に自動でやっておいて」をAIに作らせる](/recipes/github-actions-daily-cron/) に書きました。

ファイル置き場は、**スマホのブラウザから3タップで編集できる**ものを選んでください。GitHub なら、ファイルを開いて鉛筆アイコンを押して保存するだけです。

## AIへの頼み方 {: .ask }

### 1. 待ち行列を、ただのテキストファイルにさせる

最初に釘を刺します。放っておくと立派なものを作られます。

<div class="prompt">預けたいURLを溜めておく場所を作ってください。

ただのテキストファイルにしてください。専用の画面や、データベースは作らないでください。私がスマホから1行足せることが一番大事です。</div>

<mark>「一番大事なこと」を1つだけ伝えるのがコツです。</mark>これを言わないと、管理画面つきの仕組みが出てきます。よくできていますが、外出先で1行足すには重すぎます。

### 2. 終わった行を、消さずに残させる

<div class="prompt">処理が終わった行は消さないでください。印を付けて残し、何を作ったかをその下に書いてください。</div>

消させないのには理由が2つあります。**同じURLを二度預けたときに気づけること**と、**あとから「なぜこれを調べたか」を辿れること**です。

### 3. 出典を実際に開いて読ませる

ここを言わないと、URLの見出しだけで書き始めます。

<div class="prompt">預けたURLは、必ず本文を開いて読んでから書いてください。

見出しと短い説明だけで書かないでください。足りない部分を想像で埋めることになります。</div>

<mark class="warn">見出しだけで長文を書かせると、確実に作り話が混ざります。</mark>関連する話は [AIに数字を「それっぽく」埋めさせない](/recipes/numbers-not-in-the-source/) に書きました。

### 4. 書けないときは、書かせない

**この記事で一番大事な一文です。**

<div class="prompt">元の情報にたどり着けなかったときは、下書きを作らないでください。

代わりに、何が読めなかったのか・次に何をすれば読めるようになるのかを、待ち行列に書いて止まってください。まとめ記事や他のサイトの情報で埋めないでください。</div>

<figure class="figure">
<img src="/static/images/write-or-stop.svg" alt="一次情報に届いたかどうかで動きを分ける図。届いた場合は出典を読んで下書きを書き、人が読んでから公開する（例：Claude Opus 5 の比較記事）。届かなかった場合は下書きを作らず、止まった理由を書いて残す（例：Qwen3.8、公式情報が未公開）。二次情報で埋めれば表は完成するが、完成した表のほうが危ないため、そうさせない。">
<figcaption>書けたことより、書かずに止まれたことのほうが大事です</figcaption>
</figure>

<mark>自動で動くものは、失敗しても誰も見ていません。</mark>だから「できませんでした」と言える形にしておかないと、埋めた結果だけが残ります。

### 5. 出来上がりを、公開されない場所に置かせる

自動で書かせるなら、ここは必ず入れてください。

<div class="prompt">出来上がったものは、公開されない場所に置いてください。

私が読んでから公開します。置き場所を間違えても公開されないよう、仕組みのほうで分けてください。</div>

<mark>「気をつけて置く」ではなく「置けない形にする」と頼むのがコツです。</mark>実際に作ったものでは、**ファイル名の先頭に記号が1つ付いているかどうかで、公開されるかどうかが決まります**。記号が付いている限り、間違って公開されることはありません。

### 6. 詰まった理由を、次に読む人に分かる形で残させる

<div class="prompt">途中で止まったときは、次にこれを読む人が、そのまま作業を再開できるように書いてください。

何が起きたか・何を試したか・次に何をすれば直るか。この3つを入れてください。</div>

これを頼んでおいたら、止まったときに**必要な設定を11件、優先度を付けて表にして残してくれました**。しかも「この2件を先に足せばよい」まで書いてありました。<mark>止まり方の質は、指示で決まります。</mark>

## うまくいかないときの言い直し方 {: .fix }

### 待ち行列を読んでくれない {: .trouble }

<div class="prompt">作業を始める前に、必ず待ち行列のファイルを開いて中身を読んでください。

読んだ内容を最初に報告してから、作業に入ってください。</div>

**読んだことを報告させる**と、読み飛ばしが減ります。

### 1回で全部処理しようとする {: .trouble }

溜まっていると、まとめて片付けようとします。

<div class="prompt">1回の実行で処理するのは1件だけにしてください。

残りは次回に回してください。まとめて処理すると、1件あたりが雑になります。</div>

<mark class="warn">まとめて処理させると、後半になるほど雑になります。</mark>件数を絞るほうが結果は良くなります。

### 出典を読まずに書いている気がする {: .trouble }

<div class="prompt">この下書きを書くとき、実際に開いたURLを全部挙げてください。

そのうえで、それぞれのページから何を引用したかを教えてください。</div>

### 気づいたら公開されていた {: .trouble }

<div class="prompt">いま公開されているものを一覧にしてください。

そのうえで、私が読む前に公開されない形になっているか確認してください。なっていなければ、どこを直せばよいか教えてください。</div>

<mark class="warn">一度公開されたものは、消しても記録に残ることがあります。</mark>公開の場所を分けるのは、後から足すのではなく最初にやってください。

### 止まったのに、理由が分からない {: .trouble }

<div class="prompt">「できませんでした」だけでは、私には直せません。

何を試して、どう失敗したのかを書いてください。エラーの文言があれば、そのまま貼ってください。</div>

## 応用・次の一手 {: .next }

**まず1と5だけ作ってください。**「ただのテキストファイル」と「公開されない置き場所」の2つがあれば、残りは後から足せます。

慣れてきたら、預ける先を増やせます。調べもの以外にも使えます。

<div class="prompt">この待ち行列の形を、別の作業にも使いたいです。

いまの仕組みのどこを変えれば、違う種類の依頼を預けられるようになりますか。</div>

最後に、冒頭の2件の続きを。書けなかったほうは、AIが残してくれた「次にこれを足せばよい」に従って設定を1つ変えたら、次は書けるようになる見込みです。<mark>止まった場所と理由が残っていれば、詰まりは一度きりで済みます。</mark>

止まらせない仕組みより、**止まったことがすぐ分かる仕組み**のほうが、長く使えます。この考え方は [自動化が静かに壊れたのを、AIに見つけさせる](/recipes/auto-health-check/) にも書きました。
