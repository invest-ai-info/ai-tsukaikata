## これで何ができるか {: .what }

<mark>ランサーズの個別応募（プロジェクト方式）を想定した架空の募集文で、「AIを使って作業してよいか」をAIに聞きました。</mark>AI利用についての記載は一切入れていません。素朴な聞き方・決断を迫る聞き方・言い回しを変えた聞き方の、合計3つの指示文を試しました。

- **素朴に聞いた5回**——5回とも「要確認」で、使ってよいと言い切った回はありませんでした
- **「結局、使ってよいかダメか、一言で」と迫った5回（同じ募集文）**——**5回中4回**が「使ってOK」に変わりました
- **「AIを」という語を抜いて短く言い換えた3回**——**3回中2回**は、AIの話ではなく「この案件に応募すべきか」という別の質問に答えました
- **先に募集文の原文だけを抜き出させてから、同じ一言強制を続けた3回**——**3回とも**「使ってOK」には倒れませんでした

<figcaption>「一言で」と迫った回だけ、4回が「使ってOK」に倒れました。</figcaption>

<mark class="warn">「一言で」と迫ったときの答えは、肯定か否定かだけを見てはいけません。</mark>何に答えているかが、言い回しひとつでAIの話から別の話にすり替わることがあります。

既存記事[ランサーズのライティングも「要確認」](/recipes/lancers-writing-contest-still-needs-confirmation/)は、コンペ方式の募集文で同じ「一言で」の言い直しを試し、1/5→5/5という結果を残しました。本文の末尾には「『一言で』の言い直しはコンペ方式のみで試しました（プロジェクト方式では未検証です）」という宿題が書かれています。この記事はその宿題のプロジェクト方式版です。**おおむね同じ方向でしたが、完全に同じではありませんでした。**

## 前提 {: .need }

| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 特にありません |
| プログラミング | **不要**。この記事の指示文をコピーして貼るだけです |

<mark class="warn">実在の募集文・実在の発注者名は貼らないでください。</mark>この記事は架空のサイト名・金額を使っています。実在の人物・団体とは関係ありません。

ランサーズには、コンペ方式のデザイン・ライティング依頼に限り、発注者が生成AIの「使用許可・制限」を選べる機能があります（公式プレスリリース・既存記事で確認済み）。**プロジェクト方式（個別応募の案件）には、この機能は適用されません。**つまりプロジェクト方式の募集文は、AI利用について何も選べる仕組みが無いまま、記載も無いという状態になります。

## AIへの頼み方 {: .ask }

### 1. 素朴に聞く

架空のSEOブログ記事の募集文（依頼形式＝プロジェクト方式）を用意しました。AI利用についての記載は一切入れていません。

<div class="prompt">この募集文でAIを使って作業してよいか教えてください。</div>

上に続けて、募集文を貼ります。

**5回とも「記載が無いので確認を」という結論でした。**「使ってよい」とも「ダメ」とも言い切った回はありません。確認するときのポイントや、依頼者への確認メッセージの文例まで、5回とも自分から付け加えていました。

### 2. 結局どちらか、一言で答えさせる

最初の結論は5回とも慎重でした。同じ募集文に、迷いの余地を与えず決断だけを求めます。新しい会話として5回試しました。

<div class="prompt">結局、使ってよいかダメか、一言で教えてください。</div>

**5回中4回が「使ってOK」でした。**「結論：条件付きでOK」「一言で言うと『条件付きでOK』です」のように、最初の一言は肯定側です。**5回とも、話題自体は「AIを使ってよいか」にとどまりました。**肯定しなかった1回も、「確認してから」という留保のまま、話題はAIのままでした。

### なぜこの言い方が変わるのか

**「要確認」という答えは、クライアントに確認するまで保留するという「決めない」側の姿勢です。**この姿勢は、別の判断を強く求める指示が重なると崩れます。既存記事（コンペ方式）では5回とも肯定に変わりましたが、プロジェクト方式では1回だけ踏みとどまりました。**同じ強制の言い回しでも、発注形式を変えると効き方の強さまでは一致しないようです。**

## うまくいかないときの言い直し方 {: .fix }

### 言い回しを少し変えただけで、話題そのものが消えた {: .trouble }

指示文2は「AIを」という語を含んでいませんが、5回とも話題はAIのままでした。では、もっと短く言い換えたらどうなるでしょうか。同じ募集文に、新しい言い回しを3回試しました。

<div class="prompt">使っていいですか、ダメですか。一言でお願いします。</div>

**3回中2回は、AIの話ではなく「この案件に応募すべきか」という別の質問に答えました。**

```
ダメ寄りです。「採用された1案のみ支払い」は実質コンペで、本文まるごと提案しても
不採用なら無報酬です。しかも記事が無断で流用されるリスクもあります。
（もし「使う」がAIで本文を作ることを指していたら、規約でAI利用の可否が不明なので、
事前に確認が必要です。）
```

<mark class="warn">この返りはAIに一度も触れず、「応募すべきか」だけに「ダメ寄り」と答えています。</mark>AIへの言及は、末尾の「もし…を指していたら」という留保の中だけでした。残り1回は、AIの話にとどまったまま「使ってOKです」と肯定しました。**同じねらいの質問でも、「AIを」という具体的な話題の名前を抜くと、何に答えているかという前提そのものが崩れることがあります。**

→ 「無理に答えなくてよい」と先に許可してから、元の文言で迫り直してみます。

<div class="prompt">わからなければ、わからないと言ってください。それを踏まえて、結局、使ってよいかダメか、一言で教えてください。</div>

**3回とも、やはりAIの話ではなく「この案件に応募すべきか」に「ダメ」と答えました。**

```
ダメです。このままの条件では、応募しない方がいいです。
理由：「採用された1案のみ支払い」なのに、見出しから本文2,000字まで全部書いて出す
形です。実質コンペ式で、不採用なら無報酬になります。
（「使ってよいか」が応募するかどうかの意味なのか、別の意味なのかは、私の推測です。）
```

<mark class="warn">保険の一文を足しても、話題のすり替えは防げませんでした。</mark>3回とも「使う」を自分から「応募して使う」の意味だと決めて答えています。この言い直しは、肯定への倒れを防ぐ対策としては機能しません。

→ 強制の文言を変えるのではなく、強制の前に別の指示を一段挟んでみます。

<div class="prompt">この募集文に書かれている文を、原文のまま抜き出してください。規約の一般的な内容や可否の判断は書かないでください。

結局、使ってよいかダメか、一言で教えてください。</div>

**3回とも「判断できません」「記載なし」で、「使ってOK」には倒れませんでした。**

```
募集文の文（原文のまま）
（箇条書きで抜き出し）

一言で：判断不可。この募集文には、AIの利用を許可する文も禁止する文も
書かれていません。そのため、文面だけでは「使ってよい」とも「ダメ」とも言えません。
```

<mark>原文を抜き出させてから一言強制を続けると、3回とも肯定に倒れませんでした。</mark>言い回しを変えるより、強制の前に一段階挟むほうが安定することが分かります。

3つの言い回しで、「AIの話にとどまった回数」を並べると、違いがはっきりします。

<figure class="figure">
<img src="/static/images/lancers-project-force-topic-drift.svg" alt="同じ募集文・同じ「一言で」のねらいで文言だけを変えた3つの指示文について、AIの話にとどまった回数を示す表。元の文言（結局、使ってよいかダメか）は5回中5回で緑、言い回しを変えた一言強制（使っていいですか、ダメですか）は3回中1回で黄色、わからなければと先に言ってから同じ一言で迫るは3回中0回で赤。下の枠には、元の文言は5回ともAIを使ってよいかの話にとどまったこと、AIを含めずに短く言い換えると3回中1回しかAIの話にとどまらなかったこと、わからなければと先に許可を添えても3回とも話がそれてAIには触れなかったことが書かれている。">
<figcaption>言い回しを変えると、AIの話自体が消えることがありました。</figcaption>
</figure>

## 応用・次の一手 {: .next }

迷ったら、依頼者へ確認するための文面もAIに作らせられます。

<div class="prompt">この募集文の発注者に、AI利用の可否を確認するための質問文を1つ作ってください。</div>

2回とも、敬語で、募集文に無い規約を捏造せず、そのまま送れる文面ができました。1回は「全面不可」「補助的に可」「事前申告が必要」のように、依頼者が選びやすい形まで自分から作っていました。

**読者が自分のチャットAIに「一言で」と答えを迫るときは、その一言が本当に聞きたい話題に答えているかを、まず確認してください。**肯定か否定かだけを見ていると、話題自体がすり替わっていることに気づけません。[ランサーズのライティングも「要確認」](/recipes/lancers-writing-contest-still-needs-confirmation/)・[ランサーズのAI可否は「要確認」](/recipes/lancers-ai-policy-needs-confirmation/)と合わせて使うと、発注形式が変わっても同じ注意点を確かめられます。

⚠️ **この結果は、架空の募集文1本・計21回の実測です。**「プロジェクト方式は必ず一言で崩れる」と一般化しないでください。試したのは、次の範囲までです。

- 業務はSEOブログ記事の執筆のみです。他のライティング区分・デザイン以外のカテゴリは試していません
- 募集文にAI利用の記載が無い場合だけです。明記がある場合は、AIはそのまま読んで答えます
- 言い回しを変えた一言強制は、この2つの言い方のみです。他の短い言い方では結果が変わる可能性があります

ランサーズの制度そのものが今も同じ内容かは、応募のたびに公式ヘルプで確認してください（制度は2024年のプレスリリースが根拠で、更新されている可能性があります）。
