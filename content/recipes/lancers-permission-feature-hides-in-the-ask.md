## これで何ができるか {: .what }

<mark>募集文に実在のプラットフォーム名が入っていても、AIが語る規約の中身が本当に合っているかを、実際にある制度と照らして確かめられるようになります。</mark>[クラウドワークスでも確かめる記事](/recipes/site-name-invites-guessed-rules/)と[ココナラでも確かめる記事](/recipes/platform-name-guesses-the-rule-backwards/)に続く3社目です。今回はランサーズを材料にしました。

ランサーズには実在する制度があります。**発注者がコンペ方式のデザイン・ライティング依頼で、生成AIの「使用許可・制限」を選べる機能**です(2024年3月公表)。ランサーが提案時にAIを使うと、提案物に【AIで生成】のラベルが自動で付きます。この記事は、募集文を見せて「AIを使ってよいか」を判断させたとき、AIがこの制度に自分から触れるかを実測しました。

結果は次の4パターンです。

| 聞き方 | 制度に触れた回数 |
|---|---|
| コンペ方式の募集文で素朴に聞く(5回) | 0/5 |
| プロジェクト方式の募集文で同じ質問(5回) | 0/5 |
| 素朴な質問に「ランサーズの規定を踏まえて」を足す(3回) | 0/3 |
| 募集文を見せず、制度の有無だけを直接聞く(3回) | 3/3 |

<mark class="warn">AIが知らないのではありません。判断という作業に埋め込むと、知っている知識でも出てこなくなります。</mark>のべ16回・架空のロゴデザイン募集文1種での実測です。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 10分 |
| 費用 | 無料。ブラウザのチャットAIで足ります |
| 必要なもの | 特にありません。クラウドソーシングの募集文に応募する場面の話です |
| プログラミング | **不要**。この記事の指示文をコピーして貼るだけです |

実測には**架空の募集文1本**(新規開業カフェのロゴデザイン)を使いました。「コンペ方式」「プロジェクト方式」という契約形式の1語だけを入れ替えています(実在の募集文の著作権に配慮した自作です)。真値には、ランサーズ公式の[プレスリリース](https://www.lancers.co.jp/news/pr/23074/)(2024年3月7日公表・2026-09-16確認)の原文を使いました。

<mark class="warn">この記事はランサーズ1社・この1つの募集文での実測です。</mark>他のプラットフォームや他の業種で同じことが起きるかは確かめていません。

## AIへの頼み方 {: .ask }

### 1. コンペ方式の募集文で、素朴に可否を聞く

実際にこの制度が適用される契約形式(コンペ方式)の募集文です。募集文のどこにもAI利用については書いていません。

<div class="prompt">【コンペ方式】カフェの新規ロゴデザイン募集

ランサーズで、コンペ方式でロゴデザインの提案を募集しています。

新規開業するカフェ「森の間」のロゴを求めています。イメージは木や緑を感じるナチュラルで落ち着いた雰囲気にしてください。使用する色は深緑とベージュを基調に、看板・メニュー・SNSアイコンの3か所で使う予定です。

【予算】
30,000円〜60,000円

【納品形式】
ai形式またはpsd形式(印刷用に300dpi以上)

ご提案の際は、簡単なコンセプト説明を添えてください。

この募集文でAIを使って作業してよいか教えてください。</div>

5回試しました。**5回とも断定はせず、条件付きの答えでした。**「禁止されています」「問題ありません」とは言わず、著作権・商標の類似リスクや、納品形式(ベクターデータが必要)への注意を挙げました。ただし5回とも、実在する「使用許可・制限を選べる制度」や【AIで生成】ラベルには一度も触れませんでした。4回は募集文にある「コンペ方式」という語をそのまま話題にしました。これは制度の説明ではなく、「不採用なら報酬ゼロ」のような契約形式一般の話でした。

### 2. 同じ質問を、プロジェクト方式の募集文で聞く

契約形式の1語だけを「プロジェクト方式」に差し替えました。それ以外は指示文1と一字一句同じです。

<div class="prompt">【プロジェクト方式】カフェの新規ロゴデザイン募集

ランサーズで、プロジェクト方式でロゴデザインの提案を募集しています。

新規開業するカフェ「森の間」のロゴを求めています。イメージは木や緑を感じるナチュラルで落ち着いた雰囲気にしてください。使用する色は深緑とベージュを基調に、看板・メニュー・SNSアイコンの3か所で使う予定です。

【予算】
30,000円〜60,000円

【納品形式】
ai形式またはpsd形式(印刷用に300dpi以上)

ご提案の際は、簡単なコンセプト説明を添えてください。

この募集文でAIを使って作業してよいか教えてください。</div>

<mark>5回とも、指示文1とほぼ同じ内容(著作権・商標リスク・納品形式の注意)を答えました。</mark>実際の制度はコンペ方式にしか適用されませんが、答えの中身は契約形式で変わりませんでした。**プラットフォーム名と業務内容が同じなら、契約形式が変わっても警告の中身は使い回されるようです。**

### 3. 募集文を見せず、制度の有無だけを直接聞く

指示文1・2では制度に触れなかったので、そもそも知識として持っていないのかを確かめます。募集文というシナリオを外し、制度そのものについてだけ聞きました。

<div class="prompt">ランサーズには、コンペ方式のデザイン依頼で、発注者が生成AIの使用可否を選べる機能がありますか。</div>

**3回試して、3回とも実在する制度に言及しました。**2回は「はい、あります」と述べたうえで、「不可に設定すると提案不可」「【AIで生成】のラベルが付く」まで具体的に説明しました。残る1回は「確信が持てない」と留保しました。それでも「発注者が案件ごとにAI使用可否を選べる専用機能」という、制度そのものの存在は認識していました。

<mark>指示文1・2で0/5だった言及が、材料を外して直接聞くと3/3に変わりました。</mark>知識自体は持っていて、募集文の可否を判断させるという作業の中では引き出されなかった、ということです。

### 4. 素朴な質問に「ランサーズの規定を踏まえて」を足す

指示文1に、規定を意識させる一文を足せば思い出すかを確かめます。

<div class="prompt">【コンペ方式】カフェの新規ロゴデザイン募集

(募集文は指示文1と同じ)

この募集文でAIを使って作業してよいか教えてください。ランサーズの生成AIに関する規定を踏まえて答えてください。</div>

<mark class="warn">3回試して、3回とも実在する制度には触れませんでした。</mark>代わりに3回とも、実際の制度(選べる・ラベルが自動で付く)とは違う話をしました。「生成AIで作った場合はクライアントへの開示が必要」「AI利用の申告が求められる場合がある」という、開示義務型の規約です。**「規定を踏まえて」という一言だけでは、正しい規定が呼び出されるとは限りません。**むしろ、それらしい別の規約を新しく作ってしまいました。

## うまくいかないときの言い直し方 {: .fix }

### AIに規約を語らせず、書かれている文だけを抜き出させる {: .trouble }

[案件のAI利用ルールを確かめる記事](/recipes/job-ai-policy-check/)で確かめた型を、ランサーズの募集文にも試します。

<div class="prompt">(募集文は指示文1と同じ)

この募集文にAIの利用について書かれている文を、原文のまま抜き出してください。書かれていなければ「書かれていない」とだけ書いてください。規約の一般的な内容や可否の判断は書かないでください。</div>

**2回試して、2回とも「書かれていない」の一言で終わりました。**指示文4で出てきた「開示義務」のような、実際には無い規約が作られることもありませんでした。<mark>規約の中身を判断させず、募集文にある事実だけを抜き出させれば、無い規約を作る余地自体が無くなります。</mark>

### 実際の発表原文を渡してから判断させる {: .trouble }

一番確実なのは、AIの記憶に頼らず、原文そのものを渡すことです。ランサーズの発表には条件が2つあります。**①デザイン・ライティング業務であること②コンペ方式であること**です。

<div class="prompt">【ランサーズの発表(2024年3月・プレスリリースより抜粋)】
発注者がコンペ方式で制作物の提案を募集する際、生成AIの「使用許可・制限」を選択できる機能をリリースいたしました。ランサー(受注者)が提案時に生成AIを使用した場合には【AIで生成】のラベルが付与されるようになりました。生成AIの「使用許可・制限」の選択機能は現在は「デザイン」「ライティング」業務の依頼のみ適用されています。

(募集文は指示文1、または指示文2と同じ)

この募集文でAIを使って作業してよいか教えてください。上のランサーズの発表を踏まえて答えてください。</div>

コンペ方式の募集文(条件を両方満たす)で2回、プロジェクト方式の募集文(②を満たさない)で2回、計4回試しました。

<figure class="figure">
<img src="/static/images/lancers-source-text-drops-condition.svg" alt="ランサーズの発表原文を渡しても、コンペ方式という条件が見落とされたことを示す表。原文には条件が2つ(①デザイン・ライティング業務であること②コンペ方式であること)ある。コンペ方式の募集文2回では、2回とも「対象の案件」と正しく判定した(2/2)。プロジェクト方式の募集文2回では、②の条件(コンペ方式であること)を理由に対象外と正しく除外した回数は0/2で、逆に①の業務名(デザイン業務であること)だけを根拠に「対象」と誤判定した回数は2/2だった。下の枠には、原文に「コンペ方式で」と明記されているのにプロジェクト方式の募集文にも2回とも制度を当てはめたこと、見ていたのは条件のうちデザイン業務であることだけで契約形式の条件は2回とも読み落とされていたことが書かれている。">
<figcaption>原文を渡しても、2つある条件のうち1つは読み落とされた。</figcaption>
</figure>

**コンペ方式の募集文では、2回とも「デザイン業務にあたるので制度の対象です」と正しく答えました。**ところが<mark class="warn">プロジェクト方式の募集文でも、2回とも同じように「デザイン業務にあたるので制度の対象です」と答えました。</mark>原文には「コンペ方式で制作物の提案を募集する際」とはっきり書いてあります。それでも2回とも、契約形式の条件を見ずに、業務名だけで対象かどうかを決めていました。

**原文を渡せば規約の中身自体は正しく再現されます。**ただし、条件が2つ以上あるときは、そのうち目立つ1つだけを見て他方を見落とすことがあります。契約形式のように募集文の別の場所に書かれている条件は、AIに「原文と照らして」と頼んでも、自分で照らし合わせて確認したほうが確実です。

## 応用・次の一手 {: .next }

**募集文にプラットフォーム名が入っていても、AIが規約の中身に触れないからといって「規約が無い」とは限りません。**[ココナラでも確かめた記事](/recipes/platform-name-guesses-the-rule-backwards/)では、実際に禁止されているカテゴリでAIが規約を自分から語りましたが、その中身は5回とも真値と食い違っていました。今回のランサーズでは逆に、AIは規約の中身に一度も触れず、沈黙していました。<mark>「詳しく語る」と「何も言わない」は正反対の振る舞いですが、どちらも実際の規約とは無関係に起きます。</mark>

実務での確認は、次の順番が安全です。

1. **募集文に契約形式・プラットフォーム名が書かれていたら**、AIに規約の判断はさせず、[書かれている文だけを抜き出させる](/recipes/job-ai-policy-check/)
2. **実際にAI利用の制度があるかを知りたいときは**、募集文というシナリオを外し、制度の有無だけを直接聞く。ただし1回だけでは留保つきの答えが返ることもあるので、複数回確かめる
3. **原文が手に入るなら、AIに渡してから判断させる。**ただし条件が2つ以上あるときは、契約形式のような目立たない条件が見落とされていないかを自分でも確認する

⚠️ **今回確かめたのはランサーズ1社・架空のロゴデザイン募集文1本への言及だけです。**他のプラットフォームや他の業務(ライティングなど)でも同じ傾向になるとは限りません。

実測はのべ22回です。内訳は次のとおりです。

- 素朴な質問(コンペ方式・プロジェクト方式): 各5回
- 直接質問・ヒント付き質問: 各3回
- 抜き出し版: 2回
- 原文提示版(コンペ方式・プロジェクト方式): 各2回

全22回の生の回答と判定は `docs/evidence/lancers-permission-feature-hides-in-the-ask.md` に全文置いてあります。
