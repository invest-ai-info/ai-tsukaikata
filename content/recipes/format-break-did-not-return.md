## うまくいかないときの言い直し方 {: .fix }

### 前の記事で崩れた指示文を試したのに、今回は崩れなかった {: .trouble }

まず、記事どうしで同じ文言を比べるときは、**今回の結果だけを信じて「もう安全」と判断しないでください。**この記事自体が、前の記事の0/4という結果を再現できなかった実例です。<mark class="warn">同じ指示文が毎回同じ結果を返すとは限りません。</mark>自動化の中で対策の一文を使うなら、1回試して崩れなかったからといって、今後ずっと崩れないとは言えません。

### 書式指定が対策を壊すかどうかを、自分の場面で確かめたい {: .trouble }

この記事・前の記事のどちらも、架空データ・特定の材料2本での結果です。あなたが使う監視対象・書式指定で同じ現象が起きるかは、別途確かめる必要があります。やり方は、対策の一文を含む指示文を、書式指定を変えて2〜4回実行し、新着件数が真値と一致するかを見ることです。

### 表形式・絵文字以外の書式指定ではどうか {: .trouble }

この記事が試したのは「表形式に固定」「絵文字を使って見やすく」の2つだけです。箇条書きを禁止する・文字数を区切るといった他の書式指定、また数百件・数千件とさらに過去分が多い場合は、この記事では試していません。

## 応用・次の一手 {: .next }

**この記事の結論は2つです。**①前の記事が「簡潔にしてください」という書式指定だけで見つけた崩れは、別日の再実行（同じ指示文・同じ材料）では再現しませんでした。②書式指定を「表形式」「絵文字」に変えても、対策の一文の有無にかかわらず、今回は24回とも崩れませんでした。

⚠️ **②から「対策の一文は要らない」とは言えません。**この記事が確かめたのは「今回は崩れなかった」ことだけで、「今後も崩れない」ことではありません。前の記事の条件がもう一度崩れる可能性は残っています。対策の一文を外す判断はしないでください。

📌 **同じ指示文の再現性そのものについては**[監視対象を増やしても、古い記録は新着にしない](/recipes/unseen-does-not-mean-new/)と[前の記事](/recipes/backlog-scale-holds-brevity-breaks-it/)も参考にしてください。自動化のテンプレートに書式の指定を足すときは、1回確かめて終わりにせず、時期を空けてもう一度確かめることをおすすめします。

⚠️ **この記事が実測していないこと**は次の3つです。

- 表形式・絵文字以外の書式指定
- 過去分が数百件・数千件とさらに多い場合
- 材料を2本以外に増やした場合

実際に監視対象を追加する人は、最初の1回だけ、報告された件数と元の一覧を自分の目で見比べてください。
