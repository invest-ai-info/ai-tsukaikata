## これで何ができるか {: .what }

<mark>分割払いの入金が振込手数料ぶんだけ少なく着金していても、AIは合計の不一致を見逃しませんでした。</mark>材料は[前作](/recipes/three-way-split-does-not-break-the-match/)と同じ、架空のリフォーム工事12件・結婚式場12組です（一括6件・2回払い3件・3回払い3件が混在）。

- 前作は、入金が予定どおり全額そろっている状態を試しました
- 末尾で「入金額は予定額どおり（振込手数料の差引などで少しずれるケースは試していません）」と宿題を残していました

この記事はその宿題に答えます。

3回払いの1件だけ、入金を振込手数料相当（500円）少なくしました。

- **材料1（リフォーム工事）**：木村様の**完成金**（最後の回）が500円少なく着金
- **材料2（結婚式場）**：山口家の**中間金**（真ん中の回）が500円少なく着金
- 他の11件（11組）は、前作と完全に同じ金額・日付です

**材料2種×5回＝10回とも、不足した1件だけを正しく名指しで指摘しました。健全な11件（11組）を誤って不一致扱いした回は0回です。**

<mark class="warn">「500円という分かりやすい金額だから拾えたのでは」「確認してくださいと頼んだから拾えたのでは」という疑いも、それぞれ6回ずつ試して確かめました。</mark>この2つの架空の材料・全22回での実測です。確かめていないことは、記事の最後にまとめます。

| 必要なもの | 請求（契約）一覧と、入金明細の2つの表 |
| プログラミング | **不要**。この記事の指示文をコピーして貼るだけです |

<mark class="warn">口座番号や実在の顧客名は貼らないでください。</mark>入金明細は日付・氏名・金額の3列だけにしてください。この記事は架空の氏名・金額を使っています。実在の人物・団体とは関係ありません。

分割払いの入金照合そのものの基本的な挙動は[分割払いの入金照合を実測した記事](/recipes/installment-payments-add-up-correctly/)に、件数が増えたときの精度は[予約件数を3倍にした実測](/recipes/installment-scale-does-not-increase-misses/)にあります。単発の入金1行と請求1件を直接比べる場面での振込手数料ぶんの差額は[入金が合算されて未入金に見える記事](/recipes/combined-payment-missed-as-unpaid/)で確かめています。この記事が見ているのは「複数回の分割入金をAI自身が合計してから、その合計に手数料ぶんの差額が埋もれていないか」という、合算という一段階が挟まる場面です。

## AIへの頼み方 {: .ask }

### 1. リフォーム工事のデータで、完成金が500円少ない状態を試す

<div class="prompt">まだ入金されていない工事はどれですか。1件が複数回に分けて入金されることがあります。合計額が工事金額と一致するかどうかも確認してください。</div>

上に続けて、請求一覧と入金明細を貼ります。木村様（店舗改装・3,200,000円・3回払い）の完成金だけ、1,280,000円のはずが1,279,500円で着金している状態です。

**5回とも「木村様の1件だけ、残額500円」と正しく指摘しました。**

> 未入金（不足あり）の工事は、木村様の店舗改装の1件だけです。残額は500円です。
>
> 着手金30%（7/30入金）960,000円・中間金30%（8/15入金）960,000円・完成金40%（9/3入金）1,279,500円（本来1,280,000円）。入金合計3,199,500円。不足額500円。

他の11件（一括6件・2回払い3件・3回払い2件）を誤って不一致扱いした回は0回でした。

### 2. 結婚式場のデータで、中間金が500円少ない状態を試す

同じ指示文を、業種を変えて試します。山口家（プランH・1,950,000円・3回払い）の中間金だけ、585,000円のはずが584,500円で着金している状態です。

<div class="prompt">まだ入金されていないご家族はどれですか。1件が複数回に分けて入金されることがあります。合計額が請求額と一致するかどうかも確認してください。</div>

**こちらも5回とも「山口家の1件だけ、残額500円」と正しく指摘しました。**

> 未入金のご家族はありません。ただし、山口家に500円の不足があります。
>
> 着手金30%＝585,000円 → 7/29に585,000円入金（一致）。中間金30%＝585,000円 → 8/14に584,500円入金（**500円不足**）。完成金40%＝780,000円 → 9/2に780,000円入金（一致）。

🔑 **着手金・中間金・完成金の3行に分けて示し、不足が「真ん中の回」だと正しく特定しています。**最初と最後だけを見て判定しているのではなく、内訳の各回を個別に照合していることが分かります。

### なぜこの言い方が効くのか

**「合計額が一致するかどうかも確認してください」という一言が、AIに合算と突き合わせの両方をさせています。**分割払いの件は、1件ずつ単純に「入金済みか」を見るのではなく、複数回の入金を自分で足し算してから契約金額と比べる必要があります。この一言が、その足し算の工程を明示的に要求しています。

もう一つの理由は、500円という金額の性質です。契約額が数十万円から数百万円の規模に対して、500円という差は比率で見るとごくわずかです。それでも見逃されなかったのは、AIが「だいたい合っている」という近似判定ではなく、1円単位の厳密な一致を見ているからだと考えられます。この点は、下の実測でも確かめます。

## うまくいかないときの言い直し方 {: .fix }

### 500円という「分かりやすい額」だから拾えたのでは {: .trouble }

振込手数料としてよく見る金額（500円）だから、AIが「手数料ぶんかもしれない」とパターンで気づいた可能性を疑いました。そこで、不足額を437円という、振込手数料として典型的でない金額に変えて試しました。指示文は1文字も変えていません。

<div class="prompt">まだ入金されていない工事はどれですか。1件が複数回に分けて入金されることがあります。合計額が工事金額と一致するかどうかも確認してください。</div>

**材料1（リフォーム工事）で3回試しました。3回とも、437円という半端な不足額を正しく検出しました。**

> 入金が完了していないのは、木村様（店舗改装）の1件だけです。437円足りません。

同じ変更を材料2（結婚式場）にも適用します。

<div class="prompt">まだ入金されていないご家族はどれですか。1件が複数回に分けて入金されることがあります。合計額が請求額と一致するかどうかも確認してください。</div>

**こちらも3回とも、437円の不足を正しく検出しました。**丸い金額かどうかは、検出そのものには関係ありませんでした。

### 「確認してください」と頼まなくても拾うか {: .trouble }

指示文から「合計額が一致するかどうかも確認してください」という、照合を明示する一文を削りました。

<div class="prompt">まだ入金されていない工事はどれですか。1件が複数回に分けて入金されることがあります。</div>

**材料1で3回試しました。3回とも、頼んでいないのに自分から合計を照合し、500円の不足を正しく検出しました。**

> 未入金が残っているのは木村様（店舗改装）の1件で、残額は500円です。完成金が500円不足しています。振込手数料が差し引かれた可能性があるので、先方に確認するか、手数料負担の扱いを決めるとよいと思います。

材料2でも同じ短い指示文を試します。

<div class="prompt">まだ入金されていないご家族はどれですか。1件が複数回に分けて入金されることがあります。</div>

**こちらも3回とも、自分から合計を照合し、山口家の500円不足を正しく検出しました。**材料1・材料2を合わせて6回とも、照合を明示する一文が無くても見逃しませんでした。

<mark>「分割払いの件は合計を確認して」という指示そのものに、AIが自発的に反応している可能性があります。</mark>ただし、この一文を削ってよいという意味ではありません。指示を明示するほうが、何を確認したかが読む側にも伝わります。

## 応用・次の一手 {: .next }

**毎月の入金照合を自動にするなら、分割回数や差額の大きさを気にしすぎる必要はなさそうです。**この記事の範囲では、合算の工程が挟まっても、差額が丸い数字でなくても、見逃しは起きませんでした。定期実行の置き方は[「毎日決まった時刻に自動でやっておいて」をAIに作らせる記事](/recipes/github-actions-daily-cron/)にあります。

**それでも、検出した後の扱いまでは自動化しないでください。**今回の返りはすべて「振込手数料が差し引かれた可能性があります」と**推測**にとどめ、断定はしていません。先方に確認する・手数料負担の約束を確かめるといった判断は、人間が行う必要があります。

⚠️ **この結果は、この2つの架空の材料・のべ22回での実測です。**次の範囲は確かめていません。

- 不足額がさらに小さい場合（今回は437円・500円の2種類まで）
- 同じ請求の中に、手数料による差額と、本当の入金漏れが同時に混ざっている場合
- 分割回数が4回以上に増えた場合（[4分割・5分割の実測記事](/recipes/four-and-five-way-split-does-not-break-the-match/)は全額入金済みの前提でした）

今回の生の返り22回ぶんと判定コードは `docs/evidence/find-the-500-yen-gap-in-a-split-payment.md` に全文置いてあります。
