## これで何ができるか {: .what }

AIを使い始めて最初にぶつかる無駄が、これです。1件処理してもらって、次の1件で<mark>また同じ前置きを書いて、また待つ</mark>。20件あれば20回くり返します。

まとめて渡せば、<mark>説明は1回で済みます</mark>。しかも1件ずつのときより結果が揃います。同じ物差しで一気に処理されるからです。

<img src="/static/images/batch-vs-one.svg" alt="1件ずつ10回頼む場合と、10件まとめて1回頼む場合を比べた横棒グラフ。1件ずつ10回は、説明を書く時間が10回ぶん積み上がり、待ち時間も10回ぶんかかる。10件まとめて1回は、説明が1回ぶんで済み、待ち時間も1回にまとまる。待ち時間そのものは減らず、減るのは毎回同じ前置きを書き直すぶん。">
<figcaption>減るのは「毎回おなじ説明を書き直す」ぶんです。ここが一番もったいない時間です。</figcaption>

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 10分 |
| 費用 | 無料 |
| 必要なもの | どのAIでも使えます |
| プログラミング | **不要**。並べて渡すだけです |

## AIへの頼み方 {: .ask }

### 1. 基本の形 — 手順を1回、対象を並べる

<div class="prompt">同じ処理を複数の対象にまとめてやってください。

【やってほしいこと】
（1件ぶんの手順をここに1回だけ書く）

【対象】
1. （1件目）
2. （2件目）
3. （3件目）

結果は表にまとめてください。処理できなかったものは飛ばさず、理由を書いてください。</div>

<mark>最後の一文がこの記事で一番大事です。</mark>これが無いと、<mark class="warn">処理できなかったものが黙って結果から消えます</mark>。20件頼んで17件返ってきても、抜けた3件に気づきません。

### 2. 番号を返させて、抜けを機械的に見つける

数が多いときは、目で数えるのをやめます。

<div class="prompt">結果には、渡した番号をそのまま付けてください。

最後に「渡した件数」と「返した件数」を書いてください。数が合わない場合は、どの番号が欠けたかを列挙してください。</div>

<mark>自分で数えず、AIに数えさせて突き合わせます</mark>。人が20行を目で照合すると、必ずどこかで見落とします。

### 3. 1件だけ試してから、全部渡す

いきなり全件渡すと、間違った形で全件やり直しになります。

<div class="prompt">まず1件目だけやってください。

私が結果の形を確認してから、残りを渡します。この時点では他の対象に手を付けないでください。</div>

**「他に手を付けないで」まで書きます。**これが無いと親切心で全部やってしまい、確認の意味がなくなります。範囲の区切り方は[「ついでに整理しておきました」と言わせない頼み方](/recipes/limit-what-ai-touches/)にまとめました。

### 4. 揃わないときは、基準を先に決めさせる

まとめて頼むと、判断が混ざる作業では結果がばらつきます。

<div class="prompt">処理を始める前に、判断の基準を先に文章にしてください。

私が基準を確認してから、全件に同じ基準で適用してください。途中で基準を変えないでください。</div>

<mark>基準を先に出させると、あとで結果を疑わなくて済みます</mark>。おかしな結果が出ても、基準を直せば全件に効きます。

### 5. 毎回やっているなら、頼むこと自体をやめる

同じまとめ処理を毎週やっているなら、次の段階があります。

<div class="prompt">この作業を、毎週決まった時刻に自動で実行できるようにしたいです。

私はプログラムを書けません。私がやる作業を番号を振って書いて、作れるものはあなたが作ってください。</div>

ここから先は[「毎日決まった時刻に自動でやっておいて」をAIに作らせる](/recipes/github-actions-daily-cron/)に続きます。

## うまくいかないときの言い直し方 {: .fix }

### 途中で力尽きて、最後のほうが雑になった {: .trouble }

件数が多いと起こります。

<div class="prompt">後半の結果が雑になっています。10件ずつに分けて、1回目の10件からやり直してください。

各回の最後に「ここまで何件終わったか」を書いてください。</div>

<mark>1回で全部やらせようとせず、区切って渡すほうが結果は安定します</mark>。目安は10〜20件です。

### 表の形が途中から変わった {: .trouble }

<div class="prompt">表の列を最初に決めてください。列名だけ先に出して、私が確認します。

そのあと全件を、その列だけで埋めてください。途中で列を足さないでください。</div>

### 1件ずつのときより結果が浅くなった {: .trouble }

まとめると、1件あたりは浅くなることがあります。これは正直に切り分けてください。

<div class="prompt">まとめて処理したことで浅くなっていないか確認します。

いまの結果のうち、もっと詳しく見るべきものはどれですか。3件だけ選んで、その3件は1件ずつ詳しく処理し直してください。</div>

<mark>全部を深くやる必要はありません</mark>。まとめて処理して、重要なものだけ選び直すのが速いです。

### 途中でエラーになって全部消えた {: .trouble }

<div class="prompt">途中で止まりました。最初からやり直さず、止まった続きから再開してください。

どこまで終わっているかを先に教えてください。</div>

長い処理をさせる前に、途中結果を手元に貼っておくと安全です。

## 応用・次の一手 {: .next }

慣れたら、対象そのものをAIに作らせられます。

<div class="prompt">まず対象の一覧を作ってください。（どこから集めるか）

一覧ができたら私が確認します。そのあと、一覧の全件に同じ処理をしてください。</div>

もう1つ、まとめ処理は**比較**と相性がいいです。

<div class="prompt">対象を並べます。それぞれを同じ観点で評価して、比較表にしてください。

観点は（3つくらい）です。最後に、観点ごとに一番良かったものを教えてください。</div>

自分の仕事のどこにこの型が使えるかを探すなら、[渡せる作業の見つけ方](/recipes/find-what-to-delegate/)の「繰り返し」の型がそのまま入口になります。
