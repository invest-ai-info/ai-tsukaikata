## これで何ができるか {: .what }

[返事待ちの相手を毎朝出す](/recipes/who-has-not-replied-yet/)は、「確認します」「ご連絡します」とだけ返ってきた一次返信2件の行き先を、指示文のどれにも書いていませんでした。その記事はこう締めくくっています——「『書けば毎朝同じ答えになる』かどうかは、この24回では試していません」。今回はそこだけを引き継いで確かめました。同じ架空材料・同じ基本の指示文に、一次返信専用の受け皿を足して、**新規セッションで合計18回**通しています。結論は3つです。

1. **催促すべき本体の一覧（6件）は、18回のうち受け皿ありの14回で、1件も崩れませんでした。**宛先の中身まで14回とも完全に同じでした
2. **ただし「一次返信のみ・本回答待ち」という受け皿を足すと、8回中1回、具体的な回答が来ている相手までその受け皿に紛れ込みました。**人事課 早瀬さんは「8月18日までに配置案を出します」という日付入りの回答をもらっていたのに、一次返信扱いにされました
3. **受け皿の対象を「具体的な答えがあるか」で定義し直すと、早瀬さんの取り違えは新しい4回で再発しませんでした。しかし別の相手（三葉印刷 山口様）が、今度は別の受け皿〔決められない〕に1回だけ紛れ込みました**

| 版 | 何をしたか | 紛れ込みが起きた回数 |
|---|---|---|
| ① 受け皿なし | 前回記事の保存版をそのまま使う | 一次返信2件が本体に混入＝**4回中4回** |
| ② 一次返信のみの受け皿 | 「確認します」だけの返信を専用の見出しへ | 無関係な相手が紛れ込む＝**8回中1回** |
| ③ 答えの有無で定義し直す | 「具体的な答えが1つでもあるか」で判定 | 別の相手が〔決められない〕へ紛れ込む＝**6回中1回** |

📌 **この記事の数字はすべて架空データでの実測です。**材料は`who-has-not-replied-yet`の送信済み30行・受信25行（会社の総務課／お祭りの事務局）を1文字も変えずに再利用しました。各回は独立した新規セッション（毎回ゼロから起動・前の会話の記憶なし）で試しています。生の返りと機械照合は`docs/evidence/sort-holds-new-bucket-slips-once.md`に全文置いてあります。

## AIへの頼み方 {: .ask }

### 1. まず、受け皿なしの保存版をそのまま使う

前回記事の最後にたどり着いた「毎朝そのまま貼る保存版」です。一次返信の行き先は書いていません。材料A（会社の総務課）に、これをそのまま2回通しました。

<div class="prompt">毎朝の点検です。下の【送信済み】と【受信】から、私が送ったのに返事が来ていないものだけを出してください。
・1件1行で「送った日／宛先／件名／送った回数」の順。ほかには何も書かないでください。
・返事かどうかは件名の一致ではなく、受信の本文の冒頭がその用件の答えになっているかで決めてください。
・同じ用件を2回以上送っているものは1行にまとめてください。
・決められないものは〔決められない〕の見出しの下に、同じ形で並べてください。</div>

このあとに`【送信済み】`として送信の一覧を、`【受信】`として受信の一覧を、そのまま貼ります。<mark class="warn">2回とも、「確認します」「ご連絡します」としか返ってきていない一次返信2件（光陽通信・経理課）が、そのまま本体の催促一覧に混ざりました。</mark>件名は「Re:」付きで、受信自体はあります。字義どおりには「返事が来ていない」わけではないのに、具体的な答えがまだ無いという理由だけで、本当に未返信の5件と同じ並びに出てきます。もう一度送ると、「確認して折り返します」と答えたばかりの相手を、翌朝また急かすことになります。

材料B（お祭りの事務局）でも、同じ指示文をそのまま2回通しました。

・1件1行で「送った日／宛先／件名／送った回数」の順。ほかには何も書かないでください。

| | 1回目 | 2回目 |
|---|---|---|
| 〔決められない〕に出た件数 | 0件 | 4件（お礼・受領連絡のみの送信） |

🔑 **同じ指示文・同じ材料でも、「決められない」という1つの受け皿に、何を入れるかが回によって変わります。**一次返信という新しい種類の問題には、専用の行き先を作る必要がありそうです。

<div class="prompt">毎朝の点検です。下の【送信済み】と【受信】から、私が送ったのに返事が来ていないものだけを出してください。
・1件1行で「送った日／宛先／件名／送った回数」の順。ほかには何も書かないでください。
・返事かどうかは件名の一致ではなく、受信の本文の冒頭がその用件の答えになっているかで決めてください。
・同じ用件を2回以上送っているものは1行にまとめてください。

## うまくいかないときの言い直し方 {: .fix }

### 受け皿を作ると、答えが来ている相手まで吸い込まれる {: .trouble }

「受け皿は、作るだけでなく置き場所まで指定する」という、これまでの実測から積み上げた教訓は、もともと「どこに書くか」についてのものでした。今回分かったのは**もう1つ手前の問題**です——受け皿の**対象そのもの**が、思っているより広く効いてしまうことがあります。「確認します」という言葉を手がかりにした版（指示文2）では、同じ言葉を**含んでいない**早瀬さんの返信まで、8回中1回だけ引き寄せられました。

🔑 **受け皿を作ることは、仕分けを完成させることとイコールではありません。**受け皿が増えるたびに、その受け皿自身が新しい取り違えの経路になります。

### 「具体的な答えの有無」に直しても、別の相手が迷い込む {: .trouble }

指示文3で、早瀬さんの取り違えそのものは直りました。<mark class="warn">しかし、別の受け皿〔決められない〕に、三葉印刷という別の相手が1回だけ紛れ込みました。</mark>**1つの受け皿の精度を上げても、取り違えという現象そのものが消えるわけではなく、別の受け皿へ移ることがあります。**

📌 **この記事では、取り違えを完全に0にする指示文には行き着いていません。**[迷ったときの倒れ方をそろえる](/recipes/tilt-direction-per-judgment/)は「理由を書かないと、別の判定では逆に倒れる」ことを扱った記事です。今回は理由を書いても、別の場所で倒れました。受け皿を使う自動化では、**受け皿に入った行だけは、人が目を通す前提で運用するのが安全**です。

### 本体の一覧は、受け皿をどう作っても1件も崩れなかった {: .trouble }

ここまでは崩れた話ばかりでしたが、<mark>催促すべき6件の本体一覧は、受け皿ありの14回を通じて、宛先の中身まで完全に一致していました。</mark>崩れたのは、新しく作った受け皿の**周辺**だけです。振り分け先を増やす操作は、既存の判定ロジックまで巻き込んで崩すわけではなさそうです。

## 応用・次の一手 {: .next }

**受け皿は、作れば仕分けが終わるものではありません。**[返事待ちの相手を毎朝出す](/recipes/who-has-not-replied-yet/)が残した「書けば毎朝そろうか」という問いには、こう答えが出ました。**本体は8回とも1件も崩れないが、新しく足した受け皿のほうは、だいたい正しくても、ときどき想定外の相手を拾う。**自動実行に置くなら、受け皿（一次返信のみ・決められない）に入った行だけは、毎朝さっと目で見てから処理する運用にしておくと安全です。早瀬さんのような相手を取りこぼさずに済みます。

毎朝決まった時刻に走らせる仕掛けそのものは[毎日決まった時刻にAIを動かす仕掛けを作らせる](/recipes/github-actions-daily-cron/)にあります。渡した材料が正しい件数そろっているかは[定期実行させたAIが「本当に動いたか」を自分で確かめる形にする](/recipes/count-the-material-every-run/)の型で確かめられます。この型と組み合わせると、受け皿の中身が急に増えたときにも気づけます。

📌 **この記事は「同じ材料を繰り返し渡したときの揺れ」だけを測りました。**材料そのものが毎日少しずつ更新される運用でも同じ結果になるかは、この18回では試していません。
