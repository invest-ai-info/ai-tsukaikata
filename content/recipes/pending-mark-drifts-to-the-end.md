## これで何ができるか {: .what }

毎朝ひとりでに出す「返事待ちの一覧」に、**「確認します」だけの返信しか来ていない行**を分けて残す形です。[返事待ちの相手を毎朝出す](/recipes/who-has-not-replied-yet/)で、この2件の行き先が指示文にはどちらとも書いておらず、回ごとにばらばらだったと分かりました。<mark>今回はそこに「一覧から外さず、先頭に〔保留〕と付けてください」という一文を足し、印が毎回同じ行・同じ場所に付くかを実測しました。</mark>

結論は2つに分かれます。

1. **「どの行を保留にするか」は崩れませんでした。**架空の材料2本・指示文6通り・合計26回で、保留にすべき行を見落とした回は0件です。
2. **「保留をどこに書くか」は崩れました。**くだけた書式の材料では、指示文を強めても先頭に来ない回が残ります。

**材料A（表形式の一覧）は、5つの指示文バージョン・24行すべてで先頭に来ました。**一方**材料B（走り書きの一覧）は、同じ指示文を強めても71.4%（20/28行）止まり**です。③の版だけを見ると6/6で「直った」ように見えますが、同じ束ねに1点（単位の見本）を足しただけの④で2/4に戻っています。<mark class="warn">生成の指示文を詳しくする方向では、この揺れに決着がつきませんでした。</mark>

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 20分 |
| 費用 | 無料。無料のチャットAIで足ります |
| 必要なもの | ブラウザで使えるAI（ChatGPT・Claude・Geminiなど）と、送信済み・受信の2つの一覧 |
| プログラミング | **不要** |
| 前提の記事 | [返事待ちの相手を毎朝出す](/recipes/who-has-not-replied-yet/)（この記事の指示文は、あちらの保存版の末尾を書き換えたものです） |

⚠️ **この記事は「印の位置」だけを測っています。**どの行が返事待ちか、同じ用件をどう1行にまとめるかは前提の記事の実測どおりです。印の中身（〔本文未読〕）を1行目に固定する実測は[材料が足りない日に印を残させる](/recipes/mark-the-ones-not-read/)で先にやっていて、あちらは160件中160件が崩れませんでした。今回は**別の出力の形（1件1行の抽出）で同じ「位置の固定」を試す**追加実験です。

📌 **数字はすべて架空データでの実測です。**材料は前提の記事と同じ送信済み30行・受信25行を2本（会社の総務課・表形式／地域のお祭りの事務局・走り書き）、それぞれに「確認します」「折り返します」だけの一次返信を2件ずつ仕込んであります。

## AIへの頼み方 {: .ask }

### 1. まず、先頭に付けてと指定するだけ

<div class="prompt">毎朝の点検です。下の【送信済み】と【受信】から、私が送ったのに返事が来ていないものだけを出してください。

・返事かどうかは件名の一致ではなく、受信の本文の冒頭がその用件の答えになっているかで決めてください。
・同じ用件を2回以上送っているものは1行にまとめてください。
・「確認します」「折り返します」のように、本回答ではない一次返信だけが来ているものは、一覧から外さずに行を残し、先頭に〔保留〕と付けてください。</div>

このあとに `【送信済み】` `【受信】` の一覧をそのまま貼ります（前提の記事と同じ貼り方）。

**材料2本×各4回＝8回**試しました。**保留にすべき2件は、8回とも一覧から落ちませんでした。**ただし3種類の崩れが出ます。

- **材料Bの3・4回目、印が行の末尾に付きました。**「先頭に」と書いたのに、です

🔑 **3の3/3は「直った」ではなく、揺れの範囲内でたまたま揃っていただけでした。**指示文を1点増やすだけで同じ揺れが戻ってきます。

## うまくいかないときの言い直し方 {: .fix }

### くだけた書式の材料だけ、印が末尾に付く {: .trouble }

1〜4を通して、**材料A（表形式）は5つの指示文・24行すべてで先頭に来ましたが、材料B（走り書き）は指示文を強めても71.4%止まり**でした。生成の指示文を増やす方向を諦め、**出したあとに自分で見直させる1文**を足しました。

<div class="prompt">毎朝の点検です。下の【送信済み】と【受信】から、私が送ったのに返事が来ていないものだけを出してください。
・前置きや説明は書かず、1行目から一覧だけを出してください。
・1件1行で「送った日／宛先／件名／送った回数（◯回）」の順。1つの用件は一覧に1回だけ出してください。
・返事かどうかは件名の一致ではなく、受信の本文の冒頭がその用件の答えになっているかで決めてください。
・同じ用件を2回以上送っているものは1行にまとめてください。
・「確認します」「折り返します」のように、本回答ではない一次返信だけが来ているものは、一覧から外さずに行を残し、行の先頭（送った日の前）に〔保留〕と付けてください。例: 〔保留〕2026-08-05／光陽通信 白鳥様／オフィス移転時の回線工事の可否／1回
・一覧を作ったら、〔保留〕が行の先頭に来ているかを自分でもう一度確認し、先頭に来ていない行があれば直してから出してください。</div>

**材料Bで3回試して、3回とも先頭でした。**⚠️ 3の版も3/3だったので、この3回だけでは「自己確認が効いた」とは言い切れません。それでも**生成の指示を強める層とは別の層（出力の見直し）を足している**ので、本文の最終形にはこの1文を残しています。**回数を増やして確かめる価値がある部分**です。

### 方針を示している返信にまで〔保留〕が付く {: .trouble }

4の版で、「8月18日までに配置案を出します」という前向きな返信にまで〔保留〕が付きました。保留にしてよい条件を狭めます。

<div class="prompt">毎朝の点検です。下の【送信済み】と【受信】から、私が送ったのに返事が来ていないものだけを出してください。
・前置きや説明は書かず、1行目から一覧だけを出してください。
・1件1行で「送った日／宛先／件名／送った回数（◯回）」の順。1つの用件は一覧に1回だけ出してください。
・返事かどうかは件名の一致ではなく、受信の本文の冒頭がその用件の答えになっているかで決めてください。
・同じ用件を2回以上送っているものは1行にまとめてください。

### 一度直った版が、次の回でまた崩れる {: .trouble }

③の3/3を見て「これで決まり」と置いてしまうのが、この記事でいちばん危ない誤りです。<mark class="warn">同じ束ねの指示文に1点足しただけの④で、材料Bはまた2/4に戻りました。</mark>⚠️ **少ない回数で「直った」と判定しないでください。**[2回ぶんの出力を自分で見比べる](/recipes/compare-two-runs-yourself/)の型どおり、**材料を変えて複数回試してから判断する**のがここでも効きます。

## 応用・次の一手 {: .next }

**まず、くだけた書式の一覧をそのまま使っているなら、位置の崩れを疑ってください。**表形式の一覧（タブ区切りなど）に揃えられるなら、材料Aと同じように先頭が安定する見込みが高くなります。揃えられない日報や走り書きのまま使うなら、**生成の指示文を増やすより、出したあとに自分で見直させる1文を足す**ほうを先に試してください。

毎朝の自動実行に置くなら、[渡した材料を毎回数えさせる](/recipes/count-the-material-every-run/)を継ぎ目に置き、送信済みが30行あるはずの朝に20行しか貼られていなくても気づける形にしてください。

📌 **この記事は「印の位置」だけを測りました。**「保留にしてから何日経ったら本当に催促するか」は[返事待ちの相手を毎朝出す](/recipes/who-has-not-replied-yet/)でも一度も測っていません。日数の線を引くなら、それは別の記事になります。
