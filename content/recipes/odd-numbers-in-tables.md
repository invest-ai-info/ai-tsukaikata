## これで何ができるか {: .what }

Excelで作った表を人に出す前、ひととおり目で追って「たぶん大丈夫」で送っていませんか。その点検はAIに渡せます。表をそのまま貼って、探してほしい種類を指定するだけです。

ただし、頼み方でほとんど決まります。<mark>「この表でおかしい数字を見つけて」とだけ頼むと、返ってくるのは見た目が派手なものだけです</mark>。桁が1つ多い数字、1行だけ単位の違う金額、マイナスの数字は出ます。出ないのは、合計欄と中身のズレや、二重に数えている行のほうです。

<figure class="figure">
<img src="/static/images/table-anomaly-types.svg" alt="表に混ざる異常を6種類に分けた図。桁のミス（他の月の10倍の数字が1つ）、単位の混ざり（1つの行だけ円で他は千円）、符号（売上の列にマイナス）、空欄（1か月だけ何も入っていない）の4つは、数字そのものが目立つので目で見つかる。合計欄のズレ（合計欄と12か月の和が3,000違う）と行の重複（同じ数字の行が別の名前で2つある）の2つは、1つ1つの数字が正常に見えるため、足し直すまで見えない。この2つは探す種類として名指しするまで指摘に出てこない。">
<figcaption>下の2つは、セル1つを見ても異常に見えません。だから「探して」と言うだけでは出てきません。</figcaption>
</figure>

<mark>金額の被害が大きいのは、たいてい目で見つからないほうの異常です</mark>。合計が3,000ずれた表は、そのまま会議資料になります。

この記事の指示文は、異常を7つ仕込んだ架空の売上表（6支店×12か月＋合計）で1つずつ試したものです。

## 前提 {: .need }

| | |
|---|---|
| かかる時間 | 15分 |
| 費用 | 無料。無料のチャットAIで足ります |
| 必要なもの | ブラウザで使えるAI（ChatGPT・Claude・Geminiなど） |
| プログラミング | **不要**。表をコピーして貼るだけです |

Excelの範囲を選んでコピーし、チャット欄に貼れば表として渡ります。ファイルを添付できるAIならファイルのままでもかまいません。

⚠️ 社外に出せない数字が入っている表は、そのまま貼らないでください。支店名を A・B・C に置き換える、金額の桁をそろえて別の値にする、といった前処理が必要です。<mark class="warn">貼ってしまった数字は取り消せません</mark>。

## AIへの頼み方 {: .ask }

### 1. 探す前に、この表をどう読んだかを書かせる

いきなり探させないのがコツです。表の読み違いは、指摘の中身より先に起きます。

<div class="prompt">これから数字の表を渡します。異常を探す前に、まずこの表をどう読んだかを書いてください。

・列がいくつあり、それぞれ何を表していると読んだか
・行がいくつあり、どれがデータでどれが合計か
・金額の単位が表のどこかに書いてあるか。書いていないなら「書いていない」と書く
・空欄がいくつあるか

ここまで書いたら止まってください。私が確認してから、探し始めてください。</div>

この一手間で出てくるものが2つあります。1つは単位がどこにも書いていないこと。もう1つは、似た名前の行が2つ並んでいることです。架空の表では「大阪」と「大阪支店」という行が両方あり、この段階で名前として指摘されました。<mark>異常探しを始めてしまうと、行の名前は誰も見なくなります</mark>。

「止まってください」まで書くのは、確認の意味を残すためです。範囲の区切り方は[「ついでに整理しておきました」と言わせない頼み方](/recipes/limit-what-ai-touches/)にまとめてあります。

### 2. 「おかしい」を6種類に割って、種類ごとに探させる

ここが一番効きます。「おかしい数字」は曖昧すぎて、目立つものだけが返ってきます。

<div class="prompt">次の6種類に分けて、種類ごとに探してください。

1. 桁のミス（同じ行の他の数字とくらべて10倍・100倍になっているもの）
2. 単位の混ざり（1つの行や列だけ単位が違うもの）
3. 空欄（未入力なのか、0という意味なのかが分からないもの）
4. 行や列の重複（同じ数字が別の名前で2回入っているもの）
5. 符号（プラスのはずの列にマイナスが入っているもの）
6. 合計の不一致（合計欄と、中身を足した値が違うもの）

種類ごとに見出しを立ててください。該当が無い種類は「該当なし」と必ず書いてください。飛ばさないでください。</div>

<mark>「該当なしと必ず書く」の一文が、種類を飛ばさせない仕掛けです</mark>。これが無いと、見つかった種類だけが並び、探していない種類と探して無かった種類の区別がつきません。

架空の表では、この指定を入れて初めて4番（重複行）と6番（合計欄のズレ）が出ました。種類を指定せずに「おかしい数字を見つけて」と頼んだときには、どちらも出ていません。

### 3. 平均で判定させない

「平均から大きく離れた数字を挙げて」は、一見よさそうで外します。<mark class="warn">平均で判定させると、探している誤入力そのものが基準を動かして取りこぼします</mark>。

<figure class="figure">
<img src="/static/images/table-average-pulled.svg" alt="東京支店の月次売上12か月を数直線に並べた図。9月を除く11か月は44,800から61,200の間にかたまっていて、中央値は49,650。9月だけ482,000という誤入力が入っており、目盛りの外にあるため図には点として出ていない。その1つのせいで平均は50,609から86,558まで右へ動き、12か月のうち11か月が平均より下という状態になる。平均を基準に異常を探すと、この動いた平均が基準になってしまう。">
<figcaption>誤入力1つで平均は 50,609 から 86,558 へ動きます。動いたあとの平均を基準にすると、正常な11か月のほうが「平均より下」に並びます。</figcaption>
</figure>

「平均から3.5倍のばらつき以上離れたもの」（統計の言葉でいう標準偏差の3.5倍）といった条件を付けるのも、数字が12個しかない列では効きません。**12個の数字では、ばらつきの何倍離れられるかに上限があり、どう並べても3.4倍には届きません。**条件を3.5倍にすると、どれだけ極端な誤入力でも該当0件になります。実際、架空の表で3.5倍を条件にすると「異常なし」と返ってきました。

代わりにこう頼みます。

<div class="prompt">各行について、まん中の値（中央値）を出してください。

そのうえで、中央値の3倍以上、または3分の1以下になっている月だけを挙げてください。中央値そのものも一緒に書いてください。</div>

この言い方に変えると、架空の表では仕込んだ3件（桁のミス・単位の混ざり・マイナス）がちょうど出て、正常な行からは1件も出ませんでした。<mark>まん中の値は、誤入力が1つ混ざっても動きません</mark>。だから基準として使えます。

### 4. 「確実におかしい」と「気になるだけ」を分けさせる

見つかったものは、性質が2つに分かれます。混ぜて出されると、どれを追えばいいのか決められません。

<div class="prompt">見つけたものを2つに分けてください。

A：表の中だけで矛盾しているもの（表の外を調べなくても、間違いだと言い切れる）
B：気になるだけのもの（実際にそうだった可能性があり、表の外を確認しないと判断できない）

それぞれ、なぜそちらに入れたかを1行で書いてください。</div>

この分け方を頼むと、Aに入るのは合計欄のズレと、二重に数えている行だけでした。突出して大きい金額もマイナスの数字も、空欄も、Bに回されます。<mark>けたはずれに大きい数字は、表の中だけでは間違いだと言い切れません</mark>。大口の受注が本当にあったのかもしれないからです。

Aから先に片付けます。Aは表を見れば決着がつき、Bは人に聞かないと決着がつきません。

### 5. 指摘には、セル・表の数字・計算を書かせる

「不自然です」「高すぎます」だけの指摘は、確かめようがありません。

<div class="prompt">指摘は、次の3つを必ず書いてください。

・どの行のどの列か（行名と列名で）
・表に書いてある数字をそのまま
・そう判断した計算（何と何を比べて、差がいくつか）

「不自然です」「高すぎます」のように、数字を伴わない指摘は書かないでください。</div>

これを入れると、「名古屋の合計が少しずれているようです」ではなく「名古屋の合計欄は 274,700、12か月を足すと 271,700、差は 3,000」という形になります。<mark>差が数字で出ていれば、こちらが電卓で確かめられます</mark>。数字を伴わない指摘は、正しいかどうかを確かめる手段がありません。

数字の根拠を出させる言い方は[AIに数字を「それっぽく」埋めさせないための頼み方](/recipes/numbers-not-in-the-source/)にまとめてあります。

### 6. 合計欄は信じさせない。足し直させる

合計欄は、Excelの式ではなく手入力になっていることがあります。式が入っていても、範囲が1行ずれていることがあります。

<div class="prompt">合計欄は、書いてある値をそのまま信じないでください。

各行について、中身を1つずつ足し直してください。足し上げの途中経過も書いてください。そのうえで、表の合計欄と足し直した値を並べて比べてください。

全部一致した場合は「◯行とも一致」と行数つきで書いてください。省略しないでください。</div>

<mark class="warn">概算で見ると、3,000のズレは見つかりません</mark>。2万台の数字が12個なら合計は26万前後で、274,700 も 271,700 も同じくらい「それらしく」見えるからです。ざっと見て違和感が出ないものは、足し直すしかありません。

「全部一致したなら行数つきで書く」を足すのは、静かに飛ばさせないためです。確認したと言わせない頼み方は[AIに「たぶん動きます」と言わせないための頼み方](/recipes/verify-before-report/)に詳しく書きました。

### 7. 見つけるだけにさせる。直させない

頼まないと、直した表まで返ってきます。これは受け取ってはいけません。

<div class="prompt">見つけるだけにしてください。直した表は出さないでください。

どう直すかは私が決めます。直し方の案を書くのはかまいませんが、直したあとの表そのものは作らないでください。</div>

<mark class="warn">直した表を受け取ると、推測で埋められた数字が混ざります</mark>。桁が1つ多い 482,000 を見て 48,200 に直した表が返ってきますが、正しい値が 48,200 なのか 42,800 なのかは、元の伝票を見ないと誰にも分かりません。<mark>直った表は、直っているように見えるぶんだけ危険です</mark>。

## うまくいかないときの言い直し方 {: .fix }

### 指摘が多すぎて、どれから見ればいいか分からない {: .trouble }

6種類で探させると、細かい指摘まで全部出ます。絞り方を指定します。

<div class="prompt">指摘が多いので絞ってください。

「このまま人に出すと、数字が間違ったまま伝わる」ものだけを残してください。それ以外は、種類と件数だけ書いてください。</div>

**件数だけ残させるのが要点です。**消してしまうと、あとで「あれは指摘されていたのか」が分からなくなります。

### 正常な数字まで「異常」と言われる {: .trouble }

事情を知らないので当然です。事情を渡して、次から黙らせます。

<div class="prompt">指摘のうち、次のものは正常です。理由も書きます。

・（項目）＝（正常である理由）

この前提を足して、もう一度判定し直してください。次からも同じ理由のものは指摘しないでください。</div>

### 「特に問題ありません」で終わった {: .trouble }

本当に無いのか、探していないのかが区別できません。

<div class="prompt">「問題ありません」だけでは、探した結果なのか探していないのかが分かりません。

6種類のそれぞれについて、何をどう調べた結果として該当なしなのかを書いてください。表だけでは判断できない種類があれば、それも「表だけでは判断できない」と書いてください。</div>

<mark>0件は結論ではなく、確かめるべき報告です</mark>。単位が表に書かれていない表では、単位の混ざりは本来「表だけでは判断できない」が正しい答えになります。

### 見つけるだけと言ったのに、直した表が返ってきた {: .trouble }

<div class="prompt">直した表は使いません。私が渡した表は1文字も変えないでください。

指摘の一覧だけを、もう一度出してください。表は貼り直さないでください。</div>

### 行が多いと、後ろのほうが雑になる {: .trouble }

<div class="prompt">行数が多いので、10行ずつに区切って進めてください。

1回ごとに「何行目から何行目まで見たか」を書いてください。全部終わったら、見た行数の合計と、表の行数が一致しているかを確認してください。</div>

数が多いものをまとめて処理させるときの区切り方は[同じ指示を何回もコピペしているなら、まとめて1回で頼める](/recipes/batch-instead-of-repeat/)にまとめました。

## 応用・次の一手 {: .next }

同じ表を毎月作っているなら、点検も毎月同じで済みます。前回の指摘をそのまま渡すのが速いです。

<div class="prompt">先月この表を点検したときの指摘を貼ります。

（先月の指摘をそのまま貼る）

今月ぶんの表を渡すので、まず先月と同じ間違いが再発していないかだけを先に見てください。そのあとで、それ以外の異常を6種類で探してください。</div>

人から受け取った表にも同じ点検が使えます。作った人には聞きにくい確認を、先に済ませられます。

<div class="prompt">他の人が作った表を受け取りました。私はこの表の作り方を知りません。

この表を、作った人に質問しないと分からないことと、表だけで確かめられることに分けてください。質問が必要なものは、そのまま送れる質問文にしてください。</div>

数字の点検は、自分の仕事の中で「チェック」の型に当たります。他にどんな作業を渡せるかを探すなら、[渡せる作業の見つけ方](/recipes/find-what-to-delegate/)がそのまま入口になります。
