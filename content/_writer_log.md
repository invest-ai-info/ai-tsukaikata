# レシピ担当の日次ログ（沈黙禁止）

**編集者向けの内部メモ。サイトには出ない**（ファイル名が `_` で始まるのでビルド対象外）。

毎晩、**書けた本数が0でも1ブロック書く。**書かないこと自体が異常の合図になる設計。
稼ぎ方研究担当の作業ログ（`_earn_research.md`）と同じ流儀で、**番人はここだけを見る。**

## 🔢 書き方（この2行は必須。番人が読む）

```
### YYYY-MM-DD
- 公開: N本（slug を並べる。0本なら「0本」と書く）
- 実測: <何で実測したか／止めたなら理由>
```

⚠️ **`- 実測:` は回ごとに1行。**1日に複数の回がある（実測で確認＝14:15の回と21:00の回）。
**回のぶんだけ行を足すこと**——番人は全部の行を見る。1行にまとめると2回目の異常を見落とす。

**止まったときは、原因を2種類に分けて書く。ここが番人の要。**

| 書く文字列 | 意味 | 番人 |
|---|---|---|
| `❌環境` | **実測の相手を立てられない**（★91）。題材を替えても同じところで止まる | 🚨 **鳴る** |
| `❌題材` | 見立てが再現しない・設計が測れない。題材を替えれば直る | 鳴らない（健全） |

🔑 **混ぜないこと。**過去の停止記録4件のうち3件は健全な `題材` で、
環境は1件だけだった。混ぜると偽陽性75%になり、検査全体が読まれなくなる。

📌 **番人＝`tools/check_freshness.py`**（`writer_log_heartbeat` / `writer_measurement_gaps`）。
2日ぶん記録が空くと鳴る（1晩休んでも鳴らない＝0番による正常な停止があるため）。
`❌環境` は直近7日ぶんだけ鳴る（直った後も鳴り続けさせない）。

## 🛠 実測の相手が立てられないときに試す順（★91）

1. **`claude --safe-mode --tools "" -p "<指示文>"`** ← 実績あり。
   `--safe-mode` は CLAUDE.md・skills・plugins・履歴を全部無効化するので、
   別セッションより厳密に事前知識ゼロ。⚠️ **`--bare` は認証が通らない**
   （多段の会話は `--session-id <uuid>` で発行して `--resume` で続ける）
2. **Agentツール `general-purpose`**（同一セッション内の新規サブエージェント）
3. **`mcp__Claude_Code_Remote__create_session`**

🚨 **3つとも塞がったら、材料を作る前に止めてよい**（★84の系列）。
そのときは `- 実測: ❌環境 — <エラー文面>` と書く。**キューの項目は `- [ ]` のまま残す**
（`- [!]` にすると原因が直っても再試行されない）。
